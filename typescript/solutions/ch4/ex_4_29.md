# Exercise 4.29: memoization speed difference

## Approach

The same counting session runs under the section's memoized evaluator and
under a twin whose delayOperand always answers false, so every operand
delays into a recomputing wrapper and every forcing re-evaluates.
`(square (id 10))` feeds one thunk to the two demand sites of `*`, and
`(cube (id 10))` feeds one thunk to three demand sites. The counters
measure each discipline; the values agree because memoization changes how
often the body runs, not what it computes.

## Numbers

Memoized: `100`, count `1`, then `1000`, count `2`. Unmemoized: `100`,
count `2`, then `1000`, count `5`. The counts match both approved
siblings.

## Class and deviations

Translated row. Deviation: the slowness is measured in forcing counts on
the counting identity, the same measure the ocaml sibling chose, rather
than a wall-clock benchmark, so the pin is deterministic.
