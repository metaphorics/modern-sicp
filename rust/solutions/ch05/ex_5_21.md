# Exercise 5.21: count-leaves machines over the list memory (T)

## Approach

Both machines are 5.2 controllers over the 5.3.1 memory primitives:
`car`, `cdr`, `null?`, and `pair?` come from `memory_operations`, and
one counting `+` is added for the number registers. The tree is built
in the memory with real `cons` calls, and a register carries the tree
as a typed pointer word.

The two variants keep the two source definitions distinct. The first
machine is the recursive `count-leaves` whose value is the `+` of two
recursive calls: each pair level saves its continue, its pair, and
then the car side's count, and joins the two subcounts with `+` on
the way back. The second machine is the book's `count-iter`: one
explicit counter `n` threads through the whole recursion, the car
side counts starting from the running total, and the cdr side counts
starting from the car side's answer, so `+ 1` happens only at leaves
and nothing is ever joined.

Both run on the unmodified 5.2 simulator.

## Map class

`T`.

## Sample answer

Both machines answer 4 on `((1 2) 3 4)`, the list of Figure 5.14,
and 4 on `(1 (2 (3 4)))`, whose nesting sits on the cdr side. The
base cases: the empty list counts 0 and a bare number counts 1. The
first machine's measured cost on `((1 2) 3 4)` is 15 pushes and a
maximum stack depth of 6: five pair levels, each saving a continue,
a tree, and then the car count.
