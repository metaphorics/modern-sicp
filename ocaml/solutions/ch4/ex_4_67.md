# Exercise 4.67 — a loop detector for the query system (translate)

The detector is a variant rule-application path in the solution module:
a variant evaluator (`qeval_loop_safe` with `simple_query`, `conjoin`,
`disjoin`) that threads a history — one (pattern, frame) pair per rule body
now being processed on the current deduction chain. Before a renamed
rule's body is evaluated in its unified frame, the body is instantiated in
that frame with every unbound variable contracted to one wildcard symbol;
if that shape already occurs in the history, the system would begin
processing a query it is already working on, so the branch fails (the cut
is counted). The wildcard makes the comparison immune to rule-variable
renaming, which is what defeats literal (pattern, frame) equality: a
looping chain's frames grow — fresh renamed bindings every round — while
the deduction the system is effectively re-running repeats exactly. On the
married Minnie Mickey data base with its symmetric rule, the chain's keys
are `(married ?_ Mickey)`, then `(married Mickey ?_)`, then
`(married ?_ Mickey)` again — the third equals the first, the branch is
cut, and the answer the assertions still supply, `(married Mickey
Minnie)`, is delivered once and the query terminates. The stock evaluator
answers the same value and then re-derives it endlessly; a `take(3)` shows
three re-derivations.

Two finite regressions show the answers still come: `wheel` and
`outranked-by (Bitdiddle Ben)` under the detector return exactly the stock
answers (5 rows; `(Warbucks Oliver)`) — the detector prunes only chains
repeating a deduction already on the stack. (For outranked-by the detector
cuts the level-3 chain whose stock continuation produces no answers, so
nothing observable changes.)

Asserted answers (verbatim):

```
married Mickey ?who with the loop detector: 1 answer(s), 1 deduction chain cut, terminates
(married Mickey Minnie)
stock evaluator, take(3) of the same query -- the loop re-derives the answer forever:
(married Mickey Minnie)
(married Mickey Minnie)
(married Mickey Minnie)
wheel under the detector: 5 answers, identical to stock: true
outranked-by under the detector: 1 answer(s), identical to stock: true
```

Deviation: the detector lives in the solution module over the exported
layers (`find_assertions`, `fetch_rules`, `unify_match`, `rename_variables_in`,
`stream_flatmap`, `interleave_delayed`), the edition's analogue of
modifying 4.4.4's `apply-a-rule`. It covers simple queries, `and`, `or`,
and `always-true`; `not`/`lisp-value` would thread the same history
through their handlers unchanged. The wildcard comparison may collapse
duplicate derivation routes of one answer (multiplicity, not the answer
set) — the redundancy exercises 4.65/4.66 treat as noise.
