## Exercise 2.93: a rational function that does not reduce

Approach: [Rat] (numerator and denominator, any two tower values) is the
package's value, installed under the tag `rational-function` rather than
reusing the tower's own exact rational `QRat`, since that stays a
distinct, always-reduced level. [installRationalFunctionPackageBase]
takes the `makeRat` constructor as a seam (exercise 2.93's own install
passes through `{ n, d -> Rat(n, d) }`, never reducing), and every
operation (`add`/`sub`/`mul`/`div`) is the book's cross-multiplication
form, e.g. `add`'s numerator is `n1*d2 + n2*d1` over `d1*d2`, dispatched
through the generic `add`/`mul` so the numerator and denominator
arithmetic itself is generic over whatever `Num` level they hold.
`ex_2_93` builds `(x^3+1)/(x^2+1)`, adds it to itself, and shows the
unreduced result: the shared factor `x^2+1` still sits in both parts,
as `(2x^5+2x^3+2x^2+2)/(x^4+2x^2+1)`.

Class: A, per the map; a rational-function package generic over its
coefficient type needs the seam `installRationalFunctionPackageBase`
provides so exercise 2.97 can later swap in a reducing `makeRat` without
touching this file.

Deviation: the `add` handler was originally written as a direct sum of
numerators (`n1 + n2`), which only happens to answer correctly when both
operands share a denominator (as `rf + rf` does), found by a failing
test once exercise 2.97 exercised `add` on operands with genuinely
different denominators, and fixed to the book's cross-multiplication
form shown above; `ex_2_93`'s own doubled-`rf` expectation was updated
to the (larger, still unreduced) value the corrected `add` actually
produces.
