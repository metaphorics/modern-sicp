# Exercise 3.24: the table with a caller's key test

## Approach

The book's table constructor takes a `same-key?` predicate instead
of defaulting to `equal?`. The Rust solution adds the predicate as a
per-table field of the section's `Table`: `with_same_key` builds a
table whose `assoc` consults the caller's comparison. The solution
builds a table of measurements whose keys count as the same when
they lie within 0.1 of each other, stores under `100.0` and `200.0`,
and looks up `100.05`, answering the stored 1, and `150.0`,
answering nothing. The tests also confirm a default-built table
still uses structural equality, so the argument table and the
ordinary table coexist.

## Map class

`A: table state shared via RefCell`. The table's record list remains
shared and mutable under `Rc`. Each table stores the comparison predicate
used for its lookups.

## Deviation

None. The near-key scenario is the book's own measurement example,
and the boundary behavior is the statement's requirement.
