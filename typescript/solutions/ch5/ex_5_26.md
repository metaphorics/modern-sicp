# Exercise 5.26: stack behavior of the iterative factorial

Each row is measured, not stated: a session defines the iterative `factorial` of 1.2.1, calls it with `n`, and reads the stack counters of that final interaction. The counters are captured the way the book's 5.4.4 monitored driver does it, between `print-result` and the value announcement, because the next trip through the driver loop initializes the stack and would erase them.

The measured table for n = 1 to 6 is 64, 99, 134, 169, 204, and 239 pushes, the line `35n + 29`, and the maximum depth is the constant `10` for every row, exactly the independence the exercise's part (a) asks about: the iterative process keeps its state in `product` and `counter` and the argument list, never in a growing nest of saved registers. The test pins the n = 5 row at 204 pushes and depth 10, and checks every row against both constants.
