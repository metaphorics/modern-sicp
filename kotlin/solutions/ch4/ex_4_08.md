# Exercise 4.8: named let

## Approach

The parser rejects the named shape `(let name bindings body)` (a symbol
in the bindings slot) before the evaluator could see it, so the
derivation starts one level down: [namedLetExpansion] walks the read data
and renames the named shape to `named-let` (quoted data untouched, pinned),
which the parser then delivers as the application the `step` seam expects.
[namedLetToCombination] derives it to the set!-based wrapper
`((lambda (name) (set! name (lambda bindings body)) (name inits))
'*named-let*)`, pinned structurally. The set! shape is required: the
wrapper's frame binds `name`, the `set!` installs the loop procedure into
that binding, and the body's recursive self-calls resolve it there; a
direct `((lambda (name) ...) (lambda (name) ...))` nesting would shadow
`name` in the application frame and leave the self-calls unbound. Plain
`let` keeps its own derivation, and the loop name stays local: the wrapper
`set!` never touches an outer binding of the same name.

## Map class

`T`.

## Deviation

The datum-level rename is this host's parse seam: the book installs the
clause inside eval, but eval never receives the named shape here because
parsing is a typed pass. The wrapper, the derivation, and the pins are the
exercise's.

## Answer

The book's named-let Fibonacci, `(let fib ((n 10)) (if (< n 2) n (+ (fib
(- n 1)) (fib (- n 2)))))`, => 55. With `(define fib 7)` outside, the named
loop still answers 1 for `(let fib ((n 2)) (if (< n 2) n (fib (- n 1))))`
and the global `fib` remains 7; plain `let` answers 3 for the nesting probe.
