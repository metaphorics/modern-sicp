# Exercise 5.36: operand evaluation order (T)

## Approach

Compile and execute `(list (record 1) (record 2))` twice, with the
compiler configured for its default order and for left-to-right order.
The `record` primitive logs each operand evaluation, while the final
list checks that argument-list construction preserves source order.
The alternate compiler path uses end-adjoin when building `argl`,
which compensates for evaluating operands in the opposite direction.

## Map class

`T`.

## Sample answer

The default compiler evaluates operands right to left, recording `[2,
1]`; the modified compiler records `[1, 2]`. Both executions produce
`(1 2)`, and the generated blocks have equal line counts. The order is
determined in the compiler's combination code generation, not by the
list primitive.
