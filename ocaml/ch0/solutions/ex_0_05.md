# Exercise 0.5 — three fallible steps under Result.bind

The three steps each return `(_, string) result`, so they compose with
`Result.bind` without any per-step case analysis; only the final line
matches, to turn the chain's `Ok`/`Error` into one plain string:

```ocaml
match Result.bind (Result.bind (parse_age s) check_age) describe_age with
| Ok msg -> msg
| Error e -> "age check failed: " ^ e
```

Two details worth knowing:

- `Stdlib.Result.bind` takes the result first and the step second, so chains
  read inside-out rather than left-to-right. The book's chapter 4 error
  channel uses the same `(_, error) result` shape.
- The error values are plain strings here so the exercise can stay focused on
  the chaining; the section 0.8 variant shows the same chain carrying a
  variant error and rendering it with a `match`.

The tests pin the success path and both failure paths, including which step
failed: `"abc"` dies in `parse_age`, `"200"` in `check_age`, and the summary
always names the failure, never the step index.
