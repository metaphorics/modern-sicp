# Exercise 4.7: let* as nested lets

## Approach

`sequentialToNested` peels the outermost binding into a one-binding
`let` around the recursive remainder, so each initializer sees previous
bindings; with no bindings left, only the body sequence remains. The
typed shared AST cannot place this experiment's `LetNode` in a `Stmt`
body, so recursive inner levels are lowered to the equivalent call form
of exercise 4.6 when placed in the outer body. The resulting grouped
binding lowers to calls and runs with one frame per name. Thus the
book's one rewrite-and-re-evaluate case is enough, with this typed
representation boundary recorded below.

## Numbers

The book's example `(x = 3, y = x + 2, z = x + y + 5)` over `x * z` is
`39`. For two bindings, `sequentialToNested` produces an outer one-name
`LetNode` whose body carries the inner binding as a derived call; it is
structurally equivalent to `let x = 3 in (let y = x + 2 in x * y)` and
uses one frame per name. Each initializer sees previous bindings:
`x = 3, y = x + 1` over `x + y` is `7`. Empty bindings leave the body:
`42`. A lowered sequential-binding call in a procedure body, with
`a = 2, b = a * 3` over `a + b`, answers `8`.

## Class and deviations

Translated row. The derivation carries the `let` lowering of exercise
4.6 alongside the `let*` rewrite, because the expansion terminates in
grouped bindings. A-reason: the extension `LetNode` is outside shared
`Expr`/`Stmt`, so procedure-body statements cannot embed it; inner
levels and body examples use the derived call form. The book's single
rewrite-and-re-evaluate evaluator case still suffices for the supported
typed representation, and the per-binding scope semantics are retained.
