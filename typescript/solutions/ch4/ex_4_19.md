# Exercise 4.19: the internal definition scoping debate

## Approach

One dispatch, three internal-definition rules. Sequential keeps the
module's behavior: defines add to the call frame in order. Scanned is the
4.16 mechanism: names pre-bound to `*unassigned*`, one set! each, reads of
the sentinel error. Eva's rule is implemented as simultaneous definitions
whose value expressions see each other's final values: every internal name
is pre-bound to `*unassigned*`, and reading a sentinel forces that name's
value expression in the current frame and memoizes the value by writing it
back; forcing a name that is already being forced is a circular-definition
error. A let clause is added to all three so the program can run as the
book writes it.

## Numbers

The book's `(let ((a 1)) (define (f x) (define b (+ a x)) (define a 5) (+ a b)) (f 10))`:
`16` under the sequential rule, a `RuntimeError` with message "variable
used before assignment: a" under the scanned rule, and `20` under Eva's
rule. The 16 reads the outer `a` before the inner one exists; the error
catches the inner `a` still unassigned; the 20 forces `a` to 5 and `b` to
`(+ a 10)` = 15 against the final values.

## Class and deviations

Translated row. I support the Alyssa/MIT position: when the restrictions
that make the three readings agree are violated, an error beats whichever
answer the mechanism happens to produce. Deviation: Eva's semantics is a
reading, not a single recipe; this edition implements it as on-demand
forcing with memoization per call frame, with cycles rejected, and the
sequential rule delegates to the module's own evaluator unchanged.
