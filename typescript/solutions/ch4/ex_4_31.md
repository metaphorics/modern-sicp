# Exercise 4.31: lazy and lazy-memo parameter declarations

## Approach

The declaration `(name lazy)` or `(name lazy-memo)` is object-language
syntax on the parameter list: a bare name is strict, the upward-compatible
default. The modes live beside the evaluator in a table keyed by the
compound procedure's identity, because the shared CompoundProc has no
slot for them, and the application clause binds each operand per its mode
through the tuning's delayOperand: strict evaluates now, lazy delays into
a recomputing wrapper, lazy-memo delays into a memoized cell. The
evaluator intercepts procedure definitions and lambdas, strips the names
out for the frame, and registers the modes.

## Numbers

`(pick (car '()))` answers `taken`, the lazy parameter unforced.
`(f (id 1) (id (+ 2 3)) (id 4) (id (* 5 6)))` answers `(1 5 5 4 30 30)`
with count `5`: two strict calls, two recomputed lazy demands, one
computed lazy-memo demand. `g`'s lazy parameter demanded twice runs twice
(count `7`), `h`'s lazy-memo parameter demanded twice runs once more
(count `8`). The counts match the rust sibling's session.

## Class and deviations

Translated row. Deviation: the declared modes are parsed from the read
datum, since the host reader has no grammar for `(name lazy)`; malformed
specifications fail as unknown syntax.
