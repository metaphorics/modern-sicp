# Exercise 4.4: `and` and `or` with short-circuit

## Lesson

Operands must re-enter the evaluator one at a time, because
short-circuit is the specification: the first false operand stops
`and`, the first true operand stops `or`, and whatever follows never
evaluates. The probe operands record their own evaluation in counter
cells, pinning exactly which operands ran. The derived side lowers
the same forms to nested `GIf`, where the kernel's conditional keeps
the short-circuit.

## Map class

`A` (map row 4.1: sequencing and conditions). Direct evaluation and
derivation agree on the stopping points.

## Deviation

None. Both sides run over kernel values; the counters live in the
probe frame, not in the forms.

## Answer

- Direct `and` over false/true/true: `false`, counters `1`, `0`, `0`.
- Direct `or` over false/true/true: `true`, counters `1`, `1`, `0`.
- Derived `and` over false/effect: `false`, effect never runs.
- Pin: `specialAndOrTranscript() == "false\n1\n0\n0\ntrue\n1\n1\n0\n"`
  and `derivedAndTranscript() == "false\n0\n"`.
