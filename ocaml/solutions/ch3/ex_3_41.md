# Exercise 3.41: should balance reads serialize (translate)

The map class is `T`. Ben wants the `balance` message to answer through
the account's serializer; the scenario that would vindicate his worry
is a reader observing a balance the writer never wrote. The solution
builds that scenario: one domain makes `rounds` deposits of 1 while the
calling domain reads the balance in a tight loop until the writer
reports done. An OCaml `int` cell write is not torn, so every reading
lands between 0 and the deposit count (a value either the initial
state or some deposit produced), and `anomalous_reads` counts readings
outside that range, which is always 0. The honest conclusion is Ben's
scenario cannot arise for a single word on this host; the serializer
would buy ordering, not correctness.

Sample: `ex_3_41 ()` answers the reading count of one batch (for
example 12964, which varies run to run) and `0` anomalous readings.
