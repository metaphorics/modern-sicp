# Exercise 3.58: expand computes long-division digits

## Approach

The statement gives the definition outright; the exercise is to say
what the stream is. Reading one step: the next element is the integer
quotient of `num * radix` over `den`, and the recursion continues with
the remainder. That is exactly the long-division step that produces
digits, so the stream is the successive digits of `num/den` written in
the radix, one digit per element: the fractional digits of the ratio,
terminating in zeros when the division comes out even and repeating
otherwise. The tests pin the two expansions the statement asks for and
one base-2 expansion that shows the radix argument is honored.

## Pins

Computed by running the tests.

- `expand(1, 7, 10)`, first 8 elements: `[1, 4, 2, 8, 5, 7, 1, 4]`,
  the digits of 1/7 = 0.1428571428..., which repeat with period 6.
- `expand(3, 8, 10)`, first 8 elements: `[3, 7, 5, 0, 0, 0, 0, 0]`,
  the digits of 3/8 = 0.375 exactly, then zeros forever.
- `expand(1, 3, 2)`, first 8 elements: `[0, 1, 0, 1, 0, 1, 0, 1]`,
  the digits of 1/3 = 0.010101... in base 2.

## Map class

T (translate: syntax changes only). The book's `quotient` and
`remainder` map to `Math.trunc` and `%`, and `consStream` maps to the
module's `consStream`; the self-reference becomes a thunk that calls
`expand` recursively.

## Deviation

`Math.trunc((num * radix) / den)` and `(num * radix) % den` are exact
only because the digit recurrence keeps every intermediate a small
integer; the book's integer primitives make the same assumption. No
other change.
