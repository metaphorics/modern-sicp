# Exercise 4.1: operand evaluation order in list-of-values

## Lesson

The host fixes the order -- operands evaluate left to right -- so the
question the book leaves open has a definite answer here. The exercise
still matters: the kernel's `listOfValues` is the order made explicit
in code, and the right-to-left variant shows exactly what the host had
been deciding. The probe is the book's device recast: two `note`
recorders stamp a shared first/second cell, so the printed stamps pin
which operand ran first.

## Map class

`A` (map row 4.1: the host fixes order). The kernel walk is left to
right; the variant walks last-first with the same result shape.

## Deviation

None. Both walks run as guest variants over the shared kernel; the
opening pair also pins the kernel's dotted rendering.

## Answer

- Left to right: `(1 . 2)`, then stamps `1`, `2`.
- Right to left: `(1 . 2)`, then stamps `2`, `1`.
- Pin: `leftToRightTranscript() == "(1 . 2)\n1\n2\n"` and
  `rightToLeftTranscript() == "(1 . 2)\n2\n1\n"`.
