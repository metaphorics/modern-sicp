# Exercise 3.49: where the ordering fails

## Approach

The scenario: a process must hold a directory of records to discover
which record it needs next. One process holds the directory and waits
for record "checking"; the other holds "checking" and waits for the
directory to name "savings". Numbering cannot help, because the second
resource is unknown until the first lock is already held: the
acquisition order is forced by an information dependency, not chosen,
so it cannot be sorted in advance. The demo builds exactly this pair
on kotlinx mutexes and answers what happened: the `withTimeout` inside
`runTest` fires while both park, and the demo reports the deadlock.

## Map class

`T`. The scenario question is the statement's own; the code is the
scenario made runnable.
