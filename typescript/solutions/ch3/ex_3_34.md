# Exercise 3.34: Louis's squarer and its flaw

## Approach

Louis Reasoner proposes the squarer `(multiplier a a b)`. The edition
renders it as `squarerFromMultiplier`, wiring the module's
`multiplier` with the same connector in both factor positions, and
demonstrates the flaw the exercise asks for by running the device
both ways. The flaw: the multiplier box decides by asking which pairs
of its terminals have values, and its two factor terminals are one
terminal, always agreeing. A value on `a` propagates (`b = a * a`,
the product branch), but a value on `b` alone determines neither
factor: the divide branches need the product AND a factor, so
`processNewValue` falls through every branch. Nothing is computed,
no contradiction is raised, and the network is silently stuck.

## Pins

Fresh network: setting a = 7 makes b read 49 (the forward direction
works). On a fresh network, setting b = 36 throws nothing and leaves
a with no value, measured by `a.hasValue()` answering false while b
reads 36: the multiplier cannot divide b by an unknown a, so the
network just stops.

## Map class

`T: one module multiplier wired with a shared factor connector`.

## Deviation

The exercise statement asks to explain the flaw rather than to define
an export; the edition keeps the wiring under a name so the pins can
demonstrate both directions, and the flaw is stated as the
fall-through the run exhibits.
