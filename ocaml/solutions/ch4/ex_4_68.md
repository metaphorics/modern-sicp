# Exercise 4.68: reverse rules via append-to-form (translate)

Two rules over the 4.4.1 `append-to-form`: the base case reverses the empty
list; the recursive rule reverses the tail into `?w` and appends the head as a
one-element list: reverse of `(?u . ?v)` = append(reverse(`?v`), `(?u)`).
Forward queries ground the recursion and answer finitely. The backward query
`(reverse ?x (1 2 3))` leaves both ends of the recursive subquery
`(reverse ?v ?w)` unbound: the engine wades through the infinite stream of
candidate pairs, the `append-to-form` conjunct filters each against the ground
target `(1 2 3)`, and the one true answer arrives first. The empty pair and
the one-element chains die on arity mismatches, and reverse is injective, so
`(3 2 1)` is the only survivor. Forcing a second answer never returns, so the
backward direction is observed through `run` + `stream_car` (exactly one
answer); `query_upto` cannot be used here because its `stream_take` walks one
`stream_cdr` past the requested prefix and would demand a second answer that
never exists.

Asserted answers (verbatim strings of `ex_4_68 ()`):

```
(reverse (1 2 3) ?x) => (reverse (1 2 3) (3 2 1))
(reverse (a b c d) ?x) => (reverse (a b c d) (d c b a))
(reverse ?x (1 2 3)) first answer => (reverse (3 2 1) (1 2 3))
backward: forcing a second answer does not return; with both ends of (reverse ?v ?w) unbound the engine generates infinitely many candidate pairs and only (reverse (3 2 1) (1 2 3)) survives the append-to-form filter
```

Deliberate deviations: none in the rules; they are the book's two-rule
solution. The extra fourth string is the honest behavior note the exercise
asks for ("can your rules answer both?": yes for the first direction, the
second direction yields the answer but does not terminate).
