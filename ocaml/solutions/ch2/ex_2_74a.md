# Exercise 2.74a: option instead of exception (this edition's addition, extending 2.74)

The idiom note for 2.4 picks this addition: make personnel-file
lookup return `option`, not an exception. `find_employee_record`
(Exercise 2.74, part c) raises `Invalid_argument` when no division
has the requested employee, matching the book's own `error` call as
closely as OCaml's exception mechanism allows. That is a reasonable
port, but it is not the OCaml idiom for an ordinary, expected
"not found" outcome, an idiom this edition uses everywhere else a
lookup can miss (`Record_db.lookup` in 2.3.3 answers `option`, not an
exception).

`find_employee_record_opt` is `find_employee_record` restated: the
same search, the same divisions tried in the same order, but a
missing employee is the value `None` instead of a signal the caller
must wrap a `try` around. The two functions share every line of
search logic; `find_employee_record_opt` is `find_employee_record`
with `Invalid_argument` caught and converted, not a second
implementation of the search.

The distinction matters because a missing employee is not a bug in
the caller's program. An org chart searched by an out-of-date
employee list is an everyday occurrence, not a broken invariant.
`option` states this in the type: nothing about `any_record`'s API
forces a caller to remember that "not found" is even possible, but
`find_employee_record_opt`'s return type does.

Sample: with two divisions and no third-division employee, calling
`find_employee_record` on that employee raises `Invalid_argument`;
`find_employee_record_opt` on the same employee returns `None`.
