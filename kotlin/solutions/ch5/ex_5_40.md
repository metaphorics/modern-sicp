# Exercise 5.40: compile-time environment threading

A compiler needs a static account of the lexical frames surrounding each
expression so later code generation can identify the bindings visible at a
reference. `compileLambdaBody` extends that environment with the lambda's
parameter frame before compiling the body. The trace callback records the
environment and variable name as the compiler visits each variable reference.

`compileTimeEnvDump()` compiles a nested-lambda definition with tracing enabled.
The test pins four visits, in order: `+`, `x`, `y`, and `z`. At each visit the
same frames are reported: `(y z)`, `(a b c d e)`, then `(x y)`. The innermost
frame comes first, so the output shows the successive lambda parameter frames
available in the body. This exercise checks that the environment is threaded
through compilation and extended at lambda boundaries; it does not claim that
this trace changes the generated variable-access instructions.
