# Exercise 4.3: data-directed dispatch in eval

## Approach

`TableDriven` keys its registry by operation `Key.Sym("eval")` and the tag
chain of the ordered tag list (`evalTagKey`), with the book's clause
handlers installed at startup: quote, define, set!, if, lambda, begin,
cond (derived through `condToIfChain`), let (derived through
`letToCombinationExpr`), and the leftover application clause. Every handler
recurses through the dispatcher itself, so a later `put` redirects the
whole evaluator at every depth. Self-evaluating expressions and variables
stay residual tests (they dispatch on the datum, not a tag, exactly the
2.73 lesson) and a form with no table entry falls back to the base clause
chain. The D19 openness is demonstrated, not described: `put`-ing an
`unless` clause after construction runs the form, and a later `put` on
`quote` overwrites the installed handler.

## Map class

`T`, with the table on the put/get registry shape (D19).

## Deviation

The runtime `OpTable` stores `Op = List<Value> -> Value` handlers, a shape
that cannot carry the (form, environment, dispatcher) an eval clause needs,
so the table keeps OpTable's put/get semantics (absent option on a miss,
overwrite on put, two-level `(op, tag)` keying) over a `context(Raise)
(TableDriven, Expr, Env) -> Value` clause type. The sibling editions record
the same substitution.

## Answer

`(cond ((= 1 2) 'no) (else 'yes))` => yes through the table's cond clause;
`(define (square x) (* x x)) (square 7)` => 49 (define clause, then the
application clause); `(quote (a b))` => (a b). The runtime-installed
`unless` answers its alternative: `(unless (= 1 2) 'ran 'no)` => ran and
`(unless (= 1 1) 'ran 'no)` => no; overwriting the quote clause answers
`replaced` for `(quote (a b))`.
