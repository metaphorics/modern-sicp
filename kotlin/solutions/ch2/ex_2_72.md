## Exercise 2.72: encode order of growth

Approach: `encodeSymbolSteps` instruments `encodeSymbol`'s own algorithm,
charging one step per element scanned by each `symbol in
symbols(t.left)` membership test. On the skewed alphabet of exercise
2.71 (weights `1, 2, ..., 2^(n-1)`), the most frequent symbol sits at
depth 1 behind exactly one membership check, whose left branch holds
every other symbol (size `n - 1`), so encoding it costs `Θ(n)`. The
least frequent symbol sits `n - 1` levels down; at level `k` the
membership check's left branch has size `n - k`, so the total cost is
`(n-1) + (n-2) + ... + 1 = n(n-1)/2`, `Θ(n²)`. This is not special to
the skewed case: every `encodeSymbol` call pays one membership scan
per branch on its root-to-leaf path, and each scan costs the size of
that branch's left symbol set, so the total is bounded by the sum of
subtree sizes along the path, which is linear for a shallow path and
quadratic for one that stays close to `n` symbols wide all the way down
, exactly the skewed alphabet's worst case.

Class: T, per the map; a direct translation, adapted to count steps
explicitly rather than reason about growth from the algorithm's text
alone.

Deviation: none in substance.
