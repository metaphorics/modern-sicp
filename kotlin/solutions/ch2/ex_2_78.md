## Exercise 2.78: numbers that were never wrapped

Approach: the book's `type-tag`/`contents`/`attach-tag` exist because
Lisp data is untyped pairs, so an ordinary number needs an attached tag
to join the dispatch; this edition's tower already answers `typeTagOf`
from a value's own Kotlin type, so there was never a wrapper to strip.
What the exercise still has to teach is the bare case itself:
[typeTagOfAny] reads the level off the host's raw `Long` and `Double` as
well as off a tower `Num`, and [BareTable]/[applyGenericBare] dispatch
over that mixed universe so [installBareIntegerPackage] can compute
directly on `Long` values, returning bare `Long` (or a promoted [BigZ])
rather than a wrapped `ZLong`.

Class: A, per the map; the revised `type-tag` is trivial once a value
carries its own type, so the exercise is answered by building the case
this edition never needed on its own: a table that also accepts
completely untagged host primitives.

Deviation: none in substance.
