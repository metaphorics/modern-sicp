## Exercise 3.14: mystery reverses the list in place

Approach: `E3_14.kt` keeps the book's shape (an internal `loop` with
the temporary) but carries plain `Value`s, because the walk has to be
able to step off the end onto `VNil`. Each turn saves the old `cdr` in
`temp`, repoints the current pair's `cdr` at the accumulated reverse
(`VNil` on the first turn), and recurses with `(temp, current)`.

Why it reverses in place: no pair is ever created. The loop visits the
four cells of `v = (a b c d)` once each and flips one pointer per visit:
the `a` cell ends as `(a)` with `cdr` `VNil`, and the `d` cell, the
old last cell, becomes the head of `(d c b a)`. That is the answer to
"what is printed": `v` is `(a)` and `w` is `(d c b a)`, and they are not
two lists but two names over the same four pairs, rearranged.

The subtlety worth stating: after `mystery`, `v` and `w` are ordinary
variables pointing at ordinary pairs, and nothing in the printed forms
reveals that `v`'s tail was cannibalized to build `w`. Sharing is
invisible to the constructors and selectors; only identity (`===`) and
mutation can see it.

What the tests say: the first test pins both printed values of the
book's session. The second asserts the in-place property cell by cell:
`w === ` the old last cell, and walking `w` meets the old third, second,
and first cells in that order; an `mystery` that builds a fresh
reversed list passes the printed-values test but fails this one. The
third test covers the boundary: a one-pair chain is its own reverse, and
the function returns that same cell.

Class: T (direct port; only the host-language names changed).

Deviation: none.
