# Exercise 4.4: and and or as special forms

## Approach

`WithAndOr` adds the two clauses on the `step` seam and evaluates them
directly, so the operands re-enter the full evaluator at every depth
(pin: a nested `or`, `if`, and application inside an `and`). Short circuit
is the specification: the first false operand stops `and` at #f, the first
true value is `or`'s answer, and a later operand that would raise never
evaluates -- proven by an `(error ...)` operand after the decided position,
which the typed `Either.Right` result shows never ran. No operands answer
#t and #f, and the last operand is left in tail position, so `(and 1 2 3)`
is 3.

## Map class

`T`.

## Deviation

None. The book also offers the derived-to-if rewrite; direct evaluation is
the simpler design and satisfies the same statement.

## Answer

`(and (= 2 2) (> 2 1))` => #t, `(and)` => #t, `(and 1 2 3)` => 3,
`(and 1 #f (error "no operand may evaluate"))` => #f with no fault,
`(or (= 2 2) (> 2 1))` => #t, `(or)` => #f,
`(or #f 7 (error "no operand may evaluate"))` => 7, `(or 'a 'b)` => a,
`(and #f 'x)` => #f, `(or 'b 'c)` => b.
