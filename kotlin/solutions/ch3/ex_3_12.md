## Exercise 3.12: append copies, appendBang splices

Approach: `append` walks the first `Datum` list and creates a fresh `PairCell`
for each item in front of `y`. It never changes the original cells in `x`.
`appendBang` finds `x`'s last cell, assigns `y` to that cell's `second` field,
and returns the same head object. The tail accepts any `Datum`, including
`Empty`; `lastPair` accepts only a `PairCell`, so `Empty` cannot be passed to
it as the list head.

Why the results differ: after `append`, `x.second` is still its original tail.
After `appendBang`, the `b` cell points to `y`, and the result is `x` itself.
The same values therefore appear in both results, but the pair identities and
sharing are different.

What the tests say: structural comparisons check each list, while `===`
checks the unchanged tail, the returned head, and the link to `y`. An
implementation that reuses `x`'s cells in `append`, copies the tail in
`appendBang`, or stops `lastPair` one node early fails.

Class: T (the pair graph is represented by typed host data).

Deviation: textual list rendering is not retained; the same sharing and
mutation facts are pinned through structure and identity.
