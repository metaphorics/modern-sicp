# Exercise 3.10a (this edition): shared-cell capture, pointer versus binding

## Approach

`make_withdraw_cell` takes an `Rc<Cell<i128>>` instead of an owned
`i128`. Two processors built over clones of one cell share a balance:
draining 30 then 20 from a cell that started at 100 leaves it at 50, and
the second call sees the first call's withdrawal (70, then 50). The
contrast, two processors over `make_withdraw`'s copied integer, behave
independently: both start at 100 and each answers as though it were the
only withdrawal (70, then 80). `size_of_val` on the shared-cell closure
comes out to `size_of::<Rc<Cell<i128>>>()`, twice the width of exercise
3.10's plain-integer capture, which is the indirection made
measurable. An outside `Rc` handle to the same cell watches the balance
change across calls, which no code outside exercise 3.10's closures can
do.
