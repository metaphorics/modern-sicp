# Exercise 4.2: dispatch order and the call-tagged dialect

## Approach

Part (a) rebuilds Louis's hazard on the real syntax data. Over the book's
pair data the collision is structural: a definition is a pair, so moving
the application case first makes `(define x 3)` an application of the
unbound name `define`. The shared typed syntax eliminates that artifact by
construction — `Expr` is a tagged union with disjoint cases, and
`const x = 3;` is a `var-decl` declaration, not an expression at all — so
the premise is carried forward rather than the old fault:
`evalApplicationsFirst` re-assembles the complete expression case
analysis with the `call` case before `assign`, subexpressions recurse
through the same re-assembly, and a fixed input suite (declare, reassign,
call, plus literals, conditionals, and an unbound name) shows the two
dispatch orders answer identically, including the `bad-operand` fault on
const rebinding.

Part (b) keeps the book's call-prefixed proposal as a reader-level
dialect. `readCallDialect` parses the call-tagged spelling
`call(f, a, b)` and lowers it to the ordinary `call` node of the shared
syntax, so the evaluator is unchanged; a bare `f(a, b)` application is
rejected in the reader as `unknown-syntax`, before any evaluation.

## Numbers

The suite's values: `square(6)` is `36`, `n = 5` writes `5`, `n` reads
`5`, `1 + 2 * 3` is `7`, `true ? "yes" : "no"` is `"yes"`, and
`missingName` is `error:unbound-name` — all equal under both orders. The
declare case: after `const x = 3;`, `x + 1` is `4` under both; reassigning
`x` is `error:bad-operand` under both. The dialect pair: `call(add, 1, 2)`
and `add(1, 2)` are both `3`; `call(square, x) + 1` and `square(x) + 1`
are both `10`; `call((x: number): number => call(mul, x, x), 7)` is `49`.
A bare `add(1, 2)` is rejected at read time as `unknown-syntax`, and the
rejection leaves the guest `hits` counter at `0`.

## Class and deviations

The map row is `T`, but the premise is materially reworded and should
reconcile as `A`: the old solution and its test asserted a pair-data
artifact (the unbound-`define` fault) that the typed AST cannot express,
so that assertion is dropped by direction of the book owner and replaced
by the observational-equality suite and the dialect pair above. The
reader-level lowering is the same lesson as exercise 4.10 — new surface
syntax, shared `Expr`, unchanged evaluator — and no other deviation.
