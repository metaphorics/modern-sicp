# Exercise 2.72: encode order of growth

## Approach

`encodeSymbol`'s dominant cost at each node visited is the membership
search over the branch symbol lists it consults, each sized to the
subtree it roots. The solution instruments the walk with a step counter
that charges every visit the full length of both branch lists: the
worst-case convention the book's question asks about; the section's real
early-exit search only makes runs cheaper.

## Numbers

On exercise 2.71's skewed alphabet (most frequent at depth 1, least at
depth n - 1):

- Most frequent: one visit at the root, charging the whole alphabet:
  exactly n steps (n = 5, 10, 20 give 5, 10, 20). Linear.
- Least frequent: a visit at every level down the spine, charging the
  subtree size each time: n + (n - 1) + ... + 2 = n(n + 1)/2 - 1 steps
  (n = 5, 10, 20 give 14, 54, 209). Doubling n roughly quadruples the
  count: quadratic.

So the order of growth is Theta(n) for the most frequent symbol and
Theta(n^2) for the least, with the symbol-list search charged as the
book directs.
