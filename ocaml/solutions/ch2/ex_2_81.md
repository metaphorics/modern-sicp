# Exercise 2.81: self-coercion (adapt)

The map class is `A`: the coercion table is a `Hashtbl` keyed on a
type-tag pair rather than an association list, but Louis's mistake
and its fix are unchanged by that swap. `install_louis_setup`
installs the two useless self-coercions
(`"scheme-number" -> "scheme-number"` and `"complex" -> "complex"`,
both the identity) plus `"exp"` for `["scheme-number";
"scheme-number"]` only, exactly as the exercise states.

Part (a): `apply_generic_loop` is 2.5.2's coercion `apply_generic`,
with an explicit depth counter (`Loop_detected`) standing in for the
unbounded call stack an actual infinite loop would eventually
overflow. Calling `exp` on two `"complex"` arguments coerces a
`complex` to `complex` via the self-coercion, finds no `"exp"` entry
for `["complex"; "complex"]`, and recurses forever, tripping the
guard at depth 1000. Part (b) is answered in prose in the book text;
this edition supplies no separate artifact for it. Part (c):
`apply_generic_fixed` never attempts coercion when both arguments
already share a type, so the same call raises `Invalid_argument`
immediately instead of looping; `ex_2_81_c ()` confirms this.

`ex_2_81_a ()` returns the depth `Loop_detected` carries (over 1000,
confirming the guard was needed); `ex_2_81_c ()` is `true` when the
fix raises immediately.
