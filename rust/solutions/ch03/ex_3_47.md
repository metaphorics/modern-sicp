# Exercise 3.47: semaphore from mutex or test-and-set

## Approach

A semaphore of size n generalizes the mutex, and the exercise asks
for it twice. Part (a) builds it from mutexes: the permit count lives
under the book's test-and-set mutex, acquire takes the mutex, checks
the count, and either takes a permit or puts the mutex back and spins
(polling the run handle, so a demonstration can end it); release
re-enters the mutex to return one permit. Part (b) builds it from
atomic test-and-set operations: the whole permit count is one atomic
cell and acquire is a compare-and-swap loop, no lock anywhere. Both
builds also answer a nonblocking try-acquire. The run crowds twelve
real threads through a size-3 semaphore of each build: the largest
number of holders ever observed inside is at most three, every
process gets through, and the try-acquire tests show a full semaphore
refusing until a release reopens it.

## Map class

`T`. The semaphore definition, both requested constructions, and the
size-n acquire/release semantics are the statement's own.

## Deviation

The section module already carries a blocking `Semaphore` on a
condition variable as section machinery; this solution implements the
two constructions the exercise itself asks for, which are different
objects: a mutex-guarded spin and a lock-free compare-and-swap loop.
