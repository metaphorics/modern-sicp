# Exercise 4.15: the halting diagonal, executed

## Approach

`halts` is provided by the host as an oracle with an adjustable answer,
and the object language gets the book's `runForever` and `tryProgram`
verbatim. Because a diverging evaluation never returns, a fuel counter
is wrapped around the recursion: every application of `runForever`
spends one unit from the host counter, and one spend past the limit
fails with `bad-operand: out of fuel` instead of hanging, which turns
"runs forever" into an observable, pinnable outcome. The theorem the
runs demonstrate: no `halts` correctly decides halting. If the oracle
says true for `tryProgram(tryProgram)`, the try drives into
`runForever` and diverges, so the answer was false; if it says false,
the same call halts with `"halted"`, so the answer was true.

## Numbers

Under the true oracle with a 500-unit limit, `tryProgram(tryProgram)`
fails with `bad-operand: out of fuel`, and the counter reads exactly
`501` spends: the first spend past the limit is the failure. Under the
false oracle the call answers `"halted"` having spent well under `500`
units. Under the true oracle, `tryProgram(identity)` exhausts its fuel
too, again at spend `501`, because the oracle says true and the try
drives into `runForever`.

## Class and deviations

Translated row. Deviation: the book's argument ends with "runs
forever"; this edition makes the divergence observable by capping the
recursion at a fuel limit and pinning the exhaustion, which changes no
statement about `halts`. The fuel counts one unit per `runForever`
application rather than per evaluator dispatch — the old solution's
granularity — so the `501` boundary is the first spend past the limit,
not a claim about evaluator step counts.
