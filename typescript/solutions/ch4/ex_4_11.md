# Exercise 4.11: frames as association lists

## Approach

A frame becomes one list of bindings instead of two parallel lists, held in a
Ref so that define and set! can write it while every environment node sharing
the frame sees the change. `lookup-variable-value` scans the entries of the
current frame for a matching name and walks the parent chain when absent;
`set-variable-value!` finds the first frame that binds the name and rewrites
that entry in place; `define-variable!` conses a fresh binding onto the
current frame, shadowing outer ones; `frame-variables` reports a frame's
names. Lookup, set, and define are tested directly over a two-frame chain.

## Numbers

With a = 1 in the outer frame and b = 2 in the inner: looking up b from the
inner frame answers 2, looking up a from the inner frame walks out and
answers 1, and `zz` fails with UnboundVariable. After `(set! a 10)` issued
from the inner frame, the outer frame's own lookup answers 10: the write
landed in the shared frame. Defining c = 3 in the inner frame leaves
`frame-variables` of the inner frame as `(c b)` and of the outer frame as
`(a)`, and c is unbound from the outer frame's point of view. Setting an
unbound `zz` fails with UnboundVariable.

## Class and deviations

Translated row. Deviations: this edition's pairs are proper lists, so a
binding is the two-element list `(name value)` rather than a dotted pair; and
the edition's own frames are Ref-held HashMaps, which stay untouched: this
file builds the book's association-list representation beside them and
re-derives the same visible semantics.
