# Exercise 3.41: should balance reads serialize

## Approach

Ben wants the balance message answered under the serializer too. The
solution builds both accounts -- the text's, whose balance message is
a plain atomic read, and Ben's, whose read runs inside the serializer
-- and forces a reader to observe one withdrawal of 50 from $100,
once reading before the withdrawal and once after, under each
version. Both versions answer the same sorted observation set,
[50, 100]: every value a reader can see is a balance the account
really held. There is no scenario that demonstrates Ben's concern,
because a single integer read is already indivisible; the serializer
around it changes nothing observable.

## Map class

`T`. The proposed change and the question of a demonstrating scenario
are the statement's own.

## Deviation

None. The answer is that Ben's change is harmless but pointless, and
the test asserts the observation sets are identical.
