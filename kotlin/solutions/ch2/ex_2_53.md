## Exercise 2.53: predicted printed values (replaced)

Approach: SICP asks what a Scheme REPL prints for seven quoted-list
expressions. Kotlin has no REPL, so the replacement asks the same
question about `Value.toString()`, computed by hand from the section's
`vlist`/`car`/`cdr`/`pair?`/`memq` semantics: a list of three symbols
prints flat, a list holding one nested list prints with double
parentheses, `cdr`/`car` walk the pair chain exactly as in Scheme, `car`
of a short list is a bare symbol (never a pair) so `pair?` of it is
`#f`, and `memq` fails whenever the match is buried one list deeper than
the symbol being searched for.

Class: R, per the map — the exercise is about the Scheme REPL itself, so
this edition replaces the question with an equivalent one about the
runtime's own printed form, keeping the number and the section's four
underlying operations (`car`, `cdr`, `pair?`, `memq`).

Deviation: none in substance. The test file declares its own private
`memq`, matching section 2.3.1's example rather than depending on
another exercise file for it.
