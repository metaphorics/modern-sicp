# Exercise 4.23: Alyssa's analyze-sequence

## Approach

`AlyssaSequence` overrides the `analyzeSequence` seam with her looping
`execute-sequence`: for a one-expression sequence it returns the body's
own execution procedure; for a longer one it analyzes only the FIRST
expression at analysis time and the returned closure re-runs
`execute-sequence` on the tail at EXECUTION time, re-analyzing every later
expression on each execution. The library's `analyzeSequence` is the
text's version -- every body expression analyzed at analysis time, the
execution procedures composed before any call.

The comparison measures `analyze` hook calls with counting subclasses of
both analyzers. The counts are exact and deterministic: each top-level
form contributes one analysis of itself plus its subexpressions (a call
like `(f 10)` contributes the application, the operator, and the literal),
identically on both sides, so the interesting deltas are the body work at
definition and per call.

## Map class

`T` (map row 4.23: Kotlin T).

## Deviation

Her empty-sequence case raises the library's typed
`SchemeError.TypeMismatch("Empty sequence: ANALYZE")` at execution rather
than a Scheme `error`; and the structural comparison is made by counting
analyses rather than wall time, so the claim stays deterministic.

## Answer

Values agree on both versions, from the actual run: the probe
`(define (f x) (set! x (* x 2)) x)` with `(f 10)`, `(f 30)` gives the
transcript `20\n60\n` on the text version and on Alyssa's (a dropped tail
would answer 10 and 30 instead).

Analysis profiles (`AnalysisProfile(atDefinition, perCall)`):

- Two-expression body `(define (f x) x x)`: text (3, 3) -- define + both
  body expressions at definition, nothing extra per call. Alyssa (2, 4) --
  one fewer at definition (the tail is not analyzed yet) and exactly one
  more per call (the tail re-analyzed on that execution).
- One-expression body `(define (g y) y)`: text (2, 3), Alyssa (2, 3) --
  identical work; her null-tail clause returns the body's own execution
  procedure, so single-expression sequences cost the same.

That is Eva's point in numbers: Alyssa's rewrite does not change any
answer, it moves the tail's analysis from once-per-definition to
once-per-execution.
