# Exercise 3.31: why the accepted action runs immediately

## Approach

The book's `accept-action-procedure!` runs a newly accepted action once
immediately. The edition isolates the difference: `makeWireWithoutInitRun`
is the module wire minus that immediate run, and the two `demonstrate*`
functions run the book's half-adder sequence (probes on sum and carry,
build, set input-1, propagate) on each wire kind.

## Pins

Computed by running. With the immediate run: the probes print the initial
zeros at time 0 on attach, and the sum rises at time 5, exactly the module's
pinned sample run. Without it: the log is empty. Two mechanisms produce the
emptiness: the probes never print on attach because their action is never
run, and the gates never claim outputs from the initial wire values, so the
inverter's `e := 1` claim at time 2 never exists; the input change alone
leaves e at 0 and the final and-gate answers and(1, 0) = 0, no change. The
sum wire never settles to 1: the book's demo simply fails.

The why: the immediate run lets every device schedule its first response
from the values its inputs already have, so the network's state after
construction is consistent with its wiring; the input change then updates
that state from a consistent baseline instead of building it from nothing.

## Deviation

The module's wire (with the immediate run) makes the first propagate report
the sum change at time 5 rather than the book's printed 8; the mechanism is
documented at the module test pin and in the section prose, and the same 5
appears here for consistency.
