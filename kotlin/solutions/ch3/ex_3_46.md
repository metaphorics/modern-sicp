# Exercise 3.46: the test-and-set race window

## Approach

Two layers. Deterministically, `testAndSetRacy` splits the book's
plain test-and-set into its two steps with one `yield()` between them,
marking the preemption the scheduler may create at any time. Two
coroutines that both pass the test before either sets the cell both
come away holding the mutex: the test asserts two acquirers, the
book's failure in Figure 3.29's shape. On real threads, the fixed
`AtomicCell` (one `AtomicBoolean.compareAndSet`) runs 3000 two-thread
races, each round synchronized by a barrier pair so a round cannot
leak into the next, and every round has exactly one winner: the fixed
version must pass, and does.

## Map class

`T` with the map's tailored note (demonstrate the race via stress
test): the broken version is demonstrated deterministically, and the
stress test covers the fixed one.

## Deviation

The stress test runs on the fixed version only, per the brief: a
broken-version stress on real threads is probabilistic, and the
deterministic split-window run already exhibits the failure.
