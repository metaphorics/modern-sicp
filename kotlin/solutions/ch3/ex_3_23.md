## Exercise 3.23: a deque over doubly linked cells

Approach: each `DPair` stores a `Datum`, a previous cell, and a next cell.
The deque keeps pointers to both ends. Insertion links one new cell at the
requested end; deletion moves that end inward and clears the neighboring
link. Each operation changes a constant number of pointers.

Why `DPair` is local to the deque: it adds the backward link that a
one-directional pair does not have. A separate parent map would need
synchronized updates. The cell is a deque record, not a `Datum` variant;
its payload is the native datum.

What the tests say: they interleave front and rear traffic, check both
empty-end errors, and reuse the deque after emptying it from either side.

Class: T (the representation is a doubly linked host-language record).

Deviation: the cells are inspected through typed values, not a cyclic
structure printer.
