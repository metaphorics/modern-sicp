# Exercise 3.3: a password-protected account

## Approach

`PasswordAccount` wraps the section's `Account` with the password it was
created under. `send` checks the password first and forwards the request to
the inner account only on a match, so the wrong-password path never reaches
the balance. The section's dispatch logic is reused rather than duplicated.
The test pins the book's interaction (correct-password withdrawal of 40 from
100 answers 60; wrong-password deposit answers "Incorrect password") and
adds the check a plausible bug fails: a rejected deposit must leave the
balance untouched.

## Map class

`T`: the statement translates directly, with the symbol password re-expressed
as a string slice.

## Deviation

None.
