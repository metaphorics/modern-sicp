Exercise 1.41 (adapted: statement changed after reading it): `double(f)` types cleanly as `impl Fn(f64) -> f64 -> impl Fn(f64) -> f64`, so `double(inc)` compiles and adds 2 as the statement says. The book's self-application `(((double (double double)) inc) 5)` feeds `double` to itself, which needs `double` to accept its own type as an argument; a monomorphic Rust function has one argument type, so `double(double)` is a compile error (`expected f64, found impl Fn(f64) -> f64`), not a run-time event. Rust cannot express the untyped self-application at all, generically or through trait objects, without a second `double` defined at the procedure level, which the exercise does not ask for. The book's self-application nests four `double`s deep (each of the three `double`s in the expression doubles the reach of the one inside it: 1, 2, 4, 8, 16), so the recovered spelling is `double(double(double(double(inc))))`, sixteen additions of 1 to 5, which is 21 -- the value the book's expression computes.
