# Exercise 5.11: three restore disciplines

One simulator, three disciplines, differing only in what a save and a
restore do. The untagged discipline is the simulator's own. The other
two leave the simulator unchanged: `make` rewrites each `Save "r"` into
a `Perform` of the action `save-r` on the register's name and contents,
and each `Restore "r"` into an `Assign_op` to `r` from the value
operation `restore-r` of the register's name. Those two operations own
the discipline's stack, one instruction still replaces one, and the
test suite pins the tagged and per-register machines at the untagged
machine's 281 instructions for fib 6.

(a) Untagged: the book simulator's behavior. The sequence
`Save "y"; Save "x"; Restore "y"` leaves `y = 8`, the word saved from
`x`, which is the point. The advantage taken for the Fibonacci
machine: at `afterfib-n-2`, the pair `Assign ("n", Reg "val")` and
`Restore "val"` (moving the saved Fib(n-1) into `n` while pulling the
saved `val` back) collapses into the single `Restore "n"`, which
takes the saved Fibonacci value from wherever the untagged stack filed
it. One fewer instruction per level; `ex_5_11 ()` pins the answers of
the original and the one-instruction-smaller machine equal on
n = 0..9. (The 5.6 pair, deleting `afterfib-n-1`'s
`Restore "continue"` with the second `Save "continue"`, is the other
reduction; it removes two instructions, this one removes one.)

(b) Tagged: a save files the register's name with the word. The
sequence now reports the typed failure
`bad instruction: restore y but the stack holds x`; a disciplined
program still runs, and tagged fib 6 answers 8.

(c) Per-register stacks: each register owns its stack in a hash table
keyed by register name; the sequence leaves `y = 7`, its own value,
and a restore from an empty per-register stack is the typed
`bad instruction: restore x from an empty stack`, the same failure the
simulator reports for its own empty stack.
