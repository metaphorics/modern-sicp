# Exercise 3.8 — exposing operand evaluation order (translate)

The map class is `T` for this edition: the exercise's premise is that
the host language leaves operand evaluation order unspecified, and
OCaml's manual leaves the evaluation order of function arguments (and
so of operator applications such as `f 0 + f 1`) unspecified in
exactly the same way Scheme's `R7RS` does, so the exercise transfers
without becoming a statement about Scheme itself.

`make_order_probe` returns a fresh `f` whose first call answers its
own argument and whose every later call answers `0`; a captured
`bool ref` distinguishes "first" from "later." Whichever operand of
`f 0 + f 1` this build evaluates first becomes the "first call" and
contributes its own argument; the other contributes `0`.

Sample: `ex_3_08 ()` reports which order this compiler happens to
choose today; the value is not pinned to a hand-picked literal but
measured directly, since the whole point of the exercise is that the
order is not specified and could differ across compilers or
versions.
