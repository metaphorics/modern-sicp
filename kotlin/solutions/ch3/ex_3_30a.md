## Exercise 3.30a: checking the adder against integer addition

Approach: `rippleAdd(a, b, cIn)` is the checker the exercise asks for.
Each call builds a fresh `Simulation`, wires a four-bit
`rippleCarryAdder` over fourteen fresh wires, puts the bits of `a`,
`b`, and `cIn` on the input wires (wire 1 least significant, matching
figure 3.27's `A_1`), runs `propagate` to exhaustion, and assembles
the answer: `s1 + 2*s2 + 4*s3 + 8*s4` from the sum wires, plus
`16 * cOut` for the carry out. The fifth bit matters: without it,
15 + 15 + 1 would masquerade as a passing 15.

Why this check is the integer-addition contract: the circuit's claim
is that four full-adders wired in a chain compute addition of binary
numbers. That claim has an exact restatement at the wire level: for
every triple of inputs, the value you read off the output wires
(weighted by place) equals `a + b + cIn` computed in integers. Nothing
short of all 32 input triples proves it, and nothing more is needed:
an adder is not allowed to be right on average. The tests close the
gap in two layers: the boundary cases by hand (0 + 0, all ones with
and without a carry in, 8 + 7 whose carry crosses every stage, a set
`cIn` alone), then a seeded sweep of 256 cases over all inputs, each
asserted against the integer sum. Seeded, because a failure that
cannot be reproduced teaches nothing; `Random(20260924)` runs the same
256 cases every time this suite ever runs.

Why one fresh simulation per case: the simulator is stateful all the
way down (wire signals, agenda, the current time), and reusing a
simulation across cases would make each answer depend on the residue
of the previous one. A fresh `Simulation` per call costs nothing here
and makes every case an independent, reproducible experiment, the
same discipline the book's own sessions follow when they re-create
wires for each circuit.

What the tests say: `E3_30aTest.kt` asserts the eight boundary cases
by value and the 256-case sweep, including cases that overflow four
bits (30, 31, 16) so the carry-out bit is exercised, not just the sum
wires.

Class: `T` extension (map row 3.30, this edition's chosen addition;
the idea cell asked for the adder to be verified against integer
addition with a deterministic sweep).

Deviation: none.
