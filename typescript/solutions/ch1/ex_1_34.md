# Exercise 1.34: the type checker rejects self-application

## Approach

The statement's `f` is typed as `(g: (n: number) => number) => number`: its
argument must be callable with a number. `f` itself has type
`(g: (n: number) => number) => number`, which does not satisfy that
requirement - it is callable only with another function of the same shape,
not with a `number`. The self-application is refused before any program runs.

## Numbers

The two working calls give `f(square) = 4` and
`f((z) => z * (z + 1)) = 6`, asserted through `workingCalls()`. For `f(f)`,
tsc (TypeScript 7.0.2) was run on a probe file carrying `f`, both working
calls, and the `f(f)` line; the checker rejected only that line, printing

    error TS2345: Argument of type '(g: (n: number) => number) => number'
    is not assignable to parameter of type '(n: number) => number'.
      Types of parameters 'g' and 'n' are incompatible.
        Type 'number' is not assignable to type '(n: number) => number'.

The probe was removed after the run so the tree keeps type checking, and the
diagnostic's exact words are pinned in the solution and asserted by the test.
