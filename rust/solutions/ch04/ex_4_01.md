# Exercise 4.1: operand evaluation order (A: host fixes order, reword premise)

## Approach

The premise changes for Rust: the host already fixes argument order
left-to-right, so the object-language order cannot be "inherited" -- it is
whatever the book's explicit `list_of_values` recursion writes. The solution
writes both orders on the seam: the base is left-to-right by construction, and
`RightToLeft` overrides `list_of_values` to fold from the right. A probe
application `(f (begin (display 1) 1) (begin (display 2) 2))` shows the traces:
`12` left-to-right, `21` right-to-left.

## Map class

`A: host fixes order, reword premise`. The statement no longer argues from an
underlying Lisp; it asks the reader to pin the order the evaluator itself
imposes.

## Sample answer

Base trace `12`, flipped trace `21`; both give the same call value.
