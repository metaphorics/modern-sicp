# Exercise 2.1a (this edition): checked `Rational` operations and where they overflow

## Approach

`Rational::add`, `sub`, `mul`, and `div` all return `Result<Self,
SchemeError>`, using `i128::checked_mul`/`checked_add`/`checked_sub`
throughout, per this edition's numbers convention (exact integers are
`i128` with checked arithmetic returning `SchemeError::Overflow`). This
addition makes that policy concrete: it repeatedly squares
`Rational::new(99, 100)?` and counts how many self-multiplications
succeed before one overflows. Since 99 and 100 are coprime, the `gcd`
step in `Rational::new` never actually reduces anything in this chain,
so the raw product `99^(2^k) / 100^(2^k)` is exactly what
`checked_mul` sees. A short calculation (`99^16` is about `8.6 * 10^31`,
still under `i128::MAX`'s `1.7 * 10^38`; `99^32` is about `7.4 *
10^63`, far past it) predicts the fifth squaring is the first to
overflow, and the test pins that value.

## Why this addition

Section 2.1's idiom note names this as the representative addition:
"`Rational` checked operations returning `Result`, with a test pinning
the first overflowing operation in a long product." It demonstrates the
edition's checked-arithmetic policy is not just a type signature but has
an observable, reproducible failure point.
