## Exercise 3.31: why addAction runs the new action once

Approach: `Wire.addAction` appends the action and then calls it once,
immediately. The exercise asks why the call is there, so this edition
makes the answer observable: `registrationProbeLog` reproduces the
book's half-adder session up to the first signal change and answers
the probe log as it stands: two lines, one per probe, printed the
moment each probe was attached, before any `propagate`.

Why the initialization is necessary: an action procedure exists to
communicate a wire's state to the rest of the circuit, and a
newly-attached action has missed every change that happened before it
existed. Running it once at registration syncs it with the present.
Two things would go wrong without the call, both visible in the
half-adder. The probes: `probe` registers its action on a wire that
already carries its initial signal, 0; without the immediate run the
reader would see nothing until the wire happened to change, and the
book's session would open in silence instead of with `sum 0` and
`carry 0`. The gates: each gate action runs once at wiring time and
schedules its output's initial value (the carry and-gate schedules
carry = and(0,0) = 0 at time 3, the inverters schedule their wires'
initial states, and so on). Those settling events are what put the
circuit into a consistent state on the first `propagate`. Without
them, every internal wire would start stale, and the first real input
change would compute against whatever the wires happened to hold:
with an inverter in the loop, an output can sit at the wrong value
indefinitely, because an inverter only re-fires when its input
changes.

The variant the exercise proposes (appending the action without
running it) is exactly that broken circuit, and the fix is not to
pre-run something else; it is to make attachment itself a state-sync
event.

What the tests say: `E3_31Test.kt` asserts the two registration lines
with their exact times (exercise 3.31's "one line at registration"),
then rebuilds the wiring without probes and checks the agenda is
nonempty before the first `propagate` (the settling events exist)
and quiet afterwards, with every wire at its computed initial value.

Deviation: none.
