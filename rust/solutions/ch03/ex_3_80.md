# Exercise 3.80: RLC coupled streams

## Approach

The Figure 3.37 network is two integrals whose inputs are scaled sums
of each other's outputs: `dv_C = -i_L/C` and `di_L = v_C/L - (R/L)
i_L`. The Rust `rlc(r, l, c, dt)` answers the closure from the initial
state to the pair of streams; the statement's `cons` pair becomes the
tuple `(Stream<f64>, Stream<f64>)`. Both integrands go through the
section's `integral_delayed`, so each is forced only when its
integral's first tail element is demanded. Scheme gets away with two
mutually visible internal `define`s; in Rust one name must outlive its
own definition -- `i_L`'s integrand needs `v_C` while `v_C` is still
being built -- so that one name is routed through a `Rc<OnceCell<_>>`
definition slot, set the moment `v_C` exists, before any tail thunk
can run. Every integrand therefore reads finished streams only. The
book's run (`R` = 1, `L` = 1, `C` = 0.2, `dt` = 0.1, `v_C0` = 10,
`i_L0` = 0) opens at the stated physical state -- `v_C(0)` = 10,
`i_L(0)` = 0 -- and its first steps are hand-checkable: `dv_C[0] = 0`
so `v_C[1] = 10`, `di_L[0] = 10` so `i_L[1] = 1`, then `v_C[2] = 9.5`,
`i_L[2] = 1.9`, and so on; the test pins the first six samples of both
streams exactly (tolerance 1e-12) and checks the physics it models:
the current climbs positive (0 to 3.6461 A over half a second) while
the capacitor discharges (10 down to 5.5955 V), the resistor damping
both toward zero.

## Map class

`T`. The statement translates whole: `RLC`'s parameters, the returned
pair of state streams, and the book's parameter set are all the
statement's own. The Rust wrinkles: the `cons` pair is the tuple, and
the one forward reference the mutual integrands create is the explicit
definition slot described above.

## Deviation

None. The network is Figure 3.37's exactly, and the returned pair is
the statement's pair of streams.
