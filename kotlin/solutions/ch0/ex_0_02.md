## Exercise 0.2: compose and repeated, property-tested

Approach: `compose` is the one-line closure `{ x -> f(g(x)) }`; `repeated`
delegates to a `tailrec` loop so the n-fold application runs in constant
stack, which also rehearses the section 0.3 discipline before that section
arrives. The tests pair hand-computed cases (`repeated(inc, 0)` identity,
`compose(double, inc)` versus `compose(inc, double)` order) with `checkAll`
properties: composition agrees with direct application for generated
inputs, and `repeated(inc, n)` agrees with n increments, including the
`n = 0` boundary.

Class: companion-added exercise (idiom-kotlin.md, Section 5, list item 0.2);
no map row. Deviation: the companion says "property-test against
hand-computed cases"; the solution treats hand cases and generated
properties as two test groups rather than deriving properties from the hand
cases alone, which keeps the boundary case `repeated(f, 0)` explicit.
