# Exercise 5.4: the two exponentiation machines

The map class is `T`. The statement asks for controller sequences for
the recursive `(expt b n)` and its iterative reformulation
`(define (expt-iter b n) ...)`.

The recursive controller follows the 5.1.4 discipline with one economy
the section itself anticipates ("whether there are other registers that
need to be saved depends on the particular machine"): only `continue`
is saved around the recursive call. The subproblem clobbers `n`
(decrementing it) but never `b`, so `b` needs no save; each returning
level multiplies `b` into `val` once. The register set is `b`, `n`,
`val`, `continue`; the sequence is the `exptRecursiveController`
transcription of `solutions/ch5/E5_04.kt`:

```
(controller
  (assign continue (label expt-done))
expt-loop
  (test (op =) (reg n) (const 0))
  (branch (label base-expt))
  (save continue)
  (assign continue (label after-expt))
  (assign n (op -) (reg n) (const 1))
  (goto (label expt-loop))
after-expt
  (restore continue)
  (assign val (op *) (reg b) (reg val))
  (goto (reg continue))
base-expt
  (assign val (const 1))
  (goto (reg continue))
expt-done)
```

The iterative controller is the 5.1 pattern again: registers `b`,
`counter` (seeded from `n`), `product`, a single test `(op =)` against
`(const 0)`, and no stack and no `continue` at all, the state wholly in
the registers (`exptIterativeController`, answering in `product`).

Method: both sequences run on the section's hand model.
`exptMachineRuns()` answers `["1024", "243", "1024", "243"]`:
recursive on (2, 10) and (3, 5), then iterative on the same inputs,
identical answers from different machinery. `E5_04Test` also pins the
recursive machine's peak stack depth on those inputs at exactly n
(10 and 5): one saved `continue` per level, the observation 5.5 and
5.6 measure for the factorial and Fibonacci machines.
