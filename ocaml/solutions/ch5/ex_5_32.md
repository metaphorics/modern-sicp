Exercise 5.32: the symbol-operator fast path.

(a) The modified `ev-application` tests `(op symbol-operator?)` before
saving `env` and `unev`; the fast path looks the operator up in place,
initializes `argl`, sets `proc`, and joins the base operand loop at
`ev-appl-operand-loop` with `proc` saved. The pinned session: symbol
calls, a compound operator `((lambda (y) (+ y 1)) 41)`, and the
monitored factorial dropping from the base 144 pushes at n = 5.
(b) The answer to Alyssa's suggestion is no: the evaluator's dispatch
runs per evaluation, so every special case costs a test on every run,
and the tests can only see the shape of the expression, not the
register analysis `preserving` does at compile time. Compilation keeps
the analysis out of the running machine.
