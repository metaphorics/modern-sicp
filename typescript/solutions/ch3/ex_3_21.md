# Exercise 3.21: the print-queue for the pointer-pair queue

## Approach

Ben reads the queue object at the REPL and sees the raw representation:
the front pointer printed as a list beside the rear pair. Eva Lu asks for
a procedure that prints the queue as the sequence it names. `printQueue`
renders the module queue's front pointer with `showMList`; `benPrintQueue`
renders both pointers the way the naive view does, so the tests can show
the difference the exercise turns on.

## Pins

Computed by running. Over the figure 3.18 session (insert a, insert b,
delete, insert c, insert d, delete) `printQueue` is `(c d)`. Ben's view
of the same session contains `(c d)` and the rear rendering
(`(front (c d) rear (d))`), which is not what `printQueue` returns.
Deleting down to one item: `(front (a) rear (a))`; inserting b after that:
`(front (a b) rear (b))`; deleting a: `(front (b) rear (b))`. Deleting the
last item empties the front pointer and, in this edition, the rear pointer
with it: `()` and `(front () rear null)`. The book's version leaves the
rear pointer dangling at the deleted pair, which is the confusion Eva
explains; the edition's queue keeps the rear pointer honest instead, so
Ben's raw view reads `null` there.

## Deviation

The module's `deleteQueue` resets the rear pointer when the last item
leaves; the book's leaves it dangling. The raw view therefore shows
`null` where the book's transcript shows the stale item, and the
rationale states the difference instead of reproducing it.
