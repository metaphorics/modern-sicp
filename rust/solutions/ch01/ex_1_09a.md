# Exercise 1.9a (this edition)

This addition turns exercise 1.9's iterative-versus-recursive question into
a measurement. Both `deferred_depth` and `tail_shape_depth` probe the
address of a local on every frame and stop once the distance from the first
frame's address passes half the thread's stack budget, instead of letting
the thread actually crash into its guard page. Run on a 64 KiB stack, both
recursive shapes stop within a few hundred frames; run on a 256 KiB stack,
both reach roughly four times as deep, because the bytes a frame costs are
constant and the budget quadrupled. The loop form of the tail-shaped
procedure, run on the smaller 64 KiB stack for a million steps, completes
without touching the budget at all.

The comparison makes the lesson from exercise 1.9 concrete: Rust gives the
tail-shaped recursion no discount over the deferred one. Both are bounded
by the stack; only the loop is not. A Scheme implementation, required to be
tail-recursive by the standard, would let `plus_tail_shaped` run forever in
constant space: the language guarantees what Rust's compiler only
sometimes delivers as an optimization, never as a contract.
