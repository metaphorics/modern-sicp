# Exercise 5.8: a doubly defined label

The book asks what its label scan does with a controller that defines
the same label twice. Its scan folds over the controller, and the
answer depends on fold direction: a right-to-left fold keeps the last
definition, a left-to-right scan the first, so the machine assembles
and then jumps arbitrarily. Either way the book's simulator gives the
snippet a silent, order-dependent meaning.

This edition refuses the controller instead. `extractLabels` in the
5.2 assembler raises the typed `MachineError.DuplicateLabel` the
moment a name reappears, so nothing assembles. The solution feeds the
book's exact snippet (two `here` definitions, `there` defined only
after the second `here`) to `makeMachine` and reports the outcome:
`duplicateLabelOutcome()` answers `the label here is used twice`,
pinned by `E5_08Test`. A controller the book assembles into a machine
that jumps arbitrarily is not a program this simulator accepts.
