## Exercise 3.7: makeJoint shares one account

Approach: `makeJoint` returns a new `Account` object that owns no balance
of its own. It closes over the wrapped `account` and the original
`password`; a request's `attempt` is checked against `newPassword`, and
once that passes, the request is simply forwarded to `account` under the
closed-over original password. No new state cell is created, so every
transaction through either name reads and writes the one balance cell
`account` already owns -- this is `makeJoint` sharing state, not copying
it, the same aliasing point section 3.1.3 makes about `peter-acc` and
`paul-acc`.

Class: `T`, unchanged from the map. The map's tailored addition on this
row ("multi-signature joint account") was chosen by the OCaml edition as
3.7a; this edition implements exercise 3.7 itself and does not add 3.7a.
Deviation: none.
