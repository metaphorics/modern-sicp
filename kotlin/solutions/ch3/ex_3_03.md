## Exercise 3.3: password-protected accounts

Approach: `AccountError` is the section's own domain error set (the
codebase convention used since `IntervalError` in 2.1), and `makeAccount`
closes over both `balance` and the fixed `correctPassword`. Every request
compares its own `password` argument against the closed-over one before
touching `balance`; a mismatch answers `Either.Left(WrongPassword)`
instead of the book's "Incorrect password" string, and an over-large
withdrawal with the right password still answers `InsufficientFunds`.
`CallTheCops` sits in `AccountError` unused by this exercise: it is
declared once, here, so exercises 3.4, 3.4a, and 3.7 share the identical
closed error set instead of three incompatible near-duplicates.

Class: `T`, unchanged from the map. Deviation: none.
