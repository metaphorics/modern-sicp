# Exercise 1.9

Two procedures compute the same sum from `inc` and `dec`, but the shape of
the deferred work differs. In `plus_deferred`, the recursive call sits
inside the argument to `inc`, so each level defers one addition until the
base case returns: `plus_deferred(4, 5)` expands as
`inc(inc(inc(inc(plus_deferred(0, 5))))) = inc(inc(inc(inc(5)))) = 9`. That
chain of four pending `inc`s is a linear recursive process. In
`plus_tail_shaped`, the recursive call is the entire value of its branch:
`plus_tail_shaped(4, 5) = plus_tail_shaped(3, 6) = plus_tail_shaped(2, 7) =
plus_tail_shaped(1, 8) = plus_tail_shaped(0, 9) = 9`. Nothing waits outside
any call, so in Scheme this is a linear iterative process: the running
state is exactly `(a, b)` at each step.

The map class for this exercise is `A`: the statement's conclusion changes
because the host differs. Scheme's standard requires implementations to be
tail-recursive, so `plus_tail_shaped` runs in constant space no matter how
large `a` is. Rust makes no such promise. Both functions above are still
ordinary recursive calls to the compiler, and both consume one stack frame
per step; `plus_tail_shaped`'s frame is smaller because it holds no pending
`inc`, but it is not zero. The loop form of `plus_tail_shaped` (increment
`b`, decrement `a`, until `a` is zero) is the only version of this exercise
that actually runs in constant space in Rust, and it is what exercise 1.9a
measures directly.
