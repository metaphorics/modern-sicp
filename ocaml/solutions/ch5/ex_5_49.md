Exercise 5.49: the read-compile-execute-print loop.

No evaluator is involved: each item compiles into a new labelled
block, the machine reassembles with every block so far plus the shared
runtime, and the new block runs with the accumulated global
environment; keeping earlier blocks keeps their procedures' entries. Like 5.48's
compile-and-run, the loop driver is host code: guest programs cannot
quote source, so the read-compile-execute step lives outside the
evaluated language.
Pinned on fib, `fib 12`, doubling, and `double 441`: `fib`, 144,
`double`, 882. Labels stay unique because all blocks of a session
compile under one shared compiler state.
