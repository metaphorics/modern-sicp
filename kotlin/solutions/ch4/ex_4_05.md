# Exercise 4.5: cond arrow clauses

## Approach

`WithArrow` takes over the open `condToIf` seam. An arrow clause
`(test => recipient)` rewrites to
`((lambda (*cond-test*) (if *cond-test* (recipient *cond-test*) rest))
test)`, so the test evaluates exactly once and its value feeds the
recipient; the naive rewrite `(if test (recipient test) rest)` would
evaluate the test twice, and the book flags exactly that. The one-evaluation
property is pinned by a counting probe: a `set!` inside the test increments
once while the cond answers through the arrow. Plain clauses keep chaining
in order, the recipient receives the test's value rather than its truth
(`99 => (lambda (v) (* v 2))` gives 198), and an exhausted chain answers
the `false` variable.

## Map class

`T`.

## Deviation

None. `assoc` and `cadr` are used from the object language (`assoc` defined
in the program, `cadr` among the library's `c(a|d)+r` primitives).

## Answer

The book's example returns 2: `(cond ((assoc 'b '((a 1) (b 2))) => cadr)
(else 'no))` => 2, with the probe `count` left at 1 (one test evaluation).
`(cond ((= 1 2) 'first) ((= 1 1) 'second) (else 'third))` => second, and a
no-match chain without else answers #f.
