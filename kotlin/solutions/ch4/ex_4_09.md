# Exercise 4.9: designing iteration constructs

## Approach

Two constructs, `while` and `until`, each a derived expression over set! +
a local loop procedure: [whileToCombination] rewrites
`(while test body...)` to `((lambda (*while*) (set! *while* (lambda ()
(if test (begin body... (*while*)) ()))) (*while*)) '*while*)` and
[untilToCombination] mirrors the branch order. The rewrite fixes both
properties that matter: the predicate and body re-enter the full evaluator
per iteration, so nested forms get the whole language (pinned with nested
loops, each wrapper frame holding its own loop procedure), and the
self-call sits in tail position, so the loop runs an iterative process in
constant host stack -- pinned by a 100,000-iteration `while`, which a
non-tail implementation would not survive.

## Map class

`T`.

## Deviation

The loop terminates with the unspecified value; the constructs are derived
expressions rather than primitives, so nothing new enters the global
environment.

## Answer

`(while (<= i 5) ...)` summing 1 to 5 leaves `sum` at 15; a `while` whose
test starts false leaves the body untouched (`k` stays 0); `(until (> j
12) ...)` multiplying 8 through 12 leaves `product` at 95040 and `j` at 13;
an `until` whose test starts true leaves `m` at 0; the 100,000-iteration
tail loop answers 100000; the nested probe counts 6.
