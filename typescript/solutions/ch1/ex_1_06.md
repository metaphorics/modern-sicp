# Exercise 1.6: the new-if experiment

## Approach

`newIf` is an ordinary procedure, so the host evaluates all three of its
arguments before the call runs. Alyssa's rewrite therefore evaluates the
recursive branch on every iteration, whether or not the predicate is
true; the recursion never bottoms out and the process computes nothing.
The tests pin both halves: the demonstration on plain-value branches
returns `5` and `0` as Eva shows, and the rewritten iteration ends in
the host's stack-overflow RangeError, while the section's own iteration,
whose conditional operator evaluates only the branch it takes, converges.

## Numbers

`newIf(2 === 3, 0, 5)` is `5`; `newIf(1 === 1, 0, 5)` is `0`;
`sqrtIterNewIf(1.0, 2)` throws RangeError; the control `sqrtIter(1.0, 2)`
converges to `1.4142156862745097`, the absolute-tolerance answer.
