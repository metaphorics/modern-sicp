# Exercise 1.5: the evaluation-order termination test (translate)

Map class `T`. Ben's test separates the two evaluation models: `p` is the
procedure whose call reduces to itself, and `test 0 (p ())` answers `0`
under normal order but never terminates under applicative order, because
the argument is evaluated before the call.

OCaml keeps the exercise intact. `let rec p () = p ()` has type
`unit -> 'a`: it never returns, so the type variables stays unresolved.
`test x y = if x = 0 then 0 else y` gets the type `int -> int -> int`,
not the Scheme shape `any -> any`, because the two branches of an `if`
must share one type; the typed language narrows the exercise to integer
arguments, which the interfaces state and the tests keep honest.

The diverging call is deliberately never executed by a test, since a
hanging test proves nothing a counter cannot. Instead the suite observes
eagerness directly: the unneeded argument `(incr counter; 42)` is
evaluated even when `test` returns `0` without looking at it, which is
applicative order made observable. Under normal order the counter would
stay at zero. The rationale for running nothing that hangs is recorded in
the scaffold, which calls `test` only on terminating arguments.
