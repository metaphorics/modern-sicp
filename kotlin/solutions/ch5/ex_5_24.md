# Exercise 5.24: cond as a basic controller form

The controller gains `ev-cond`, a loop over the clause list. Each
iteration takes the first clause word, advances the walk in `unev`,
stashes the clause in `proc` for the duration of the predicate test, and
tests the predicate through `eval-dispatch`; a true predicate (or an
`else`) selects the clause and its actions go to `ev-sequence`, so the
clause's last expression is still in tail position. The clause word
rides in `proc`, whose live value every enclosing argument loop has
already saved on the stack.

Two answers the derived form gives for free are handled explicitly: a
selected clause with no actions returns the predicate's value (the
bodyless session answers `#t`), and no true clause with no `else`
answers `#f`, exactly what `cond->if` produced in exercise 5.23.

The tail-position claim is measured, not asserted: the monitored driver
runs an iterative loop whose recursion is a cond action, and the maximum
depth is constant (10 for n = 10, 50, 100, and 200), the same constant
the book's evaluator gives the 5.26 iterative factorial. The session
values (`zero`, `one`, `many`, `#t`, `#f`) match the derived form's.
