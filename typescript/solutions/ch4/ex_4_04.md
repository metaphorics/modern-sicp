# Exercise 4.4: and and or as special forms

## Approach

The book offers both routes; this solution installs and and or as new
special forms with `evalWithAndOr`, a full dispatch whose recursion stays
inside the evaluator, so both forms also work in nested positions such as
procedure bodies, where the module's own evaluate would never reach them.
`and` evaluates its conjuncts in turn and stops with false as soon as one
is false, otherwise returning the last value; `or` returns the first
non-false value and stops.

## Numbers

`(and)` is `#t` and `(or)` is `#f`. `(and 1 2 3)` is `3`, `(and 1 false 3)`
is `#f`, `(or false false 4)` is `4`, `(or false false)` is `#f`. After
`(define hits 0)`: `(and false (set! hits 99))` is `#f` with `hits` still
`0`; `(or 7 (set! hits 99))` is `7` with `hits` still `0`;
`(and (set! hits 99) hits)` is `99`. In bodies: `(both? 2 3)` is `#t`,
`(both? 2 -3)` is `#f`, `(fallback)` is `fallback`.

## Class and deviations

Translated row. The special-form route is taken, not the derived-expression
route, and the full dispatch mirrors the module's helpers for nesting; the
truthiness rule is the edition's, where every value but the false object
counts as true. No other deviation.
