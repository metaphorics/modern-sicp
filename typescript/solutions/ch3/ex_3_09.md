# Exercise 3.9: two factorials, two frame shapes

## Approach

The book asks for the environment structures `factorial(6)` builds in
each version. In this edition the frames of that drawing are call
frames, so the solution measures rather than draws: `factorialTraced`
walks the recursive version with a depth parameter and records the
maximum, `factorialIterTraced` runs the edition's loop spelling of the
iterative version, and `recursiveFrames`/`iterativeFrameStates` record
the frames themselves, one row per pending call for the recursion and
one row per iteration for the single reused loop frame.
`renderFactorialStructures` then renders the two structures from those
traces, so the pinned drawing is produced by an instrumented run.

## Pins

Recursive at `n = 6`: result 720, deepest 6; the frame trace is
`n: 6, 5, 4, 3, 2, 1`, each frame waiting on the one below it and each
pointing at the global frame where the binding of `factorialRecursive`
lives. Iterative at `n = 6`: result 720, deepest 1; the frame trace
holds six states of the one frame (`product: 1, counter: 1` through
`product: 120, counter: 6`), reassigned rather than stacked. The same
holds at `n = 1` (depth 1 both ways) and `n = 4` (depth 4 against 1).

## Map class

`R: diagram call stack growth, no TCO`. The drawing became a
measurement; the footnote's tail-recursion honesty became the point of
the iterative column.

## Deviation

The probe is raw JavaScript, not Effect (the raw-closure precedent of
exercise 3.8): the stack of ordinary function frames is the thing being
diagrammed, and an Effect rendering would measure the fiber machinery's
frames instead of the language's. The iterative version is the
`while`-loop spelling of 1.2.1 rather than a literal `fact-iter`
self-call, because JavaScript engines make no tail-call promise (ES2015
specified proper tail calls; V8 never shipped them, while JavaScriptCore
did), so a pinned depth for a tail-recursive helper would depend on the
engine running the test. The loop is the only version whose frame count
is guaranteed, which is exactly the footnote's claim.
