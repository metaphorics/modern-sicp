# Exercise 1.11

The recursive process is the definition read straight off the page: `f(n)
= n` below 3, otherwise the sum of the three prior calls with their
coefficients. The iterative process carries the last three values as state
variables `(a, b, c)` and advances them each pass of a loop, in place of
the recursive calls; the map class is `A` because Rust has no tail-call
guarantee to lean on, so the iterative version has to be a real loop, not
a Scheme-style recursive call to `f-iter`.

Both compute `f(8) = 335`: `f(3) = 4`, `f(4) = 11`, `f(5) = 25`, `f(6) =
59`, `f(7) = 142`, `f(8) = 335`, checked by hand against the loop's trace
`(a, b, c)` at each step and confirmed by the passing test.
