# Exercise 5.24: cond as a basic controller form

The controller gains `ev-cond`, a loop over the clause list. Each
iteration takes the first clause word, advances the walk in `unev`,
stashes the clause's actions in `argl`-free registers, and tests the
predicate through `eval-dispatch`; a true predicate (or an `else`)
selects the clause, and its actions are evaluated by `ev-sequence`, so
the clause's last expression is still in tail position. The clause
under test rides in `proc`, whose live value every enclosing argument
loop has already saved on the stack.

Two answers the derived form gives for free are handled explicitly:
a selected clause with no actions returns the predicate's value (the
book's answer for `(cond (p))`), and no true clause with no `else`
answers `false`, exactly what `cond->if` would have produced.

`ex_5_24 ()` pins the sessions: `zero`, `one`, `many`, the bodyless
clause answering `#t`, and the no-true-clause cond answering `#f`.
