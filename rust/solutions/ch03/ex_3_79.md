# Exercise 3.79: general second-order solver

## Approach

The generalization keeps exercise 3.78's network and swaps one box:
where the loop fed back `a dy + b y`, it now feeds back `f` applied to
the `dy`/`y` pair, mapped elementwise with the section's
`stream_map2` over the two named streams. The integrand thunks are
still forced only after both definitions complete, so `f` always sees
current elements of finished streams. Two runs test it. The
undamped run `f(dy, y) = -y` is exercise 3.78's equation exactly, and
the general solver answers its exact forward-Euler stream back -- the
same four pinned samples inside the same measured cos tolerances
(1e-12, 0.01, 0.001, 0.05). The damped run `f(dy, y) = -0.1 dy - y`
is judged by its envelope: the peak `|y|` of each of five successive
one-period windows (629 samples at `dt` = 0.01) is pinned exactly and
is strictly smaller than the one before, with a measured per-window
ratio of 0.7534 -- the e^(-0.05 t) envelope decay over one period
(0.730) times explicit Euler's slow amplitude pump per window
(about 1.032). The amplitude decays; the oscillation survives.

## Map class

`T`. The statement translates whole: same arguments as `solve-2nd`
with `f` in place of the constants. The Rust wrinkles are the two from
exercise 3.78 (self-referential streams need `self_stream` names, the
delayed integrand is a thunk) plus one: `f` must be `Clone`, because
`stream_map2`'s mapper is cloned into the tail thunk that continues
the stream.

## Deviation

None. The solver is the statement's `solve-2nd` with `f` in the
feedback path, and the two test runs are the textbook oscillator plus
the damped case the map calls for.
