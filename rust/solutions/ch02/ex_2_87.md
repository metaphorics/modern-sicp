# Exercise 2.87: polynomial =zero?

## Approach

The library's `install_polynomial_is_zero` puts a `=zero?` entry for polynomials in the operation table: a polynomial is zero exactly when every coefficient in its term list is itself zero, so an empty term list is the zero polynomial. The solution assembles a table with the generic arithmetic package, the polynomial package, and this entry, then checks both sides: `is_zero` on a `y`-polynomial built from `the_empty_termlist` answers `true`, and on `y` itself answers `false`.

The second half of the probe shows why the entry exists. `adjoin_term` consults the generic `=zero?`, so a zero coefficient of any type is dropped on the way in, just like a zero number. The solution tries to adjoin `(y - y)`, the zero polynomial in `y`, as the order-1 coefficient of an `x`-polynomial, and it never appears: after doubling, the printed sum is `(polynomial (x (0 (polynomial (y (0 2))))))`, with only the order-0 constant surviving and its inner constant doubled. A nested zero coefficient collapsing out of an addition is the case the exercise is after, and the run demonstrates it end to end.

## Map class

T, a straight translation in this edition's runtime types. The book's `=zero?` clause for the polynomial term-list representation becomes one table entry over `Value` coefficients, with `adjoin_term` consuming it unchanged.
