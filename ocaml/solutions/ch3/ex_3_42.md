# Exercise 3.42 — serialize once outside dispatch (translate)

The map class is `T`. Ben hoists the `protected` applications out of
the message dispatch, so the serialized withdraw and deposit are built
once when the account is made. Both versions route through the same
serializer — its mutex is the same object whether it is fetched once
or per message — so the change only moves where the wrapped procedures
are allocated, and the concurrency each version allows is identical.
The solution drives both accounts through the same concurrent deposit
workload (half the deposits on a spawned domain, half on the calling
domain) and checks that either way every unit lands.

Sample: `ex_3_42 ()` answers `(400, 400)`.
