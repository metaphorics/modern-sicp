# Exercise 5.8: duplicate labels are an assembly error

The book's `extract-labels` scan silently folds onto whichever definition
comes last, so the ambiguous controller assembles and then jumps
arbitrarily. The TypeScript scan refuses the controller at assembly time:
the second definition of a label makes `extractLabels` return the typed
`DuplicateLabel` error, and `makeMachine` returns it instead of a machine.

The test pins `duplicateLabelOutcome()` on the book's own snippet, which
defines `here` twice and `there` only after the second `here`: the answer
is the rendered fault "the label here is used twice", never a machine, so
the question the book asks (what will register `a` hold when control
reaches `there`?) has no answer worth computing.
