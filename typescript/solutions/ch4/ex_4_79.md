# Exercise 4.79: environments instead of renaming (translate)

## Approach

The Lisp evaluator avoids parameter collisions with local
environments; the query system instead renames rule variables on
every application. The solution demonstrates the environment
strategy the exercise asks for: each rule application evaluates its
body in a fresh local layer holding the parameter bindings, with
lookups falling through to the enclosing frame, so a caller and a
callee parameter sharing one name never collide. A small infix
rewrite shows the same surface handling queries would need for
non-prefix input.

## Numbers

Applying with parameter `x` bound to 4 over an outer layer binding
`x` and `outer` to 99 yields `[4, 99]`: the local layer shadows
without destroying the outer lookup. The infix rewrite turns
`(?x + 3)` into `(+ ?x 3)`. The tests pin both.

## Class and deviations

Translated row. Deviation: the exercise is open-ended (the book
calls a good answer worth a Ph.D.); the solution demonstrates the
local-environment mechanism on the procedure analogy rather than a
full scoped query evaluator.
