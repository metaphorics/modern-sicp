# Exercise 4.22 — let in the analyzed evaluator (translate)

The map class is `T`: the statement's request — the analyzed evaluator
of 4.1.7 gains the `let` of exercise 4.6 — is a one-clause extension of
the analyzer. The solution duplicates the section's analyzer locally and
adds `analyze_let`, which builds the lambda application (a lambda over
the parameters and body, applied to the inits) and analyzes it once, at
analysis time. The execution procedure of a `let` is therefore the
analyzed application itself; no rewrite and no construction runs at
execution, which is the difference from a direct evaluator's per-call
lowering.

The demonstration runs `(let ((x 3) (y 4)) (+ x y))` through the
analyzed evaluator and through the direct evaluator extended with the
same special form via the standard `Core` dispatch, which redoes the
rewrite at every execution. Both answer 7.

Sample: `ex_4_22 ()` answers `["7"; "7"]`.
