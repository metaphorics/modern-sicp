# Exercise 3.54a: stream of Catalan numbers

## Approach

The Catalan numbers are built exactly the way 3.54 builds the
factorials: name the stream, cons the seed element onto the recurrence
over the stream's own past. `catalan` is C_0 = 1 consed onto
`stream_map2` pairing the named stream with the integers from 0 -- each
element multiplies the one at the same position by 4n + 2 and divides
by n + 2, where n counts that position from 0, so every new element is
one multiplication and one exact division past the memoized element
before it. The statement's "computed from the factorials stream" is
honored for the cross-check: `C_n = (2n)! / (n! * (n + 1)!)` with each
factorial read by index off 3.54's factorials stream, whose memoized
spine makes the repeated `stream-ref`s cheap. The test pins the
canonical C_0 through C_10 (1 1 2 5 14 42 132 429 1430 4862 16796),
walks the recurrence asserting the division is exact at every step --
(n + 2) always divides C_n * (4n + 2), because C_{n+1} =
(2n+2)! / ((n+1)! * (n+2)!) is an integer equal to exactly that
quotient -- and lands that walk on the stream's own C_20, so any
truncation in the stream's integer division would show. Finally the
stream must agree with the closed form: element for element through
n = 16 as read off the factorials stream, and through n = 20 in the
overflow-safe form of the same formula.

## Map class

`T` for the statement it extends (3.54), with the map's

## Why this addition

The Catalan recurrence is the sharpest second instance of the
self-referential stream discipline the section teaches, because it
cannot be written as a map or filter over an existing stream: each
element needs the stream's own past, one step behind. It also makes the
integer-exactness of the runtime load-bearing -- the recurrence only
produces the Catalan numbers if `(n + 2)` divides evenly every time,
over exact `i128` arithmetic -- and it consumes 3.54's factorials
stream as data for the closed form, exercising `stream_ref` over a
memoized spine as a computation tool rather than a display device.

## Deviation

Two honest bounds. The pairing stream is `integers_starting_from(0)`,
not `integers()`: the recurrence's n is the 0-based index of the
element being extended, and 1-based integers would shift the formula
and lose the stream's second 1. And the factorials-stream closed form
stops at n = 16, because `(2 * n)!` overflows `i128` at n = 17 (34!
exceeds i128::MAX, near 1.7e38); agreement through n = 20 uses the same
formula rearranged as `(n + 2) * ... * (2n) / n!`, whose intermediates
peak near 1.6e28 and whose division stays exact. Both bounds are
stated in the solution docs.
