# Exercise 0.5: sum of cubes, twice, then a checked average

## Two sums, one answer

`sum_cubes_recursive` follows the shape of section 0.2's `sum_to_recursive`:
a base case (`a > b` sums to nothing) and a recursive case that adds one
term and recurses on a smaller range.

```rust
fn sum_cubes_recursive(a: i64, b: i64) -> i128 {
    if a > b {
        0
    } else {
        i128::from(a).pow(3) + sum_cubes_recursive(a + 1, b)
    }
}
```

`sum_cubes_iterative` computes the identical sum as one iterator chain:
`(a..=b).map(|i| i128::from(i).pow(3)).sum()`. Both are asserted equal on
`sum_cubes_*(1, 4) == 100` (`1 + 8 + 27 + 64`), which is also how the test
checks the two implementations agree rather than merely each looking
plausible on its own.

## Propagating with `?`

`average_cube_recursive` and `average_cube_iterative` each compute their
respective sum, then divide by the count of terms using
`ch00::sec_0_8::safe_div`, which returns `Result<i128, ArithError>`:

```rust
pub fn average_cube_recursive(a: i64, b: i64) -> Result<i128, ArithError> {
    let total = sum_cubes_recursive(a, b);
    let average = safe_div(total, i128::from(b - a + 1))?;
    Ok(average)
}
```

The `?` after `safe_div(...)` is the point of the exercise: if `safe_div`
returns `Err(ArithError::DivideByZero)`, the `?` immediately returns that
same `Err` from `average_cube_recursive`, with no explicit `match`. This
only type-checks because `average_cube_recursive`'s own return type is a
`Result` with the same error type `safe_div` produces.

## When division fails

`b - a + 1` is the count of integers in `a..=b`; it is zero exactly when
`a == b + 1` (an empty range stated backwards), which is what the test's
`average_cube_recursive(5, 4)` exercises: `sum_cubes_recursive(5, 4)` is `0`
(the base case, since `5 > 4`), and dividing by a count of `0` returns
`Err(ArithError::DivideByZero)`, which the `?` propagates unchanged out of
`average_cube_recursive` for the test to observe.
