# Exercise 4.6: `let` as a derived expression

## Lesson

One binding lowers exactly to an application of a procedure to its
init, and the kernel's curried application shapes that derivation.
Multi-binding `let` stays simultaneous -- every init evaluates in the
outer frame before any name binds -- which nested single derivations
cannot promise under shadowing. The shadowing pin answers `5`, not
`3`: the second init reads the outer `x`. Nesting agrees wherever
inits ignore the bound names.

## Map class

`A` (map row 4.1: derived forms). Single lets derive; multi lets bind
simultaneously by the frame rule.

## Deviation

The multi lowering evaluates inits in the outer frame rather than
nesting single derivations, because nesting would read the wrong `x`.
The rationale above is the justification, not a shortcut.

## Answer

- Single derivation: `6`.
- Simultaneous shadowing: `5`, not `3`.
- Nested agreement: `7`.
- Pin: `letDerivedTranscript() == "6\n5\n7\n"`.
