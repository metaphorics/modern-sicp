# Exercise 3.55: the partial-sums combinator

## Approach

`partialSums` returns its input's head followed by the elementwise sum
of the partial sums with the shifted input: element k + 1 adds S(k + 1)
to the running total. The tail thunk reads a tie cell filled by the last
line, which lets the result reference itself the way the book's
definition does while keeping one memoized chain. The Long overload
adds with `Math.addExact`; the Double overload serves the section's pi
series. The tests pin the triangular numbers 1, 3, 6, 10, 15, 21, 28,
36, 45, 55 over `integers`, 1 through 6 over `ones`, and the pi rows
from scaling the partial sums of 1, -1/3, 1/5, ... by 4.0: 4.0,
2.666666666666667, 3.466666666666667, 2.8952380952380956,
3.3396825396825403, 2.9760461760461765, 3.2837384837384844,
3.017071817071818. A python3 script recomputes those doubles with the
identical operation order and matches bit for bit.

`T` (map row 3.55: Kotlin T).

None. The two overloads carry `@JvmName` because the erased JVM
signatures would clash; section 3.65 builds its own private twin rather
