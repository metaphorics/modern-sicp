# Exercise 1.26

Eva is right. The proper `expmod` computes `expmod(base, exp / 2, m)` once
per even step and squares the result; Louis's version calls
`expmod(base, exp / 2, m)` twice, so every halving of the exponent doubles
the number of pending calls instead of leaving it the same. Instrumented
with a call counter, `expmod(2, 1000, 251)` takes 16 calls (roughly `2 *
log2(1000)`), while Louis's version takes 2023 calls for the same
arguments (roughly `2 * 1000`): the single reused call turns a chain of
squarings into a `Theta(log n)` process, and the doubled call turns it back
into a `Theta(n)` process, one recursive call per unit of the exponent
instead of one per halving. Both versions compute the same value, so the
inefficiency is invisible in the answer and only shows up in the call
count (or the wall-clock time Louis noticed).

The map class is `T`: the two implementations and the question of why they
differ translate directly; no host-specific rewording is needed.
