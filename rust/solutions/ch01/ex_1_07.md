# Exercise 1.7: `good-enough?` fails at the extremes

## The book's absolute-tolerance test, reproduced

```rust
pub fn good_enough_absolute(guess: f64, x: f64) -> bool {
    abs(square(guess) - x) < 0.001
}

pub fn sqrt_absolute(x: f64) -> f64 {
    fn iter(guess: f64, x: f64) -> f64 {
        if good_enough_absolute(guess, x) {
            guess
        } else {
            iter(f64::midpoint(guess, x / guess), x)
        }
    }
    iter(1.0, x)
}
```

## Small radicands

For `x = 0.0001` the true square root is `0.01`, but a guess of `0.03` is
already accepted: `0.03² = 0.0009`, and `|0.0009 - 0.0001| = 0.0008 <
0.001`. The fixed absolute tolerance of `0.001` is larger than the
radicand itself, so `good-enough?` declares victory before the guess is
anywhere near `0.01`; the reference test checks exactly this case and
confirms the accepted guess is off by more than half its own true value.

## Large radicands

For a very large `x`, floating-point arithmetic loses precision: two
adjacent representable `f64` values near a large guess can differ by more
than `0.001` once squared, so `square(guess) - x` may never land inside the
`0.001` window no matter how close `guess` already is to the true root.
`sqrt_absolute` genuinely fails to terminate on large enough inputs for
this reason (not tested here directly, since a non-terminating call would
hang the test suite; the book's text is the source for this claim).

## The relative-tolerance fix

```rust
pub fn sqrt_relative(x: f64) -> f64 {
    fn good_enough_relative(guess: f64, next: f64) -> bool {
        abs(next - guess) < 0.001 * guess
    }
    fn iter(guess: f64, x: f64) -> f64 {
        let next = f64::midpoint(guess, x / guess);
        if good_enough_relative(guess, next) {
            next
        } else {
            iter(next, x)
        }
    }
    iter(1.0, x)
}
```

Comparing successive guesses instead of comparing against a fixed absolute
tolerance makes the stopping test scale with the radicand: for a small `x`
the guesses must stabilize to within `0.001 * guess`, a much tighter
absolute bound than `0.001` alone, so it does not stop early; for a huge
`x` the same relative bound is easy to reach in floating point, since it
scales with the guess instead of demanding a fixed absolute precision the
guess's own representable spacing cannot deliver.

## Test

`good_enough_absolute(0.03, 0.0001)` is `true` (the failure case above).
`sqrt_relative(9.0)` is within `1e-3` of `3.0`. `sqrt_relative(0.0001)` is
within `1e-6` of `0.01` (accurate, unlike the absolute version).
`sqrt_relative(1.0e20)` is within `1.0e5` of `1.0e10` (terminates, unlike
the absolute version).
