# Exercise 3.23: the deque

## Approach

The book asks for a deque with constant-time insertion and deletion
at both ends, and asks the solution to show that no operation scans.
The Rust solution gives every node a `previous` handle alongside
`next` and stores both end handles in the `Deque`. Each operation
touches one node and its neighbor, so `front_insert`, `rear_insert`,
`front_delete`, and `rear_delete` take a fixed number of steps. The
solution follows the book's sequence: it builds `(a b c)` by rear
insertion, inserts `z` at the front, then deletes once from each end.
The remaining items are `[a, b]`. The tests drive every operation,
the error paths on an empty deque, and the length.

## Map class

`A: doubly linked cells need RefCell`. The backward pointers the
book draws are `RefCell<Option<Rc<DequeNode>>>` fields, and the
two-way linkage is exactly what the extra cell mutability buys.

## Deviation

None. The statement's operations, its constant-time requirement by
construction, and the worked sequence are kept.
