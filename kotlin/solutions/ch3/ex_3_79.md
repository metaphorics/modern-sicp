# Exercise 3.79: the general second-order solver

## Approach

`solve2ndGeneral(f, dt, y0, dy0)` keeps 3.78's loop of two delayed
integrals and replaces the scaled sum with `zipStream(dy, y) { d, yy ->
f(d, yy) }`: the acceleration is `f` of the current velocity and
position. Any second-order equation becomes a one-argument change.
Pins: `f = { _, yy -> -yy }`, `dt = 0.01`, from rest at displacement 0
and velocity 1 gives first values `0.0, 0.01, 0.02, 0.029999,
0.039996000000000004`, probed from the compiled solution and re-derived
bit-identically in a python3 same-order script. The solution tracks the
sine: `|y_k - sin(0.01 k)| < 4 * dt` holds for every `k` up to 300 with
room to spare (the observed maximum error over the range is about
0.0092, and the test also bounds the endpoint at 0.02). Consistency:
specializing `f` back to `{ d, yy -> -0.2 * d + -1.0 * yy }` reproduces
`solve2nd(-0.2, -1.0, 0.01, 1.0, 0.0)` element for element over 50
values, the same products and sum in the same order.

## Map class

`T` (map row 3.79: parameterized acceleration over the 3.78 loop).

## Deviation

None.
