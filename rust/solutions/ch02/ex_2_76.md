# Exercise 2.76: adding types versus adding operations

## Approach

The same two-operation, two-representation probe — the real part and
the magnitude of `(3, 4)` — is served three ways: an explicit-dispatch
`enum Z` with a `match` in each of `ed_real_part` and `ed_magnitude`;
the section's operation table, both packages installed; and
message-passing objects, one per representation. All three answer
`(3.0, 5.0)`, which is the point: the three organizations are
equivalent in what they can express, and differ only in what a change
costs.

Explicit dispatch pays when a **type** is added: every operation's
`match` needs a new arm, so `ed_real_part` and `ed_magnitude` both
change. It is cheap when an **operation** is added: one new function,
written once against every existing variant, changes nothing that
exists. Message passing is the mirror image: a new type is one new
object, and no existing object's code changes (`polar_message_object`
never touches the rectangular one), but a new operation means visiting
every object and adding an arm to each. Data-directed programming is
additive in both directions: `additive_install_leaves_existing_handlers_untouched`
proves this is more than an absence of a diff — the very `Rc` behind an
already-installed handler is unchanged, by pointer, after a second
package installs. In Rust terms: an `enum` plus `match` is a closed
type set the compiler checks exhaustively (explicit dispatch); a
trait object is closer to message passing, one virtual call per object
with the operation set fixed at the trait's definition; the table
keeps both axes open at the cost of a runtime lookup and no
compile-time exhaustiveness check at all — which is exactly why the
book calls it what it is, and not the default.

A system where new types are added often favors data-directed
programming or message passing, since both let a new type arrive
without touching what already exists. A system where new operations
are added often favors data-directed programming or explicit dispatch,
for the same reason with the axes swapped; message passing is the
worst fit there, since every object must learn the new operation.
