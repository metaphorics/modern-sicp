# Exercise 2.76: adding types versus adding operations

## Approach

The answer mounts the book's coercion tower on the section's table and
reads the change costs off it. Three packages --- integer, rational,
real --- install same-type `add` and `mul` handlers keyed by the
ordered pair of argument tags, and each type but the top installs a
one-step coercion keyed by its source type (the tower is linear, so
the target is implied). `applyTowerOp` is apply-generic extended: the
same-type handler first, then an argument raised along the coercion
chain --- integer to rational to real --- until the types agree, then
the book's "No method for these types".

Adding a **type** added one install and two coercions and rewrote
nothing: the test holds the rational package's handler by reference
across two later installs and it is the very same function. Adding an
**operation** (`mul`) added three table entries over the same
packages. Explicit dispatch is the mirror image and the edition shows
it plainly: a closed union plus exhaustive switches makes `tsc` the
edit counter --- a new variant flags every switch missing the case ---
while a new operation is one function written against the whole union.
Message passing decomposes the table into columns: a new type is one
new closure and nothing else changes, but a new operation means
editing every closure's dispatch. In TypeScript terms: the union is
closed and compiler-checked, the registry keeps both axes open at the
price of a runtime lookup and no exhaustiveness proof, and the message
object fixes its operation set where it is defined --- which is why
the book calls the table what it is, and not the default.

A system where new **types** are often added favors data-directed
programming or message passing; a system where new **operations** are
often added favors data-directed programming or explicit dispatch.
Data-directed style is the only one additive in both directions,
which is the section's point.

## Numbers

`addTower(3, 1/2)` raises the integer to rational `3/1` and answers
`7/2`; `addTower(1/2, 0.25)` raises the rational to real and answers
`0.75`; `addTower(3, 0.5)` walks the chain two steps, integer to
rational to real, and answers the real `3.5`; `mulTower` reaches
`3/2` and `0.125` the same way; `applyTowerOp("expt", ...)` has no
handler and answers `NoMethod for (expt (integer integer))`.
