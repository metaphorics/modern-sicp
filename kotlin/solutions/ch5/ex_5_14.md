# Exercise 5.14: measuring the factorial machine

The factorial machine of figure 5.11, transcribed line for line as
`recursiveFactorialSimController`, runs for n = 1 to 6 on the
monitored stack of 5.2.4, and `factorialStackStatistics()` reads the
counters after each run. The table is pinned in `E5_14Test`: each
level saves `continue` and `n` once, so the counts are exactly
2(n - 1): zero pushes and depth 0 for n = 1 up to ten pushes and
depth 10 for n = 6. The relation is linear because the controller is
linear-recursive, one pair of pushes per level and no other stack use.

One run carries the book's own measuring trick: `measuredController`
inserts `(perform (op print-stack-statistics))` before `fact-done`,
so the machine prints its own statistics as part of the run. The pin
shows the printed line and the read counters agree: for n = 5 the
measured machine prints
`(total-pushes = 8 maximum-depth = 8)`, the same numbers the table
row for n = 5 reports.

The machine's value path is pinned separately against the host:
`factorialMachineFactorial(5)` reads `val` after the run and answers
120, so the machine whose stack is being measured is the factorial
machine and not a controller that merely pushes.
