# Exercise 4.5: cond arrow clauses

## Approach

The clause syntax `(test => recipient)` is handled by extending the
book's expand-clauses in this file: an arrow clause becomes a lambda
application that binds the test value to a parameter and calls the
recipient on it, so a true test is evaluated exactly once and handed to
the recipient, and a false test moves on to the expansion of the
remaining clauses. The dispatch is the full one, so arrow conds work in
nested bodies such as a lookup defined with define.

## Numbers

With assoc and lookup defined in the evaluated language: `(lookup 'b)` is
`2`, `(lookup 'a)` is `1`, `(lookup 'c)` is `missing`. After
`(define count 0)`, `(cond ((begin (set! count (+ count 1)) true) =>
(lambda (v) v)) (else 'no))` is `#t` with `count` equal to `1`: the test
ran once and its value reached the recipient.

## Class and deviations

Translated row. Deviation: the expansion binds the test value with a
generated lambda application, the book's recommended shape for avoiding a
second evaluation of the test, rather than the naive
`(if test (recipient test) ...)`; the book's exercise text allows either
but the single-evaluation shape is the faithful one.
