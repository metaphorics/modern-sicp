# Exercise 3.25: the table under key lists

## Approach

The book extends `lookup` and `insert!` so a key may be a list of
any length: every key but the last names a subtable, and the last
names an ordinary record. The Rust solution writes `lookup_path` and
`insert_path` over the section's records: the walk descends through
`assoc_by` on each prefix key, and insertion builds any missing
subtable on the way in, with `build_nested` producing the record
list for the remaining keys so every level keeps the table invariant
that a table's cdr is a list of entries. The solution stores `1`
under `(a b)` and `2` under `(a c d)`, then reads back `1`, `2`, and
nothing for `(a c)`, whose prefix exists with a different
continuation. The tests add a three-key store and read, a
replacement through a shorter path, and the resulting shadowing of
the deeper entry.

## Map class

`A: table state shared via RefCell`. Subtables are entries in the
same shared mutable table. Insertion builds a subtable with the same
`set-cdr!` mutation that the one-key table uses.

## Deviation

None. The multi-key semantics, the lookups, and the miss are the
statement's own.
