# Exercise 4.14: Louis's primitive map, and Eva's object-language map

## Approach

Louis Reasoner installs the host `map` as a primitive procedure and
cannot see why it breaks. The broken mechanism, made concrete here:
`LouisMap` overrides `applyProcedure` to route every `VPrimitive`
through `callPrimitive` -- no `map`/`apply` interception, primitives
apply as primitives -- and Louis's `map` handler can therefore only
`callPrimitive` its procedure argument per element. But the argument of
`(map (lambda (x) (* x x)) '(1 2 3))` is a compound procedure, a
`VProc`, and `callPrimitive` on a non-primitive raises the typed
`NotApplicable` fault: a plain primitive cannot apply a closure, it has
no eval/apply machinery, only the host handler. Eva Lu Ator's fix is the
book's point about where `map` belongs: defined in the object language,
her `map` is a `VProc`, the evaluator applies compound procedures
normally (evaluating the operator, extending the environment, applying
`p` through the ordinary application clause), and the same call answers
the mapped list. The two runs share the printer-contract driver; only
the evaluator and where `map` lives differ.

## Map class

`T`.

## Deviation

None. The base library's `map` name is a placeholder whose handler is
unreachable; Louis's environment replaces it with the plain primitive,
which is the configuration the exercise describes.

## Answer

- Louis: `"Error: not a procedure: #[compound-procedure]\n"` -- the
  typed `NotApplicable` fault, its irritant the anonymous lambda
  rendered `#[compound-procedure]`, raised on the first element.
- Eva: `"(1 4 9)\n"` -- the same call with `map` defined in the object
  language answers the mapped list.
