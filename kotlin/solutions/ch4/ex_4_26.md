# Exercise 4.26: `unless` as a special form versus a lazy procedure

## Approach

Ben's side, [WithUnlessDerived]: `step` recognizes the three-arm
`(unless condition usual-value exceptional-value)` application and lowers
it to `(if condition exceptional-value usual-value)`, the same
derived-expression move as `cond` and `let`. The untouched arm never
evaluates, which the armed call pins. But the derivation is pure syntax:
nothing binds `unless`, so using the name as a value (
`(apply unless '(#f 1 2))`) fails the unbound lookup, which is exactly
Alyssa's objection.

Alyssa's side: the same `unless` defined as a procedure under
[LazyEvaluator]. Its arms are thunks; the body's `if` forces only the
condition. Three pins show composition the special form cannot offer:
`(unless #f 42 (/ 1 0))` answers 42 with the exceptional arm unforced;
`map` maps `unless` over quoted triples, answering `(42 7)`; `apply`
applies the procedure value to a quoted argument list, answering 7:
`apply` re-binds each applied value as a fresh expression thunk, so the
applied lazy procedure stays lazy past the call.

## Map class

`T` unchanged. The edition's strict-primitive ruling shows up once here:
`map` and `apply` are strict primitives, so their results force, and the
mapped transcript reads `(42 7)` rather than a list of thunks.

## Answer

From the actual runs (`E4_26Test` pins all five transcripts):

- Derived, armed: => `42`. Derived as a value: => `Error: unbound
  variable: unless`.
- Lazy procedure: => `42`; mapped: => `(42 7)`; applied: => `7`.
