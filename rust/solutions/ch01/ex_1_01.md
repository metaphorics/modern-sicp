# Exercise 1.1: evaluate a sequence of expressions in order

## Approach

Rust has no read-eval-print loop, so there is no interpreter printing a
result after each top-level form the way the book's transcript does. The
solution instead runs the book's ten expressions, in the book's order,
inside one function, and pushes each expression's value onto a `Vec<i64>`
as it is produced:

```rust
pub fn ex_1_01() -> Vec<i64> {
    let mut printed: Vec<i64> = vec![10, 5 + 3 + 4, 9 - 1, 6 / 2, 2 * 4 + (4 - 6)];
    let a: i64 = 3;
    let b: i64 = a + 1;
    printed.push(a + b + a * b);
    let _ = a == b;
    printed.push(if b > a && b < a * b { b } else { a });
    printed.push(match a {
        _ if a == 4 => 6,
        _ if b == 4 => 6 + 7 + a,
        _ => 25,
    });
    printed.push(2 + if b > a { b } else { a });
    printed.push(
        match a.cmp(&b) {
            std::cmp::Ordering::Greater => a,
            std::cmp::Ordering::Less => b,
            std::cmp::Ordering::Equal => -1,
        } * (a + 1),
    );
    printed
}
```

The `Vec` is what the test checks against, standing in for the sequence of
values the book's interpreter would have printed at the terminal.

## The two silent lines

The book's sequence includes two `define` lines and one `(= a b)` test that
print nothing (in this book's own drawing convention, `@i{...}` marks a
printed result; a `define` in the source produces none). The `let a = 3`
and `let b = a + 1` bindings are the Rust equivalents of those `define`
lines, and `a == b` is the equivalent of `(= a b)`: it is genuinely
evaluated, in order, exactly where the book evaluates it, but its `bool`
result is discarded (`let _ = a == b;`) rather than pushed, because it is
not one of the ten numbers the exercise asks for.

## The `cond`-shaped comparison

The book's `(cond ((> a b) a) ((< a b) b) (else -1))` is a three-way
branch on the ordering of `a` and `b`. `match a.cmp(&b)` is the direct Rust
translation of that shape (three exhaustive arms on `Ordering`, not an
if/else-if chain), and it is what the edition's lints (`comparison_chain`)
require once more than one `if`/`else if` compares the same two values.

## Test

With `a = 3` and `b = 4`, the reference solution's test pins the whole
sequence: `[10, 12, 8, 3, 6, 19, 4, 16, 6, 16]`, matching the book's stated
results for this section.
