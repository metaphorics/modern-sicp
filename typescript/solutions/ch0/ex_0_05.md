# Exercise 0.5: parseAmount as a Result

## Approach

The guards mirror `parseAmountEager` in the same order, and each
`throw` becomes a returned `{ _tag: "Error", ... }` value: blank after
trimming is `Blank`, a character outside `0..9` is `NotDigits`
carrying the original (untrimmed) input, and surviving input becomes
`{ _tag: "Ok", value: Number(t) }`. The failure values are plain data,
so a test compares them with `toEqual` instead of asserting a throw.

## Proof

Four assertions cover the statement's cases: `" 42 "` parses to `42`,
blank input raises `Blank`, `"12x3"` raises `NotDigits` carrying the
original string, and the eager original still throws (`RangeError` and
`TypeError` respectively) where `parseAmount` returns a value.
