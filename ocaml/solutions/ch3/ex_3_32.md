# Exercise 3.32: agenda segment order matters (translate)

The map class is `T`: the argument is about the queue discipline
inside one agenda time segment, so the exercise is answered by
building a second, minimal agenda (`lifo_sim`) whose segments are
plain stacks instead of the section's FIFO `Queue`, and running the
same `and-gate` scenario (both inputs changing within one segment)
against both. The book's agenda must run actions in the order they
were scheduled, because a later-scheduled action can depend on an
earlier one's effect within the same instant; a LIFO segment runs them
backwards and reads the and-gate's stale, pre-update value instead of
the current one.

Sample: `ex_3_32 ()` answers `(0, 1)`: the FIFO agenda's correct
output, then the LIFO agenda's wrong one.
