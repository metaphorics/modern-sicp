# Exercise 5.11: the three restore disciplines

One simulator, three disciplines, differing only in the save and
restore clauses.

(a) Untagged: the book simulator's behavior. The sequence
`(save y) (save x) (restore y)` leaves `y = 8`, the value saved from
`x`, which is the point. The advantage taken for the Fibonacci
machine: at `afterfib-n-2`, the pair `(assign n (reg val))` +
`(restore val)` (moving the saved Fib(n-1) into `n` while pulling the
saved `val` back) collapses into the single `(restore n)`, which
takes the saved Fibonacci value from wherever the untagged stack filed
it. One fewer instruction per level; `ex_5_11 ()` pins the answers of
the original and the one-instruction-smaller machine equal on
n = 0..9. (The 5.6 pair, deleting `afterfib-n-1`'s
`(restore continue)` with the second `(save continue)`, is the other
reduction; it removes two instructions, this one removes one.)

(b) Tagged: `save` files the register's name with the value. The
sequence now reports the typed failure
`restore y but the stack holds x`; a disciplined program still runs,
and tagged fib 6 answers 8.

(c) Per-register stacks: each register owns its stack; the sequence
leaves `y = 7`, its own value; `initialize-stack` clears every
register's stack (`Hashtbl.reset`); and a restore from an empty
per-register stack is the typed `Stack_underflow x`.
