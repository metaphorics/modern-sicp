# Exercise 4.78: the query as a nondeterministic program

## Lesson

One question runs two ways: as a query over the data base, answered
in data-base order, and as a search program choosing staff indices
and demanding the supervisor relation from a guest table. Each
entered alternative is one choice, counted by a permanent write so
the cumulative count survives backtracking; answers arrive with the
count that delivered them. Both engines agree on the three answers,
and the engine's own end-of-run counter agrees with the guest count
at eight.

## Map class

`T` (map row 4.4: `Query` + `Search`). The search program is guest
source over the search intrinsics; the query is domain data. No
driver prompts survive on either side.

## Deviation

The old amb-driver transcript is gone by contract -- engines emit no
prompts -- so the session is answer lines plus counts, not a
try-again log.

## Answer

- Search: the three reports with choice counts `1`, `2`, `3`.
- Stream: the same three answer lines.
- Total: `8` choices by both counters.
- Pin: `ambQueryDemos() == ["Hacker Alyssa P (choice 1)",
  "Fect Cy D (choice 2)", "Tweakit Lem E (choice 3)",
  "?x = [Hacker, Alyssa, P]", "?x = [Fect, Cy, D]",
  "?x = [Tweakit, Lem, E]", "total choices: 8"]`.
