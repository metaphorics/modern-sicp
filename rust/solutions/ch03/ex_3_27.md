# Exercise 3.27: memoized fib traced

## Approach

The book asks for `memo-fib` and an environment diagram explaining
why redoing the work is avoided. The diagram is a question about
Scheme frames, so this edition traces it instead: the solution wraps
`fib` with the section's `MemoTable`, shared by every recursive
level because all the closures capture it, and counts. For
`memo-fib` of 25 the trace answers the value 75025 with exactly 26
computed steps and 26 stored entries, against 242,785 calls for the
unwrapped procedure of the same shape. A second probe shows the
table doing its job on a smaller input: 11 real computations for
`(memo-fib 10)`'s 177 total calls, and a repeated query answered
from storage without running anything.

## Map class

`A: RefCell memo table; diagram becomes trace`. The memo table is
shared mutable state under `Rc`, and the counts are the diagram's
picture of stored bindings made observable.

## Deviation

The replacement is by design (the row's Rust cell says the diagram
becomes a trace). The memoization scheme, the shared table, and the
linear-versus-exponential contrast are the book's own.

## Note

Counts are asserted, not decorative: the test pins 26/26/242785 for
the traced run and 11/177 for the small one, so a regression that
recomputes fails the suite.
