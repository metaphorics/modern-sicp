# Exercise 5.49: a read-compile-execute-print loop

Instead of the evaluator's read-eval-print loop, one machine runs a
read-compile-execute-print loop: the host compiles every form into a
block under the shared compile state, and the assembled controller
chains the blocks through a driver that prompts, runs each form, and
prints each value. Definitions persist because every block shares the
one machine's global environment, and no interpreter sits anywhere in
the path. The external entry stays out of the controller since the
flag never arms.

`readCompileExecutePrint()` loops over the square and twice
definitions and calls from the exercise's shape and answers one joined
line per form, pinned by the test: `ok`, 144, `ok`, 882. The values
match the OCaml edition's loop exactly.
