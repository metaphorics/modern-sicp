## Exercise 2.45: split

Approach: `split` takes the two combining operations as parameters and
returns a two-argument closure over them; the inner recursion is exactly
`rightSplit`'s (or `upSplit`'s) shape with `bigOp`/`smallOp` standing in
for `beside`/`below`. `rightSplitViaSplit` and `upSplitViaSplit` are then
one-line instances, `split(::beside, ::below)` and `split(::below,
::beside)`, each proved equal segment-for-segment to the hand-written
versions from exercise 2.44 and the shared `Painters.kt` file.

Class: A. Kotlin already treats painters as first-class function values,
so `split` needs no new abstraction mechanism beyond an ordinary
higher-order function returning a closure, matching the map's note that
`split` returns a generic higher-order function.
