# Exercise 5.32: the symbol-operator fast path

The fast path recognizes a call whose operator is one of the open-coded names and answers the arithmetic directly, skipping the generic application machinery for exactly those calls. The session runs the same program on both paths and the answers agree, so the fast path is an optimization and never a semantic change.

The design answer the exercise asks for: the fast path only helps the operator evaluation of a symbol call, so the compiler's compile-time analysis is strictly better. It avoids the run-time test per call and turns the arithmetic into ordinary instructions the register machinery already understands.
