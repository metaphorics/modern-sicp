# Exercise 3.46: test-and-set race window

## Approach

The book's plain-procedure `test-and-set!` reads the cell and then,
if it read false, writes it -- two separate operations with a window
between them. The timing diagram the statement asks for is the
interleaving read, read, write, write: both processes read `false`
before either writes, so both acquire a mutex that admits one.

The demonstration forces that interleaving instead of hoping a
free-scheduling stress run lands in it. A stress test that releases two
threads and waits for a double acquisition can run a thousand times and
see one winner every time: a quiet scheduler serializes the threads,
and the test fails without any bug in the code. The solution therefore
runs the diagram itself. Each trial owns one fresh cell. Two real
threads load it, meet at a two-party barrier that confirms both have
loaded, and only then store. Both see `false`, both store, both acquire
-- every trial, on every schedule. No trial can inherit the set its
predecessor left behind.

The comparison is the module's atomic `TestAndSetCell`, one fresh cell
per trial, with the two threads released together and free to interleave
as the scheduler likes. Exactly one thread wins every trial, asserted as
exactly one winner, not merely as the absence of two. The indivisible
compare-and-swap is the fix the text says multiprocessing hardware
provides.

The module's plain-procedure version works on a `Cell<bool>`. This type
is `Send` but not `Sync`: ownership can move to another thread, but
threads cannot share a reference to the cell. The solution uses an
`AtomicBool` so that both threads can access the cell safely. Its
separate load and store still leave the complete operation non-atomic.

## Map class

`T`. The non-atomic implementation and the timing-diagram demand are
the statement's own.

## Deviation

The shared cell changes from `Cell<bool>` to `AtomicBool` because the
demonstration requires shared access from two threads. The operation
still consists of one load followed by one store.
