# Exercise 4.13: unbind removes a binding

## Approach

This edition replaces SICP exercise 4.13 with a host-language exercise
that keeps its number and teaching objective. The statement leaves the
specification open, so it is pinned first: the guest extension
`unbind(name)` removes the binding from exactly the first frame of the
chain that has one, and fails with `unbound-name` when no frame has it.
That keeps unbinding local: an inner binding can be dropped to expose
the outer one, while outer frames are never touched by an inner unbind.
The extension node is handled by the evaluator's own case — placed
before the ordinary forms — and procedure bodies recurse through the
same dispatch, so an unbind inside a call removes the call frame's
binding. A later read behaves exactly as if the name had never been
bound there: it finds the outer binding, or fails; it is never a TDZ
read, because the removed cell is gone rather than uninitialized.

## Numbers

With global `a = 1` and an inner `a = 2`, the shadowing call answers
`2`. Adding `unbind("a")` before the read answers `1`, and the outer
binding survives untouched. In the retargeting call — bind `a = 2`,
unbind, then write `50` — the call answers `50` and the global `a`
reads back `50`: with the inner binding gone, the write landed in the
outer frame. `unbind("zz")` fails with `unbound-name`; after unbinding
the global `a`, a lookup fails and a second unbind fails again.

## Class and deviations

`R` row: the replacement keeps the number and the binding-removal
objective under the fixed opener above. Deviation: the book says only
to give `make-unbound!` a reasonable meaning, so the first-frame-only
specification and the no-binding-is-an-error rule are this solution's
stated choice, argued for in the answer: silent success on a missing
name would hide real mistakes, and removing more than one frame's
binding would let an inner scope rewrite its ancestors.
