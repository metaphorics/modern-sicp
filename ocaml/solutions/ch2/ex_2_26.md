# Exercise 2.26: predicting the list combinations (replace)

The map class is `R` (map row: "predict collection printing
instead"). For `x = [1; 2; 3]` and `y = [4; 5; 6]` the OCaml edition
asks for `x @ y`, which prints `[1; 2; 3; 4; 5; 6]`, and `[x; y]`,
which prints `[[1; 2; 3]; [4; 5; 6]]`; `ex_2_26 ()` returns both.

The third expression of the book, `(cons x y)`, has no OCaml
rendering that prints: `x :: y` does not type-check, because `::`
requires its right argument to be a list of its left argument's type,
and `int list` is not `int`. That rejection is the edition's lesson:
Scheme's `cons` silently builds an improper pair where OCaml's `::`
states the list discipline in the type. The rationale and the book's
statement both carry the explanation.
