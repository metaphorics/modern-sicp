# Exercise 3.68: Louis's whole-first-row pairs

## Approach

Louis's definition interleaves the whole first row with the recursive
call on the tails. It does not work: the recursive call is an argument
to `interleave`, and both Scheme and Kotlin evaluate arguments before
the call. The diagonal `consStream` of 3.5.3's `pairs` is what made the
tail a delayed thunk; Louis removed it, so no cons ever fires, the
recursion has no base case, and `louisPairs(integers, integers)` runs
out of stack before producing even the first element. The test asserts
exactly that: `shouldThrow<StackOverflowError>` around taking the first
element, which never gets that far.

Independent check: a python3 twin of the same shape dies with
RecursionError while constructing the stream, confirming the divergence
happens at construction time, not during consumption.
