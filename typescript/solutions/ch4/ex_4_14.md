# Exercise 4.14: two maps, two fates

## Approach

Louis installs the host's array map as a primitive. His wrapper hands
the host the procedure's own representation: a primitive offers a real
host function, which the host map calls per element; an evaluator
closure offers nothing the host can call, so the call dies at the host
boundary — the representation mismatch the book predicts — and is
re-surfaced on the evaluator's error channel. Eva Lu Ator instead types
the definition of map into the object language: a recursive compound
procedure whose per-element call goes through the evaluator's own
apply. Both maps are run on the same inputs.

## Numbers

Louis: mapping `head` over `[[1, 2], [3, 4]]` answers `[1, 3]`, but
mapping an identity closure over `[[9]]` fails with `bad-operand` whose
detail is `map: the host could not call this procedure`. Eva: the same
head map answers `[1, 3]`, `square` over `[1, 2, 3]` answers
`[1, 4, 9]`, and the identity over `[[9]]` — the call that killed
Louis's map — answers `[[9]]`.

## Class and deviations

Translated row. Deviations: in the book the failing call dies with the
underlying Lisp's error text; this edition never throws across the
evaluator boundary, so the host failure is answered as `bad-operand`
carrying the old message in its detail. The wrapper discriminates
closure from primitive explicitly rather than letting the host throw
the TypeError — the same mismatch, observed through runtime shape
checks instead of an exception.
