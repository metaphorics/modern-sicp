# Exercise 4.6: let as a derived expression

## Approach

`WithLetDerived` overrides the evaluator's open `letToCombination` seam with
the exercise's own derivation, [letRewrite]: `(let ((x 3) (y 4)) (+ x y))`
becomes `((lambda (x y) (+ x y)) 3 4)`, pinned structurally in the test.
Because the rewrite is a lambda application, the inits evaluate as operands
-- in the outer environment -- which is the scoping rule the exercise is
about: with `x` bound to 5 outside, `(let ((x 3) (y x)) y)` is 5, not 3.
The base grammar carries plain `let` (the metacircular corpus program reads
it), so the exercise re-derives the form through the seam and pins the
rule; nested `let`s re-enter the derivation at every depth.

## Map class

`T`.

## Deviation

None. The base evaluator already derives `let` the same way; the exercise
owns the derivation and its scoping pin instead of inheriting it.

## Answer

The printed rewrite is `((lambda (x y) (+ x y)) 3 4)` and
`(let ((x 3) (y 4)) (+ x y))` => 7; the scoping probe answers 5; a
malformed binding list `(let (x))` fails typed at parse
(`Parse("bad let form: (let (x))")`); `(let ((x 5)) (let ((x 2)) x))` => 2
with the outer `x` still 5.
