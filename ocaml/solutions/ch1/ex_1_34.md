# Exercise 1.34 — applying a procedure to itself (adapt: type checker rejects it)

The map class is `A`: the statement survives (what happens when you
apply `f` to itself?) but its answer changes shape entirely. In Scheme,
`(f f)` is a *runtime* error: the evaluator reduces `(f f)` to `(f 2)`,
then tries to apply `2` as a procedure and fails, because Scheme
carries no static guarantee that `f`'s argument is itself applicable.
In OCaml, `(f square)` and `(f (fun z -> z * (z + 1)))` in the section
text force `f`'s principal type to `(int -> 'a) -> 'a` (`f g = g 2`
puts no constraint on `'a` beyond "whatever `g 2` returns"), and `f f`
never reaches evaluation at all: it is rejected while type-checking,
before the program can run.

Grounded by actually compiling it this session (`ocamlopt` against
`let f g = g 2 in ... ignore (f f)`):

```
Error: The value f has type (int -> 'a) -> 'a
       but an expression was expected of type int -> 'b
       Type int -> 'a is not compatible with type int
```

`f`'s parameter position wants something of type `int -> 'a`; `f`
itself has type `(int -> 'a) -> 'a`, whose domain is a function type,
not `int`, so unification fails immediately at the call site — no
value of `f 2`'s kind is ever computed, unlike Scheme's `(f 2)` which
runs and then fails to apply `2`. `ex_1_34 () = (4, 6)`, matching the
book's own `(f square) => 4` and
`(f (lambda (z) (* z (+ z 1)))) => 6`.

The map's tailored addition 1.34a (compare compile rejection with
runtime failure) is effectively this rationale; it was not built out
as a separate `1.34a` exercise, since 1.46a is this edition's one
addition.
