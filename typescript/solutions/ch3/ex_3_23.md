# Exercise 3.23: the deque with constant-time ends

## Approach

The book asks for a deque whose four operations are all O(1), which the
pointer-pair queue cannot do because its cells lack backward links. The
edition spells the doubly linked representation: `DequeNode` carries the
item plus mutable `prev` and `next` links, and the deque holds front and
rear pointers. Each operation rewires a constant number of links; the
file contains no loops except the linear render helper `showDeque`, which
the pins use and which is not part of the deque's contract.

## Pins

Computed by running. Rear inserts a, b then front delete a leaves [a, b];
front insert c and rear insert d leave [c, b, d]; rear delete answers d
and leaves [c, b]. The links stay consistent through a mixed session: forward
and backward walks agree, the end links are null, a front delete resets
the new front's prev, a rear delete resets the new rear's next. Deleting
the last item through either end empties both pointers, and the deque
accepts insertions again afterward (the constant-time-ends analog of the
queue's rear-pointer reset). Reading or deleting an empty deque fails
with the module's `EmptyQueueError` carrying the operation name.
