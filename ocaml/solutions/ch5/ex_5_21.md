# Exercise 5.21: the two count-leaves machines

Both machines run over the list-structure memory: the tree is planted
in the word vector first (`plant`, through the same allocation path
the machines' `cons` uses), and the controllers read it with the
machine primitives `car`, `cdr`, `null?`, `pair?`: each one the
vector operation of 5.3.1 through the index part of a pair pointer.
Save and restore are the 5.3.1 expansions, so the recursion's stack
lives in the memory as a chain of cells, and the monitored counters
answer after the run. Each controller is an OCaml list of `Sec_5_1`
instructions over memory words (`Save "tree"`,
`Assign_op ("tree", "car", [ Reg "tree" ])`), and each tree is named
in the transcript by its planted cells written back in OCaml list
notation.

**(a) Pure recursion** returns each subtree's count in `val` and adds
the two answers on the way back: `tree-case` saves `continue` and
`tree`, counts the car with `continue := after-car`, then parks the
car's answer in `temp`, counts the cdr, and adds. The answer word is
`val`.

**(b) The explicit counter** carries `n` through both subcalls, so the
car's answer needs no parking: `n` accumulates across the whole run
and only `continue` and `tree` ever take stack room. The answer word is
`n`.

`ex_5_21 ()` runs both machines beside the host oracle (`count`, the
book's `count-leaves` as an OCaml function over the same `tree`
variant) over three trees:

- `[1; 2; [3; [4; 5]]]`: both answer `n5`, oracle 5; the recursive machine
  pushes 21 times to depth 14, the iterative one 14 times to depth 10.
- `[[7]]`: both answer `n1`, oracle 1; 6/4 pushes, depth 4/4.
- `[]`: both answer `n0`, oracle 0. The empty node is the `null?`
  base case, no stack at all.

The counters quantify the register economy the exercise is after: the
accumulator version never parks a partial answer, so it saves one
fewer word per level than the pure-recursion machine.
