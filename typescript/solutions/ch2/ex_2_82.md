# Exercise 2.82: multi-argument coercion

## Approach

The strategy: for each argument's type in turn, try to bring every argument
to that target through the coercion table, and if all succeed, apply the
operation at the coerced tags; if no target works, report the miss. The
rationale records the required counterexample: with only the section's
one-step coercions (here `scheme-number` to `complex`), the strategy never
walks a two-step chain, so an operation defined only on `(real real)` is not
tried for `(scheme-number, rational)` even though both arguments can reach
real --- Louis's scheme needs transitive closure it does not have.

## Numbers

A same-shape example pins the strategy working: with entries from
`scheme-number` to `complex` only, `add` of an ordinary number and a complex
number succeeds through the all-at-once coercion, and the (real, real)
counterexample answers the book's error report instead of inventing a chain
the table does not contain.

## Map class

A (multi-arg coercion needs conversion search): the search is the loop over
candidate target types, one `coerce` per argument per candidate.

## Deviation

The exercise's generic apply lives beside the section's `apply-generic`
rather than replacing it, so the section system's one-step behavior that
2.84 and 2.85 build on is untouched.
