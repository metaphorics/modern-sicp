# Exercise 4.18: the alternative scan-out strategy

## Approach

Two scans run over one body. The text's scan runs the initializing
writes in order, so a write whose value expression reads an earlier
sibling sees that sibling's value. The alternative computes every value
expression first — in one inner scope, before any write runs — and only
then assigns the results into the pre-bound names, so a value
expression that reads a sibling lands while that sibling is still
uninitialized and fails on the TDZ guard. A sibling read deferred
through a procedure defined earlier, and only called after the writes,
never reads during the value-computation phase, so both scans agree.

## Numbers

`const a = 1; const b = a + 1; return b;` answers `2` under the text's
scan and fails with `tdz-access` under the alternative: `b`'s value
expression reads `a` before any write has run. The deferred reader —
`get` closing over `b`, `b = 5`, then `get()` — answers `5` under both
scans. The book's `solve` fails under the alternative exactly as the
sibling-reader does: `dy`'s value expression reads `y`'s first element
during the value-computation phase, before `y`'s write.

## Class and deviations

Translated row. Deviations: both scans emit assignment writes rather
than `set!` forms, since the pre-binding supplies the let's frame
semantics; the alternative's temporaries are the inner scope itself,
not the book's generated fresh names; and only the scanned names are
reordered, matching the old solution's leading-defines scope.
