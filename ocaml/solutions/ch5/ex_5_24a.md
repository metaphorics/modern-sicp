# Exercise 5.24a: && and || chains as basic controller forms

The addition extends 5.24's treatment to the Boolean operators. The
base controller evaluates `a && b && c` as nested binary nodes, saving
`exp`, `env`, and `continue` at each node. The chain loops flatten the
right-nested chain into one operand sequence: `continue` is saved once
for the whole chain, each operand but the last runs with the rest of
the chain and `env` saved, a deciding value (`false` for `&&`, `true`
for `||`) ends the loop, and the last operand runs in tail position.
The book's empty `(and)`, `(or)`, and non-Boolean operand values do not
exist in the typed subset, so the demonstrations are Boolean.

`ex_5_24a ()` pins `true`, `false`, `true`, `false`, `true`, `true`,
`false`: an all-true chain, a first-false chain that never reaches its
`1 / 0 = 0` operand, a first-true `||` chain that never reaches its
`1 / 0 = 0` operand, an all-false chain, nesting, and `within 5` and
`within 50`. Without short-circuit evaluation the chains would stop at
the division by zero; the base `ev-and` short-circuits too, so these
answers match the base controller and only the cost differs.
A four-operand `&&` costs 27 pushes through the chain loop against 29
through the base `ev-and`: one save of `continue` per chain instead of
one per node. The chain loop executes more instructions (322 against
293), because each added dispatch test costs two instructions at every
`eval-dispatch` arrival; pushes carry no such overhead.
