# Exercise 5.40: threading the compile-time environment (T)

## Approach

Compile the nested-lambda example with a trace callback that records
the compile-time environment whenever a variable is looked up. Each
lambda extends the environment with a parameter frame, so code inside
the innermost lambda sees the local `(y z)` frame first, followed by
`(a b c d e)` and then the outer `(x y)` frame. The callback exposes
the environment threading that enables lexical address computation.

## Map class

`T`.

## Sample answer

During compilation, lookup of `x` and `z` sees
`((y z) (a b c d e) (x y))`. Thus `z` is in the innermost frame, while
`x` is found in the outermost frame. The trace is gathered from the
compiler rather than inferred from runtime lookup.
