# Exercise 5.16: instruction tracing

The tracing machine uses the same ordered trace with a switch: when the switch is on, each executed instruction's text is taken from the machine's trace, so the trace is exactly the executed instructions in execution order. The text is the machine's own statement rendering, the way the book writes the instruction, `(assign t (op rem) (reg a) (reg b))`.

The test pins the gcd(206, 40) trace at 26 lines: four full loop
iterations of six instructions each, then the final `(test ...)` and the
taken `(branch (label gcd-done))`, never the trailing label. The switch
off leaves the transcript empty, so tracing adds output and nothing
else, and the same machine object answers both halves of the exercise:
the `trace-on` and `trace-off` messages of the book are the
`setTrace(true)` and `setTrace(false)` calls between runs.
