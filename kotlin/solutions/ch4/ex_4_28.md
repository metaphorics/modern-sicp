# Exercise 4.28: forcing the operator

## Approach

The edition's rule is the book's: `eval` uses `actual-value` on the
operator because the application dispatches on the procedure VALUE --
primitive versus compound -- and only a forced value supports that. The
example is `((id +) 2 3)` with `(define (id x) x)`: the operator
expression `(id +)` evaluates to `id`'s parameter, which the application
delayed, so the operator is a thunk until the forcing at the application
site yields the `+` primitive and the call answers 5.

[UnforcedOperator] is the counterfactual the exercise asks for: it
overrides the application clause to pass `eval`'s result along unforced,
so the call dispatches on a `VThunk` and dies with the typed fault naming
the thunk. The pair of transcripts is the demonstration: same program,
the forcing is the only difference.

## Map class

`T` unchanged; the pin matches the siblings (5 versus not-a-procedure).

## Answer

From the actual runs (`E4_28Test` pins both transcripts):

- Forced operator => `5`.
- Unforced operator => `Error: not a procedure: #[thunk]`.
