# Exercise 3.81: the resettable generator as a stream machine

## Approach

The request vocabulary is a sealed hierarchy: `RandRequest.Generate`
asks for the next word, `RandRequest.Reset(value)` restarts the
sequence. `randStream` consumes requests with the current generator word
as a plain recursion argument, seeded with the 3.1.2 initial word: a
generate outputs `randNext(word)` and threads that word on, a reset
outputs `value` and threads it as the new word, and an exhausted request
stream ends the output. No assignment anywhere. Pins: requests
`generate, generate, reset(7), generate` produce
`6255019084209693600, 15601610542105701163, 7, 15130880334998875822`
(the first two are the known `randomNumbers` successors of 42, the last
is `randNext(7)`, all confirmed by a python3 xorshift64* mirror). Two
independently built request streams produce identical outputs; after a
`reset(7)` the remaining output equals a fresh generator restarted at 7;
and `reset(initial word)` followed by a generate matches the prelude
`randomNumbers` prefix, tying the stream machine to the section's
generator.

## Map class

`T` (map row 3.81: request stream in, words out, no assignment).

## Deviation

The initial word is the prelude's `RANDOM_INIT` (42), the same value the
book's `random-init` names; the statement leaves the starting word to
the 3.1.2 setting.
