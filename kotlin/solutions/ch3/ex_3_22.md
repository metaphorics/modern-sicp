## Exercise 3.22: a queue as a message-passing object

Approach: `makeQueue` creates local `front` and `rear` pointers and returns
an object whose methods close over them. Insert links a fresh `PairCell` at
the rear; delete advances the front and clears the rear when the last item
leaves.

Why each factory call is independent: each call creates new local pointers
and a new object. The object expression supplies shared method bodies, but
the captured queue state belongs to that one returned object.

What the tests say: they pin insertion/deletion order through `items()`,
empty-queue errors, reuse after emptying, and independent state across two
factory calls.

Class: T (the pointer state lives in the object's closure).

Deviation: the queue returns typed items instead of rendering a pair chain
as text.
