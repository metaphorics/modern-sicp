# Exercise 3.39 — which serialized outcomes remain (translate)

The map class is `T`. The statement wraps only the squaring's reads in
the serializer, so the two reads of `x` collapse into one event that
can no longer be split by the increment; but the assignment `x := ...`
itself stays outside the critical section, and that write can still
land before, inside, or after the increment's read-then-write pair.
The solution models the four schedules the mutex still allows and
simulates each one, which turns the diagram-drawing exercise into an
enumeration: the serialized run keeps 11, 100, 101, and 121 — the old
110 disappears because its split reads are gone, while 100 survives as
the stale write clobbering the increment. Live `sample_runs` draws from
this set alone.

Sample: `ex_3_39 ()` answers `[11; 100; 101; 121]`.
