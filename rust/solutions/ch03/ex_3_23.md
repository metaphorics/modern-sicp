# Exercise 3.23: the deque

## Approach

The book asks for a deque, insertion and deletion at both ends in
constant time, and for each operation to be shown never to scan. The
Rust solution gives every node a `previous` handle alongside `next`
and keeps both end handles in the `Deque`, so each operation touches
one node and its neighbor: `front_insert`, `rear_insert`,
`front_delete`, and `rear_delete` all run in a fixed number of
steps. The solution runs the book-shaped sequence, rear-building
`(a b c)`, front-inserting `z`, then deleting from both ends once,
and answers the remaining items `[a, b]`. The tests drive every
operation, the error paths on an empty deque, and the length.

## Map class

`A: doubly linked cells need RefCell`. The backward pointers the
book draws are `RefCell<Option<Rc<DequeNode>>>` fields, and the
two-way linkage is exactly what the extra cell mutability buys.

## Deviation

None. The statement's operations, its constant-time requirement by
construction, and the worked sequence are kept.
