# Exercise 5.44: respecting shadowing during open coding

Open coding may use a primitive's instruction only when its
resolution cannot be changed by a nearer lexical binding. In this
Kotlin subset, arithmetic operators are syntax, not ordinary
identifiers that a function parameter can rebind as in Scheme.
The shadowed-name probe uses a local named `plus` and a binary
`+`; the local is a value operand, not a replacement `+` operator.

`openCodingShadowingReport` identifies that local reference and
compares the answers compiled with `+` enabled and disabled for
open coding. The run guards behavioral agreement, but it does not
prove an open-code shadowing guard for a rebound operator. Such a
guard would require an operator rebinding capability absent from
the admitted guest grammar.
