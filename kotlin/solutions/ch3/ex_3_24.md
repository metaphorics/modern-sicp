## Exercise 3.24: the table constructor that takes the key test

Approach: `makeTable(sameKey)` constructs the section's `Table` with
the caller's predicate in place of the default `equalv`. That is the
whole of the code, and it is short because the exercise's demand --
"the keys are tested for equality using equal?, and this is not always
the appropriate test" -- is a constructor-parameter shape, which the
section's class anticipated: the scan in `assoc` already routes every
key comparison through `sameKey`, so the predicate the caller hands
over governs lookup, insert overwrite, and the two-dimensional
operations with no further code.

Why the solution is one line but the exercise is not empty: the book's
reader was asked to restructure a table whose test was hardwired; this
edition's section already made the test a parameter, so the remaining
work is to see what a non-`equal?` test does to the table's behavior,
and the tests carry that. With a tolerance predicate -- numbers within
5 of each other are "the same key" -- looking up `41` finds the record
stored under `40`; storing under `43` after storing under `40`
overwrites it, because the predicate makes them one slot; and a
case-folding predicate on symbols finds `car` under `Car`. The default
table still demands the exact key, which pins that the plain
constructor did not silently change.

Why the overloads coexist: `makeTable()` with no argument is the
section's basic constructor, and `makeTable(sameKey)` is the exercise
constructor -- same book name, one more argument, resolved as ordinary
Kotlin overloading.

What the tests say: `E3_24Test.kt` runs the tolerance table for a
near hit and a far miss, proves the near-key overwrite collapses two
stores into one record, checks the default table's exactness, and
exercises a symbol-level predicate, so a solution that ignores
`sameKey` anywhere in the scan fails at least one of these.

Class: `T` (mechanical translation; the dispatch-procedure return of
the original is the constructed table object here).

Deviation: none.
