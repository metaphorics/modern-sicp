# Exercise 5.3: Newton square-root machines

For both designs, `x` is input and `guess` starts at 1.0. The controller tests the absolute difference between `guess * guess` and `x` against 0.001. If it is not small enough, it replaces `guess` with `(guess + x / guess) / 2` and repeats. The output is `guess`.

## Primitive-operation data path

```text
x ------+--------------------+
        |                    v
        +--> [good-enough?(guess, x)] --> branch to done
        |                    ^
        +--> [improve(guess, x)] --> guess
```

Controller: initialize `guess` to 1.0; at `test-guess`, test `(good-enough? guess x)`; branch to `sqrt-done` when true; otherwise assign `(improve guess x)` to `guess` and jump to `test-guess`.

## Expanded arithmetic data path

```text
x ------+-----------------------+------------------+
        |                       |                  v
        +--> [ - x ] <-- [ * guess guess ]     [ / x guess ]
                 |                                  |
               [abs]                                +--+
                 |                                     v
           [ < 0.001 ] --> branch                  [ + guess ]
                                                       |
                                                     [ / 2 ] --> guess
```

The expanded controller uses `t` for each intermediate result: square `guess`, subtract `x`, take absolute value, compare with 0.001, then calculate `x / guess`, add `guess`, and divide by 2. `sqrtPrimitive` and `sqrtExpanded` are the two executable instruction sequences. For input 2 both converge to a value within 0.01 of the mathematical square root. The first design supplies `good-enough?` and `improve` as machine operations; the second expands them.
