# Exercise 3.23: deque with constant-time insertion and deletion at both ends (adapt)

The map class is `A`: a single-linked pair chain cannot support
constant-time deletion at the rear (the book notes this directly), so
the deque needs doubly linked nodes with mutable `prev` and `next`
fields: a structure the mutable-record world builds naturally but
that would need an extra indirection layer (`Rc<RefCell<_>>`-style
sharing) in a language without native mutable aliasing. Every
operation touches a fixed, small number of pointers regardless of
deque length, which `items` (a testing-only O(n) walk, never used by
the operations themselves) makes checkable without breaking the
constant-time contract of the real interface.
