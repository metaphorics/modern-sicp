# Exercise 5.9: refusing labels as operands of operations

The book's assembler accepts a label wherever a primitive expression
may stand, including the operands of an operation call, and hands the
operation the label's instruction sequence number, a nonsense datum
for arithmetic. The exercise asks to change the simulator so this is
an error.

This edition makes the check a property of assembly, not of the
machine: `assemble` takes `strictLabels` and raises the typed
`MachineError.LabelOperand` while building the operation's value
procedure, naming the label. `labelOperandOutcome()` assembles the one
line `(assign t (op +) (reg a) (label b))` under the strict assembler
and answers the error text, pinned by `E5_09Test`.

To show what is being refused, the same controller without the strict
flag demonstrates the book's behavior: `labelOperandUnderBaseAssembler()`
assembles `(assign t (op +) (reg a) (label addr))` on the base
assembler, where the label names address 0, sets `a` to 5, runs, and
answers 5: the operation computed `5 + 0`. The pair of pins fixes both
sides: the base assembler computes the address, the strict one refuses.
