# Exercise 4.26: unless as a special form versus a procedure (translate)

The map class is `T`. Ben's side: `unless` as a derived expression, a
rewrite of `unless c u e` to `if c then e else u` that runs over the
checked syntax (through `Ast.map_children`) before the
applicative-order direct evaluator sees it. The program's own
definition of `unless` only declares the syntax to the pinned type
checker; the rewrite consumes it instead of binding a value. The
rewrite works under strictness and never evaluates the unchosen arm,
so the armed call `unless (1 = 1) (1 / 0) 42` prints 42.

Alyssa's side: under the lazy experiment `unless` stays an ordinary
procedure, so it is a value. The demonstration passes it to a
higher-order `map3` over two triples built by a compound procedure,
each triple armed with a division by zero in the arm laziness skips,
and prints `42 7`. The same value use under Ben's rewrite answers
`error: unbound variable unless`, which is the cost Ben's syntax has:
syntax is not a first-class value, so it cannot travel as an argument.
This maps the debate onto the edition's rule that primitives stay
strict while compound procedures delay: a procedure `unless` is only
useful eagerly when the language is lazy.

Sample: `ex_4_26 ()` answers `"42\n"`, the lazy transcript beginning
`"42\n"`, the lazy transcript beginning `"42 7 \n"`, and
`"error: unbound variable unless"`.
