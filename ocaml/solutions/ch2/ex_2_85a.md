# Exercise 2.85a: coercion-graph cycle detection (this edition's addition, extending 2.85)

The idiom note for 2.5 picks this addition from the map's idea
column, implemented as coercion-graph cycle detection rather than the
idea column's literal "simplify complex zero to real" text (already
covered by Exercise 2.85 itself); the map row records the deviation.
Exercise 2.81's Louis Reasoner bug is exactly a self-loop in the
coercion graph: a `"scheme-number" -> "scheme-number"` entry is an
edge from a node back to itself, the smallest possible cycle, and
`apply_generic_loop`'s infinite recursion is the runtime symptom of
that cycle. This addition asks whether a coercion table, viewed as a
directed graph of `put_coercion` edges, is acyclic before installing
it: the same question that would have caught Louis's mistake
statically instead of at a depth-1000 guard.

`has_cycle edges` runs a three-color depth-first search (white:
unseen, gray: on the current path, black: finished) over the directed
graph `edges` describes, the standard "back edge to a gray node" test
any graph-cycle detector uses. `ex_2_85a ()` checks three graphs: the
tower's chain of coercions (integer to rational to real to complex,
no cycle), Exercise 2.81's self-coercion (`"scheme-number" ->
"scheme-number"`, a one-edge cycle), and an `a -> b -> c -> a` chain
(a three-edge cycle), returning `(false, true, true)`.
