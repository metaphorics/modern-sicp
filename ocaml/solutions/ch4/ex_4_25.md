# Exercise 4.25: unless breaks under applicative order (translate)

The map class is `T`. The guest program is subset OCaml:
`let unless condition usual_value exceptional_value = if condition then exceptional_value else usual_value`
and `let rec factorial n = unless (n = 1) (n * factorial (n - 1)) 1`.
Under the section's lazy experiment the recursive operand
`n * factorial (n - 1)` stays a thunk until the `if` inside `unless`
has chosen, so the descent stops at the base case and `factorial 5`
prints 120. Under applicative order the operand is evaluated before
`unless` is called, so `factorial` calls itself past every base case
and never terminates: the definitions do not work unchanged in a
language without normal order.

The strict side runs under a fuel-bounded variant of the direct
evaluator, built on `Sec_4_1.open_eval` with one clause that spends a
unit per application node. The divergence is therefore observed as a
typed error naming the budget of 200 applications instead of a hung
run. The armed call `unless (1 = 1) (1 / 0) 42` pins the same
mechanism without the loop: the lazy experiment prints 42, the
applicative-order evaluator dies in the division. Lazy transcripts end
with the experiment's four thunk counts.

Sample: `ex_4_25 ()` answers the lazy transcripts beginning `"120\n"`
and `"42\n"`, then
`"error: the strict evaluation is still descending after 200 applications"`
and `"error: division by zero"`.
