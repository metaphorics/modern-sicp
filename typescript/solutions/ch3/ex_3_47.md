# Exercise 3.47: semaphores from mutexes and test-and-set

## Approach

The exercise builds the mechanism anyway, next to the library
semaphore the map's tailored note points at, and holds the builds to
the library's bound. Version (a) guards a permit count and a waiter
list with the module's mutex; release hands its permit directly to the
first waiter, so a woken process never finds the store empty. Version
(b) spells the guard from the book's cell and the atomic `testAndSet`,
the same construction the text's `make-mutex` makes, with the burning
retry replaced by a rescheduling yield. Both expose a fail-fast
`tryAcquire`. Mechanism for the pins: real Effect fibers through a
max-concurrency probe that spends one suspension inside each critical
section.

## Pins

Computed: the size-2 mutex-built semaphore caps four concurrent
acquirers at exactly 2 holders; the size-3 test-and-set-built
semaphore caps five acquirers at exactly 3; every one of five acquirers
on the size-2 build completes, so waiters are woken, none lost; and
tryAcquire on a size-2 semaphore answers true, true, false, then true
again after one release. Effect's own `Semaphore.makeUnsafe(2)` under
the same probe also answers 2, the parity the map's A-note asks the
build to stand next to.
