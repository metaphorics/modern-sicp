# Exercise 3.82: Monte Carlo integration as streams

## Approach

Exercise 3.5's `estimateIntegral` samples random points in a
rectangle and runs the predicate outcomes through the Monte Carlo
method; the stream version keeps the experiment but drops the trial
count. The solution builds the point stream with the module's
`mapSuccessivePairs` over `randomNumbers` (two generator states per
point, mapped uniformly onto the rectangle), maps the predicate over
the points into a boolean experiment stream, feeds that to the
section's `monteCarloStream(experiments, 0, 0)`, and scales the
passing fraction by the rectangle's area. For exercise 3.5's trial
run, the predicate holds inside the unit circle within the square
`[-1, 1] x [-1, 1]`: the square's area is 4, the circle's is pi, so
the passing fraction `p` converges to `pi / 4` and the estimate
stream, `4 * p`, converges to pi. Estimate `n` covers `n + 1` trials,
matching the section's `monteCarloStream`, whose first estimate already
reflects one trial.

## Pins

Computed by running. The first eight circle estimates are
`[0, 0, 1.3333333333333333, 2, 2.4, 2.6666666666666665,
2.2857142857142856, 2.5]`, coarse early fractions of the square's
area exactly as one trial, two trials, and so on produce them.
Estimate 200 is `3.2238805970149254`, off `Math.PI` by
`0.08228794342513224`, inside the pinned quarter-unit band (the
Monte Carlo standard deviation at 201 trials is about 0.12). The
degenerate rectangles are exact: a predicate that always holds over
the unit square answers `[1, 1, 1]`, a predicate that never holds
answers `[0, 0, 0]`. This pipeline uses the module's deterministic
xorshift32 generator seeded by `randomInit = 42`, so every one of
these pins is exact, not statistical.

## Map class

T (translate: syntax changes only). The row's tailored idea,
streaming estimates with confidence, is the tests' work: the pinned
deviation band around pi at trial 200 plus the exact degenerate
rectangles that bound the estimator's scale.

## Deviation

The uniform mapping divides a generator state by `2^32 - 1`, the
largest value `randUpdate` answers, mapping the uint32 span onto
`[0, 1]` before scaling to the rectangle; the choice is documented at
the `randMax` constant in the source. The estimate stream carries
areas (fraction times the rectangle's area), not raw fractions, and
the circle instance is exported as the stream
`unitCircleEstimates` per the edition's value-oriented idiom.
