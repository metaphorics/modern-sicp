# Exercise 1.6 — new_if as an ordinary procedure (translate)

Map class `T`. Alyssa wants `if` as an ordinary function; Eva's
`new_if` is one line in OCaml, and the demonstration values match the
book: `new_if (2 = 3) 0 5` is `5`, `new_if (1 = 1) 0 5` is `0`.

The failure is structural. A function call in OCaml, as in Scheme's
applicative order, evaluates every argument before the body runs, so
Alyssa's rewritten `sqrt_iter` evaluates its own recursive call on every
iteration, including the one that should have stopped. The square-root
loop never settles. The solution includes `ex_1_06_sqrt_iter` to state
the rewritten program, but no test runs it, for the same reason as
exercise 1.5: a hanging test is not evidence.

The suite proves the mechanism with a counter instead. Evaluating
`new_if true 1 (incr counter; 2)` returns `1`, the chosen branch, but
leaves the counter at `1`: the unchosen branch was evaluated anyway.
The special form `if` would have skipped it. That observable difference
is exactly the "special forms are not procedures" point of the section,
and it fails if a future edit replaces the ordinary function with
compiler magic that short-circuits.
