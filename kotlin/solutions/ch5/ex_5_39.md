# Exercise 5.39: lexical-address lookup and assignment

The runtime environment is a chain of frames, and a lexical address
names a slot by frame number and displacement. `lexicalAddressLookup`
walks out to the addressed frame and reads the slot; it faults when the
address is out of range and when the slot still holds the
`*unassigned*` marker that scanning out internal definitions (5.43)
plants. `lexicalAddressSet` rebinds the same slot through the owning
frame, so shadowing outer bindings stay untouched.

`lexicalMachineRuns()` builds a global frame holding `g`, an outer
frame holding `x`, and an inner frame holding `y`, then reads slot
(0 0) as `inner`, reads slot (1 0) as `outer`, rebinds slot (1 0) to
`changed`, and reads it back. The run answers `inner`, `outer`, `ok`,
`changed`: lookup crosses frames by number, assignment lands in the
addressed frame, and the displacement indexes the frame's bindings in
their insertion order, the order `extend-environment` bound the
parameters in.
