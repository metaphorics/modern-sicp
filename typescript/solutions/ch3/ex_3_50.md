# Exercise 3.50: the multi-stream stream-map

## Approach

The book leaves two blanks in the variadic skeleton: the emptiness test
guarding the base case and the application that produces the head. The
edition completes them as "every stream must still be non-empty" and
"apply the procedure across all the cars", spelled with rest
parameters: `streamMapN(proc, ...streams)`. The cdr side re-calls the
map on all the tails advanced by one, so the result ends where the
shortest input ends. `addStreamsN` rebuilds the text's `add-streams`
over the completed map, and `integersThroughMapN` replays the text's
self-reference check through it.

## Pins

Computed by running. `addStreamsN(integers, integers)` begins 2 4 6 8 10
12. Zipping three enumerate streams (1..100, 10..100, 100..103) begins
111 114 117 120 and stops after the third stream runs out at four
elements. Two streams of lengths 2 and 5 give two sums (2, 4) and then
the empty stream. Calling with no streams answers the empty stream.
`integersThroughMapN` at index 9 is 10, matching the module's own
integers.

## Map class

T (translate: syntax changes only). The Rust and OCaml columns adapt the
row because their maps take a stream list; TypeScript's rest parameters
keep the variadic shape the book draws, so this column translates whole.

## Deviation

The book's skeleton tests only `(stream-null? (car argstreams))`, the
first stream; the completion tests every stream, which the exercise's
prose ("allow procedures that take multiple arguments") requires for
correct termination on unequal lengths. No other change.
