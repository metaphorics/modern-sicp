# Exercise 1.23 — skip even test divisors (adapt: clock API as in 1.22)

The map class is `A`, for the same `Sys.time` reason as exercise 1.22.

`next_test_divisor d` returns 3 when `d` is 2 and `d + 2` otherwise, so
`find_divisor_fast` tests 2, 3, 5, 7, 9, ... instead of 2, 3, 4, 5, 6,
..., skipping every even candidate above 2. `smallest_divisor_fast`
agrees with the naive `smallest_divisor_naive` (kept private in this
file, re-derived rather than imported, so the file stands alone) on
every input the test tries, including the three numbers of exercise 1.21
and a composite with a small even factor (561 = 3 * 11 * 17).

Skipping evens halves the number of test steps, so the naive expectation
is that the fast search runs about twice as fast. In practice the ratio
measured with a real clock tends to fall short of 2, because the
constant overhead per call (the function-call machinery itself, not the
comparison it does) does not shrink along with the step count — halving
the number of steps does not halve the fixed per-step cost the way the
asymptotic analysis of step count alone suggests. The comparison is a
timing exercise, subject to the same clock-resolution caveat exercise
1.22 raises: only a well-measured average over repeated runs, not a
single call, can answer it honestly.
