# Exercise 5.22: append and append! machines (T)

## Approach

Two controllers over the same memory primitives. `append` recurses
down the cdr side of the first list, saving continue and pair at
each level; on the way back it conses each saved car onto the result,
so the first list's cells are copied and the second list is shared.
`append!` allocates nothing: it walks to the last pair of the first
list with a `temp` register and splices the second list in with one
`set-cdr!`, so the result is the first list's own head pointer.

The sharing is proved in the tests by pointer identity, not by
printing: the fourth cell of the appended result is the second
list's head word, and after `append!` the cell after the 3 is
likewise the second list's head word.

## Map class

`T`.

## Sample answer

`append` of `(1 2 3)` and `(4 5)` reads `(1 2 3 4 5)` from three
fresh cells (the free pointer advances by 3), and the original
`(1 2 3)` still reads unchanged. `append!` of the same arguments
reads `(1 2 3 4 5)` through the unchanged head pointer with the free
pointer exactly where it was: the splice moved no bytes.
