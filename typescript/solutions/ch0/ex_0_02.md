# Exercise 0.2: compose and repeated

## Approach

`compose(f, g)` returns a closure that applies `g` first and feeds the
result to `f`; its type is the section's `Mapper` alias in both
positions. `repeated` recurses on the count, not on the values: the
`n = 0` case is the identity function, and each larger `n` wraps one
more application of `f` around the result of `repeated(f, n - 1)`. The
recursion depth is the count `n`, not the magnitude of `x`, so the
statement's "exactly n times" is expressed directly and the frame cost
stays negligible for practical counts.

## Proof

Two hand-computed cases pin the both-orders requirement, because the
orders genuinely differ: `compose(inc, dbl)(3)` is `2 * 3 + 1 = 7`
while `compose(dbl, inc)(3)` is `2 * (3 + 1) = 8`. The `n = 0`
boundary is explicit (`repeated(inc, 0)(41)` is `41`). Two fast-check
properties carry the generated load: `repeated(inc, n)(x)` must equal
`x + n`, and `repeated(compose(inc, inc), n)(x)` must equal `x + 2n`,
which checks that `repeated` counts applications of the composed
procedure, not of its parts.
