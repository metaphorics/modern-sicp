# Exercise 4.31: lazy and memo parameter declarations (T)

## Approach

The declaration `(name lazy)` / `(name lazy-memo)` is object-language syntax on
the reader's grammar: a parameter specification parses as a bare name (strict,
the upward-compatible default) or a two-item list carrying the mode. The modes
live beside the evaluator in a table keyed by the procedure's identity (the
4.1.7 bodies-table shape, because the shared `Closure` has no slot for them);
the application clause binds each operand per its mode -- strict evaluates now,
`lazy` delays into a recomputing wrapper, `lazy-memo` delays into a memoized
cell -- and the forcing discipline follows the wrapper a value carries.

## Map class

`T`.

## Sample answer

`(pick (car '()))` -> taken, the lazy parameter unforced. `(f (id 1) (id (+ 2 3)) (id 4) (id (* 5 6)))`
-> `(1 5 5 4 30 30)` with count 5 (two strict calls, two recomputed `lazy`
demands, one computed `lazy-memo` demand). Then `lazy` used twice runs twice
(count 7) and `lazy-memo` used twice runs once more (count 8).
