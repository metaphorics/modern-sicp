# Exercise 4.62: last-pair rules

## Approach

Two rules: the singleton base (head and result are the same one-pair
dotted term) and the tail step (a longer list's last pair is its
tail's). The three ground-input book queries terminate and are pinned
exactly. The open-ended `(last-pair ?x (3))` is exhibited as data but
never executed: every rule head unifies with a longer pre-image, so
the answer set is infinite and the driver would never return — the
honest finite-prefix discipline from 4.47 applies. Addition 4.62a
implements the inverter as two ground rules and checks both signal
directions.

## Numbers

`(3)` ends in `(3)`; `(1 2 3)` ends in `(3)`; `(2 ?x)` ends in `(3)`
with `?x = 3`. The inverter maps `0 → 1` and `1 → 0`. The open query
would enumerate `(3)`, `(?_, 3)`, `(?_, ?_, 3)`, … without end.

## Class and deviations

Translated row. Deviation: the dot-headed list patterns are atoms
with `qpair` terms, since rule heads must be atoms. No deviation in
the termination lesson: the fourth query's infinitude is structural
(longer pre-images always unify), so exhibiting it unrun is a
persistence of the objective, not a deletion.
