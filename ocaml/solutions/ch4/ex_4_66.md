# Exercise 4.66: Ben's accumulation scheme and the wheel duplication (translate)

Ben's scheme feeds the query pattern to `qeval`, extracts the designated
variable from every frame of the resulting frame stream, and hands the
value stream to the accumulation function, here a `sum` over `Value.Int`
bindings read with `binding_in_frame`. The scheme is correct for the book's
programmer query (two frames, 40000 + 35000 = 75000) and breaks exactly as
Cy's wheel result predicts: `qeval` emits one frame per derivation route,
so summing over `(and (wheel ?who) (salary ?who ?amount))` counts Warbucks's
150000 salary four times: 660000 from 5 frames instead of the true 210000.

The salvage: accumulate over distinct answers only. Each frame is
instantiated to its full answer (the string the driver would print),
duplicate instantiations are dropped before the variable is read, and the
same accumulation over the distinct frames collapses the sum to the true
payroll of the wheels: 210000 from 2 frames. (Filtering on the salary
value alone would be wrong: Ben and a hypothetical second 60000 earner
must not collapse; the full-instantiation key keeps exactly the duplicate
derivations.)

Asserted answers (verbatim):

```
sum over the book's query = 75000 (from 2 frames)
Ben's scheme on the wheel query = 660000 (from 5 frames): Warbucks's 150000 counted 4 times, 3 duplicate frames
salvage, distinct answers only = 210000 (from 2 frames): the true payroll of the wheels
```

Deviation: the accumulator is implemented against the exported `qeval`
frame stream in the solution module (the edition's realization of "pass
the stream through a mapping function"); no engine file is touched.
Frames lacking the designated variable would be skipped; none occur in the
demo.
