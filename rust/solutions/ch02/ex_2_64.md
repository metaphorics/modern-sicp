# Exercise 2.64: `list->tree`

## Approach

**Part a.** `partial_tree(elts, n)` splits `n` into a left count
(`(n - 1) / 2`), one entry, and a right count (whatever remains),
builds the left subtree from the first `left_size` elements, takes the
next element as the entry, and builds the right subtree from the rest,
returning the tree together with the elements not yet placed (the
book's `cons` pair becomes a `(Tree, &[i128])` return, using Rust's
slice splitting instead of chasing `cdr`). For `[1, 3, 5, 7, 9, 11]`
this produces `(5 (1 () (3 () ())) (9 (7 () ()) (11 () ())))`: `5` at
the root, `1` and `3` on the left, `9`, `7`, and `11` on the right.

**Part b.** Every element becomes exactly one tree node (one
`make_tree` call each end to end, no element visited more than once),
so `list->tree` is `Θ(n)`. The solution counts `make_tree` calls
directly and confirms the count equals the input length exactly at
both 11 and 101 elements, not just asymptotically.

## Map class

`A`: `partial-tree` returns a pair in the book; this edition returns a
tuple `(Tree, &[i128])`, matching the map's Rust class for this row.
