# Exercise 3.71: Ramanujan numbers via weighted pairs

## Approach

`ramanujanNumbers` generates `weightedPairs(integers, integers)` with
the cube-sum weight `i^3 + j^3` and scans for runs of consecutive pairs
sharing a weight; because `mergeWeighted` emits equal weights adjacent,
each run holds every way of writing the number. A run of two or more
emits its weight once. The first six weights the stream yields are
1729, 4104, 13832, 20683, 32832, and 39312, and they arrive in
increasing order; the tests pin the prefix and the ordering. The scan
to the next qualifying run is a cursor loop inside the tail thunk, so
the long stretches between hits stay off the stack.

Independent check: a python3 brute force over all cube sums
`i^3 + j^3` with `1 <= i <= j < 60` produces exactly the same six values
as the first taxicab weights (7th and 8th are 40033 and 46683, beyond
the pinned prefix), and it confirms 1729's representations are
(1, 12) and (9, 10) and 4104's are (2, 16) and (9, 15).

## Map class

`T` (map row 3.71: the Ramanujan search translated to Kotlin's memoized
streams as written).

## Deviation

A number with three cube-pair representations would be emitted once,
not twice (the scan groups whole runs); no such number occurs inside
the pinned prefix.
