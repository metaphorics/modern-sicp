# Exercise 2.78: primitive type tags

## Approach

The wrapped system is rebuilt locally as the baseline:
`attach_tag_wrapped` tags every datum, `type_tag_wrapped` answers the
wrapper's tag or raises `SicpError::UserRaised` on an untagged datum,
and `contents_wrapped` strips the single wrapper.
`install_integer_wrapped` runs its handlers on bare integers and
rewraps each answer, so the first observation is that `3` plus `4`
answers a tagged `7`: ordinary numbers are wrapped on the way in and
unwrapped per call, exactly the situation the exercise starts from.

After the modification the tag functions read the runtime's own
variant. `type_tag` of `Value::Int(7)` answers `integer` and `contents`
answers the number itself, with no wrapper constructed anywhere. The
runtime enum carries plain `Int` and `Real` variants, so an ordinary
number is represented as itself and the trio needs no wrapper case
beyond the identity.

The generic interface treats the two shapes alike. With the section
package installed, `apply_generic` on `mul` of `6` and `7` answers the
bare `Value::Int(42)`. Handlers always receive contents, so nothing in
the packages distinguishes the bare representation from the wrapped
one; only the trio changed. The test asserts these structural facts —
the wrapper round-trip, the bare number's own tag and contents, and the
bare product — rather than any printed trace.

## Map class

`A`: untagged numbers need enum with plain variant. The runtime enum
carries `Int` and `Real` as plain variants, and the accommodation is
that `attach_tag` is the identity on their own domain tags (`integer`
and `real`) while `type_tag` reads the variant off the datum instead of
a wrapper.

## Deviation

The modified trio is the library's own `attach_tag`, `type_tag`, and
`contents` in `crates/ch02/src/sec_2_5.rs`, which the section text
assumes from this exercise on; the solution file rebuilds only the
pre-2.78 wrapped trio locally and demonstrates both against the same
generic interface rather than defining a second trio of its own.
