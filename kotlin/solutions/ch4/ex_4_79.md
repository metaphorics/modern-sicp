# Exercise 4.79: rules over parent-linked frames

## Lesson

Each rule application runs in a fresh scope parented on the caller's
frame, so rule variables resolve lexically instead of by renaming:
the pattern's `boss` reads the query's binding through the parent
chain, while `x` binds per application. Two patterns share one
scope, so a variable bound by the first constrains the second -- the
merge that renaming would have hidden. Facts disagreeing on a shared
variable fail the application.

matching is guest code; no freshened names appear anywhere.
