# Exercise 3.20: tracing object aliasing through closures

## Approach

The book draws environment diagrams for `(define x (cons 1 2))`,
`(define z (cons x x))`, `(set-car! (cdr z) 17)`, and the read-back of
`x`, under the procedural pair implementation. The map's TypeScript row
replaces the drawing with a trace of object aliasing via closures, so
`makePair` spells the procedural pair as a closure over two separately
typed local slots with the book's accessor and mutator members, and
`tracePairAliasing` runs the book's four-expression sequence while
recording what each step did.

## Pins

Computed by running. `zCarIsZCdr` is true: z's two slots hold the same
pair object, and `zCdrIsX` is true: that object is the one x names. After
`(set-car! (cdr z) 17)`, reading through the car handle answers 17
(`readCarX`), and so does the read through z's slot (`readThroughZ`):
one mutation through one handle is visible through the other. The event
log records PairCreated, Aliased, SlotSet, ReadThroughAlias in the order
the sequence performs them, and a control pair built as two distinct
pairs fails the identity check (Object.is false).
