# Exercise 4.23: analyze-sequence comparison

## Approach

Both versions are implemented over one analyzer with counters attached to
every body procedure: a `leafRuns` `Ref` counting execution-procedure runs
and a `walks` `Ref` counting Alyssa's runtime walk. The text's version
folds left at analysis time, so a one-expression body returns the body's
own procedure and nothing sequence-shaped exists at run time. Alyssa's
version analyzes into a list and walks it on every execution, incrementing
the walk counter once per run. Each program is analyzed once and executed
five times, so run counts are comparable.

## Numbers

One-expression body `(begin 1)`, five executions: text's version, leafRuns
`5`, walks `0`; Alyssa's version, leafRuns `5`, walks `5`. Two-expression
body `(begin 1 2)`, five executions: text's version, leafRuns `10`, walks
`0`; Alyssa's version, leafRuns `10`, walks `5`. Body work is identical;
the walk is the difference, one per execution in Alyssa's version and zero
in the text's, for both body sizes.

## Class and deviations

Translated row. The answer to the statement: for one expression, the
text's execution procedure IS the body's procedure, while Alyssa's loops
through a one-element list before calling it; for two expressions, the
text's fold has built proc1-then-proc2 into the procedure tree at analysis
time, while Alyssa's version walks the list every run. Deviation: counters
are host `Ref`s wrapping body procedures, an instrumentation the book
leaves to the reader; empty sequences fail in both versions as the book's
error does.
