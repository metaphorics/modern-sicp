# Exercise 4.15: the halting diagonal, executed

## Approach

halts? is provided by the host as an oracle with an adjustable answer, and
the object language gets the book's run-forever and try verbatim. Because a
diverging evaluation never returns, a fuel counter is wrapped around a
complete dispatch: every dispatch spends one unit from a Ref, and one step
past the limit fails with a RuntimeError instead of hanging, which turns
"runs forever" into an observable, pinnable outcome. The theorem the runs
demonstrate: no halts? correctly decides halting. If halts? says true for
`(try try)`, try calls run-forever and diverges, so the answer was false; if
it says false, `(try try)` halts with 'halted, so the answer was true.

## Numbers

Under the true oracle with fuel 500, `(try try)` fails with RuntimeError
whose message is "out of fuel", and the counter reads exactly 501 steps: the
first spend past the limit is the failure. Under the false oracle the same
fuel, `(try (lambda (u) u))` answers the symbol `halted` having spent well
under 500 steps. Under the true oracle that same `(try (lambda (u) u))`
exhausts its fuel too, because the oracle answers true and try drives into
run-forever. So the false oracle's answer for a procedure that halts on
itself is wrong, and the true oracle never gets to answer at all.

## Class and deviations

Translated row. Deviation: the book's argument ends with "runs forever"; this
edition makes the divergence observable by capping the evaluator at a fuel
limit and pinning the exhaustion, which changes no statement about halts?.
