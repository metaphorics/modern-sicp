# Exercise 3.53: the self-referential doubling stream

## Approach

The book's `s` is 1 followed by add-streams of `s` with itself. Zipping
a stream with itself pairs element k with element k, so every element
doubles its predecessor: 1, 2, 4, 8, ..., the powers of two. Kotlin
locals cannot appear in their own initializer, so the builder ties the
cell first and the tail thunk reads the tie: the zip arguments are the
one shared memoized stream, exactly the book's shape. The test pins the
first twelve elements, `streamRef` at indices 30 and 40 (`2^30`,
`2^40`), and a fresh call's element 20, which shows each call yields
its own independent doubling stream.

## Map class

`T` (map row 3.53: Kotlin T; the prediction is stated in the KDoc and
pinned by the tests).

## Deviation

The book defines one global `s`; the edition's API is the function
`doubledStream()`, and each call returns a fresh memoized stream over
the same construction. Zipping two fresh sibling chains per level, the
literal function-body reading, would re-derive exponentially many cells
on a deep walk; the tie cell keeps the book's single shared chain.
