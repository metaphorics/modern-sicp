# Exercise 5.3: the sqrt machine in two stages

The map class is `T`. The statement asks for the square-root machine of
1.1.7 twice: first with `good-enough?` and `improve` available as
primitives, then with both expanded in terms of arithmetic operations,
each version drawn as a data-path diagram and written as a controller
definition.

Stage 1 needs two registers, `guess` (started at 1.0) and `x`, plus two
primitives in the operations table: `good-enough?` answers whether
`abs(square(guess) - x) < 0.001` and `improve` answers the average of
`guess` and `x / guess`. Data paths:

```
+---------+                      +---------+
|  guess  |<-------(X) g<-imp ---+   x     |
+----+----+                      +---------+
     |                                    |
     |          .**************.          |
     +--------->*  good-enough? *<--------+
     |          *  **********  *          |
     |           * ********** *  (test, no output)
     |          *  *        *  *
     |         *  *          *  *
     |            *  improve *
     |             *        *
     |              ********
```

The controller:

```
      sqrt-loop
          |
          V
         / \  yes
+------->* *--------> sqrt-done --> (perform print guess)
|        \ /
|         | no
|         V
|    +-----------+
+----+ g<-imp    |
     +-----------+
```

Stage 2 expands the primitives. `good-enough?` becomes three assigns
computing `abs(guess * guess - x)` into a temporary and one test
against `(const 0.001)`; `improve` becomes `(x / guess) + guess`
divided by `(const 2)`. Two temporaries, `t` and `u`, carry the
intermediate values, because an operation's inputs are registers and
constants only: the section's rule that operations cannot operate on
the results of other operations. One deviation, recorded deliberately:
`abs` stays primitive. The book's 1.1.7 counts it among the arithmetic
operations the expansion may use (`good-enough?` was written with `abs`
there), so `*`, `-`, `<`, `/`, `+`, `=`, and `abs` are the arithmetic
table of this stage, while `average` is expanded away.

The point of the two-stage design is that the expanded machine computes
the same fixed point, so the driver transcripts must agree, and do.
`ex_5_03 ()` answers
`["1.4142156862745097"; "3.00009155413138";
"1.4142156862745097"; "3.00009155413138"]`: stage 1 then stage 2 on
x = 2 and x = 9, each transcript the single printed line at
`sqrt-done`. The answer for x = 2 is the Newton fixed point within the
0.001 tolerance, not the true root. The machine stops at
1.4142156862745097, the book's 0.001-good-enough answer rendered at
full host precision.
