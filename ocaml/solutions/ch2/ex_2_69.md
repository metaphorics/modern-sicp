# Exercise 2.69: generate-huffman-tree and successive-merge (translate)

The map class is `T`: only the syntax changes. `successive_merge`
repeatedly takes the two lightest elements off the front of the
weight-ordered leaf set, merges them into one code tree with
`make_code_tree`, and uses `adjoin_set` to put the merge back in its
ordered place, until one tree is left. Because the set stays ordered,
the two lightest elements are always its first two, so no search for
them is needed.

Sample: `ex_2_69 ()`, `generate_huffman_tree` applied to the
statement's four pairs `[("A", 4); ("B", 2); ("C", 1); ("D", 1)]`,
reproduces Exercise 2.67's hand-built `sample_tree` exactly; a
single-pair alphabet generates its own leaf with no merging.
