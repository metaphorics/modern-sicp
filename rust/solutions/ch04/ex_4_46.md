# Exercise 4.46: left-to-right operands in amb (T)

## Approach

The engine's operand walk (`continue_args`) consumes the operand list
from the front, so the left operand evaluates first. The demonstration
makes each operand announce itself with `display` before choosing: the
captured display text reads `leftright` exactly once, the answers
enumerate left-major, and a `try-again` re-enters the walk without
replaying the left operand's side effect -- the resumable-frame design
resumes after the done prefix. The parser needs this order because
`parse-word` consumes `*unparsed*` from the front: a right-to-left
evaluator would match sentence-final words first and every parse would
fail its word-class requirement.

## Map class

`T`.

## Sample answer

`displayed = "leftright"`, answers `(1 1)`, `(1 2)`, `(2 1)` in that
order with no further display -- the left operand chose first and once.
