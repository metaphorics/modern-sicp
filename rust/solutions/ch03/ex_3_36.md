# Exercise 3.36: the connector's dispatch, traced

## Approach

The book's exercise asks for an environment diagram showing how
`(set-value! a 10 'user)` reaches a constraint's local state; that
is a question about Scheme frames, so this edition replaces it. The
replacement traces the same call graph as a flat list of dispatch
labels: setting a connector runs `Connector::set_value`, which calls
every attached constraint's `inform_about_value`, which runs the
constraint's own `process_new_value`. A spy constraint attaches to
connector `a` and records the labels it receives. The trace answers
`inform_about_value` then `process_new_value`. A second test runs
`forget_value` and traces `inform_about_no_value` then
`process_forget_value`; both paths reach the same constraint.

## Map class

`R: trace connector closure call graph`. The diagram became
runnable: each arrow the figure would draw is a call the trace
logs, in the order the connector actually issues it.

## Deviation

The replacement is by design (this row is R for Rust). The setting,
the informant, and the constraint whose state is reached are the
book's own; the drawing became the logged dispatch.

## Note

The spy is kept alive by the caller: the connector holds its
constraints weakly, so a spy owned only by the helper that attaches
it would be collected before the first `set_value`, and the trace
would come back empty. The regression tests caught exactly that.
