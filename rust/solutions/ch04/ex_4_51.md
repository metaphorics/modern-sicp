# Exercise 4.51: permanent-set! (T)

## Approach

The engine's assignment clause takes a trail kind. `set!` saves the
old value and records the undo entry -- the book's `*1*`/`*2*` pair.
Backtracking applies the restoration when it crosses the assignment.
`permanent-set!` assigns without recording an undo entry, so no
backtracking restores the value. The book's program under
`permanent-set!` counts every trial, including failed ones, because
each trial increments before the engine tests its `require`. Under `set!`,
the driver's `try-again` passes back through the answered path's
assignment interception -- the book's `*2*` restoration -- so the
count returns to its pre-problem value before the next alternative
runs.

## Map class

`T`.

## Sample answer

`permanent-set!`: `(a b 2)`, `(a c 3)`, `(b a 4)`, `(b c 6)`, `(c a 7)`,
`(c b 8)` -- the gaps at 5 are the failed `(a a)` and `(b b)` trials.
`set!`: every answer reads 1 -- `(a b 1)`, `(a c 1)`, ... -- and
backtracking restores the count before the next alternative.
