# Exercise 3.75: the bug in Louis's smoothed detector

## Approach

The bug: Louis's single `last-value` thread serves two jobs. Because the
recursion passes the average `avpt` as the new `last-value`, the raw
previous input is lost after the first element, so every later average
is taken against the previous AVERAGE; the smoothing drifts into an
exponential average instead of averaging each value with the previous
raw value. On a noisy input the corrupted average leaks the noise and
reports crossings that are not in the data. The fix keeps the structure
and separates the threads: a private recursion carries both the raw
previous value (the averaging partner) and the previous average (the
comparison target), exposed as `makeZeroCrossingsSmoothed(input,
lastAvg)`; `lastAvg` seeds both threads, reading the signal as at rest
before the first sample. The test drives both programs with a slow drift
`0.4 - 0.02 k` plus alternating noise of half a unit over 41 samples:
Louis's version emits a 17-flip alternating run (`-1, +1, -1, ...`)
around the crossing while the fixed version reports exactly one crossing
at the true zero. Both crossing lists are pinned, and the same lists
were reproduced in a python3 mirror of the two recursions.

## Map class

`T` (map row 3.75: state-threading fix over the 3.74 extractor).

## Deviation

The noisy input is a ramp through zero rather than a sine: period-2
noise cancels exactly in the correct two-tap average but leaks through
Louis's corrupted average, which separates the two programs sharply.
The pinned contract signature takes one seed argument, so
`makeZeroCrossingsSmoothed` seeds both the average thread and the raw
thread with `lastAvg`.
