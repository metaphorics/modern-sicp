# Exercise 3.47: semaphores from mutexes and from test-and-set

## Approach

Three constructions, each parkable, because a Mutex-plus-counter alone
cannot park a waiter (the section text says so). Part (a):
`MutexSemaphore` guards a count with a mutex and parks waiters on a
ticket channel: Dijkstra's negative count, where |count| waiters are
parked and each release wakes exactly one. Part (b):
`TestAndSetSemaphore` keeps the count as a CAS target; acquire succeeds
exactly when a compare-and-exchange moves it from c to c - 1 for some
c > 0, and a waiter retries with `yield()` between attempts. The
edition's token semaphore (`TokenSemaphore`) prefills a
`Channel<Unit>(n)`; receive acquires, send in `finally` releases, and
`use` brackets the critical section. The statement's library fact is
kept: kotlinx's `Semaphore` exists, and the probe asserts permit
conservation for all four: six users through n = 3, every user
completes, occupancy never exceeds three.

## Map class

`A` (map row 3.47: kotlinx provides Semaphore; build anyway). The
statement says both facts, and the code does both.

## Deviation

Part (a)'s parking uses a channel ticket queue alongside the mutex;
the book's mutex-plus-retry cannot express a parked waiter in Kotlin,
and the section's mutex footnote states this.
