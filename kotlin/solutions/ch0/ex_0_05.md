## Exercise 0.5: cold Sequence versus memoized LStream

Approach: both shapes produce 1, 4, 9, ... forever, and both take a
`force` callback so the probe can count element computations without
touching the production shapes. The `Sequence` is a `sequence { }` builder
whose loop ticks `force` per yielded element, so two `take(5)` passes count
10: the pipeline is cold and recomputes from the start. The `LStream` is
the runtime's `consStream`, with `force` at each node materialization, so
building the first node plus forcing five tails counts 6, and the second
walk finds every tail memoized and adds nothing. The fifth tail is the
lookahead of the runtime's `take`, which forces one tail past the last head
it keeps. `ex_0_05` returns (10, 6).

Class: companion-added exercise (idiom-kotlin.md, Section 5, list item 0.5);
no map row. Deviation: the companion says "use a counting probe to show
which recomputes on a second pass"; the solution makes the counts the
return value so the property is asserted, not merely observed in a
transcript.
