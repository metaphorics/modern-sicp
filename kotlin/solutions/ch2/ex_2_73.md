## Exercise 2.73: data-directed deriv

Approach: `OperatorExpr` gives sums, products, and powers typed cases.
`derivDataDirected` handles numbers and variables directly, then dispatches
compound expressions through a `DerivTable` keyed by the operator.

Part (a): numbers and variables have no operator to use as a table key,
so they remain direct cases.

Part (b): install the sum and product rules under `"+"` and `"*"`.

Part (c): install the power rule under `"**"` without changing the
dispatcher or the existing rules.

Part (d): an operation-and-operator table would change the lookup key
shape, but not the derivative rules or their results.

Class: A, per the map; the table-driven rule technique is retained, while
the expression forms are sealed Kotlin data variants. Adding an
expression shape requires a variant and dispatcher case; adding a rule
for an existing shape remains a table insertion. The tests verify that
installing the power rule leaves the sum rule unchanged.

Deviation: the table stores rules returning `OperatorExpr`, so it is a
small exercise-local table rather than a table for unrelated runtime
values or operations.
