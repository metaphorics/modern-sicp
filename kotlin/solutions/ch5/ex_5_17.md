# Exercise 5.17: traced lines with their labels

The label-aware tracing machine extends 5.16 with the one datum the
plain trace drops: the label currently in effect. `execute()` builds
an address-to-name map from the assembler's label table once per run,
carries `currentLabel` across instructions, and updates it whenever
`pc` sits on a label address, so every traced line is prefixed with
the most recently passed label definition and the trace reads like
the controller listing.

`labelTracedGcdTrace()` pins all 26 lines of the same gcd run, each
prefixed `test-b: `: every instruction the machine executes lies
under the `test-b` label, because the loop's goto returns to it and
`gcd-done` names the stop address one past the last instruction,
which the machine reaches but never executes. A controller that
spread its instructions over several labels would show the prefixes
change mid-run; the point of the exercise, the label tracking, is
what the uniform prefix here still pins, since it comes from the
label table lookup and not from string prepending.
