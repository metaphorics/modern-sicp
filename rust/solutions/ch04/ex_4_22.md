# Exercise 4.22: `let` in the analyzed evaluator (T)

## Contract

`ch04::sec_4_1::{analyze,run_analyzed_program}` over checked Rust source and
its retained `Plan` tree.

## Lesson

The `twice` body analyzes to one `Plan::Seq` containing two `PlanStmt::Let`
bindings and a binary tail. The same retained plan is executed twice; its
stdout matches the direct evaluator, so the `let` rewrite is an analysis-time
transformation rather than per-call parsing.

## Map class

`T`.

## Sample answer

The analyzed `twice` plan has two `Let` statements, and both retained runs
print `7\n7\n`, matching direct execution.
