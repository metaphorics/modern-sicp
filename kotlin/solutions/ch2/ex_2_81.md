## Exercise 2.81: Louis's identity coercions

Approach: (a) [installIdentityCoercions] installs `complex -> complex`
in [CoercionTable], keyed by [KClass] pairs as every entry in this
edition's coercion registry is; with `exp` present only for
`(integer, integer)`, [applyGenericLouis] on two complexes misses,
coerces the first argument to its own type -- a no-op -- and retries,
missing again forever, so the budgeted version in `ex_2_79` reports the
loop as capped rather than let it hang. (b) Louis is wrong that a
same-type miss is broken today: plain [applyGeneric] never consults the
coercion table at all, so it answers a same-type miss with `NoMethod`
directly, no loop. (c) [applyGenericNoSelfCoercion] is the actual fix --
it skips coercion entirely once both arguments already share a tag, so
Louis's identity coercions become unreachable dead code rather than a
hazard.

Class: A, per the map -- the book's coercion table is a nested alist
keyed by symbol pairs; this edition's version is keyed by `KClass<*>`
pairs, which is the natural way to hold "how to turn a `ZLong` into a
`QRat`" as data in a typed table.

Deviation: none in substance.
