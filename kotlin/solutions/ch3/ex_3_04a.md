## Exercise 3.4a: lockout with an audit log

Approach: `makeAccountWithAuditLog` adds one more captured cell, `log`, a
`PersistentList<AuditEntry>` rebound on every request by the shared
`record` helper. Every branch of `withdraw` and `deposit` -- the wrong
password, the lockout, insufficient funds, and success -- calls `record`
exactly once with the operation name and outcome before returning, so the
log is a complete, ordered account of everything the object was ever
asked, not just of what it did.

Class: this is the section's one chosen tailored addition (map row 3.4,
idea "lockout with audit log"), recorded as `chosen: kotlin` on that row.
Deviation: none; `AuditedAccount` extends exercise 3.3's `Account`
unchanged, so every existing `Account` consumer still accepts it.
