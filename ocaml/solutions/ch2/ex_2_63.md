# Exercise 2.63: two tree-to-list procedures (translate)

The map class is `T`: only the syntax changes. Both procedures
produce the sorted element list for every tree, including the three
differently shaped trees of Figure 2.16 that all represent
`{1, 3, 5, 7, 9, 11}`. They differ in growth: `tree_to_list_1`'s `@`
costs the size of its left argument at every node it visits, which
sums to `Theta(n log n)` for a balanced tree (worse for an
unbalanced one), while `tree_to_list_2` carries an accumulator and
conses onto it on the way down, doing `Theta(1)` work per node for a
true `Theta(n)` total. `tree_to_list_2` is the one worth keeping.

Sample: `ex_2_63 ()` pairs both procedures' results for all three
Figure 2.16 trees; every pair is `([1; 3; 5; 7; 9; 11], [1; 3; 5; 7;
9; 11])`.
