# Exercise 4.20: recursive bindings as a derived expression

## Approach

The `RecursiveBindings` node derives to the book's let-and-writes
shape as a grouped binding with uninitialized cells: one immediately
called block whose declarations pre-bind every name before the
initializing writes run, so an initializer may refer to its siblings.
The derived let evaluates immediately, and because the lowered form is
pure shared syntax it works nested inside procedure bodies. Louis's
claim is tested against the same program spelled with a plain grouped
binding: a plain binding's initializers are the call's arguments and
see only the outer frame, so an initializer that reads a sibling is
unbound there.

## Numbers

The mutually recursive `even?`/`odd?` answers `false` for `5`.
Factorial `10` by recursive binding answers `3628800`. The nested
`double` body answers `42` for `21`. Louis's `a = 1, b = a + 1` over
`b` fails with `unbound-name` on `a`, while the recursive analog
answers `2`. The emitted shape is pinned: `recursiveToCall` over
`a = 1, b = a + 1` is the immediately called block with the two
declarations followed by the body.

## Class and deviations

Translated row. Deviations: the pre-binding values are the runtime's
real uninitialized cells rather than a `'*unassigned*` marker, and the
transformation emits declarations whose pre-binding the runtime
supplies, rather than an explicit generated `let` of markers plus
`set!` writes.
