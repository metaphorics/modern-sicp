# Exercise 5.1a — the factorial driver loop (this edition's addition)

Recorded in the map's 5.1 idea cell as `chosen: ocaml`; this file, the
`solutions/ch5/sec_5_1.ml` entry `ex_5_01a`, the matching scaffold
entry, and the book statement inserted after Exercise 5.1 are the
addition's artifacts.

The addition turns the 5.1 machine into the driver-loop structure of
5.1.1's Actions: the machine's `read` operation produces a value from
outside the machine, `print` is the action performed on a register, and
instead of stopping after one answer the controller starts over. Two
design decisions to record:

- The loop needs an exit, so the input language gains the symbol
  `end`, compared by the machine's own `=` test against the constant
  written `(const end)` — the symbol constant that 5.1.5's summary
  announces for later sections. Symbols and numbers never compare
  equal, so a number can never be mistaken for the sentinel.
- The per-pass initialization `(assign product (const 1))` and
  `(assign counter (const 1))` lives inside the loop body, because each
  pass must restart the iteration from `(iter 1 1)`.

The transcript of two consecutive runs (inputs 5 then 6, and 1 then 10,
each closed by `end`) is the exercise's deliverable, so
`ex_5_01a ()` answers
`["120"; "720"; "end"; "1"; "3628800"; "end"; "120";
"Error: operation failed: read: the input is exhausted"]`: two passes
per run printing 120 and 720, then 1 and 3628800, each run closed by
the `end` report, and a third run left with a live `n = 5` in flight
whose next read dries up — the typed failure is what stops the
otherwise unbounded loop of Figure 5.4's design in this edition.
