## Exercise 2.9: interval width algebra

Approach: `width(addInterval(x, y))` expands to
`((x.upperBound + y.upperBound) - (x.lowerBound + y.lowerBound)) / 2`,
which regroups to `width(x) + width(y)` exactly, for any `x` and `y`; the
property test checks this algebraically over many generated intervals.
Multiplication has no such law: `[1, 3]` and `[10, 12]` both have width 1,
but `[1, 3] * [1, 3]` is `[1, 9]`, width 4, while `[10, 12] * [10, 12]` is
`[100, 144]`, width 22. Equal input widths, different output widths, so
the product's width cannot be a function of the factors' widths alone.

Class: A. The idea survives unchanged, but the statement gains a Kotlin
design decision the original raises implicitly: `Interval` here places no
invariant on `lowerBound <= upperBound`, so `width` can be negative for a
reversed interval rather than reject it at construction. This edition
leaves that unenforced, because `makeInterval` never receives a reversed
pair in the whole extended exercise and adding a `require` would guard
against a case this section never exercises; a stricter edition could add
it to `Interval`'s constructor instead. Deviation: `width` is defined
here rather than accepted as given, since this is the exercise that
introduces it.
