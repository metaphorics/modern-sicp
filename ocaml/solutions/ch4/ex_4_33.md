# Exercise 4.33: literal lists become lazy lists (translate)

The map class is `T`. The subset has no quotation; the analogue of the
text's quoted list is the literal list notation `[a; b; c]`. Ben's
problem is real in the same shape: under the section evaluator a lazy
list is what the program's own `cons` builds, a compound call whose
operands stay thunks, while a literal list evaluates its elements as it
is built. The literal is therefore not the structure the program's
lazy-list procedures expect, and an armed element the walk never
reaches still stops the program: `head_or 0 (tail [1 / 0; 42])` answers
the division error, while the same list built with `cons` answers 42.

The fix lifts the list clause, a variant over `Sec_4_2.open_eval`: a
literal cell delays its element and its tail through `Sec_4_2.delay`,
exactly as the program's `cons` does, so the literal becomes the same
lazy structure. Under the lifted clause the literal answers 42, and
`list_ref [1 / 0; 42; 1 / 0; 7] 3` walks the lazy spine to 7, forcing
only the element it answers.

Sample: `ex_4_33 ()` answers `"error: division by zero"`, then the
transcripts beginning `"42\n"`, `"42\n"`, and `"7\n"`.
