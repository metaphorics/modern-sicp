# Exercise 2.22: two failed iterative square-lists

## Approach

`squareListIter` is Louis's first rewrite: a while loop that conses each
square onto the front of the accumulated answer. Because every new
square lands on the front, the squares come out in reverse order: the
first failure the book explains. `squareListSwapped` models the second
rewrite, where the `cons` arguments are interchanged so the answer grows
on the left. The literal `cons(answer, square)` does not typecheck
against the edition's `List` (a `List<number>` is not a `number`), so
the shape the swapped call builds is shown with the tree union: the
answer starts as the empty node (printed `()`) and every step wraps it
around the next square, `node(answer, leaf(square))`, which `showTree`
prints as the book's `((((() 1) 4) 9) 16)`.

## Numbers

`squareListIter` of `(1 2 3 4)` prints the reversed `(16 9 4 1)`;
`squareListSwapped` of `(1 2 3 4)` prints `((((() 1) 4) 9) 16)`.

## Map class

`T`: the statement translates directly; only the second rewrite's
interchanged `cons` needs the tree union to be a value the edition can
hold and print.

## Deviation

None.
