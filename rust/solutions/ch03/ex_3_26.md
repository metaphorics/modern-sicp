# Exercise 3.26: the binary-tree table

## Approach

The book rebuilds the table over binary-tree nodes so lookups and
insertions take steps proportional to the tree's height. The Rust
solution keeps the section's table shape, a list of entries, but each
entry is a tree node: key, value, and left/right children in
`RefCell`s, ordered by key. `insert` walks to the null child and sets
it to a fresh node; `lookup` walks by comparison.
The solution inserts five keys out of order, replaces key 3's value
in place, and reports both the lookups and a full in-order read of
the keys, sorted. The tests cover the replacement, the missing-key
error, and the ordering.

## Map class

`A: in-place tree mutation via RefCell`. Setting a child and rewriting
a value mutate the same cells as the list-backed table. The tree shape
is what makes the walk logarithmic.

## Deviation

None. The statement's ordering requirement and its two operations
are kept; reading keys in order is the demonstration the section
asks for that the tree is ordered.
