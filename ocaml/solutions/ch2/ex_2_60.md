# Exercise 2.60 — sets that allow duplicates (translate)

The map class is `T`: only the syntax changes. `element_of_set` is
unchanged, since a duplicate cannot hide a missing element from a
linear scan. `adjoin_set` drops its check and becomes plain `cons`;
`union_set` drops its filter and becomes plain `@`; both trade a
linear-in-the-set-size check for a constant-time one, at the cost of
letting the set grow without bound. `intersection_set` keeps every
occurrence in `set1` that `set2` carries at least one of, so
duplicates in `set1` survive into the result while `set2`'s own
duplicate count is not consulted; this is the natural reading of
"intersection" for a representation whose own multiplicities are not
otherwise meaningful, and it matches the exercise's observation that
a representation with cheap insertion (this one) trades away cheap,
precise set algebra.

Samples: adjoining `1` onto the book's example set `(2 3 2 1 3 2 2)`
gives `[1; 2; 3; 2; 1; 3; 2; 2]`; the set unioned with itself doubles
every count; the set intersected with `[3; 2]` keeps every element
except the lone `1`.
