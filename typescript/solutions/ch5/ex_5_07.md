# Exercise 5.7: the designed machines run on the real simulator

The two controllers designed by hand in 5.4 become ordinary data here:
`exptRecursiveController` and `exptIterativeController` are line-for-line
transcriptions of the 5.4 solutions into the controller language, the
register-machine instructions of 5.1 as data. Each run builds a fresh
machine with `makeMachine`, sets `b` and `n`, starts, and reads the answer
register (`val` for the recursive machine, `product` for the iterative
one), so no register carries over between runs.

Every simulated run is paired with `hostExpt`, the same repeated
multiplication done by the host, and the test pins the four pairing
lines: both machines answer 1024 for expt(2, 10) and 243 for expt(3, 5),
each equal to its oracle. A machine run is correct exactly when its
answer equals the host's, which is the only correctness notion the
simulator supports.

The file also builds the book's own example machine of 5.2 once:
`gcdMachine` from `gcdController`, the 5.1.1 reduction step. The later
exercises of the section (5.12, 5.13, 5.15 to 5.19) reuse this
controller unchanged, 5.10 transcribes it into the new syntax of
exercise 5.10, and 5.19 sets its breakpoints on it, so the test pins
the shared machine directly: gcd(206, 40) answers 2.
