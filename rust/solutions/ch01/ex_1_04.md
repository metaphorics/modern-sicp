# Exercise 1.4: `a + |b|`, built by letting a branch choose the operator

## Why this is an `A` exercise in this edition

The exercise asks a conditional to select addition or subtraction.
Rust's built-in `+` and `-` are syntax resolved to trait methods at
compile time, not first-class values a variable can hold. The Rust
adaptation therefore gives the two operations names and chooses between
function pointers of type `fn(i64, i64) -> i64`:

```rust
pub fn add(a: i64, b: i64) -> i64 { a + b }
pub fn sub(a: i64, b: i64) -> i64 { a - b }

pub fn a_plus_abs_b(a: i64, b: i64) -> i64 {
    let op: fn(i64, i64) -> i64 = if b > 0 { add } else { sub };
    op(a, b)
}
```

## Why `sub`, not a second `add`

`a - b` is `a + (-b)`, so choosing `sub` for a non-positive `b` computes
`a + |b|` exactly the same way `add` does for a positive `b`; the two
branches are genuinely the same procedure shape, `a @ b`, with `@` chosen
by the sign of `b`, matching the book's `+`/`-` choice one for one.

## Test

`a_plus_abs_b(1, 5) == 6` (`b` positive, uses `add`), `a_plus_abs_b(1, -5)
== 6` (`b` negative, uses `sub`, `1 - (-5) = 6`), and the boundary
`a_plus_abs_b(2, 0) == 2` (`b` is not greater than 0, so `sub` runs:
`2 - 0 = 2`, the same answer `add` would have given here).
