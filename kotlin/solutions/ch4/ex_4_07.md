# Exercise 4.7: let* as nested lets

## Approach

`WithLetStar` adds one clause on the `step` seam for the application the
parser leaves for `let*`, and [letStarToNestedLets] folds the bindings
right to left: `(let* ((x 3) (y (+ x 1))) (* x y))` becomes
`(let ((x 3)) (let ((y (+ x 1))) (* x y)))`, pinned structurally. Adding
the one clause is sufficient, and the seam makes that literally true: each
derived `let` re-enters `step`, so a `let*` inside another's body is
handled with no extra code (pinned), and each init sees the earlier
bindings of the same `let*`: with `x` bound to 9 outside,
`(let* ((x 1) (y x)) y)` is 1, the shadowing-from-the-first-binding-on rule
that distinguishes `let*` from `let`.

## Map class

`T`.

## Deviation

None. The parsed form arrives as the application chain the parser
documents, so the bindings are recovered from the application shapes
`(name init)`.

## Answer

The book's shape: `(let* ((x 3) (y (+ x 1))) (* x y))` => 12.
Sequential visibility: `(let* ((x 2) (y (* x x)) (z (* y x))) z)` => 8;
shadowing probe => 1; nested `let*` in another's body => 2.
