# Exercise 4.14a: the host sort as a primitive (this edition's addition)

The map class is `T`. This edition adds 4.14a because 4.14 raises a
question its `map` story answers only halfway: does the host boundary
care which higher-order primitive carries it? The host `sort` repeats
the 4.14 mechanism with a comparator instead of a mapping argument. A
primitive comparator such as `<` resolves through the evaluator's
table and sorts; a compound comparator answers the typed error. An
object-language insertion sort, defined through the evaluator, takes
the same compound comparator and sorts with it, because the evaluator
applies the comparator at every comparison.

The design choice to record: the host's typing, not malice, excludes
compound procedures from host higher-order primitives: the primitive
protocol hands over dead values and no `apply` ships with them, so
the failure is the boundary's typed error, not a crash.

Sample: `ex_4_14a ()` answers
`["(1 2 3)"; "Error: type error: sort: the comparator argument is not a primitive procedure"; "(3 2 1)"]`.
