# Exercise 3.38 — enumerate interleaved balance outcomes (translate)

The map class is `T`: the exercise's three commands — Peter's +10,
Paul's -20, Mary's halving — translate into a `process` record whose
`read_write` field is the one `int -> int` the book's `set!` lines
express. Sequential orders are the six permutations folded over the
opening 100. Interleaved orders enumerate every merge of the three
per-process read/write event pairs that keeps each pair in order, and
run each merge against a read table, so a process writes the value it
actually read — the timing-diagram mechanics, made executable. The
live sampler runs real `Domain.spawn`ed processes, but the suite only
asks that its batch land inside the enumerated set, since no single
schedule is entitled to happen.

Sample: `ex_3_38 ()` answers the sequential set
`[35; 40; 45; 50]`, the interleaved set
`[30; 35; 40; 45; 50; 55; 60; 80; 90; 110]`, and one live batch that
always sits inside the second list.
