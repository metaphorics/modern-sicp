# Exercise 4.27: lazy id with a counter (translate)

The map class is `T`. The subset has no assignment to a variable, so
`count` is a reference and `id` is `let id x = count := !count + 1; x`.
The experiment's top level forces every binding, which would hide the
text's unforced `define`; the interaction therefore keeps
`id (id 10)` in a tuple component, the one place the experiment stores
the value an expression evaluates to without forcing it, exactly as the
text's `define` binds `w`.

Evaluating `id (id 10)` applies the outer `id` at once: the assignment
runs through strict primitives, `count` becomes 1, and the body's last
expression `x` is evaluated, not forced, so the component holds the
thunk of `id 10`. The first response is therefore 1. Asking for `w`
drives the forcing: the thunk's body applies the inner `id`, whose
assignment advances `count` to 2 and whose result 10 fills the memo
cell, so the second response is 10 and the third is 2. Printing `w` and
`count` again adds nothing: the memoized thunk answers from its cell
without re-running, which the experiment's counts confirm with one memo
hit.
