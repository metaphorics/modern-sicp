# Exercise 3.32: why a segment's actions run in order

## Approach

The book asks why the agenda's per-segment queue must be
first-in-first-out, using the and-gate whose inputs move from
`(0, 1)` to `(1, 0)` inside one segment: both input changes schedule
an output update into the same later segment. The Rust solution
compares the section's FIFO `Agenda` with a stack-based agenda. The FIFO
agenda settles the gate at its final inputs, output 0. The stack agenda
runs the updates in reverse: the update based on stale inputs `(1, 1)`
runs after the update based on the correct reading `(1, 0)`, so output 1
overwrites the correct output. The solution reports the stack-agenda
answer, and the tests pin both outcomes.

## Map class

`T`. The scenario, the ordering question, and the two outcomes are
the statement's own; the LIFO agenda exists only to run the
comparison the question poses.

## Deviation

The LIFO agenda is an instrument built for the demonstration; the
section's own `Agenda` is untouched and remains FIFO.
