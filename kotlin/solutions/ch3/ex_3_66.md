# Exercise 3.66: the order of pairs

## Approach

The walk (`positionOf`) follows `pairs(integers, integers)` from the
front, counting elements until it reaches the pair asked about, and
returns that count as a 0-based index (the number of pairs preceding the
target; the 1-based position is the index plus 1). The walk gives up
after 65536 elements and returns null, which no walked pin exceeds. The
order laws, derived from the recursion (level `k` opens at `2^k - 2`,
first-row elements fill the alternating gaps, so row `i` starts at
`2^(i-1) - 2` and steps by `2^i` per column):

- `(1, j)` at index `2j - 3`, so (1, 100) is preceded by 197 pairs (the
  statement asks "approximately", the stream's exact answer);
- the diagonal `(k, k)` at index `2^k - 2`, so (100, 100) is preceded by
  `2^100 - 2` pairs;
- the upper triangle `(i, j)` with `1 < i < j` at index
  `2^i (j - i) + 2^(i-1) - 2`, so (99, 100) is preceded by
  `2^99 + 2^98 - 2 = 950737950171172051122527404030` pairs, far past any
  walk and asserted from the law with `BigInteger`.

The tests pin the walked indices (1, 2) 1, (2, 2) 2, (3, 3) 6, (2, 6) 16,
(1, 100) 197, re-derive each law for j up to 40, k up to 16, check every
element of a 2000-element prefix against the laws, and assert the
(99, 100) BigInteger value and the null results for a pair past the walk
limit and for `(2, 1)`, which the `i <= j` stream never contains.

Independent check: a python3 simulation of the same cons/interleave law
(matching two independent engines, memoized cons cells and generators)
confirmed every pinned index, the whole 2000-element prefix against the
formulas, and the value `2^99 + 2^98 - 2 = 950737950171172051122527404030`.
