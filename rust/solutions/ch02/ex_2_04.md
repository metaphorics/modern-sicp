# Exercise 2.4: an alternative procedural representation of pairs

## Approach

The book's version, `(define (cons x y) (lambda (m) (m x y)))`, hands the
pair's two parts to a caller-supplied selector. In Scheme the selector's
result type is unconstrained; in Rust a closure's return type is fixed
once, at its own definition, so the same trick cannot be spelled as one
literal closure that both `car` and `cdr` call with different selectors
returning different types. The solution keeps the message-passing shape
but as a generic method: `Cons<A, B>::apply<R>(&self, selector: impl
FnOnce(&A, &B) -> R) -> R`. `car` calls `apply` with `|p, _q| p.clone()`
and `cdr` with `|_p, q| q.clone()`, exactly mirroring
`car(z) = z(lambda (p q) p)` and the analogous definition for `cdr`.
`Cons`'s fields stay private, so `apply` (and therefore the selector
closure) is still the only way to reach `x` or `y`, matching the book's
point that this representation carries no data structure a caller can
inspect directly.

## Map class

`A`: the idea survives (a pair as pure dispatch, no data structure), but
