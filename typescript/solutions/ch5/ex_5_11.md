# Exercise 5.11: the three save and restore disciplines

The book's three readings of `restore` are all implemented as assembler
options over the same simulator, not as three simulators: the
`saveRestore` seam lets one builder replace the standard save and
restore execution procedures while every other instruction keeps the
standard builder.

- Discipline (a), the standard name-blind pop: the out-of-order sequence
  `save y`, `save x`, `restore y` leaves 2 in `y`, the `x` value that was
  saved last.
- Discipline (b), the checking stack: each cell is tagged with the
  register it was saved from, so the same sequence raises the typed
  `RestoreMismatch`, rendered "restore y but the stack holds x".
- Discipline (c), one stack per register: `restore y` pops from `y`'s own
  stack, so the same sequence answers 1, and interleaved saves of other
  registers never disturb it.

All three run the figure 5.12 Fibonacci controller and answer fib(3) = 2,
so the disciplines differ only on the sequences the book distinguishes
them by. Part (a)'s elimination: because `(restore n)` at `afterfib-n-2`
pops the same slot `(restore val)` would, the pair `(assign n (reg val))`,
`(restore val)` collapses to one `(restore n)`, and the name-blind
controller answers fib(3) = 2 and fib(5) = 5. Under the checking
discipline the same controller is refused with "restore n but the stack
holds val", which is exactly the pairing the elimination exploits.
