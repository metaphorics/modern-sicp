# Exercise 4.18: the alternative scan-out strategy

## Approach

Two scans are implemented over one shared complete dispatch: the text's
scan runs the set!s in order; the alternative computes every value
expression in one inner let before any set! runs, then assigns the results
into the `*unassigned*` pre-bindings. A program whose value expression
reads a sibling separates them: the read lands before the sibling's set!
under the alternative and fails on the `*unassigned*` guard, while the
text's scan has already assigned it. A program whose sibling read is
deferred through a closure defined earlier, and only called in the body,
never reads during the defines, so both scans agree.

## Numbers

`(define (g) (define a 1) (define b (+ a 1)) b)` then `(g)`: `2` under the
text's scan; a `RuntimeError` ("variable used before assignment: a") under
the alternative. `(define (h) (define (get) b) (define b 5) (get))` then
`(h)`: `5` under both scans. For the book's solve, dy's value expression
`(stream-map f y)` reads y's first element during the defines, so the
alternative fails exactly as the sibling-reader does, while the text's
`set! y` has run by then.

## Class and deviations

Translated row. Deviations: both scans emit lambda applications instead of
`let` expressions, since the evaluator has no let clause; the alternative's
fresh names are spelled `%value-1`, `%value-2`, and so on; only leading
defines are scanned; and the dispatch is local for the same nested-body
reason as exercise 4.17.
