# Exercise 4.2: dispatch order and call-prefixed applications (T)

## Approach

`ApplicationsFirst` runs the application clause before any special-form check:
`(define x 3)` is a pair, so it evaluates the operator `define` and fails with
`unbound variable: define` -- the flaw Louis missed. `CallSyntax` then changes
the syntax: pairs tagged `call` are applications, the special forms still
dispatch, and any other pair is a syntax error. The call-prefixed factorial
runs: `(call factorial 5)` is 120, bare `(factorial 5)` is rejected.

## Map class

`T`: the statement translates whole; both parts run on the seam without
touching the base evaluator.

## Sample answer

Part (a): the definition is read as an application of an unbound operator.
Part (b): 120 with `call`-prefixed applications everywhere.
