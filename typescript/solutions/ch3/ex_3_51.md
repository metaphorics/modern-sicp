# Exercise 3.51: show reveals memoized delay timing

## Approach

The book's `show` prints and returns its argument; this edition appends
the rendered line to a caller-supplied transcript array, so the printed
transcript is data the tests can pin. `makeX` maps `show` over the
interval 0 through 10. The sequence the exercise asks about runs over
one shared `x` in `ex351`: the definition, `(stream-ref x 5)`,
`(stream-ref x 7)`. A second builder, `makeUnmemoizedX`, spells the
delay as a plain thunk without the section's `memo-proc`, so the same
sequence can be run against the counterfactual the timing depends on.

## Pins

Computed by running. The definition computes only the map's first cell,
so the transcript holds `0`: `cons-stream`'s car is eager even though
its tail is delayed. `(stream-ref x 5)` walks cells 0 through 5 and the
transcript grows to `0 1 2 3 4 5`, answering 5. `(stream-ref x 7)`
finds every walked cell memoized and announces exactly the two new
cells, `6 7`, answering 7. Without memoization the same second ref
rebuilds every cell it passes: the transcript then reads `0 1 2 3 4 5
6 7 0 1 2 3 4 5 6 7`, the whole prefix announced twice.

## Map class

T (translate: syntax changes only). The book's transcript becomes the
edition's transcript array, which is the same events; the memoized
answers are the canonical ones from the section's `memo-proc` delay.

## Deviation

None of substance. The book prints; the edition records the same lines
in an array so the answer is executable rather than quoted.
