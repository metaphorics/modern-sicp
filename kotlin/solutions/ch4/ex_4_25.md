# Exercise 4.25: `unless` under delayed arguments

## Approach

The lazy evaluator makes the statement's `unless` an ordinary procedure
whose condition is forced only when the body's `if` demands it and whose
two arms are thunks. `factorial` therefore bottoms out: `(factorial 5)`
enters `unless` with the product arm still uncomputed, the guard
`(= n 1)` forces at the `if`, and at `n = 1` the exceptional arm answers 1
while the product arm is discarded.

The strict contrast runs on the base evaluator. The armed call pins the
definition of strictness directly: `(unless (= 1 1) (/ 1 0) 42)` evaluates
its operands left to right, so `(/ 1 0)` raises before the call happens
and `42` is never reached. The recursion pins the consequence: the product
arm `(* n (factorial (- n 1)))` evaluates on every entry, so the descent
never reaches the guard. An unbounded strict run is a hang, not evidence,
so it runs on the 4.15 budgeted evaluator (`Bounded`, 200 steps) and dies
with the typed machine fault.

## Map class

`T` unchanged: the row builds the book's unless/factorial argument; the
budgeted strict run replaces only the hang an honest host cannot show.
