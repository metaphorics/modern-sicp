# Exercise 3.45: double serialization deadlocks (translate)

The map class is `T`. Louis routes the account's own withdraw and
deposit through the very serializer the account exports, and then
`serialized-exchange` wraps the whole exchange in that serializer
again. The exchange body asks a domain to acquire a mutex the same
domain already holds, which no host can grant. The solution separates
the two halves of the fact: `inner_acquire_is_impossible` shows the
runtime refuses the re-acquisition of a held mutex, and
`exchange_stalls` runs Louis's exchange on a spawned domain and
reports that it never completes. On this host the collision surfaces
immediately as the runtime's deadlock error, which the worker reports
as the failed exchange. Both verdicts are deterministic.
