# Exercise 1.15

`p` is applied 5 times: `sine(12.15)` reduces the angle by a factor of 3 at
each application, `12.15, 4.05, 1.35, 0.45, 0.15, 0.05`, and stops
reducing once the magnitude is at most 0.1, which first happens at 0.05.
Five divisions separate 12.15 from that base case, so `p` runs 5 times on
the way back up.

Each application divides the angle by 3, so the number of applications
needed for an angle `a` grows as `log_3(a)`, and by the properties of
logarithms that is `Theta(log a)` in any base. Since each level's state is
just the one pending multiplication `p` performs on its way back up, the
space needed grows the same way, `Theta(log a)`. The identity `sin(x) = 3
sin(x/3) - 4 sin^3(x/3)` is exact, so the only approximation error comes
from treating `sin(0.05)` as `0.05` at the base case; that error is small
but not negligible once it propagates up through five applications of `p`,
which is why the test checks `sine(12.15)` against `f64::sin` with a
tolerance of `1e-2` rather than machine precision. The map class is `T`.
