# Exercise 4.28: forcing the operator

## Approach

`force(delay(add))(2, 3)` is the demonstration: the operator position
holds a thunk whose expression is the operator, so the application must
take the actual value of the operator before apply can dispatch, and
the forced call answers `5`. The negation proves the point: leaving the
operator unforced hands the thunk itself to apply, which answers the
typed `not-callable` fault instead of dispatching.

## Numbers

Forced: `5`. Unforced variant: `error:not-callable`, the thunk rendered
as `#[thunk]` in the engine's neutral display.

## Class and deviations

Translated row. Deviation: the old failure text `not a procedure:
#[thunk]` migrates to the engine's `not-callable` fault category, with
the same `#[thunk]` rendering preserved in the display; the variant is
otherwise the same one-clause contrast.
