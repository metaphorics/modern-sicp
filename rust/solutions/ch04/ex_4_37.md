# Exercise 4.37: Ben's triple generator efficiency (T)

## Approach

Ben is right. Both generators answer the same first triple `(3 4 5)`
over the bounds 1 to 20, but Ben's `sqrt` filter rejects each candidate
`(i, j)` immediately -- the test's session defines `isqrt`, an exact
integer square root, so the port keeps the book's `(require (integer?
(sqrt ksq)))` shape as `(require (= ksq (* k k)))` -- where the 4.35
order walks a third choice point over every `k` below the hypotenuse.
The comparison uses the engine's failure counter, counting one Fail
delivery per failed alternative replay and one per choice-frame
exhaustion, over identical bounds and identical definition order.

## Map class

`T`.

## Sample answer

Both answer `(3 4 5)` first. Fail deliveries over the same bounds:
1836 for the 4.35 order against 162 for Ben's -- an order of magnitude
less search.
