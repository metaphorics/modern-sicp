# Exercise 4.39: restriction order effects (T)

## Approach

In the book's procedure every restriction follows every choice, so the
order of the `require`s changes neither the answer nor the work: the
search tree has the same shape whichever restriction rejects a branch
first, and the same assignments are rejected at the same depth. The
test demonstrates this by measuring both orders with the engine's
failure counter (one Fail delivery per failed alternative replay plus
one per frame exhaustion): the counts are identical. Reordering pays
only when restrictions interleave with choices, which is exercise
4.40's pruning.

## Map class

`T`.

## Sample answer

Both orders answer `((baker 3) (cooper 2) (fletcher 4) (miller 5)
(smith 1))` and deliver exactly 3670 Fail deliveries to the choice
frames. The reordering cannot beat the original until restrictions
move between the `amb`s.
