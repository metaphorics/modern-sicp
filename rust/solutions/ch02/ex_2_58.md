# Exercise 2.58: infix notation

## Approach

Since the section's `Expr` is a closed enum rather than raw list
structure, "changing the predicates, selectors, and constructors" for
a new concrete syntax means writing a small parser that builds `Expr`
values by calling the library's existing `make_sum`/`make_product`;
`deriv` itself needs no change at all. Part a parses fully
parenthesized infix (`"(" expr op expr ")"`, no precedence needed
because every operation is explicitly grouped). Part b parses ordinary
infix with the standard grammar (`expr := term ("+" term)*`,
`term := factor ("*" factor)*`), giving `*` higher precedence than `+`
and dropping unnecessary parentheses. Both parses of
`x + 3 * (x + y + 2)` (parenthesized and bare) produce structurally
equivalent expressions, and both differentiate to `4`.

## Map class

`A`: infix parsing changes the expression constructors, matching the
map's Rust class for this row.
