# Exercise 4.51: permanent_set (translate)

`permanent_set` is a clause added to the search evaluator by open
recursion. It evaluates the new value and writes it into the named
top-level reference through `Sec_4_3.permanent_assign`, the
experiment's permanent store. That write survives backtracking, while
the plain `:=` is rolled back with its branch.

The experiment searches to exhaustion, so the demonstration shows every
answer instead of the book's first two. With `permanent_set` the count
records every trial so far: `(a b 2)`, where the rejected `x = a, y = a`
trial is counted, then `(a c 3) (b a 4) (b c 6) (c a 7) (c b 8)`. The
book's question has the answer the `:=` run shows: every answer reports
1, because each rejected trial's increment is undone before the next
alternative runs.

The permanent store holds named top-level references, so the guest's
`count` is a top-level `ref`.
