## Exercise 0.4: parseAmount as Raise<ParseError>

Approach: the error set is a sealed interface with one variant per failure
mode, and the parser is a `context(r: Raise<ParseError>)` function whose
guard clauses call `r.raise`; `raise` returns `Nothing`, so the happy path
needs no `else`. The driver wraps calls in `either { }`, where the context
argument resolves from the block's `Raise` receiver. The test drives both
branches and also pins the contrast: the kept-for-comparison
`parseAmountEager` throws an `IllegalArgumentException` where the Raise
version returns `Either.Left`.

Class: companion-added exercise (idiom-kotlin.md, Section 5, list item 0.4);
no map row. Deviation: the companion pins context parameters behind
`-Xexplicit-context-arguments`; on the pinned Kotlin 2.4.20 they are stable
and resolve implicitly, so the edition builds with no flag and no `@OptIn`.
The scaffold passes the `Raise` explicitly only where the runtime's own
code does.
