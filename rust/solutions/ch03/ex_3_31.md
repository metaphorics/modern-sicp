# Exercise 3.31: why the immediate run matters

## Approach

The book asks what would go wrong if `add-action!` did not run each
new action once immediately. The Rust solution answers it by
running the same scenario twice over an and-gate whose inputs are
already set to 1: once with the section's immediate run, once with
`add_action_deferred`, the variant that only attaches. Propagating
each agenda answers 1 and 0: the immediate run computes the standing
inputs at attach time and raises the output, while the deferred
variant sits at 0 forever, since no input ever changes to wake it. A
second test shows the probe half of the same story: with the
immediate run the probe reports the wire's starting value, and
deferred, it stays silent.

## Map class

`T`. The exercise is a question about the text's own `add-action!`
and translates by implementing both variants and comparing them.

## Deviation

None. The already-set-inputs scenario is the heart of the book's
own answer, and both observed symptoms, the never-computed output
and the unreported initial value, are the statement's question.
