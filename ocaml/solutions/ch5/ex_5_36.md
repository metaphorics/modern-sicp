Exercise 5.36: operand evaluation order, measured.

The compiler evaluates operands right to left: `construct-arglist`
reverses the operand codes so the last operand initializes `argl` and
each earlier operand conses onto it. The order is decided in that one
`reverse`; the `left_to_right` configuration turns it off. The
observable order is pinned with a recording `list` operation: the
default compilation of `(list (record 1) (record 2))` records `2 1`,
the reordered one records `1 2`. The efficiency answer is measured,
not argued: both orders emit the same number of instructions (one
`list`, one `cons` per additional operand, the same preserves), so
the code size is unaffected by the choice.
