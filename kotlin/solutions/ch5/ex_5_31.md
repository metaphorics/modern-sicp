# Exercise 5.31: saves in procedure applications

The compiler's `preserving` analysis saves a register only when the first
instruction sequence changes it and the following sequence needs its old
value. Exercise 5.31 asks which saves remain for four combinations.

Compiling `(f 'x 'y)` needs no saves: the operator and operands are
lookups or constants, so their sequences do not clobber registers needed
later. For `((f) 'x 'y)`, the operator is itself an application. Its
execution may change `continue`, which the enclosing application needs,
so `continue` is saved and restored. In `(f (g 'x) y)` and
`(f (g 'x) 'y)`, evaluating `(g 'x)` may clobber both `proc` and
`argl`; the compiler preserves them, along with `continue`. The constant
last operand in the fourth case does not alter this register analysis.

`superfluousSaves()` compiles each expression with the real compiler and
the test pins the emitted saves and restores in order. This answers the
exercise from the generated instruction sequences rather than from a
separate model of register use.
