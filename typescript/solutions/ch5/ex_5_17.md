# Exercise 5.17: labels in the trace

The label-aware tracing machine keeps the label currently in effect,
the most recently passed label definition, and prints it ahead of each
traced instruction, so the trace reads like the controller listing.
The assembler supplies it: at install time the machine derives
the label-in-effect array from its own label table, and the trace hook
reads the entry at the program counter, so the book's warning about not
interfering with instruction counting is answered structurally: both
are the same hook, and neither changes what executes.

The test pins the gcd(206, 40) run at 26 lines, every one prefixed
`test-b`: the loop instructions are under the loop's label, and the
final taken branch is still `test-b` because the machine halts on
reaching `gcd-done` and never executes an instruction under it. The
empty filter for `gcd-done:` lines is that fact's direct pin.
