# Exercise 4.17 — the extra frame of the scanned-out let (translate)

The map class is `T`. The statement asks for the two environment
structures at `<e3>`; this edition makes the difference observable by
counting frames live: a local copy of the standard dispatch routes
every frame creation through one counting extend, and the global frame
costs nothing because defines build it. Under sequential definitions
`<e3>` runs in the parameter frame alone, count 1; the scan-out lowers
the body to a let whose application pushes a second frame, count 2.
Behavior is unaffected because each define still lands where the body
finds it: `set!` rebinds the reserved name whether the frame is the
parameter frame or the let frame, and lookups search that frame first
either way. The frame is avoidable the way the book's note suggests:
reserve the defined names directly in the parameter frame at
application time, and the simultaneous scope costs one frame, the same
as the sequential rule.

Sample: `ex_4_17 ()` answers `["1"; "2"]`.
