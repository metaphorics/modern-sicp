# Exercise 4.14: two maps, two fates

## Approach

Louis installs the host's Array.prototype.map as a primitive. Like the book's
apply-primitive-procedure, his wrapper hands the host the procedure's
underlying implementation: a primitive offers a real host function, which
Array.prototype.map calls per element. An evaluator closure object offers
nothing callable, so the host call itself throws the TypeError the book
predicts, caught at the primitive boundary and surfaced as a RuntimeError.
Eva Lu Ator instead types the definition of map into the object language, a
recursive compound procedure whose per-element call `(p (car x))` goes
through the evaluator's own apply. Both environments are built and both
calls are run in each.

## Numbers

Louis: `(map car '((1 2) (3 4)))` answers `(1 3)`, but
`(map (lambda (p) p) '((9)))` fails with RuntimeError carrying the message
"map: the host could not call this procedure" and the host's own complaint in
the detail. Eva: `(map car '((1 2) (3 4)))` answers `(1 3)`,
`(map (lambda (n) (* n n)) '(1 2 3))` answers `(1 4 9)`, and
`(map (lambda (p) p) '((9)))`, the call that killed Louis's map, answers
`((9))`.

## Class and deviations

Translated row. Deviations: in the book the failing call dies with the
underlying Lisp's error text; this edition never throws across the evaluator
boundary, so the host TypeError is caught in the wrapper and re-surfaced as a
RuntimeError on the evaluator's error channel. Eva's map returns `'()` at the
end of the list, exactly as her typed-in definition reads.
