# Exercise 4.32: chapter 3 streams versus lazy lists (translate)

The map class is `T`. The difference the statement asks for is the
laziness of the element: a chapter 3 stream evaluates its element at
construction time and delays only the tail, while under the lazy
experiment the program's own `cons` (`let cons x y = x :: y`) is a
compound procedure, so it delays both operands and no element of a
lazy list is produced until something forces it. The demonstration
arms the skipped element with a division by zero:
`head_or 0 (tail (cons (1 / 0) (cons 42 [])))` answers 42 under the
lazy experiment, because the first element is never produced. The
same construction as a chapter 3 stream under the strict core
(`type 'a stream = Empty | Cons of 'a * (unit -> 'a stream)`) dies in
the division before the stream exists. The armed tail of
`cons 7 [1 / 0]` is skipped just as freely, which is the advantage the
extra laziness buys: an element costs nothing unless it is actually
needed, so delayed versions of general structures, such as lazy trees,
fall out of the same non-strict `cons`.

Sample: `ex_4_32 ()` answers the lazy transcript beginning `"42\n"`,
`"error: division by zero"`, and the lazy transcript beginning `"7\n"`.
