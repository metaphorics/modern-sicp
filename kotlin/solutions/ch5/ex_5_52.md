# Exercise 5.52: the compiler emits C

The exercise's emitter translates the compiler's typed instruction
sequence into C statements: machine registers become C globals,
instruction labels become C labels (procedure and method entries are
registered by label address), and operations call the C support layer
keyed to the compiler's `compiled-*` vocabulary. `runtimeC` implements
that whole vocabulary: environments and lexical addresses, procedure
entries and captured closures, class and object construction, methods,
lists, pairs, maps, the collection carrier of `map`/`filter`/`fold`/
`any`/`all`, type tests, arithmetic with the host's wrapping and
division rules, `Double.toString` rendering, and output. A guest error
leaves the C process with status 1 and its category on stderr; a request
outside the admitted library surface leaves with status 3 and a
`C backend fault:` line rather than a fabricated result.

`compiledCAgreement` builds the emitted program with `cc -O1`, runs it,
and compares its output and error category with the direct engine, the
explicit-control evaluator, and the compiled machine. It is pinned for
an erroring probe (`DivisionByZero`), a structured probe (sealed data
classes, a data object, a method, a closure over a `var`, a mutable map,
collections, destructuring, a set of pairs), and the canonical
self-interpreter of exercise 5.50, which prints 120 in all four runs.
`compiledCRuns` keeps the single-program run of the factorial probe.

`CBackend.emitProgram` is a separate, complete reference C artifact
with closure entry and its own `main`. `compiledCVerdicts` compiles
and executes that reference artifact for comparison as well as
reporting structural properties of the exercise's emitted code.
The exercise's emitter and the reference backend are deliberately
not presented as the same implementation.
