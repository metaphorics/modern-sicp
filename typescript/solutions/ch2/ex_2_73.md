# Exercise 2.73: data-directed deriv

## Approach

The section 2.3.2 `deriv` is rebuilt so the dispatch lives in the
section's operation-and-type table: each differentiation rule is
installed under the key `(deriv (operator))`, where the expression
union's operator (`+`, `*`, and the `**` added here) plays the
book's type tag. The constant and variable shapes stay residual arms
outside the table, which is part (a)'s answer: the table is indexed by
the operator that binds a compound expression, and a number or a
variable has no operator to index by, so there is no entry for them to
be assimilated into. Part (b) installs the sum and product rules
against the simplifying constructors the section ended with; part (c)
installs the exponentiation rule of exercise 2.56 as one more `put`;
part (d) re-indexes the same rules with the axes swapped, operator
first and the operation name as the tag, and gets identical answers
from the identical rule values: only the index changed.

## Numbers

The asserted derivatives (printed by the section's prefix convention):
`d(x)/dx = 1`; `d(3 + y)/dx = 1` when the sum is `(x + 3)`, and
`d(y)/dx = 0` for the variable alone; `d(x * y)/dx = y`; part (b)'s
simplification shows `d(3 * x^2)/dx = (* 3 (* 2 (** x 1)))`; part (c)
gives `d(x^3)/dx = (* 3 (** x 2))`; a ruleless operator (here `x^x`,
whose symbolic exponent the rule does not cover) answers the book's
error `unknown expression type: DERIV **`. The flipped table of part
(d) answers `1`, `y`, and `(* 3 (** x 2))` for the same questions.

## Map class

A (discriminated union replaces type tags): the union's `_tag` plays
the type tag, and the table keys the operator it carries.

## Deviation

None. The rust edition's part (c) chose the `atan` rule; this edition
follows the book's own suggestion, the exponentiation rule of exercise
2.56.
