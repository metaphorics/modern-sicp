# Exercise 4.9: while and for as derived expressions

## Approach

Iteration belongs in the evaluator, not in the programmer's discipline. `while`
and `for` are derived expressions: at evaluation time each expands into a core
language combination that binds a freshly named cell, installs in it a loop
procedure, and calls it. The loop's recursive call is an ordinary application,
so termination needs no new machinery and no escape through make-procedure or
the host's apply. `for` evaluates its bounds once (the limit is bound before
the loop cell) and walks the variable inclusively; the loop's value is the
empty list. The dispatch here is complete, mirroring the module's `evaluate`
with the two new clauses first, so the constructs work inside lambda bodies,
which the tally test exercises.

## Numbers

`(for (n 1 5) ...)` accumulating into total answers 15, and the manual
recursion `(sum-to 5)` also answers 15. A top-level while summing 1 through 4
answers 10, and the same while nested in `(tally 5)`'s body answers 10. A
while with a false predicate leaves `ran` at 0 and itself evaluates to `()`.
`(for (n 3 3) ...)` runs its body once and answers 3, pinning the inclusive
bound.

## Class and deviations

Translated row. Deviations: the loop's value is the empty list (the statement
leaves it open); the false branch of the derived if is `'()` because a bare
empty list is not an expression in this edition; and the inclusive bound is
written `(< v (+ limit 1))` because the edition's primitive table ships `<`
but no `<=`. Loop cells get generated names like `while-loop:3`, so nested
loops cannot capture each other.
