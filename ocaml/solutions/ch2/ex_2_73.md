# Exercise 2.73: data-directed differentiation (adapt)

The map class is `A`: OCaml's variant types replace the book's type
tags and per-operation dispatch tables. `expr` gains a `Compound of
string * expr list` case beside `Const` and `Var`; the operator
string plays the role the book's tagged list's `car` plays, and
`operands` its `cdr`. Installing a rule means one `Hashtbl.replace`
into a `(string, deriv_rule) Hashtbl.t`; `deriv` never grows a new
`match` arm when a rule is added.

**Part (a).** `number?` and `variable?` (here, matching `Const` and
`Var`) cannot be assimilated into the table because they carry no
operator to key a lookup on. A `Compound` names an operator applied
to operands; `Const 5` and `Var "x"` are not applications of
anything: they are the base cases a recursive `deriv` bottoms out
at, prior to any dispatch. This holds in OCaml exactly as it holds
in Scheme: the table dispatches on structure a leaf does not have.

**Part (b).** `install_sum_rule` and `install_product_rule` install
the two rules the book's `deriv-sum` and `deriv-product` state,
written against the ambient `deriv` function each rule closure
receives as its first argument (so a rule can differentiate its own
operands without a forward reference to a not-yet-defined global,
which OCaml, unlike Scheme's single mutable environment, does not
allow).

**Part (c).** `install_expt_rule` adds Exercise 2.56's power rule,
`d(u^n)/dx = n * u^(n - 1) * du/dx`, for `Compound ("**", [base;
Const n])`. Installing it costs one function; `deriv` and the two
existing rules are untouched, which is the additivity the exercise
is demonstrating.

**Part (d).** Indexing the other way (operator first, operation
second) is exactly what `Data_directed.install_rectangular_package`
does in the main text: each operator would own a small table of its
own operations (`deriv`, and later perhaps `simplify` or `pretty`),
and a new operator would mean installing one such table rather than
adding one row to every existing operation's table. The corresponding
change to `deriv` is `get (operator exp) 'deriv` in place of `get
'deriv (operator exp)`, indexing into the operator's own table
under the operation name, instead of into the `deriv` table under
the operator name.

Sample: `ex_2_73 ()` differentiates `x + 3`, `x * y`, and `x**3`, all
with respect to `x`: `(Const 1, Var "y", Compound ("*", [Const 3;
Compound ("**", [Var "x"; Const 2])]))`, i.e. `1`, `y`, and `3 * x^2`.
