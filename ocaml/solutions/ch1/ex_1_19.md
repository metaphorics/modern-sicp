# Exercise 1.19 — logarithmic Fibonacci via T_pq (adapt: 63-bit int overflows fast)

The map class is `A`: this edition's `int` is a signed 63-bit value, so
the derivation is the book's but the honest bound is new.

**Deriving p' and q'.** `T_pq` sends `(a, b)` to `(bq + aq + ap, bp +
aq)`. Applying it twice, writing `(a1, b1)` for the result of the first
application:

    a1 = bq + aq + ap
    b1 = bp + aq

    a2 = b1*q + a1*q + a1*p
       = (bp + aq)q + (bq + aq + ap)q + (bq + aq + ap)p
       = bpq + aq^2 + bq^2 + aq^2 + apq + bpq + apq + ap^2
       = b(2pq + q^2) + a(2pq + q^2) + a(p^2 + q^2)
       = b(2pq + q^2) + a(2pq + q^2) + a(p^2 + q^2)

    b2 = b1*p + a1*q
       = (bp + aq)p + (bq + aq + ap)q
       = bp^2 + apq + bq^2 + aq^2 + apq
       = b(p^2 + q^2) + a(2pq + q^2)

Matching `a2 = bq' + aq' + ap'` and `b2 = bp' + aq'` against these
gives `p' = p^2 + q^2` and `q' = 2pq + q^2`: applying `T_pq` twice equals
one application of `T_p'q'`. This is exactly the invariant technique of
exercise 1.16 applied to a 2x2 transformation instead of a scalar power,
so `T^n` computes by successive squaring in `Theta(log n)` steps.

**The bound.** `fib_iter_log` carries `a`, `b`, `p`, `q` in plain `int`,
63 bits, maximum `2^62 - 1` = 4,611,686,018,427,387,903. `fib 90` is
2,880,067,194,370,816,120, under the bound. `fib 91` needs
4,660,046,610,375,530,309, over it; OCaml's `int` arithmetic wraps
silently rather than raising, so `ex_1_19 91` returns
-4,563,325,426,479,245,499 — negative, which no true Fibonacci number can
be, and the surest sign of the wrap without knowing the exact true value
by heart. `ex_1_19 92` similarly wraps.

Interestingly, the linear iterative `fib_iter` of @ref{1.2.2} and this
logarithmic `fib_iter_log` wrap to the *same* wrong value at 91 and 92:
both live in the same 63-bit ring, and OCaml's `+` and `*` are ring
homomorphisms into it, so two mathematically equal recurrences stay
equal after wrapping. Agreement between two implementations cannot catch
this bug; only an independently known correct value (or the sign check
above) can.

The test checks `ex_1_19 n` against the linear `fib_iter` for every `n`
from 0 to 90 and pins `ex_1_19 91`.
