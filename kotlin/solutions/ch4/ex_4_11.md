# Exercise 4.11: frames as association lists

## Lesson

The kernel threads map frames through every call; this exercise
replays the same four environment operations over frames built as
data -- one `(name . value)` pair list per frame, pairs as kernel
`Pair` objects. `define` conses a fresh pair onto the front, `set!`
scans outward and rewrites the nearest pair's value slot, lookup
answers the first hit, and extension checks arity before building.

## Map class

`A` (map row 4.1: frames as data). The representation changes; the
four operations keep their contracts.

## Deviation

None. The alist lives in one cell per kernel frame, so the kernel
chain still carries the nesting.

## Answer

- Define, lookup, outward `set!`: `2`, `10`, `10`.
- A call-frame binding dies with the call: `2`, then failure.
- Arity mismatch still refused.
- Pin: `alistTranscript() == "2\n10\n10\n"`,
  `alistFreshFrameTranscript() == "2\nerror\n"`,
  `alistArityTranscript() == "error\n"`.
