# Exercise 4.1: the two evaluation orders of list-of-values

## Approach

The book asks for both orders because Lisp leaves operand evaluation
unspecified. This host does not: JavaScript evaluates call arguments and
Array operations left to right, so the edition's `listOfValues` is already
the book's no-defer left-to-right version written with cons. The exercise
is reworded accordingly: instead of asking which order the language will
take, it states the host's order and asks for both book-faithful variants,
`listOfValuesLr` and `listOfValuesRl`, written with explicit recursion and
no map, and pins the module's version against them. Operand order is made
observable with an object-language recorder: `(rec tag)` appends the tag
to a global `sequence` list and returns the tag.

## Numbers

Left to right over `((lambda (x y z) (list x y z)) (rec 'a) (rec 'b)
(rec 'c))`: `sequence` is `(a b c)` and the argument list is `(a b c)`.
Right to left: `sequence` is `(c b a)` and the argument list is still
`(a b c)`. The module's `listOfValues`: `sequence` is `(a b c)`, matching
`listOfValuesLr` operand for operand.

## Class and deviations

Adapted row: the premise is reworded. The book leaves the order open; this
edition states the host's left-to-right order and pins the module against
the two variants. Both variants translate the book's code directly; no
other deviation.
