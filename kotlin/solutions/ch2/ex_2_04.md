## Exercise 2.4: procedural cons, car, cdr

Approach: `consFn(x, y)` closes over `x` and `y` and returns a function
that applies whatever selector it is given to the closed-over pair.
`carFn` passes a selector returning its first argument; `cdrFn` is the
same idea, passing a selector returning its second argument instead.
Kotlin needs the closure's type spelled out, `((T, T) -> T) -> T`, where
Scheme's `lambda` needed no annotation at all; that explicit function
type is the hard spot this exercise's class points at. `cdrFn(consFn(3,
4))` is `4`.

Class: A. The idea survives unchanged; the statement gains the explicit
closure type Kotlin's static typing requires. Deviation: named `consFn`,
`carFn`, `cdrFn` rather than `cons`, `car`, `cdr`, because exercises 2.5's
procedural pair and this one would otherwise collide as two incompatible
overloads in the same compiled solutions module.
