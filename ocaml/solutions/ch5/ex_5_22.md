# Exercise 5.22: append and append!

Both machines run over the list-structure memory with the lists
planted in it; the memory dumps the solutions print are the
before/after drawings the book asks for, one column per cell.

**`append`** copies. The controller walks `x` saving the cars and its
own return address, reaches `e0`, answers `z := y`, and on the way
back conses each saved car onto `z`: three fresh cells for
`x = [1; 2; 3]`. Every save is itself a cons onto `the-stack` (5.3.1),
so the walk down costs six more cells. The run shows both: `z = p13`
is `[1; 2; 3; 4; 5]`, `x` still writes `[1; 2; 3]` from the cells it
started with, and `free` moved from `p5` to `p14`, six cells for the
saved words and three for the copy. The result shares `y` but not
`x`.

**`append!`** splices. The controller walks to the last pair of `x`
(the pair whose cdr is `e0`) and performs one `set-cdr!`: the cell at
index 0 in the dump, whose cdr changes from `e0` to `y`'s pointer.
Nothing is allocated: `free` is `p5` before and after. The drawing
memory has eight cells and no collector, so none of them is reserved
for a root strip. There is no `z` register in the book's machine, and
there is none here: the answer is `x` itself, the same pointer the caller passed, now writing
`[1; 2; 3; 4; 5]` through cells that belong to `x` and, for the tail,
cells that belong to `y`.

The before/after dumps are pinned word for word in
`test/ch5/test_sec_5_3.ml`, one cell column apart exactly where the
`set-cdr!` bit the list.
