# Exercise 5.51: the explicit-control evaluator translated to C

The translation is the controller itself: the machine's registers are file-scope variables, every evaluation entry point is a C label, a continue assignment stores a label address, and save and restore are push and pop on the tagged machine stack. The object world is the guest runtime's own: IEEE-754 double numbers, strings, booleans, and the record, array, map, set, and list structs of the exchange format, with no legacy pair or symbol/nil printing.

Input is serialized typed data, never source text and never a second parser: the boundary driver reads the guest program with the shared reader, serializes the typed syntax records, builds the C translation with the system C compiler, and runs it. The same program runs through the direct evaluator, and the C process transcript must equal the direct transcript line for line; the machine-stream mode consumes the typed instruction stream with recursively nested operation calls, the exchange contract of section 6.
