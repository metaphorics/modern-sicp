# Exercise 1.2: write the fraction as pure nested calls

## Why this is an `R` exercise in this edition

The book's exercise is about prefix notation: given an infix mathematical
formula, translate it into Lisp's `(operator operand...)` form, where every
combination nests inside its parent the way the expression tree does. Rust
has no infix-to-prefix translation step to teach, because Rust source *is*
infix arithmetic already; writing `5.0 + 4.0 + ...` would just restate the
original formula and teach nothing about this section. The exercise map
records this section-1.1 exercise as replaced (`R`): the same number stays,
but the task becomes what the exercise is really testing in this book's own
terms, which is the shape of a call tree.

## Approach

Four one-line functions stand in for `+`, `-`, `*`, `/` as ordinary named
procedures rather than operators:

```rust
pub fn add(a: f64, b: f64) -> f64 { a + b }
pub fn sub(a: f64, b: f64) -> f64 { a - b }
pub fn mul(a: f64, b: f64) -> f64 { a * b }
pub fn div(a: f64, b: f64) -> f64 { a / b }
```

The exercise itself is then built out of nothing but calls to these four,
nested exactly the way the book's expression tree nests:

```rust
pub fn ex_1_02() -> f64 {
    div(
        add(add(5.0, 4.0), sub(2.0, sub(3.0, add(6.0, div(4.0, 5.0))))),
        mul(mul(3.0, sub(6.0, 2.0)), sub(2.0, 7.0)),
    )
}
```

The outer `div` separates the numerator from the denominator; inside the
numerator, `add` and `sub` build up the running sums and differences from
the innermost `(4 / 5)` outward; the denominator's `mul` flattens the
product `3(6-2)(2-7)` left to right. Nothing here is a Rust operator: the
call nesting alone carries the expression's structure, which is the point
`R` preserves from the original prefix-notation exercise.

## Test

The reference value is `-37/150 ≈ -0.24667`, checked to `1e-12` since the
computation only involves ordinary floating-point arithmetic with no
cancellation-prone subtraction near zero.
