# Exercise 2.82: multi-argument coercion

## Approach

`multi_apply_generic` is the generalization. It dispatches on the
exact tag list first; on a miss it collects each distinct argument tag
in order into `targets` and, for each target, calls `coerce_all`,
which either maps every argument onto that target (an argument already
of the target passes through, the rest go through their
`put_coercion` entries) or fails. The first target that takes all the
arguments wins, and the call recurses on the coerced list.

The demo table carries the strategy's payoff: `install_add3` puts a
three-argument `add` under `(complex complex complex)`, and two
coercions reach it, `number_to_complex` for ordinary numbers
and a rational conversion that promotes inexactly. The mixed triple
`1 + 1/2 + (1 + i)` then answers `(complex (rectangular (2.5 . 1)))`,
the asserted string.

The limit the statement asks for is the next probe. `1 + 1/2` has no
`(integer, rational)` entry, and the strategy's targets are only
the argument types themselves, so `complex`, the type both arguments
could reach, is never tried; the call ends in the plain
"No method for these types" error. The third probe shows the strategy
still respects exact matches: adding a complex to an ordinary number
tries the mixed key first, then coerces the number to the complex
target, and answers `(complex (rectangular (6 . 3)))`.

## Map class

`A`: multi-arg coercion needs conversion search. The search is the
ordered `targets` list driven through `coerce_all`, and the recorded
limit is the conversion the search cannot invent, a common supertype
that none of the arguments already has.

## Deviation

None.
