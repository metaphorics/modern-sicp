# Exercise 3.2: a monitored procedure counts and resets

## Approach

The book's `how-many-calls?` and `reset-count` symbols become the variants of
`MonitorRequest`, and the two kinds of answers become `MonitorReply`. The
wrapper closure owns the counter and the wrapped function; real calls
increment the counter, the two bookkeeping requests read and zero it without
touching `f`. The test replays the book's interaction (monitored `sqrt` at
100 answers 10 with count 1) and checks the transition the counter exists
for: calls advance it, bookkeeping leaves it alone, reset restarts it.

## Map class

`T`: the statement translates directly, with Scheme symbols re-expressed as
enum values because Rust has no quoted symbols in this position.

## Deviation

The reply is an enum (`Result(f64)` or `Count(u64)`) rather than one
untyped value, since a single return type cannot carry both.
