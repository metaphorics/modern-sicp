# Exercise 5.13: the controller decides the registers

Instead of naming the registers by hand, the machine's register list is
the assembler's own scan of the controller: `controllerRegisters` walks
the instructions once and names every assign target, every register
source or operand, every `goto (reg r)` target, and every save and
restore register. The scan is the same one the 5.12 summary uses for its
registers line, so the two cannot drift apart.

The test pins the three lines: the derived list is `a b t`, the machine
built from that list answers gcd(206, 40) = 2 exactly as the
hand-listed machine does, and the machine's allocated register table
names the same three registers. A second construction path exists in the
simulator itself, `makeMachineDerivingRegisters`, which allocates each
register at first sight during assembly; the exercise machinery uses the
explicit scan because the scan's result is itself part of the answer.
