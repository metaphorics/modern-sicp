# Exercise 3.25: tables under arbitrary key lists

## Approach

The book asks for a table whose values sit under key lists of any
length, with `lookup` and `insert!` taking the key list. The section's
two-dimensional table already hangs a second record chain off each
first-key record; the generalization keeps hanging chains off chains,
one level per key. Each record carries its key, the value stored under
the full path ending at it (`undefined` while the record is spine
only), and the chain the next key descends into, so a record is spine
and value at once and one path can be a prefix of another. The table
object is the sentinel record the book prints as `*table*`. The chains
are the section's mutable pairs (`mcons` over the module's
`03-mutable-data`), and insert mutates them in place, the book's
`insert!` discipline: it conses missing spine records onto the parent
chain as it walks and sets the last key's value, replacing it when the
record is already there. `lookup` answers the value only where the
whole key path lands on a record carrying one.

## Pins

Inserting `["a", "b", "c"]` -> 1, `["a", "b", "d"]` -> 2,
`["a", "x"]` -> 3 makes the three lookups answer 1, 2, 3. The
intermediate spines carry no value: `lookup(["a", "b"])` and
`lookup(["a"])` answer `undefined`. A path never inserted
(`["q", "r"]`) answers `undefined`. Inserting
`["a", "b", "c", "e"]` -> 4 extends the existing spine: that lookup
answers 4, and the three earlier lookups still answer 1, 2, 3.

## Map class

tables, chains over the section's pairs`.
