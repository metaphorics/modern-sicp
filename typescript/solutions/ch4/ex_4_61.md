# Exercise 4.61: next-to as atoms

## Approach

The book states the relation as list patterns; the typed engine
relates atoms, so each five-position pattern becomes a `next-to`
atom whose third field is the list term. The base rule's head is a
two-deep dotted pair naming the adjacent elements; the step rule
strips one element and recurses. Both book queries run over finite
lists and terminate.

## Numbers

Two adjacent pairs in `(1 (2 3) 4)`: `(1, (2 3))` and `((2 3), 4)`.
Two predecessors of `1` in `(2 1 3 1)`: `2` and `3` — the rule finds
both occurrences of `1`, not just the first. The tests pin both
answer lists exactly.

## Class and deviations

Translated row with an `A` reason: list-pattern rule heads have no
typed-query counterpart (rule heads must be atoms), so the relation
name moved into an explicit atom position and the list became a
field. The adjacency logic, the dotted-tail car/cdr naming, and both
query outcomes are unchanged.
