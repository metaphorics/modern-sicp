# Exercise 5.35: recovering the compiled expression

Figure 5.18 defines a one-argument procedure `f`. Its body adds `x` to the result of calling `g` on `(+ x 2)`, so the source expression is:

```scheme
(define (f x) (+ x (g (+ x 2))))
```

The listing supports this reconstruction: the procedure extends its environment with parameter `x`; it looks up `g`; then it compiles the inner addition using `x` and `2`; after that result returns, the outer addition uses it with `x`. The saved `proc`, `env`, and `continue` registers preserve values needed across the nested calls.

The figure's labels depend on the compiler's prior label allocations. `figure5_18Compilation` seeds `CompilerState` with `14`, renders the compiler's statements, and compares them in order with the figure listing. This Kotlin solution therefore checks the whole statement sequence, rather than relying only on a matching expression guess.
