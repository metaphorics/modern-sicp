# Exercise 3.24: the table keyed by same-key?

## Approach

The book generalizes the section's table constructor to take a `same-key?`
predicate and return a `lookup`/`insert!` pair over one local table. The
edition spells that constructor as `makeTableSameKey`: the local table is a
module `Table`, and the two returned closures thread the predicate through
the section's `tableLookup` and `tableInsert`, so key matching is entirely
the caller predicate's business.

## Pins

Computed by running. A case-insensitive table answers lookups under any
spelling the predicate matches: insert `a`, look up `A` and get 1. A
second insert whose key matches an existing record replaces the value in
place: after inserting `Warp` then `warp`, every matched spelling reads
the new value 25. A key the predicate rejects stays undefined. Two tables
built with different predicates (case-insensitive versus strict equality)
hold their records separately: the same key spelling answers 1 in the
loose table and is absent in the strict table until inserted there.
