# Exercise 3.11: where account state lives

## Approach

The book draws the environment structure of a `deposit`/`withdraw`
sequence on one account and a second account built afterward. The
Rust replacement runs the same sequence and turns the drawing's three
questions into experiments. `Account::same_object_as` (already defined
in 3.1.1 with `Rc::ptr_eq`) tells a clone of `acc` from `acc2`: the
clone answers `true`, the second account `false`. Depositing and
withdrawing through the clone and reading the balance through the
original name (30) shows the state is shared through the name, not the
call. The solution then rebuilds the same picture with the section's
own model: two `Env` frames, `E1` and `E2`, each holding a `balance`,
both extending one global frame, with `make_withdraw_procedure` over
each frame mutating only its own. The book's two questions map to
two guarantees: a Rust experiment can show which state is shared
(`Rc::ptr_eq` or the alias's visible effect). The compiler guarantees
that every `Account` uses the same compiled `send`; no experiment can
contradict code sharing.

## Map class

`R: diagram closure state sharing between accounts`. The diagram became
runnable: every claim the book's figure would show is checked by an
assertion instead of read off a drawing.

## Deviation

None. The exercise keeps the book's exact interaction (deposit 40,
withdraw 60, from a starting balance of 50) and its exact questions.
