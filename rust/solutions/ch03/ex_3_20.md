# Exercise 3.20: aliasing through the dispatch closure, traced

## Approach

The book's exercise asks for an environment diagram of the
procedural `cons`; that is a question about Scheme frames, so this
edition replaces it. The replacement keeps the exercise's point,
that two names can reach one mutable object, and runs it against the
main text's dispatch closure instead of a drawing. `procedural_cons`
answers a `ProcPair` whose captured state is the pair's two cells;
`ProcPair::clone` copies the handle, so `alias` and `x` dispatch to
the same captured state. Sending `SetCar 17` through `alias` and
then reading `Car` through `x` answers 17, while a separately built
pair still answers its own 1. The trace the book would have drawn,
two closure environments over one captured cell pair, is exactly the
two handles over one `Rc` state that the run exercises, and the
tests hold each step of it as an assertion.

## Map class

`R: trace aliasing through closure dispatch`. The environment

message dispatch the test actually sends, and the answer the book
asks the reader to predict is asserted.

The replacement is by design (this row is R for Rust). The aliasing
