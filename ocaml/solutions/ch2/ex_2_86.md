# Exercise 2.86: generic complex parts (adapt)

The map class is `A`, taken as a module-signature adaptation rather
than another dispatch-table layer: the operations a complex number's
real part, imaginary part, magnitude, and angle need from whatever
numeric type backs them (ordinary numbers, rationals, or "other
numbers we might wish to add to the system," in the exercise's own
words) become a `Scalar` module signature (`add`, `mul`, `sine`,
`cosine`, `sqrt`, `atan2`). `Make_complex (S : Scalar)` is a functor
building one complex-number package generic over `S.t`: magnitude via
`S.sqrt` of the sum of squares, angle via `S.atan2`, both constructors,
all built from `S`'s six operations and nothing else: a compile-time
answer to "describe and implement the changes needed to accommodate
this," in place of adding runtime dispatch entries for each new
scalar type. `Float_scalar` and `Complex_float` are the ordinary-number
instance: OCaml's own `float` already satisfies `Scalar`.

`ex_2_86 ()` builds the rectangular `(3, 4)` through
`Complex_float.make_from_real_imag` and returns its `(real_part,
imag_part, magnitude, angle)`: `3.0`, `4.0`, `5.0`, and `atan2 4.0
3.0`.
