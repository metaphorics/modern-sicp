# Exercise 3.68: Louis's whole-first-row pairs

## Approach

Louis builds the stream of pairs from two parts instead of three: the
whole first row, `(S0, Tj)` for every j, glued to the recursively
defined rest over the cdrs. The demonstration appends the two parts
and answers "does this work?" by execution under a step budget: the
row map's closure ticks a meter once per first-row element computed
and throws `LouisBudgetExceeded` past 200 steps. Two spellings of the
rest are measured. With the rest delayed, `streamAppendDelayed` serves
the first row element by element and only reaches the rest when the
row runs empty, so the stream never yields anything from its second
component: the append must finish the infinite first row first. With
the rest spelled as the statement's plain argument, applicative order
evaluates the recursion before the append can serve anything at all,
and the construction itself dives row through row until the meter
aborts it.

## Pins

Computed by running with a 200-step budget over the integers.

- Taking the first pair succeeds: element 0 is `[1, 1]`, computed with
  exactly 1 metered step.
- The whole visible stream is the first row: the first 199 elements
  are exactly `[1, 1], [1, 2], ..., [1, 199]`, consuming exactly 200
  metered steps. No pair with first coordinate above 1 ever appears.
- Demanding one element past that prefix throws `LouisBudgetExceeded`
  with the meter at exactly 201 steps: even 200 steps of honest work
  leave the rest infinitely far away.
- The statement's plain-argument construction never produces a stream
  at all: building it throws `LouisBudgetExceeded` with the meter at
  exactly 201 steps, one row head per level of the dive.

## Map class

T (translate: syntax changes only). The row is plain T, so the tests
do the statement's work: Louis's definition is implemented, executed
against the integers, and its failure is measured rather than argued.

## Deviation

The statement's combinator is `interleave`; this edition's brief
prescribes appending the whole first row to the rest, which keeps the
lesson clean because an interleave of the whole row with a delayed
rest would produce every pair (the module's interleave
alternates, so an infinite first argument cannot starve the second).
The phrase "never yields the second element" is sharpened to match the
mechanism: the stream's own second element `[1, 2]` is as cheap as the
first; what is never yielded is any element of the second component,
the recursive rest. Finally, `streamAppendDelayed` exists because an
eager language evaluates a plain argument before the append can run;
it is the spelling that gives Louis's definition its best case, and
the plain-argument variant is the statement's literal discipline.
