# Exercise 2.6: Church numerals `one`, `two`, and `churchAdd`, defined directly

## Approach

`one` applies its step exactly once, `two` exactly twice, and `churchAdd(m,
n)` builds the numeral whose step application is `m(f)` composed after
`n(f)`: `(f) => (x) => m(f)(n(f)(x))`. None of the three is built from
`churchZero` or repeated `add1`, which is the exercise's requirement; the
statement's `zero` and `add1` are kept only for the substitution check
(`add1(churchZero)` = `(f) => (x) => f(x)` = `one`).

The map's `A` reason is the function-encoded zero, and this is where
TypeScript is at its strongest: the numeral is the plain generic function
type `type Church = <T>(f: (x: T) => T) => (x: T) => T`. No wrapper type is
needed to break a self-reference, because `Church` mentions itself only in
positions the host's type structure already allows; the zero is literally a
function value.

## Numbers

`churchZero` decodes to 0; `add1(churchZero)`, `one`, and `add1(one)` decode
to 1 and 2; `churchAdd(one, one)`, `churchAdd(one, two)`, and
`churchAdd(two, two)` decode to 2, 3, and 4.

## Map class

`A` (map: "church numerals need function-encoded zero"): the idea survives
and the statement names what the encoding needs - the zero is a function,
not a number.

## Deviation

The statement's `+` becomes `churchAdd`, since the host's `+` is taken;
the book's `one` and `two` keep their names.
