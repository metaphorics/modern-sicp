# Exercise 4.19: the internal-definition scoping debate

## Approach

One program, three evaluators. Ben's sequential rule is the plain
evaluator: `b`'s initializer runs before `a` is redefined in the frame, so
it reads the outer `a` of 1 and `(+ a b)` answers 5 + 11. Alyssa's
mechanism is the 4.16 scan-out: every internal name is reserved with the
marker first, so the read of `a` in `b`'s initializer fails the typed
premature-read check. Eva's simultaneous rule reserves the names and emits
the assignments in eager-read dependency order, computed from an occurrence
check that collects the variables an initializer reads eagerly; a read
inside a lambda defers until the lambda is called, so mutual recursion
stays order-free. `b` depends on `a`, so `a`'s assignment runs first and
`b` is initialized against the final `a` of 5; `(+ a b)` answers 5 + 15.

The position taken, with the book's footnote: an error in the hard cases
beats a silently wrong answer, and a general Eva needs a dependency
fixpoint. Genuinely cyclic initializers fall back to source order, where
the reservation check reports the deadlock instead of looping.

## Map class

`T` (map row 4.19: Kotlin T).

## Deviation

Eva's rule is implemented as dependency-ordered assignments over the 4.16
reservation rather than a literal simultaneous evaluation; for acyclic
eager reads the two agree, and cycles have no simultaneous answer.
