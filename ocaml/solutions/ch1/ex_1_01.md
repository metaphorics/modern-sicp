# Exercise 1.1 — evaluate an expression sequence in order (translate)

The map class is `T`: syntax changes only. The Scheme sequence becomes a
sequence of OCaml phrases; the two `define`s become `let` bindings, the
`cond`s become `if`/`else if` chains, and the arithmetic stays infix. The
results are the book's: `10, 12, 8, 3, 6`, then `19` for `a + b + (a * b)`,
`false` for `a = b`, `4` for the guarded conditional, `16` for the `cond`
over `b = 4`, `6`, and `16` again for the product with `(a + 1)`.

The typed shape carries the whole answer: `int list * bool` pairs the ten
integer results in source order with the equality test. The test pins both
parts, so a wrong `cond` translation or a swapped operand order fails it.

One detail worth reading twice: `6 / 2` is integer division, but the
operands divide evenly, so it matches the book's `3`. The precedence notes
(`2 * 4 + (4 - 6)` needs no parentheses around the product) are the
infix-notation counterpart of the book's prefix discussion.
