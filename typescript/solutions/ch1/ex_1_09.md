# Exercise 1.9: the processes of two additions in terms of inc and dec

## Approach

Both functions walk the same states, `(a, b) -> (a-1, b+1) -> ... ->
(0, a+b)`; what differs is where the state lives. `plusRecursive` carries
`b` as an argument but defers an `inc` at every level, so the process
expands to a chain of `a` pending increments and then contracts: a
linear recursive process, shaped like the factorial of Figure 1.3.
`plusIterative` keeps everything in the two state variables `x` and `y`
and updates them in place: a linear iterative process, shaped like
Figure 1.4.

```
plusRecursiveTrace(4, 5):              plusIterativeTrace(4, 5):
  (4, 5)                                 (4, 5)
  (3, 6)   deferred chain of incs        (3, 6)
  (2, 7)   ....v....                     (2, 7)
  (1, 8)            inc(inc(inc(inc(9))))
  (0, 9)   <- returns 9                  (0, 9)  <- returns 9
```

## Numbers

`plusRecursive(4, 5)` and `plusIterative(4, 5)` both return `9`; both
traces pass through the five states `[[4,5],[3,6],[2,7],[1,8],[0,9]]`.
The recursive one holds all five frames at once; the loop holds one.
`plusIterative(100000, 1)` returns `100001`; `plusRecursive(100000, 1)`
throws `RangeError: Maximum call stack size exceeded`.

## Class and deviations

Adapted row, per the map: Node/V8 gives no tail-call guarantee, so the
book's second `+`, whose self-call sits in tail position, is presented in
this edition as the explicit loop (the iterative shape of section 1.2.1)
rather than as a call chain. The statement also asks which function can
run in constant space: only the loop, since every call in the recursive
spelling - tail call or not - takes a stack frame on this host.
