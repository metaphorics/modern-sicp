# Exercise 2.70a — decode after encode is the identity (this edition's addition, extending 2.70)

The map's idea column for 2.70 offers "bit savings assertion test";
Exercise 2.70 itself already asserts the bit savings (84 bits against
a fixed-length 108). This addition extends 2.70 with the property the
whole exercise implicitly rests on: for a Huffman tree over any
alphabet and a message drawn from it, encoding then decoding gives
back the message. A handful of hand-picked examples (the rock song,
the sample tree) cannot show a property holds for every tree and
every message; `Prop_sec_2_70` generates 300 random alphabets of 2 to
8 symbols with random positive weights, and for each, 0 to 30 random
symbols drawn from it, and checks `decode (encode message tree) tree
= message` every time.

A single-symbol alphabet is excluded from the generator: encoding a
symbol against a one-leaf tree costs zero bits, so a message of any
number of repetitions of that symbol encodes to the empty bit list,
and `decode` has nothing left to tell it how many times to repeat the
symbol. This is not a bug in this edition's `encode`/`decode`: the
book's own procedures, ported verbatim, have exactly the same
degenerate case, because a code with one symbol has nothing to
distinguish. Huffman coding is defined for alphabets of two symbols
or more, where every code word needs at least one bit.

Sample: `ex_2_70a ()`, a deterministic battery covering the rock
song's tree and the sample tree of Exercise 2.67 with a short
message, is `true`; `Prop_sec_2_70`'s 300 random cases all pass.
