## Exercise 2.58: infix notation

Approach: two small recursive-descent parsers, both tokenizing with the
same `tokenize` and both building this section's ordinary two-argument
`Expr` (`AlgExpr.kt`), so `deriv` differentiates either parser's output
unchanged, matching the book's claim that only the front end needs to
change. Part a) assumes full parenthesization, so one grammar rule
suffices: an expression is a number, a variable, or `(a op b)`. Part b)
drops that assumption and needs the standard two-level grammar
(`sum := product ('+' product)*`, `product := factor ('*' factor)*`,
`factor := '(' sum ')' | NUM | VAR`) so that `*` binds tighter than `+`
without any parentheses at all.

Class: A, per the map — the idea survives (`deriv` is unchanged data
abstraction over `Expr`), but the statement changes from "assume the
selectors already exist" to "write them," since nothing in Kotlin
parses a string as a program the way Scheme's reader does.

Deviation: none from the two parts as stated. Worked by hand, the
derivative of `x + 3 * (x + y + 2)` w.r.t. `x` is `d/dx(x) = 1` plus
`d/dx(3 * (x + y + 2)) = 3 * d/dx(x + y + 2) = 3 * 1 = 3`, for a total
of `4`, which is what the test and `ex_2_58` both assert.
