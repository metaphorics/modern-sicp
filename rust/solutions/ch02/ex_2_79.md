# Exercise 2.79: generic is_equ

## Approach

`install_equ` puts `is_equ` under four two-tag keys, one per package
the section builds. Ordinary numbers compare after the exact-to-
inexact promotion the section's arithmetic shares (`as_f64` on both
sides); rationals compare by cross-multiplication through
`checked_mul`, so an extreme numerator surfaces `SicpError::Overflow`
instead of wrapping; reals compare their tagged contents; complex
numbers compare `real_part_dispatch` and `imag_part_dispatch` parts,
read through the second rectangular or polar tag.

The probes cover the three domains the statement names. `6` equals `6`
and not `7`; `1/2` equals `2/4` and not `1/3`, equality judged by
cross-multiplied products so no reduction is assumed; the complex
`(1 + 2i)` equals itself and not `(1 + 3i)`. The asserted answer
vector is `[true, false, true, false, true, false]`.

One generic name now spans representations with different internal
shapes, which is the point of the exercise: each handler stays in its
own package's arithmetic, and the dispatcher alone decides which one
runs for a given pair of tags.

The map's class for this row is a straight translation in this
