# Exercise 5.6: the Fibonacci machine's redundant save and restore (T)

## Approach

The pair is the `(restore continue)` at `afterfib-n-1` and the
`(save continue)` in the second setup block: the restore brings back
the caller's return label only for the next save to push it straight
back, and exercise 5.5a's annotations name exactly these two events.
The pruned machine leaves the stack balanced because the final
`(restore continue)` at `afterfib-n-2` then pops the copy saved at
the first setup. The test removes the two instructions from the
controller and checks the machine against the host's own Fibonacci
for every n up to 10, then pins the instruction and push counts.

## Map class

`T`.

## Sample answer

At n = 6 the original machine executes 281 instructions with 48
pushes; the pruned machine 257 instructions with 36 pushes: one save
and one restore per internal call, twelve of them.
