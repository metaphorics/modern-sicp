# Exercise 2.38: fold-left and fold-right

## Approach

fold-right is the module's accumulate: combine the head with the fold of
the tail, so fold-right applies the leftmost element last, outside-in. fold-left
is the mirror iteration: start from the initial and combine the running
result with each element left to right, so fold-left applies the
leftmost element first, inside-out. Division on (1 2 3) shows the difference -
3/2 against 1/6 - and the pairing operation shows it structurally:
fold-right nests the initial at the deepest right, fold-left wraps it at
the deepest left. The property the exercise asks for is commutativity,
with the initial a two-sided identity; associativity alone is not
enough, because even an associative op receives the initial on opposite
sides in the two folds, which is precisely what the division case shows.

## Numbers

`accumulate((a, b) => a / b, 1, list(1, 2, 3))` is 1/(2/3) = 1.5;
`foldLeft((a, b) => a / b, 1, list(1, 2, 3))` is ((1/1)/2)/3 = 1/6.
With the two-element-list pairing operation and initial `()`: fold-right
renders `"(1 (2 (3 ())))"` and fold-left renders `"(((() 1) 2) 3)"`.

## Map class

`T`: the book's fold-left translates directly as an iterative walk;
the solution spells Scheme's one untyped pairing lambda as two typed
wrappers, one per fold's argument order, with identical bodies.

## Deviation

None.
