# Exercise 1.20 — counting remainder calls under eager evaluation (replace: R)

The map class is `R`. SICP exercise 1.20 asks the reader to trace
Scheme's normal-order evaluation by hand; OCaml has no normal-order mode
to instrument, so this edition replaces it with an exercise that keeps
the number and teaches the same lesson — the process a procedure
generates depends on the evaluation rule — through a measurement OCaml
can actually make, plus the substitution argument the book asks for.

**Measured: eager (applicative) order.** Wrapping `mod` in a counting
`remainder` and running `gcd 206 40` gives the value 2 and exactly 4
remainder calls: `remainder 206 40 = 6` reduces to `gcd 40 6`,
`remainder 40 6 = 4` reduces to `gcd 6 4`, `remainder 6 4 = 2` reduces to
`gcd 4 2`, `remainder 4 2 = 0` reduces to `gcd 2 0`, which returns `2`
directly without a fifth call.

**Argued: normal order.** Under normal order, `if`'s predicate is always
evaluated, but an argument is substituted unevaluated and only forced
where it is actually used — so an expression used twice is evaluated
twice. Writing out the substitution (as @ref{Exercise 1.5} defines
normal order for `if`) and counting every `remainder` the predicate and
the body force:

    gcd 206 40
    = if 40 = 0 then 206 else gcd 40 (remainder 206 40)
        predicate is a plain 40: no call; the else branch substitutes
        (remainder 206 40) unevaluated
    = gcd 40 (remainder 206 40)
    = if (remainder 206 40) = 0 then 40
        else gcd (remainder 206 40) (remainder 40 (remainder 206 40))
        predicate forces one call: 206 mod 40 = 6                          -- +1
    = gcd (remainder 206 40) (remainder 40 (remainder 206 40))
    = if (remainder 40 (remainder 206 40)) = 0
        then (remainder 206 40)
        else gcd (remainder 40 (remainder 206 40))
                 (remainder (remainder 206 40) (remainder 40 (remainder 206 40)))
        predicate forces 206 mod 40 again, then 40 mod 6 = 4               -- +2
    = gcd (remainder 40 (remainder 206 40))
          (remainder (remainder 206 40) (remainder 40 (remainder 206 40)))
    = if (remainder (remainder 206 40) (remainder 40 (remainder 206 40))) = 0
        then ...
        else gcd (remainder (remainder 206 40) (remainder 40 (remainder 206 40)))
                 (remainder (remainder 40 (remainder 206 40))
                            (remainder (remainder 206 40)
                                       (remainder 40 (remainder 206 40))))
        predicate forces 6 again, 40 mod 6 again, then 6 mod 4 = 2         -- +4
    = gcd (remainder (remainder 206 40) (remainder 40 (remainder 206 40)))
          (remainder (remainder 40 (remainder 206 40))
                     (remainder (remainder 206 40)
                                (remainder 40 (remainder 206 40))))
    = if (remainder (remainder 40 (remainder 206 40))
                    (remainder (remainder 206 40)
                               (remainder 40 (remainder 206 40)))) = 0
        then (remainder (remainder 206 40) (remainder 40 (remainder 206 40)))
        else ...
        predicate forces the whole nest again, ending in 4 mod 2 = 0       -- +7

The forced expressions grow as 1, 2, 4, 7 because each `gcd` step
substitutes the previous step's two `remainder`s inside a new one, so
forcing a predicate re-forces everything nested in it. The last `if`
forces only its predicate `b`: the predicate is 0, so the else branch is
never touched. The `then` branch is `a`, and `a` is what `gcd 206 40`
reduces to, so producing the answer forces it once more — 6 mod 4, a
fifth group of 4 calls:

    1 + 2 + 4 + 7 + 4 = 18 total remainder evaluations by the time
    `gcd 206 40` finally reduces to `2`, against the 4 that eager
    evaluation needs.

The eager count is `Theta(log n)`, matching
the number of `gcd` calls exactly; the normal-order count is asymptotically
worse, because every level re-derives every remainder the levels below it
already computed.
