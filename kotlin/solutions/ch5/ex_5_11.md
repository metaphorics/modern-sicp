# Exercise 5.11: the save and restore disciplines

The exercise asks for the three possible `restore` disciplines side by
side. All three live in `E5_11.kt` as variant assemblers over the same
machine, not as three edited copies of the simulator: `assembleWith`
recomposes the standard builders, substituting only the save and
restore execution procedures, which is the seam the book's structure
already provides.

- Discipline (a) is the standard machine: `restore` pops the most
  recent value, whatever register it was saved from.
- Discipline (b) is the checking stack: `TaggedStackMachine` keeps
  pairs of register name and value; `taggedRestoreProc` raises the
  typed `MachineError.RestoreMismatch` when the popped pair names
  another register.
- Discipline (c) is a stack per register: `PerRegisterStackMachine`
  keeps one `ArrayDeque` per register name and `restore` pops the
  named register's own stack.

Part (a)'s elimination question is answered by running, not arguing.
In the figure 5.12 controller, `afterfib-n-2` reads
`(assign n (reg val))` then `(restore val)`; because a name-blind
`(restore n)` pops the same slot `(restore val)` would, the pair
collapses to one `(restore n)` and the final sum's operands swap.
`fibNameBlindController` is the trimmed controller. Under discipline
(a) it answers fib(3) = 2 and fib(5) = 5, the same values the full
controller answers under all three disciplines, which is the pin.
The same trimmed controller under discipline (b) is refused with
`restore n but the stack holds val`: the elimination depends on the
name-blindness that the checking discipline removes. The out-of-order
sequence (`save y`, `save x`, `restore y`) separates the disciplines
on a three-instruction controller: (a) answers y = 2, (b) refuses
with `restore y but the stack holds x`, (c) answers y = 1.
