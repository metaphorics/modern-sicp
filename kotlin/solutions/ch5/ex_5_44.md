# Exercise 5.44: respecting shadowing during open coding

Open coding is valid only when the operator refers to the compiler's primitive,
not to a lexically shadowing parameter. The compiler checks whether an operator
is one of its open-coded names and whether that name is absent from the
compile-time environment. A shadowed name therefore follows ordinary
application compilation instead of receiving primitive instructions.

`openCodeShadowingCounts()` compiles the book's linear-combination body once
with `+` and `*` as parameters and once with those names free. The test pins zero
open-coded operations in the shadowed case and three in the free case: one `+`
and two `*` operations. It also defines `+` in compiler state and pins the
warning `open-coded primitive + is rebound`. The warning is the behavior this
example establishes for rebinding; it does not claim that rebinding such a name
is supported while preserving open-coded semantics. The test also pins the
compiler's open-coded name list as `+ - * < =`.
