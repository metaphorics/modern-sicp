# Exercise 2.63: comparing `tree_to_list_1` and `tree_to_list_2`

## Approach

**Part a.** In-order traversal always visits a binary search tree's
elements in sorted order, so both procedures produce `[1, 3, 5, 7, 9,
11]` for all three of Figure 2.16's trees, regardless of which of the
several valid shapes represents the set.

**Part b.** `tree_to_list_1` builds its result by appending the right
subtree's list at every node (`out.extend(right_list)`), which copies
that subtree's whole result; on a balanced tree this recurrence is
`Θ(n log n)`. `tree_to_list_2` accumulates with a `VecDeque` and
`push_front`, one `Θ(1)` step per node, giving `Θ(n)`. Measuring exact
copy counts on balanced trees of 15 and 127 elements shows
`tree_to_list_2`'s count equal to the element count exactly, while
`tree_to_list_1`'s count grows from about 1.1x that at 15 elements to
about 2.5x at 127 — the `Θ(n log n)` versus `Θ(n)` gap widening with
`n`, exactly as the growth-order analysis predicts.
