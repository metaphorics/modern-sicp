# Exercise 2.63: tree to list, two ways

## Approach

`treeToList1` recurses on both subtrees and appends the pieces;
`treeToList2` threads an accumulator through `copyToList`, consing each
entry onto the result built so far.

## Answer

(a) Both produce the in-order list for every tree, so they never differ:
for all three trees of figure 2.16 the answer is `[1, 3, 5, 7, 9, 11]`.
(b) On a balanced tree, `treeToList2` does one cons per entry:
Theta(n). `treeToList1` appends at every node, and appending a
k-element list to an l-element list costs k steps, so each level of
recursion re-copies the elements accumulated to its left: Theta(n log n)
for a balanced tree (and Theta(n^2) for a fully skewed one). The
accumulator version grows more slowly.

## Map class

T (translate): the given procedures re-expressed over the tree union.

## Deviation

None.
