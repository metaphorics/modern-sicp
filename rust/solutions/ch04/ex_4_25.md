# Exercise 4.25: unless breaks under applicative order (T)

## Approach

Two evaluators run the same `unless`-based `factorial`. The lazy evaluator delays
`unless`'s arms: the condition forces, only the chosen arm is demanded, and the
recursion bottoms out. The strict base evaluator keeps the edition's
strict-primitive rule: every argument of a primitive (and of an ordinary
procedure call under applicative order) evaluates before the call, so an armed
`(/ 1 0)` fires before `unless` is entered, and the strict `factorial` only
stops at a step budget, the host stand-in for "runs forever".

## Map class

`T`.

## Sample answer

Lazy `(factorial 5)` -> 120; strict armed `(unless (= 1 1) (/ 1 0) 42)` ->
division by zero; strict `factorial` under fuel 200 -> the "still descending"
budget error.
