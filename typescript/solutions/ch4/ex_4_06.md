# Exercise 4.6: let as a derived expression

## Approach

`letToCall` rebuilds the grouped binding `LetNode { tag: "let",
bindings, body, span }` as the book's combination
`((x1, ..., xn) => { body })(e1, ..., en)`: one `call` of one `arrow`
over the group's names, applied to the group's initializers, with every
constructed node carrying the source node's span. The evaluator's single
case lowers and re-evaluates in the same environment; the lowerer
recurses through shared expressions and grouped-binding initializers.
However, this experiment's `LetNode` is outside the shared `Expr` and `Stmt`
unions: a shared procedure-body statement cannot embed a `LetNode`
directly, so the procedure-body example explicitly lowers it to a call.

## Numbers

A let evaluates as its combination: over `x = 3, y = 4` the body
`x + y` is `7`. `letToCall` on that form is structurally the
hand-written `((x, y) => x + y)(3, 4)` — equal after erasing spans, the
typed analog of the old `equal?` check. A lowered let call in a procedure
body answers `42` (`x = 2` over `x * 21`). The body runs as a sequence in
the new frame: `x = 10` then `x` is `10`. Nested grouped bindings in
supported expression positions answer `7` through the same lowering.

## Class and deviations

Translated row. The transformation and evaluator case follow the book.
