# Exercise 3.4: lockout after seven bad passwords

## Approach

The 3.3 account gains its second local state variable: a `Ref` counting
consecutive wrong-password accesses. A correct access zeroes it; a
wrong access increments it; once the count passes seven the account
invokes the `callTheCops` callback (the book's procedure, passed in)
and fails with `CallTheCops` instead of the password complaint. The
counter is strictly consecutive, so the book's "more than seven
consecutive times" is the eighth wrong access in a row.

## Numbers

Seven wrong accesses fail `IncorrectPassword` with the callback never
firing; the eighth fails `CallTheCops` and fires it once. A correct
access between streaks resets the count, so two seven-wrong streaks
with a correct login in between never fire. Wrong accesses past the
threshold keep firing the callback (count 9, 10, and so on).

## Map class

T (plain port; kotlin holds the tailored 3.4a addition, the audit
log).

## Deviation

The book does not say what the account does after calling the cops;
this solution keeps counting and keeps calling on each further wrong
access, and correct accesses still work.
