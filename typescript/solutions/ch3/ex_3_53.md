# Exercise 3.53: the self-referential doubling stream

## Approach

The statement defines, sight unseen, `const s = consStream(1, () => addStreams(s, s));` and asks
what the elements are. The prediction: the powers of 2. The head is 1; every later element of
`addStreams(s, s)` is the sum of the two copies at the same position, which is the element one
place back plus itself, twice the element before. So element n is 2 to the n. The solution
translates the statement's definition directly (`consStream(1, () => addStreams(s, s))`, the
thunk referencing the finished binding) and adds the same stream read as a doubling,
`double = consStream(1, () => scaleStream(double, 2))`, whose agreement with `s` the tests
check element-wise; the equivalence is the description the exercise asks for, spelled as a
second construction.

## Pins

Computed by running. `streamTake(s, 8)` is 1 2 4 8 16 32 64 128, the prediction. `streamRef(s,
12)` is 4096 and `streamRef(s, 20)` is 1048576, the powers of 2 at depth. `streamTake(double,
8)` equals `streamTake(s, 8)` and `streamRef(double, 20)` equals `streamRef(s, 20)`.

## Map class

T (translate: syntax changes only). All four columns are plain T; TypeScript's closure
self-reference needs the thunk-after-binding idiom the module's `ones` and `integers`
already use.

## Deviation

The solution exports `double`, the `scaleStream` construction, alongside the statement's own
`addStreams` definition; the exercise as printed defines only `s` and asks for a description,
so the second construction is an addition (the batch assignment requested it), not a
replacement. The prediction is stated in this file's Approach and asserted by execution, not
by copying the book.
