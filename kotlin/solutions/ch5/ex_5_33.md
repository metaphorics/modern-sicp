# Exercise 5.33: compiling the alternative factorial

The two definitions differ in operand order: the book's factorial computes `(* (factorial (- n 1)) n)`, while `factorial-alt` computes `(* n (factorial-alt (- n 1)))`. The compiler evaluates operands right to left. In the book's form it evaluates `n` before making the recursive call, so it can use that value afterward without returning to the environment for it. In the alternative, the recursive call happens before the first operand `n` is evaluated. The compiled sequence therefore has to preserve the environment across that call so it can still look up `n` when control returns.

`altFactorialComparison` compiles both forms with the same `CompilerConfig`, filters each emitted listing to its save/restore instructions, and runs both compiled definitions at input `5`. The implementation identifies one additional save/restore pair in the alternative compilation and reports both results. The difference is register and stack work introduced by the evaluation order, not a change to the factorial recurrence or its answer.

In Kotlin, the comparison uses the shared `compiledStatements` and `runCompiled` helpers and derives the listing sizes from the returned statement lists. It does not hard-code compiler output or a host-specific statement count.
