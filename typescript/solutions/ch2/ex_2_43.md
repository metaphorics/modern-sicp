# Exercise 2.43: Louis Reasoner's eight-queens slowdown

## Approach

Louis interchanged the two nested mappings: the flatmap now runs over
the candidate rows and the recursive `queenCols(k - 1)` call sits inside
the per-row map, so the per-row map re-solves the (k-1)-board once for every
row tried; the book's nesting solves it once and shares it across all
rows. The
answer set is unchanged, because the placements generated are the same
row-plus-rest combinations in a different order and the `isSafe` filter
keeps exactly the same ones; only the cost changes. The swapped version
reuses exercise 2.42's `emptyBoard`, `adjoinPosition`, and `isSafe`.

## Numbers

The standard version calls queenCols(k-1) once per level; Louis's calls
it once per candidate row at every level, multiplying the work by
boardSize at each of the boardSize levels, so his runtime is about
boardSize^(boardSize-1) times the standard T - for 6x6, 6^5 = 7776 T as
an upper bound, which is why he never sees 6x6 finish. A scratch timing
run over this edition's lists measured board 6: standard queens about
0.14 ms per solve against about 25 ms per solve for queensSwapped, a
ratio near 180; at board 7 the same run measured 0.63 ms against
633 ms, a ratio near 1000. The ratio growing by roughly boardSize per
added board row is the per-level multiplication showing directly. These
are scratch observations only; the tests assert no timing.

## Map class

`T`: the book's interchanged program translates directly, keeping the
standard `queens`'s filter, flatmap, and map shell with the two nested
mappings swapped.

## Deviation

None.
