# Exercise 3.51: show reveals memoized delay timing

## Approach

`show` records an element at the moment it is computed and hands it
back unchanged, so one shared log, threaded through the `show` closure
as an `Rc<RefCell<Vec<String>>>` in place of the book's printing,
timestamps the delay. The exact sequence: building `x` computes only
the first square, so the log holds `0`; `stream-ref x 5` demands
elements 0 through 5 for the first time and the log grows to
`0 1 4 9 16 25` with the answer 25; `stream-ref x 7` finds every memo
up to index 5 already in place and runs `show` for exactly the two new
squares, `36 49`, answering 49. The log's exact contents prove the
memoized-delay answer the exercise asks for: each element computes
once, at the moment it is first demanded, never twice.

## Map class

`T`. The statement translates whole. The one Rust wrinkle is
mechanical: the book's `show` prints, and this edition's runtime never
prints, so the log is the display -- `show(x, &log)` records the same
line `display-line` would print, and the test asserts the log instead
of reading a transcript.

## Deviation

None. The printed transcript and the recorded log are the same events;
the values pinned are the exercise's canonical ones.
