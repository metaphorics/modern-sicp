# Exercise 4.1: the two operand orders (adapt)

The map class is `A`: the statement's premise ("inherited from the
underlying Lisp") does not survive the host, because the evaluator's
`list_of_values` is an explicit recursion, so this edition states the
order as a property of the written recursion instead of an inherited
accident. The solution writes both orders the statement asks for:
`list_of_values_left_to_right` evaluates the first operand, then the
rest; `list_of_values_right_to_left` evaluates the rest, then the
first operand, and reassembles the values in operand order.

The order is observable without host trivia: `ex_4_01` evaluates the
operands `1` and an unbound variable with each version, logging every
evaluation. Left to right logs `["1"; "Error: unbound variable
not-there"]`; right to left logs
`["Error: unbound variable not-there"]`, because the failure happens
before `1` is ever evaluated.

Sample: `ex_4_01 ()` answers
`(["1"; "Error: unbound variable not-there"],
 ["Error: unbound variable not-there"])`.
