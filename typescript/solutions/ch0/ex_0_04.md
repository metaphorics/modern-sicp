# Exercise 0.4: exhaustive area and the compile experiment

## Approach

`area` switches on the `_tag` discriminant and returns from every
case, with no default: the union is closed, so the compiler knows the
switch is total. The third variant is `Square` with one side, the
obvious neighbor to `Circle` and `Rect` from the section listing.

## The compile experiment

With the `Square` case deleted, `pnpm -r --filter './packages/*' exec
tsc --noEmit` refuses the file with:

```
solutions/ch0/ex_0_04.ts(17,33): error TS2366: Function lacks ending
return statement and return type does not include 'undefined'.
```

The message is section 0.4's exhaustiveness guarantee stated as an
error: because the switch no longer covers the union and the return
type admits no fall-off, the missing case is a compile failure, not a
runtime surprise. The case was restored and the suite is green again.

## Proof

Hand cases pin all three areas (`π`, `6`, `16`), and a fast-check
property over positive dimensions asserts `Rect` and `Square` areas
equal their products for generated inputs.
