# Exercise 3.30: the ripple-carry adder

## Approach

The book composes n full-adders, each stage's carry-out feeding the next
stage's carry-in. `rippleCarryAdder` takes the operand and sum wires as
arrays ordered least significant bit first (the order the book's `Ak`,
`Bk`, `Sk` indices run), threads the carries through fresh wires, and
returns the most significant carry-out so the arithmetic is checkable.
Tests build adders over `numberToBits` operands, propagate, and read the
result with `bitsToNumber` plus the carry-out bit.

## Pins

Computed by running. With k = 4: 13 + 7 answers 20, 5 + 5 answers 10, and
15 + 1 answers 16 (sum bits 0 with the carry-out as bit 4), each compared
against integer addition. A spread of operand pairs (0+0, 1+0, 0+1, 7+8,
6+9, 12+3, 10+10) all match integer addition. The bit helpers round-trip
13, and mismatched list lengths fail with the equality error.

## Map class

T (translate: syntax changes only). The map's tailored idea for the row
(verify the adder against integer addition) is chosen: kotlin, so this
edition's tests do the plain T-row work; the integer-addition checks here
follow the exercise's own construction rather than the addition.

## Deviation

The constructor returns the final carry-out wire where the book returns
`ok`: the carry-out is otherwise unreachable from outside the circuit,
and the verification the unit needs reads it directly.
