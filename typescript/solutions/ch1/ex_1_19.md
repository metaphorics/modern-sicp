# Exercise 1.19: transform-squaring Fibonacci over bigint

## Approach

Applying `T_pq` twice to `(a, b)` is applying `T_p'q'` once with
`p' = p^2 + q^2` and `q' = q^2 + 2pq` (expand
`T_pq(T_pq(a, b))` and collect terms). Halving the count with a squared
`(p, q)` therefore reaches `T^n` in about `2 * log2(n)` transformation
steps. One subtlety costs correctness if missed: `q'` must be computed
from the old `p` and `q`, so both next values are bound before either
overwrites its source. The whole state machine is one explicit loop over
`(a, b, p, q, count)`, this edition's iterative shape, and the
arithmetic is `bigint` throughout.

## Numbers

`fibLog` matches the linear iteration exactly for `n` in `0..78` (the
range where `number` addition is still exact; `Fib(78) = 8944394323791464`
is the last one under `2^53`), then keeps going where `number` cannot:
`fibLog(79) = 14472334024676221n` - the number-arithmetic iteration
returns `14472334024676220`, off by one - `fibLog(93) =
12200160415121876738n` (past the 2^64 line a `Long` host would fail at),
`fibLog(100) = 354224848179261915075n`.

## Class and deviations

Adapted row, per the map: "number precision, use bigint". The statement
says so explicitly (`Fib(93)` exceeds number's exact range) and the
rationale pins the exact crossover: `Fib(79)` is the first Fibonacci
number the linear `number` iteration computes wrongly. The skeleton's
slots are `p'`, `q'`, and the T application, filled as above.
