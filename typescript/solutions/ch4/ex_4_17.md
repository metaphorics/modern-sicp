# Exercise 4.17: the extra frame of scanned-out definitions

## Approach

The answer is carried by running the same body under three application
strategies: sequential runs the body's declarations in order in the
call frame; the scanned strategy runs the 4.16 scan's own frame — one
child of the call frame per application whose only bindings are the
pre-bound names — so the extra frame is structural; and the design
answer extends the call frame once, with parameters plus the pre-bound
names, then runs the writes, so no second frame is built. Frame counts
are observed on the environment chain: a program returns a closure and
the closure's environment depth is the frame count.

## Numbers

`const a = 1; const b = a + 1; return a + b;` answers `3` under all
three strategies. A body returning a closure over its local `a` gives
that closure an environment depth of `2` under sequential, `3` under
the scanned strategy, and `2` under the same-frame variant: the two
scanned variants differ from sequential by exactly one frame. Applying
the same-frame closure answers `1`.

## Class and deviations

Translated row. Deviations: the scan's extra frame is a child frame
holding the pre-bound names, not the book's generated lambda
application — the typed pre-binding supplies the let's frame semantics
directly — and the write items are assignments in place of `set!`.
