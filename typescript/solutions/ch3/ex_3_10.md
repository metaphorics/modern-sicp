# Exercise 3.10: the let spelling's binding lifetimes

## Approach

The book's alternate `make-withdraw` binds `balance` with a `let`;
since `let` is sugar for applying a lambda (1.3.2), the edition spells
the alternate version as its own desugaring in `makeWithdrawLet`: the
balance cell is created as the argument of an immediately applied
function, so it is born one call deeper than in the parameter version,
which is the section's own `makeWithdraw`. Traced variants
(`makeWithdrawTraced`, `makeWithdrawLetTraced`) log every frame the
factory call opens, the binding it holds, and its fate after the
factory returns; `renderWithdrawalStructures` renders the two
structures from those logs, so the pinned drawing comes from the runs.

## Pins

Same behavior: running the script "w1 = make(100); w1(50); w2 =
make(100); w2(10)" over both spellings answers `[50, 90]` each time.
Different structures: the parameter spelling opens one frame (E1,
binding `balance: 100`) and the processor carries E1's cell; the let
spelling opens two (E1 binding `initial-amount`, then E2, the applied
let, binding the balance cell), the processor is born in E2, and E1
dies at the factory's return because nothing below E2 reads
`initial-amount`. Frame entries logged: one `FrameEntered` against two;
fates: E1 survives in the parameter version, E2 survives and E1 dies in
the let version. One more call, one more frame, same answers.

## Map class

`R: trace captured binding lifetimes`. The question "how do the
environment structures differ" became a lifetime trace: which frames
the processor keeps alive and which die with the factory call.

## Deviation

The parameter version is the section module's own `makeWithdraw` rather
than a local copy, since the exercise compares the section's spelling
against its `let` alternate; the traced variants inline the same arm
bodies so the logs record the real frames. A natural TypeScript `const`
declaration would add no frame (the book's point is that Scheme's
`let` does), so the alternate is spelled as the desugaring itself,
which is what makes the extra frame real in this edition: each frame is
one call, and the desugared `let` is literally one more call.
