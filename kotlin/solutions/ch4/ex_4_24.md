# Exercise 4.24: the direct evaluator against the analyzer

## Approach

Both engines run the same program in fresh global environments:
`(define (fib n) ...)` and repeated calls of `(fib 12)`. Each reading
takes 100 unmeasured warmup calls, then the median of 7 timed batches of
100 calls each (`System.nanoTime` via `measureNanoTime`). The driver has
two named entry points, `directEvaluatorTiming()` and `analyzerTiming()`,
because the two engines share no supertype beyond their `eval` signature.

The TEST asserts only structural facts: both engines compute the same
value (`fib 12` = 144) and both medians are positive. Nothing asserts on
measured time: a timing assertion would flake on any other host. The
measured ratio lives in the `// =>` comment above and here, reported
honestly for one recording run plus repeats on one machine.

## Map class

`T` (map row 4.24: Kotlin T).

## Deviation

None in design. In OUTCOME, the book's expectation that the analyzer
"performs somewhat better" did not hold on this host, and the honest
number is reported below rather than a manufactured speedup.

## Answer

Both engines compute `fib 12` = 144, and both medians are positive
(`E4_24Test` pins exactly these structural facts).

Measured on the recording run (Xeon Gold 6138, Kotlin/JVM 2.2.21,
medians of 7 batches of 100 `(fib 12)` calls):

- direct evaluator: 43.3 ms per batch (repeats: 40.9-45.1 ms)
- analyzer: 53.9 ms per batch (repeats: 47.4-53.9 ms)
- ratio direct/analyzer = 0.80 on the recording run, 0.80-0.94 over five
  runs: the analyzer ran 1.06-1.25x SLOWER every time, with both
  orderings of warm-up.

Why the book's expectation inverts here: the edition's direct evaluator
is already a compiled dispatch loop (a `when` over a sealed expression
type that unwinds tail positions in constant host stack), so the
re-dispatch work that analysis exists to hoist out is already cheap,
while the analyzer pays, on every compound-procedure application, an
identity-table lookup for the analyzed body plus a chain of closure
calls that the direct loop replaces with one environment extension and a
loop hop. The book's modest analyzer win was measured against a naive
tree-walking `eval` with list-based dispatch; against this evaluator,
analysis buys no measurable advantage on tree recursion.
