## The answer

Build four self-contained editions of SICP in the `modern-sicp` monorepo, one each in Rust (edition 2024 on Rust 1.98.1), OCaml (5.5.1, Stdlib main text with a Jane Street Base and Core appendix per chapter), TypeScript (7.0.2 with Effect 4.0.0-rc.117 on Node 24 LTS), and Kotlin (2.4.20 on JDK 25 with Arrow 2.2.3). Each edition covers all five chapters and all 356 exercises, opens with a Chapter 0 primer of about thirty pages that teaches only the language subset the book uses, keeps SICP's section and exercise numbering one to one, and re-cuts the prose of 3.2 (the language's own closure and ownership model), 3.4 (the language's own concurrency mechanisms), and 4.3 (the language's own search mechanism) where the language changes the lesson; 5.3 stays a memory simulation in every edition. Chapters 4 and 5 implement evaluators, a register-machine simulator, and a compiler for one shared Scheme subset in each host language, checked against one shared conformance corpus partitioned by capability. Every listing, exercise scaffold, and reference solution lives in the edition's `examples/`, `exercises/`, and `solutions/` directories and runs under that language's test gate; an unsolved scaffold never turns the gate red. The source stays Texinfo: stock Texinfo 7.3 builds HTML, EPUB 3, and PDF per edition with MathML math and Pygments highlighting, and the custom 2014 machinery (vendored Texinfo 5.1, PhantomJS math, prettify, Ruby and Perl scripts) is cut. Text and figures stay CC BY-SA 4.0; the three code trees are GPL-3.0-only under the compatibility Creative Commons declared; original tooling is MIT. Authoring is staggered lockstep: Rust writes each section first, the other three editions follow one section behind, and each chapter closes with a sync note. The site publishes as sections land: the landing page and the Pages deployment exist from Phase A, the section 1.1 prototype is the first published content, and each chapter close publishes that chapter. A wayfinder map on GitHub issues with one ticket per chapter and edition tracks the multi-session build. Executing this plan means running the bootstrap phase (Phase A), creating the map and the first tickets, and stopping; every later phase is a ticket that an agent executes from this plan and its companions.

## Edition design

### Shared decisions across the four editions

- Object language for chapters 4 and 5 (D9): the SICP Scheme subset. Data: integers, floats, booleans, strings, symbols, pairs, the empty list, primitive and compound procedures. Special forms: `quote`, `define`, `set!`, `if`, `cond` (derived), `lambda`, `let` (derived), `begin`, `and`, `or`, `delay`, `cons-stream` (lazy chapter), `amb`, `require`, `ramb`, `if-fail`, `permanent-set!` (nondeterministic chapter), and the query language of 4.4. `spec/scheme-subset/grammar.md` fixes the core grammar plus the `lazy`, `amb`, `query`, and `machine` subgrammars; `spec/scheme-subset/printer.md` fixes the printed form of booleans (`#t`, `#f`), symbols, strings (double-quoted), pairs and lists, the empty list (`()`), compound procedures (`#[compound-procedure name]`), primitives (`#[primitive-procedure name]`), errors (`Error: <message>`), query results (one per line in the book's order), machine traces (`register = value` lines), and LF line endings; `manifest.txt` assigns each program a capability (`core`, `lazy`, `amb`, `query`, `machine`, `compiler`), its output mode, and the evaluators that must run it. Core programs run under 4.1 metacircular, 4.1.7 analyzing, 5.4 explicit-control, and 5.5 compiled code; `lazy` under 4.2; `amb` under 4.3 with the solution order fixed; `query` under 4.4; `machine` programs are controller texts with expected register traces under 5.2; `compiler` programs compare 5.5's compiled output with 5.4's. `programs/core/metacircular.scm` is the chapter 4 evaluator in the object language (D23). Each edition's chapter 4 and 5 test suites read the manifest directly.
- Reader and printer (D23): each edition supplies an S-expression reader and a printer as given code in `examples/ch4/`, presented in an appendix note the way SICP JS presents `parse`; the text does not derive them.
- Pairs and empties (D20): chapters 1 and 2 use the host's native immutable data; the mutable pair type of 3.3 is the pair of the `Value` type in chapters 4 and 5; one object-language `nil` is the empty list and the base of the environment chain; typed host streams and environments have their own empties, named in each companion (Rust `Stream<T>` is non-empty typed with `Option<Env>`; OCaml `Nil` and `Cons` streams; Kotlin `VNil` and `SNil`). Identity (`eq?`) is pointer identity: `Rc::ptr_eq`, `==`, `===`, `===`.
- Unassigned inhabitant: the evaluator's environment has a distinct unassigned marker for scanned-out internal definitions (4.1.6), never `None` or a default.
- Streams (D18): `delay` builds a memoized thunk; `cons-stream` is a function that takes the tail as a thunk; the demand-driven trace of 3.5.1 is kept; the host's cold sequence appears once, as a comparison, and never carries a book example.
- Data-directed dispatch (D19): `put` and `get` on a table keyed by the operation name plus the ordered list of type tags; `get` on a missing key returns the absent option, never `false`; `put` overwrites; handlers return the edition's typed error; `apply-generic` raises it.
- Numbers: fixed-width integers and floats in the host (`i128` checked and `f64`; `int` and `float`; `number` with `bigint` where the book exceeds 2^53; `Long` checked and `Double` with `BigInteger` for exact rationals in 2.5); no bignum library in Rust or OCaml; overflow is discussed once, in 1.2, where the book's Scheme relies on bignums, and exercises 1.25 and 1.26 become the overflow demonstration in Rust and OCaml. `random` is a seeded xorshift64* in every runtime (D31).
- Tail calls: OCaml guarantees them; Kotlin uses `tailrec`; Rust and TypeScript express iterative processes as loops and say so in 1.2; the chapter 4 evaluators in Rust and TypeScript say that they are not tail recursive, as SICP JS does, and 5.4 restores tail recursion in the explicit-control evaluator.
- Errors: SICP's `error` becomes the edition's typed error: `Result<T, E>` with `thiserror`, `result` with a variant, Effect's error channel with `Schema.TaggedError` (a plain `Result` in chapters 1 and 2), Arrow `Either` with `Raise`. The rule holds in chapter 5: `Machine.run` returns the typed error for an absent operation or an invalid instruction, and the corpus has a case for each.
- Concurrency (3.4, re-cut): Rust `std::thread::scope`, `Arc<Mutex>`, `AtomicBool::compare_exchange`, `Condvar`; OCaml `Domain.spawn` and `Mutex.protect`; TypeScript Effect fibers, `Effect.all` with concurrency, `Semaphore`, and `Effect.tx` with `TxRef`; Kotlin structured coroutines, `Mutex`, `AtomicBoolean.compareAndSet`, a token channel for the 3.47 semaphore. The serializer is one mutex around a function in all four; `parallel-execute` returns a handle whose `halt` sets a shared flag the workers poll (D32); exercises 3.38 to 3.49 keep their numbers.
- Environment model (3.2, re-cut): each edition draws frames for its own closure model; Rust adds ownership and borrowing of captured state; exercises 3.9 to 3.11 keep their numbers and become closure-capture and pointer-identity drawings.
- Nondeterminism (4.3, re-cut, D25): the search mechanism is the host's own; `try-again` is a solution iterator in the typed editions; exercises 4.35 to 4.54 keep their numbers.
- Picture language (2.2.4): painters are functions from a frame to segments; output is SVG written under `book/figures/generated/`; the generated figures are checked in so the book builds without running examples.
- Symbols and quotation (2.3.1): an interned `Symbol` newtype in Rust, `Symbol of string` in OCaml, a branded string type in TypeScript, a `value class Symbol` in Kotlin; quoting a list is a helper that builds the list of symbols.
- Interaction display (D29): the source prints results as `@i{…}` lines after the expression. Each edition shows the definition, the call, and the result in one `@example <language>` block. The result is a comment line with a `=>` marker: `// => 441` in Rust, TypeScript, and Kotlin; `(* => 441 *)` in OCaml. The marker keeps results valid comments in every format and readable in the unhighlighted PDF. Printed output lines (`for-each`, probes, `display-stream`) are comment lines without the marker, in order, then the returned value with the marker; a call with no useful value ends `// => ok`; strings print double-quoted; from 4.1 on, compound procedures print `// => compound-procedure` and errors print `// => Error: <message>`; a wrapped result ends with a comment line holding only the comment opener and an ellipsis. Each companion fixes its call-line shape (OCaml keeps the utop form with inferred types); Rust has no REPL, so its call line is a comment naming the example that printed the result. Section 0.8 states the convention and shows one worked example per format. The same value is asserted in the `examples/` test, so the printed outputs are true by construction.
- Highlighting theme: `text/assets/css/highlight.css` is the one Pygments theme for all four languages, assembled into both stylesheets. Result lines are comments, so Pygments renders them in the comment style; that is intended. Class map: keyword `.k .kd .kr` #5a3696; type and class `.kt .nc` #7a3e00; string `.s .s1 .s2 .sc` #2f6b2f; number `.m .mi .mf .mh` #8a4b08; builtin `.nb` #0b5fa5; function name `.nf .fm` #383838 bold; comment and results `.c .c1 .cm .cp` #6a737d italic; operator and punctuation `.o .p` #383838; lexer error `.err` #b00020. Every color meets WCAG AA contrast against the page background. Code keeps the book faces (Inconsolata LGC at the existing size).
- Chapter appendix per edition: sections 2.4, 2.5, 3.3, and 4.1 close with an "In this language" note set as a quotation block whose first line is `@strong{In this language: <topic>.}`, where `<topic>` names the host mechanism. The note runs at most fifteen lines: one paragraph naming the host mechanism, one short typed sketch, one sentence saying when the book's table mechanism still wins. It sits after the section's last prose paragraph and before its first exercise; `tools/closing_notes_check.py` fails `just book` when a required note is missing. The OCaml edition closes every chapter with the Base and Core appendix in this fixed six-subsection format: Base translation; Core translation; Errors; Collections; Data interchange; Tests (D5).
- Term index: the adapted prose keeps every `@newterm` and `@cindex` of the source paragraph and adds `@newterm` for each host-language concept the section introduces, so the Term Index stays complete per edition.

## Exercise policy

- Numbering is 1:1 with SICP in every edition (D4, D24). A tailored addition is numbered as the exercise it extends plus a lowercase letter and sits right after it; at most one addition per section per edition, chosen at unit start from the map's idea column and recorded in the map (D30); a second addition per section never happens.
- Every exercise carries one of three classes per language, fixed in `docs/exercise-map.md`: `T` translate (syntax changes only), `A` adapt (the idea survives, the statement changes, the reason is recorded), `R` replace (the exercise is about Scheme itself; a language-tailored exercise under the same number replaces it).
- Reader-facing signposts are fixed sentences. An `R` statement opens with `@emph{SICP exercise N.M is about Scheme itself, so this edition replaces it; the exercise below keeps the number and teaches the same section material.}` An addition opens with `@emph{Exercise N.Ma is added by this edition and extends exercise N.M; SICP numbers stop at N.M.}` Anchors follow the numbers (`@anchor{Exercise N.Ma}`).
- Map overrides are recorded in the map's policy header: 2.5 uses checked `u128` in Rust and 63-bit `int` in OCaml with the overflow bound stated in the statement, `bigint` in TypeScript and `BigInteger` in Kotlin (D14, D17); 2.86 uses a trait defined in the section, not `num-traits`; 2.74 and 2.75 in TypeScript use plain unions, not `Schema` (D33); 5.50 and 5.52 compile `programs/core/metacircular.scm` (D23); fourteen chapter 4 rows classified from context are confirmed by the unit that writes the section.
- Every exercise has three artifacts in every edition: the statement in `book/`, a pending scaffold in `exercises/`, and a reference solution with passing tests and a rationale in `solutions/`. Tests are property, boundary, or transition tests that a plausible bug would fail; a solution with no observable contract (a diagram, a proof, a discussion) has a Markdown answer and no test, and the map marks it `prose`.
- Scaffold contract (D28). Rust: `crates/chNN/exercises/sec_X_Y.rs` compiled by a dedicated `[[test]] name = "scaffold_sec_X_Y"` target, each test `#[ignore = "pending solution"]`. OCaml: the signature in the `sicp_chN_exercises` library plus a pending executable under `(alias (name scaffold))` that `dune runtest` never runs. TypeScript: `packages/chN/exercises/ex_N_MM.test.ts` with `test.todo`. Kotlin: `src/exercises/kotlin/.../E*.kt` with an exercises test source set, `@Disabled("pending solution")`; the `exercises` and `solutions` source sets are attached to `check` by explicit compile tasks (compile-only for exercises), because a source set with no attached task compiles nothing. - `tools/exercise_map_check.py` fails when any edition lacks any of the three artifacts for any of the 356 numbers plus its chosen additions, when an exercise exists on disk that the map does not list, or when a section's counts differ from the map.
- Chapter 0 exercises (0.1 onward) and tailored additions are original work and are marked as such in the map.

## Work breakdown

The unit of work and of commit is one section of one edition; the unit of tracking is one chapter of one edition (D26). Sizes: S (at most 8 exercises, no hard spot), M (9 to 20 exercises), L (more than 20 exercises or a hard spot). A hard spot is any section whose mechanism the shared decisions re-cut or whose companion marks it hard: 2.2, 2.4, 2.5, 3.2, 3.3, 3.4, 3.5, 4.1, 4.3, 4.4, 5.2, 5.4, 5.5. One S or M unit is one agent session; an L unit is two or three sessions, each a named slice on the chapter ticket's checklist, each starting from the previous committed state. 88 section units plus 4 primer units.

Staggered lockstep in practice: the Rust unit for section N.M commits first and posts a section note on the chapter ticket (re-cut applied or not, `R` replacements written, chosen addition, corpus deltas, map row changes); the OCaml, TypeScript, and Kotlin units for N.M start from that note; a red gate in one edition never blocks the other three; the chapter close is one commit that reconciles the four editions' map rows and writes the sync note on the four chapter tickets.

Unit contract (every unit, every edition):

1. Read the section in `text/split/`, its rows in `docs/exercise-map.md`, its notes in `docs/plan/idiom-<language>.md`, and, for a follower edition, the Rust section note on the chapter ticket.
2. Write `examples/` for every listing in the section, with the printed outputs asserted.
3. Adapt the prose in `book/`: keep the section structure; replace every Scheme listing with the edition's listing in an `@example <language>` block under the interaction convention (D29); rewrite sentences that speak about Scheme; preserve every `@newterm` and `@cindex` and add `@newterm` for new host concepts; add the closing "In this language" note where the shared decisions call for it; apply the re-cut where the companion records one. A companion sketch is pseudocode until this unit compiles it.
4. Write `exercises/` scaffolds and `solutions/` for every exercise number in the section, plus the one chosen addition, with the signposts on `R` rows and additions.
5. Run the language gate, `tools/exercise_map_check.py --lang <lang> --section N.M`, and `just book` for the edition.
6. Commit atomically per concern (examples, prose, exercises and solutions), tick the section on the chapter ticket, post the section note (Rust) or the divergence note (followers), and record any map change in the same commit.

## Tool interfaces

Every script under `tools/` runs from the repository root with `uv run tools/<name>.py`, uses `argparse` with `--help`, prints its report line on stdout and diagnostics on stderr, and exits 0 on pass, 1 on a failed check, 2 on usage error. Each has a pytest suite covering its arguments, its exit codes, and its report format.

- `split_texi.py --src text/original/sicp-pocket.texi --out text/split --figures-rel ../../text/original/figures`: the split of step 2 with its manifest and the join-inverse byte comparison; the join-inverse test is written before the split itself.
- `texi_indexes.py --tree <lang>/book [--check]`: regenerates `back/exercises.texi` and `back/figures.texi`; `--check` writes nothing and exits 1 when either file is stale.
- `parity_check.py [--split text/split] [--tree <lang>/book]`: prints the parity line of step 4; with `--tree` it also runs `texi2any --html` and counts undefined references; exits 1 when `texi2any --version` is not 7.3.
- `figures_pdf.py --src text/original/figures --out text/original/figures/pdf [--check] [--jobs N]`: `rsvg-convert -f pdf` per SVG, skipping outputs newer than the source; `--check` exits 1 on missing or stale PDFs; exits 1 when `rsvg-convert` is absent.
- `exercise_map_check.py [--lang rust|ocaml|typescript|kotlin] [--section N.M]`: parses `docs/exercise-map.md` and checks the three artifacts per number for all editions or the named one, including Chapter 0 exercises and chosen additions; the statement check is the `Exercise N.M` anchor in `<lang>/book/ch*/`; one line per defect (`rust 1.7: missing solutions test`); exits 1 for an exercise on disk that the map does not list.
- `build_css.py --assets text/assets/css --out <lang>/book [--font-url-prefix <prefix>]`: writes `book.css` and `book-epub.css` as step 5 describes; exits 1 when an `@import` survives.
- `check_html_assets.py --html <lang>/book/_build/html`: every `img` or `object` `src` and every CSS `url()` resolves to an existing file; prints `pages=<n> images=<n> fonts=<n>`; exits 1 on the first unresolved reference. The prototype ticket records the one chosen URL convention (root-relative for the site) and this script enforces it from then on.
- `epub_manifest_fix.py --epub <file>`: rewrites the OPF inside the zip in place: `image/svg+xml` for `.svg` items, `properties="mathml"` on XHTML items containing `<math`, `mimetype` kept first and stored; prints `svg_items=<n> mathml_docs=<n>`; idempotent.
- `edition_switcher.py --html <lang>/book/_build/html --edition <lang>`: injects `<nav class="editions">` into every page linking to the same section file in the other three editions; the mapping is mechanical because section numbers and node names are 1:1; exits 1 when a page has no counterpart.
- `closing_notes_check.py --tree <lang>/book`: sections 2.4, 2.5, 3.3, and 4.1 contain a quotation block starting `@strong{In this language:`; exits 1 otherwise.
