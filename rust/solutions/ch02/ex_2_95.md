# Exercise 2.95: the integer-arithmetic failure

## Approach

The solution builds `P_1 = x^2 - 2x + 1`, `P_2 = 11x^2 + 7`, and
`P_3 = 13x + 5` as plain integer term lists, multiplies out
`Q_1 = P_1 P_2 = 11x^4 - 22x^3 + 18x^2 - 14x + 7` and
`Q_2 = P_1 P_3 = 13x^3 - 21x^2 + 3x + 5` with a term-list `mul_terms`
(2.94's file had no use for one; building the products needs it), and
runs 2.94's `gcd_terms`, unmodified, on the pair. With exact rational
arithmetic the Euclidean-style loop would divide out to something
proportional to `P_1`. This edition's `div_terms` insists on an exact
integer quotient at every step, and the very first quotient coefficient
it tries is 11 divided by 13, so the computation stops immediately with
`type mismatch: div_terms: 11 does not divide evenly by 13`. The test
asserts both products term by term and that exact failure message:
instead of drifting into limited-precision rational coefficients, this
edition fails outright, its own shape of the footnote's "we may fail to
get a valid divisor."

## Map class

`T`: the row is a straight translation, and the solution keeps the
book's objects (the three polynomials, their two products,
2.94's `gcd_terms`) and the book's outcome, an unusable GCD computation,
in this edition's term-list types.

## Deviation

The book's system quietly introduces noninteger coefficients; this
edition's integer-only `div_terms` raises instead, so the exercise is
answered by capturing that failure rather than by printing a wrong
polynomial. The exercise's substance, that plain `gcd_terms` cannot
handle `Q_1` and `Q_2`, is preserved.
