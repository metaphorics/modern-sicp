# Exercise 3.46: test-and-set race window

## Approach

The book asks what happens when `test-and-set!` is an ordinary
procedure, without atomicity. The failure lives between the read of the
cell and the write, so the racy variant makes that window one explicit
fiber suspension: read, suspend, write. The mutex is the book's retry
protocol over it, with the parking behavior the footnote describes
instead of a burning loop, and a stress of 25 trials with two processes
each counts how often both end up inside the critical section at once.
The control reruns the stress on the module's atomic mutex, whose
test-and-set is one synchronous step that nothing can preempt.
Mechanism: real Effect fibers; the interleaving is scheduled, not
simulated.

## Pins

Computed: all 25 racy trials saw both processes inside at once -- the
timing diagram of the failure is: process A tests the cell and finds it
false; A suspends in the window; process B tests the same cell and also
finds it false; B suspends; A writes true and enters its critical
section believing it holds the mutex; B writes true and enters too.
Two holders, so the mutual exclusion the mutex was to provide is gone.
The atomic control over the same 25 trials answered 0 both-inside
trials: once a process's test comes back false, the cell is already
true before any other process can test it, which is precisely the
guarantee the text says must hold.
