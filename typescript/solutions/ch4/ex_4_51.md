# Exercise 4.51: reversible set! versus permanent assignment

## Approach

The same book counting program runs under two assignment forms.
Ordinary `=` restores the previous binding when its failure
continuation runs; `permanentAssign` leaves the write in place.
The distinct-pair requirement rejects equal x/y trials after the
counter increments, making those rejected writes the observable
difference. Both runs use the engine's real deferred-backtrack and
step counters; the failure totals agree because assignment kind
does not change the choice/require tree.

## Numbers

With reversible assignment, all six distinct pairs carry count 1.
With permanent assignment, they carry 2, 3, 4, 6, 7, 8: rejected
trials persist. The tests pin both complete answer lists, counter
parity, and completed status.

## Class and deviations

Translated row. The assigned excerpt is now run as actual guest
source under both forms; the host no longer models permanence or
backtracking. The exact `permanentAssign(target, value)` spelling
is the edition's named experiment form from the shared syntax
