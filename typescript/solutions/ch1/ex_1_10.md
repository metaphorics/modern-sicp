# Exercise 1.10: values of Ackermann's function

## Approach

Evaluate the three expressions straight through the given definition; no
new code is needed, only care with the nested self-call
`ackermann(x - 1, ackermann(x, y - 1))`, which makes the process
tree-recursive for `x, y >= 2`.

## Numbers

`ackermann(1, 10)` is `1024`, `ackermann(2, 4)` is `65536`, and
`ackermann(3, 3)` is also `65536`.

The concise mathematical definitions, for positive integer `n`:

- `ackermannF(n) = ackermann(0, n) = 2n`
- `ackermannG(n) = ackermann(1, n) = 2^n` (a doubling, `2^2` at `n = 1`)
- `ackermannH(n) = ackermann(2, n) = 2^2^...^2` (a tower of `n` twos; e.g.
  `ackermannH(4) = 65536 = 2^16 = 2^(2^(2^2))`)
- and `ackermannK(n) = 5n^2`, the statement's own example.

## Class and deviations

Translated row: the definition is unchanged except for syntax
(`cond` chains become guarded returns, `(A x y)` becomes
`ackermann(x, y)`). The test pins the three printed values plus one rung
of each wrapper's ladder, so a wrong definition of the wrappers or of
`ackermann` itself fails it.
