# Exercise 4.33: quote produces lazy lists (translate)

The map class is `T`. Ben's error is real: after the 4.2.3 definitions
shadow the pair primitives, `'(a b c)` is still an ordinary pair of the
shared runtime, and the procedural `car` applies its argument. The pair
is not applicable, and the typed error says so. The fix lifts the
`Quote` clause: a quoted proper list is rebuilt as the application of
the environment's own `cons` to the quoted elements and the quoted empty
tail, evaluated in the current environment, so the list the driver hands
out is the same lazy structure the program builds by hand; any other
datum stays ordinary data.

The demonstration: under the section evaluator with the 4.2.3
definitions installed, `(car '(a b c))` answers the not-applicable error;
under the lifted quote it answers `a`, `(car (cdr '(a b c)))` answers
`b` through the lazy spine, and the object-language `list-ref` walks the
quoted lazy list to `d`. The elements are quoted data wrapped by the
procedural `cons`, so they are forced only when used, the same rule the
program's own lists follow.

Sample: `ex_4_33 ()` answers
`["Error: not applicable: (a b c) is not a procedure"; "a"; "b"; "d"]`.
