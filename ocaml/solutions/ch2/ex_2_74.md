# Exercise 2.74 — division personnel files (adapt)

The map class is `A`: first-class modules model each division's own
record structure. `PERSONNEL_FILE` is the signature headquarters
needs from a division — `get_record` and `get_salary` — with `file`
and `record` left abstract, because each division's structures
really do differ. `division` packs a first-class `(module
PERSONNEL_FILE with type file = 'f and type record = 'r)` together
with a `'f` file value; `any_record` packs a module together with
the `'r` record it produced. Both existentially hide the type
parameters the GADT constructor names, so a `division list` can mix
divisions whose files and records share no structure at all.

**Part (a).** `get_record division name` is `name`'s record in
`division`, still paired with the module that can read it. The "type
information" a division must supply is exactly the first-class
module value: a division is data plus the functions that know what
the data means.


**Part (b).** `get_salary` applies whichever division's `get_salary`
produced the `any_record` it is given; the record's own type never
needs naming outside the module that produced it.

**Part (c).** `find_employee_record` tries the divisions in order,
returning the first hit. It raises `Invalid_argument` when no
division has the employee — the book's `error` call, ported as
directly as OCaml allows: an unhandled failure, not a value the
caller must check.

**Part (d).** Taking over a new company costs one line at the call
site: `make_division (module New_division) file :: divisions`. No
existing division's module, no signature, and no function above
changes; the type-hiding `division`/`any_record` wrappers are exactly
what makes this possible, mirroring the data-directed table's own
"install a package, touch nothing else" story.

Sample: two divisions, one keying records by name in a `Hashtbl` of
plain fields, the other keying them in an association list of a
different record shape, both answer `find_employee_record` and
`get_salary` through the same two functions.
