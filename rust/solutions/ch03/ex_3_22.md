# Exercise 3.22: the queue as a dispatch closure

## Approach

The book rebuilds the queue as a message-passing object and asks for
the queue operations as dispatch clauses over shared local state.
The Rust solution writes `make_queue` as one closure over a `Queue`
handle, with `QueueMsg` clauses for `Insert`, `Delete`, `Front`, and
`Empty`. It runs the book's sequence, two insertions, a deletion,
one more insertion, and reports the front `b` and the items
`[b, c]`. The tests cover the empty-queue error path and the state
question the exercise is about: a second queue from the same factory
holds separate state, while two names for one closure share it.

## Map class

`A: shared nodes and state via RefCell`. The state the closure
captures is the front/rear pointer pair of the section, shared
because the closure holds its `Rc` handle, and the two-queues test
is that fact made visible.

## Deviation

None. The book's messages, sequence, and answers are kept; the
`QueueMsg` enum is the dispatch vocabulary the exercise's `define`
clauses become.
