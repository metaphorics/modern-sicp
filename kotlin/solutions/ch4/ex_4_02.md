# Exercise 4.2: applications-first order and the `call` sugar

## Lesson

Louis checks the application clause before assignment and definition,
so a definition evaluates as an application of the unbound operator
`define`. The kernel's typed dispatch keeps the lesson sharp: the
variant dispatcher checks `GApp` first, a use of `define` in operator
position fails unbound, and the kernel's own binding forms route by
their own tags whatever order the application clause takes. Part (b)
lowers `call(operator, operand)` to the kernel's single-argument
application.

## Map class

`A` (map row 4.1: dispatch order). The failure mode survives as an
operator-position lookup; the kernel forms are immune by construction.

## Deviation

None. No parser is involved: the sugar is a guest rewrite over kernel
data, evaluated by the untouched kernel.

## Answer

- Applications-first: `define` in operator position fails, `GLet`
  answers `3`, `GSet` answers `true`.
- `call` on the square procedure answers `49`.
- Pin: `louisDefineTranscript() == "error\n3\ntrue\n"` and
  `callSugarTranscript() == "49\n"`.
