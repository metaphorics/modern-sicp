# Exercise 3.1: an accumulator keeps a running sum

## Approach

`make_accumulator` returns a closure that owns its running sum and sees it
mutably on every call (`move |value| { sum += value; sum }`), which is
`make_withdraw` from the section body with the balance check removed. The
test pins the book's interaction (5, then 15, then 25) and checks that two
accumulators built from the same initial value stay independent, since
independence is the part a plausible bug (capturing the sum by reference to
a shared cell) would break.

## Map class

`T`: the statement translates directly; the closure-with-owned-state pattern
is the section's own `make_withdraw` idiom.

## Deviation

None. The book's `A` becomes a bound closure so the test can call it twice;
the pending scaffold mirrors the same two observable answers.
