# Exercise 4.19: the internal definition scoping debate

## Approach

One body, three rules. Sequential keeps the engine's own application;
the guest runtime pre-binds internal names as uninitialized cells, so
this reading settles on Alyssa's side — the sibling read faults with
TDZ rather than silently seeing an outer binding, and the old
sequential answer is unreachable in this guest by construction.
Scanned is the 4.16 mechanism and answers the same fault. Eva's rule
is implemented as simultaneous definitions whose value expressions see
each other's final values: every internal name is pre-bound
uninitialized, and reading one forces that name's value expression in
the current frame and memoizes the value by writing it back; forcing a
name already being forced is a circular-definition error. The forcing
reader covers the expression forms a value expression can use.

## Numbers

The book's `const b = a + x; const a = 5; return a + b;` over outer
`a = 1` with `x = 10`: `error:tdz-access:a` under the sequential rule,
the same `error:tdz-access:a` under the scanned rule, and `20` under
Eva's rule — forcing `a` to its final value `5` gives `b = 15` and the
answer `a + b = 20`. Ben's `16` needs sequential define semantics the
typed runtime excludes; the runtime settles the debate on Alyssa's
error. A cyclic pair (`a = b`, `b = a`) answers
`error:bad-operand: circular definition: a` instead of hanging.

## Class and deviations

Translated row. Deviations: the `*unassigned*` marker is the runtime's
real uninitialized cell, so the error category is `tdz-access`; Eva's
semantics is a reading, not a single recipe, and this edition
implements it as on-demand forcing with memoization per call frame,
with cycles rejected; the sequential rule delegates to the engine
unchanged.
