# Exercise 1.5: applicative-order versus normal-order termination

## Approach

The answer is carried empirically. `test(0, p())` evaluates the argument
expression `p()` first - the host is applicative-order - and that
evaluation diverges; the observable end is the host's stack-overflow
RangeError, not `0`. The `testThunk` stand-in states the counterfactual:
taking `y` as a thunk and running it only when `x` is not `0` is exactly
what normal order would do, and a called-flag proves the thunk is never
run for `x = 0`.

## Numbers

`test(0, 5)` is `0` and `test(1, 9)` is `9`; `test(0, p())` throws
RangeError; `testThunk(0, thunk)` returns `0` with the flag still false,
and `testThunk(2, () => 9)` returns `9`.

## Class and deviations

Translated row. The code translates with one spelling note: `p` returns
`never`, the type of an expression that never finishes, which is the
closest thing the host has to the book's diverging definition. No other
deviation.
