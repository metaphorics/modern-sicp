# Exercise 3.8: operand evaluation order is defined

## Approach

The probe is the book's `f`: it answers its argument on the first call and 0
on every call after, so `f(0) + f(1)` sums first-answer 0 and second-answer 0
only when the left operand goes first, while a fresh probe's `g(1) + g(0)`
sums 1 and 0 under the same rule. The map class is `A`: Scheme leaves the
order unspecified, which is the exercise's premise, but Rust defines operand
evaluation left to right, so the statement changes from "design f that
returns 0 or 1 depending on the order" to "verify the defined order" — the
sums come out 0 and 1 respectively, and the test pins both.

## Map class

`A` (order defined; exercise verifies it): the idea survives, the statement
changes because the uncertainty the original exercises is gone.

## Deviation

None.
