# Exercise 4.77: delayed filtering for not (translate)

## Approach

Negation as failure goes wrong on unbound variables: `not` with a
free variable filters against answers the variable could still take.
The solution pairs each delayed `not` with its variable list and
holds the filter until every variable is bound, then runs the
negated query in the extended frame and keeps the frame only when it
fails.

## Numbers

With `?x` unbound the filter is not ready and forcing it throws the
waits error; with `?x` bound to `bob` the `(blocked ?x)` query fails
and the frame survives; with `?x` bound to `alice` it succeeds and
the frame is rejected. The tests pin all three outcomes.

## Class and deviations

Translated row. Deviation: readiness checks bindings with an
unbound-preserving instantiation, because the default contracted
form would hide unbound variables as symbols; the core engine
itself is untouched.
