# Exercise 4.70: the let binding in add-assertion! (translate)

## Approach

The book's `add-assertion!` wraps the stream extension in a `let` so
the extended assertion stream is built once and the delayed tail
reuses it. Without the binding, each forcing of the tail would
re-run the extension: on a self-referential assertion stream that
repeats the insertion forever instead of once. The solution models
the mechanism directly: capture the extended value in a closure and
prove the extension runs exactly once no matter how often the tail
is forced.

## Numbers

The extension runs once at construction (`calls` is 1 before any
forcing) and every forcing returns the same captured value with no
further calls. The tests pin the single call and the stable tail.

## Class and deviations

Translated row. Deviation: the mechanism is modeled as a standalone
closure rather than engine surgery on the assertion stream.
