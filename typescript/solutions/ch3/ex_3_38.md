# Exercise 3.38: interleaved balance outcomes

## Approach

Each command is the book's three-step `set!`: access the balance, compute
the new value, set it. The edition spells the three steps as a generator
process (Mary's expression gets two separate accesses, so an interleaving
can change the balance between them) and runs the schedules through the
module's step scheduler. Part 1 runs the six permutations with each
process's steps contiguous; part 2 runs all 1680 interleavings of three
three-step processes, one at a time, and collects the distinct finals.
Mechanism: explicit step-scheduler enumeration; the single-threaded
runtime cannot interleave two machine steps on its own, so the schedules
are the hardware's freedom made executable.

## Pins

Sequential order, in permutation order (Peter, Paul, Mary = 0, 1, 2):
PQM 45, PMQ 35, QPM 45, QMP 50, MPQ 40, MQP 40, so the distinct
sequential values are {35, 40, 45, 50}. The interleaved set over all
1680 schedules is {25, 30, 35, 40, 45, 50, 55, 60, 65, 70, 80, 90, 110};
the values only interleaving produces are {25, 30, 55, 60, 65, 70, 80,
90, 110}. The 110 replay is Figure 3.29's shape: Mary and Peter both
access 100, Mary writes 50, Peter writes 110 last from the stale access
(order 0,2,0,2,2,0). The 25 is the chained case: Mary's minuend access
sees 100, Peter's write lands, Mary's subtrahend access sees 110, Mary
writes 45, and Paul spends that stale 45 down to 25.
