# Exercise 5.13: deriving the register list from the controller

The exercise asks for a machine that needs no hand-written register
list. This edition derives it from the controller text with
`controllerRegisters`, the assembler's own scan: every assign target,
every register source anywhere (assign sources, test and perform
operands), every `goto (reg r)` register, and every save and restore
register. The machine can then allocate registers as the assembler
first names them (`makeMachineDerivingRegisters`, the `Machine`
constructed with `deriveRegisters`), so a register the controller
names but the constructor was not told about is allocated at first
sight instead of faulting.

`E5_13.kt` runs the gcd controller both ways in one machine:
`derivedRegisterRuns()` reports the scan's answer, the run's result,
and the registers actually allocated. The pins are
`derived registers: a b t` (the scan finds exactly the three
registers, no flag: the flag is the machine's own register that
`test` and `branch` share), `gcd(206, 40) = 2` (the hand-listed
machine of 5.7 answers the same), and `allocated registers: a b t`
(first-sight allocation allocated exactly the derived set and nothing
more).
