# Exercise 2.89: dense term lists

## Approach

The dense representation stores one coefficient per order: a `Dense` term list holds a `coeffs: Vec<i128>` whose first slot is the highest order and whose last slot is the constant term, so order is never stored, position in the vector is the order. The invariants live in the constructor. `adjoin_term` conses a new leading term onto the front and fills every order between the new term and the list's current top with explicit zero coefficients, which is where the representation pays for its density: those gap zeros are stored, never skipped. `from_pairs` folds the pairs through `adjoin_term`, and `to_pairs` reads the stored orders back out.

The term-list algorithms are written only against `is_empty`, `first_term`, `rest_terms`, and `adjoin_term`, the same four operations the sparse package uses, so `add_terms` and `mul_terms` read like the book's versions with no knowledge of how zeros are kept. `mul_term_by_all_terms` handles the scalar-times-list piece of multiplication.

The probes cover addition, multiplication, and the representation's signature cost. `(x^2 + 3x + 7) + (5x^2 + 3x)` gives `[(2, 6), (1, 6), (0, 7)]`; `(x + 1)(x - 1)` gives `[(2, 1), (1, 0), (0, -1)]`, keeping the cancelled `x` coefficient as an explicit zero; and `x^3 + 1`, whose input pairs skip orders 2 and 1, reads back as `[(3, 1), (2, 0), (1, 0), (0, 1)]`. That last list is the dense contract stated as data: a genuine internal gap becomes stored zero-coefficient terms a sparse list would never contain.

## Map class

`A`: dense term lists as Vec with invariants. The `coeffs` vector with its position-is-order rule, gap-filling `adjoin_term`, and paired `from_pairs`/`to_pairs` is exactly that class made concrete.

## Deviation

None.
