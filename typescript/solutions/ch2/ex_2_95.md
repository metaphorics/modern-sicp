# Exercise 2.95: where integer arithmetic fails the gcd

## Approach

The book's P1 = `x^2 - 2x + 1`, P2 = `11x^2 + 7`, P3 = `13x + 5`, with Q1 =
P1 P2 and Q2 = P1 P3, share the factor P1. But the Euclid run never reaches
it under the edition's exact integer arithmetic: the first division step of
gcd-terms(Q1, Q2) divides the leading coefficients 11 by 13, truncation
answers 0, the quotient term contributes no terms, and the step subtracts
nothing: the algorithm would hand the same pair back to itself forever.
The run is therefore examined exactly one step deep, replicated through
`firstDivisionStep`; `remainder-terms` is never called on Q1 and Q2, by
design, because the call does not terminate.

## Numbers

Q1 = `(polynomial x (4 11) (3 -22) (2 18) (1 -14) (0 7))` and Q2 =
`(polynomial x (3 13) (2 -21) (1 3) (0 5))`; the first step's `newC` is
`div(11, 13)` = 0, its product is the empty term list, and its dividend is
bit-identical to Q1: the cycle evidence. The book's fallback observation
(an exact-rational implementation answers with rational coefficients; a
limited-precision one may answer nothing valid) is recorded in the prose.

## Map class

T (translate), with the edition's truncation making the failure mechanism
directly assertable.

## Deviation

The book asks for the gcd of Q1 and Q2 and to observe the wrong answer; this
edition observes the non-termination mechanism instead, since the truncated
run cycles before it can answer at all.
