# Exercise 5.21: the two count-leaves machines

Both machines run on the 5.2 simulator with the section's
`listOperations(memory)` installed: `null?` and `pair?` check only the
type field of the word in `tree`, and `car` and `cdr` go through the
index part of the pair pointer into `the-cars` and `the-cdrs`, exactly
the book's assumption that the list-structure operations are machine
primitives.

The tree itself lives in the memory. `plantTree` builds it through the
same allocation path the machines' `cons` uses: a leaf is the number
word itself, a node is the `e0`-terminated list of its planted
subtrees. Planting allocates innermost first, the same forced order
exercise 5.20 pins.

The machine of part (a) is the statement's recursive definition line
for line: `null?` answers 0, a non-pair answers 1, and the pair case
saves `continue` and `tree`, counts the car with a return to
`after-car`, then saves the car's answer in `temp`, counts the cdr,
and combines the two answers with `+`.

The machine of part (b) is the explicit-counter reformulation: `n` is
a register, the leaf case bumps it with `+`, and both subcalls share
it, so the only stacked words are `continue` and `tree` at each level.

`countLeavesRuns()` plants three trees and reads each machine's answer
beside the host oracle `countLeavesHost`, with the 5.2.4 monitored
stack meters pricing the recursion:

- `(1 2 (3 (4 5)))`: recursive `n5`, iterative `n5`, oracle 5;
  recursive stack `(total-pushes = 21 maximum-depth = 14)`, iterative
  stack `(total-pushes = 14 maximum-depth = 10)`. The recursive
  machine pays one extra saved word, the car's answer, for every pair
  whose car subtree was counted, which is the difference the counters
  show.
- `((7))`: both machines answer `n1`, oracle 1; recursive stack
  `(total-pushes = 6 maximum-depth = 4)`, iterative stack
  `(total-pushes = 4 maximum-depth = 4)`.
- `()`: both machines answer `n0`, oracle 0, with empty stack lines:
  the null case falls straight through to `count-done`.
