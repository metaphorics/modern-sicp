# Exercise 4.51: permanent-set! (T)

## Approach

The engine's assignment clause takes a trail kind. `set!` saves the old
value and records the undo entry -- the book's `*1*`/`*2*` pair, with
the restoration applied when backtracking crosses the assignment.
`permanent-set!` assigns and skips the record, so nothing ever restores
it. The book's program under `permanent-set!` counts every trial,
failed ones included, because each trial increments before its
`require` is tested. Under `set!`, the driver's `try-again` passes back
through the answered path's assignment interception -- the book's `*2*`
restoration -- so the count is restored to its pre-problem value before
the next alternative runs.

## Map class

`T`.

## Sample answer

`permanent-set!`: `(a b 2)`, `(a c 3)`, `(b a 4)`, `(b c 6)`, `(c a 7)`,
`(c b 8)` -- the gaps at 5 are the failed `(a a)` and `(b b)` trials.
`set!`: every answer reads 1 -- `(a b 1)`, `(a c 1)`, ... -- the count
the answered trial set, restored before its successor.
