# Exercise 5.36: operand evaluation order

The order in which a compiler evaluates call arguments matters when
an argument is itself a call. `CompilerOptions.leftToRightArguments`
turns the order policy both ways for `f(g("x"), y)`; each option
produces a separate typed instruction sequence. `operandOrderReport`
reports the statement and save-pair counts, checks that saves precede
their restores, and compares the compiled result with direct
execution. This probe has no side effects in its arguments, so its
answer agreement does not purport to observe an effect-order trace.
