# Exercise 1.25 — Alyssa's shortcut expmod (adapt: 63-bit overflow wraps silently)

The map class is `A`. In a language with unbounded integers, as Scheme's
usually are, Alyssa is right that her one-line `expmod` computes the
same mathematical function as the section's: both reduce
`base ** exp mod m`, and `fast_expt base exp mod m` is a correct, if
wasteful, way to compute it — wasteful because it builds the full power
`base ** exp` before reducing, a number with `exp * log2(base)` bits,
where the section's version never holds anything larger than `m^2`. In
Scheme's exact arithmetic this is only a performance complaint: still
`Theta(log n)` multiplications, but each on numbers that grow to full
size instead of staying capped at `m`.

In this edition it is a correctness complaint too. `int` is a signed
63-bit value, and `fast_expt` computes `base ** exp` with ordinary
wrapping multiplication: `expmod_correct 7 200 13` is 3, the true
remainder, while `expmod_naive 7 200 13` is 0, because `7 ** 23` already
exceeds `2^62 - 1` (`7 ** 22` is about `3.9 * 10^18`, still under the
bound; `7 ** 23` is about `2.7 * 10^19`, the first power past it, and
every multiplication after that point continues on wrapped, wrong values) and the wrap propagates silently through the rest of the
computation with no exception raised. Alyssa's version would not serve
as a prime tester in this edition: it reports a wrong remainder without
any signal that anything went wrong, exactly the failure mode a
primality test cannot afford.
