# Exercise 3.39: which serialized outcomes remain

## Approach

The program serializes only the multiplication; the assignment of its
result to `x` stays bare. The solution splits P1 into two forced steps
-- the protected square, which parks its product in a private slot,
and the bare assignment that stores the slot -- and P2 into the single
protected increment. Three schedules are possible and all three are
forced on real threads: square then increment (101), increment then
square (121), and square, increment, bare stale write (100). The
sorted set is [100, 101, 121]: 110 is gone because P1's two reads sit
inside one protected block, and 11 is gone because P2's increment is
atomic, so its write of 11 cannot land after P1's assignment.

## Map class

`T`. The partially serialized program and the five original
possibilities are the statement's own.

## Deviation

None. The three remaining values match the standard answer, and the
test also re-checks the fully serialized pair (101, 121) from the
section module's `X_RACE_SERIALIZED_VALUES` for contrast.
