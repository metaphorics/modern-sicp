# Exercise 5.9: no labels as operation operands

The book's base assembler accepts a label wherever a primitive expression
may stand, including the operands of an operation call, and hands the
operation the label's instruction address, a nonsense datum for
arithmetic. The strict seam lives in `operationExp`: with
`strictLabels: true` in the assembler options, an operand written
`(label x)` returns the typed `LabelOperand` error at assembly time,
before the machine exists. The check happens once, during assembly, not
on every simulated execution.

The base behavior is pinned too: the same controller assembled without
the flag computes the address. With `a` = 5 and the label first in the
controller, `(assign t (op +) (reg a) (label addr))` leaves 5 in `t`,
the address 0 added to 5. The rendered fault is the same sentence every
5.9 edition reports: an operation input is written `(reg r)` or
`(const c)`, not `(label b)`.
