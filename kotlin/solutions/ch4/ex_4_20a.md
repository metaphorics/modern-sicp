# Exercise 4.20a: nested shadowing under the reservation

## Lesson

While an inner scope's initializers run, the names it binds are
already in scope with no values yet: an inner reservation of `f`
shadows the outer recursive `f` from its first initializer onward,
and the initializer's call reads the empty inner binding. Read with
the outer binding in scope instead, the same call finds the recursive
procedure and answers.

## Map class

`A` (map row 4.1: shadowing). The reservation frame is built
explicitly; the contrast frame leaves the outer binding visible.

## Deviation

The inner scope is emulated with explicit frames rather than nested
binders, because nesting would bind -- not reserve -- the names. The
emulation is the point, stated here.

## Answer

- Shadowed initializer: failure on the empty inner `f`.
- Outer binding in scope: the call recurses to `1`.
- Pin: `shadowedPrematureReadTranscript() == "error\n"` and
  `outerScopeRecursionTranscript() == "1\n"`.
