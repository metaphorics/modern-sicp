# Exercise 2.58: infix notation

## Approach

Both parsers consume the section's quoted data and produce the section's
`Expr`, leaving `deriv` untouched. Part (a) assumes full parenthesization:
a three-item datum `(a op b)` parses recursively, with bare symbols and
numbers as leaves. Part (b) splits the flat token list at top-level `+`
(signs of the sum), then each part at top-level `*`, then parses
parenthesized groups recursively: the standard precedence.

## Numbers

For `(x + (3 * (x + (y + 2))))` the parse differentiates to
`makeSum(1, makeProduct(3, 1))`, which folds to the constant `4`. The
part (b) datum `(x + 3 * (x + y + 2))` parses to
`(+ x (* 3 (+ (+ x y) 2)))` and also differentiates to `4`.

## Map class

abstract-data argument become the parsers themselves; the differentiation
switch is reused unchanged.
