# Exercise 3.28: the or-gate as a primitive function box

## Approach

The book asks for an or-gate constructor similar to and-gate, plus the
logical-or the gates use. The edition builds both locally: `logicalOrExercise`
is the exercise's own two-input or, and `orGatePrimitive` mirrors the
and-gate shape, one action procedure attached to both input wires that
schedules `output := logicalOrExercise(...)` one `orGateDelay` after either
input changes. The circuit bundle (`buildPrimitiveOrCircuit`) exists so the
tests drive real wires through the module agenda instead of calling boolean
selectors.

## Pins

All computed by running against the module agenda. Probe attach records
`output = false` at time 0. One input rising answers true at time 5
(`orGateDelay`); both inputs rising in one propagate still yields exactly one
change event at time 5 because the wire only reports actual changes; an input
falling later reports the fall at time 5 relative to the new clock (10 in the
pinned run); with no input change nothing fires. The logical-or table is
pinned false/false false, false/true true, true/false true, true/true true.

## Map class

T (translate: syntax changes only).

## Deviation

The module already ships an `orGate`; the exercise intentionally re-derives
it from the and-gate shape with its own logical function, as the book asks,
rather than aliasing the module's constructor.
