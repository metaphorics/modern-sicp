# Exercise 3.32: the agenda segment is FIFO

## Approach

The book's `add-to-agenda!` appends a same-time action to the rear of its
segment's queue, so equal-time actions run in insertion order. The edition
measures both orders: `addToAgendaLifo` is a local variant of the module's
scan that pushes a same-time action at the FRONT of the segment's queue
(the module's segments and queues otherwise), interoperating with the
module's `propagate`, and `runSchedule` drives the same labeled schedule
through either add function.

## Pins

Computed by running. FIFO order for A@5, B@3, C@5, D@2 is D, B, A, C; the
LIFO variant gives D, B, C, A. The half-adder demo under a fully LIFO
agenda (local gate constructors scheduling through the LIFO add) prints
sum false and carry false at attach, then sum true at time 8, carry true
at 11, sum false at 16. The FIFO run of the same circuit (the module's
pinned sample) reports the sum at time 5 instead: the LIFO order fires the
time-2 inverter response's and-gate item at the front of the time-5
segment, before the or-gate's `d := 1` lands, so the sum waits for the
item d triggers rather than firing within d's own segment.

The book's warning stands: with LIFO segments the actions of one time run
against inputs the other same-time items have not produced yet, and the
measured run shows the visible effect, a delayed and reordered sum. What
the measurement does not show is a wrong final circuit: this demo settles
correctly under both orders, and the transient differs. The book's printed
sum-8 trace, incidentally, matches the LIFO artifact rather than the
module's FIFO run.
