# Exercise 3.49: ordering avoidance fails scenario (translate)

The map class is `T`. Numbering shared resources works only when a
process knows the full set it will touch before it starts. The
solution builds the scenario where it cannot: account `a` routes
overdrafts to account `b`, and `b` routes them to `a`, so each process
must hold its own account before it can even read which account comes
next. Two processes each take their own lock, only then learn the
other's account is their target, and both re-acquisition attempts are
refused: a deadlock no numbering prevents, because neither side could
have ordered its acquisitions without information it does not have
yet. The three facts (own lock held, second lock refused, deadlock)
are answered as one deterministic verdict.
