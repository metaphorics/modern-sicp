# Exercise 3.9 — stack growth of the two factorials (replace)

The map class is `R` for this edition: the SICP exercise asks for
environment diagrams of Scheme interpreter structures, so the edition
replaces it with the same question about OCaml's call stack, which the
section's re-cut makes the observable counterpart of the frame story.

Both factorials of 1.2.1 are restated and instrumented the same way: a
`deepest` ref records the largest depth any call passes through, and
each traced variant returns the plain result next to that depth. The
instruments encode the model's frame rule. The recursive call has a
pending multiplication, so the caller's frame stays alive and the
callee is handed `depth + 1`; `factorial_traced` therefore reports `n`.
The iterative call is its caller's whole result, so the callee's frame
takes the caller's place and is handed the same depth;
`factorial_iter_traced` therefore reports 1, and the language
guarantees the compiled loop follows the same rule — checked in
practice by running the plain iterative version at `n = 1000000`,
where linear growth would have exhausted the stack.

Sample: `ex_3_09 ()` runs both instrumented versions at `n = 6` and
answers `((720, 6), (720, 1))`, exactly the drawing the statement
calls for.
