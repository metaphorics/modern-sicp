# Exercise 2.45: split, the shared pattern of right-split and up-split

## Approach

`right-split` and `up-split` are one recursive procedure written twice,
differing only in two combining operations: how the painter joins the
branch, and how the branch joins its own two copies. `split` takes
those two operations as arguments and returns the depth-indexed
branching procedure - depth 0 is the painter itself, deeper depths are
`combiner(painter, subCombiner(smaller, smaller))`. The book's
procedures then fall out as one-line instances: `split(beside, below)`
and `split(below, beside)`.

## Numbers

At depth 2 on the module's wave over the unit square, both derived
splits agree segment-for-segment with the section's `rightSplit` and
`upSplit`, checked by walking every segment's endpoints. Depth 0
returns the painter itself: 18 segments, the wave's own count.

## Map class

`A`: the book's higher-order procedure becomes a TypeScript
function returning the split painter; structure and segment placement
are preserved, only the output medium differs.

## Deviation

None in substance: the briefed `showList` equalities were run and pass,
but `showList` cannot see inside a segment object (it renders each as
`[]`), so it pins only the segment count. The test therefore also
compares a coordinate-exact rendering of every segment, which is what
verifies the agreement claim.
