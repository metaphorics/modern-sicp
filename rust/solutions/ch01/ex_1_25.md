# Exercise 1.25

Alyssa is not correct, or at least not for Rust's fixed-width arithmetic.
`alyssa_expmod` needs the entire value of `base^exp` to exist before it can
reduce it modulo `m`; the book's `expmod` never lets its intermediates
leave the neighborhood of `m`, because it reduces after every
multiplication instead of at the very end. For a small case where the full
power still fits, both agree: `alyssa_expmod(3, 5, 7) = Some(5)`, matching
`3^5 mod 7 = 243 mod 7 = 5`. For a prime-sized case, `base = 1,000,002` and
`exp = 1,000,003`, `fast_expt_checked` overflows `i128` (whose full range
is about `1.7 * 10^38`, far short of a million-digit intermediate) well
before it produces an answer, and `alyssa_expmod` reports `None`.

The map class is `A`: "i128 overflows, debug panics." The book's unbounded
arithmetic makes Alyssa's version merely inefficient; Rust's bounded
arithmetic makes it wrong for any input the fast prime tester actually
needs, since primality testing runs `expmod` on exponents the size of the
number itself.
