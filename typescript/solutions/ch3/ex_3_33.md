# Exercise 3.33: averager

## Approach

The book asks for an `averager` built from the primitive multiplier,
adder, and constant constraints, establishing that `c` is the average
of `a` and `b`. The edition spells the same device as one primitive
constraint in the module's adder shape (the three-way arithmetic in
one `processNewValue` instead of a network of boxes), because the
constraint, not its construction, is what the exercise is about: any
two of the three values determine the third, `c = (a + b) / 2`,
`b = 2c - a`, or `a = 2c - b`. It follows the module's discipline
exactly: all three connectors are connected, a lost value withdraws
all three claims (only ones the averager itself set are lost) and
rechecks what remains, and a second, different value is the module's
`ContradictionError`, the book's `Contradiction` error.

## Pins

Fresh network each time. Setting a = 10, b = 20 makes c read 15.
Forgetting a withdraws the averager's claims: a and c are unset, but b
still reads 20 because its claim belongs to the user, not the
averager. Forgetting b too, then setting a = 10 and c = 25, makes b
read 40. On a fresh network, setting b = 40 and c = 25 makes a read
10. After a = 10, b = 20, c = 15, setting c to 20 throws the module's
`ContradictionError`.

## Map class

`T: primitive constraint in the module's adder shape, over the
module's connectors`.
