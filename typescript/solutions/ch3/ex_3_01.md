# Exercise 3.1: `makeAccumulator`

## Approach

The accumulator's local state is one `Ref` captured by the returned
procedure; a call is a single `Ref.modify` that adds the argument and
answers the new sum, the book's `begin` of increment-and-return
collapsed into one atomic update. Each call to `makeAccumulator`
creates its own cell, so independence of accumulators is structural.

## Numbers

The book's example: `makeAccumulator(5)` then calls with `10` and `10`
answer `15` and `25`. A second accumulator built at `100` moves `101`,
`102` without disturbing the first.

## Map class

T (plain port; TS in the map's note is spelled by the edition's D33
rendering, a `Ref` rather than a raw `let`).

## Deviation

The book's accumulator is the raw assignment idiom; the edition
renders local state with `Effect` `Ref`s everywhere in 3.1 (D33), so
the call returns an `Effect` to run rather than answering the number
synchronously.
