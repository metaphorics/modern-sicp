# Exercise 1.24 — timed Fermat test (adapt: Random module plus Sys.time)

The map class is `A`: the book's `random` primitive becomes this
edition's seeded `Random` module, threaded explicitly, and timing still
goes through `Sys.time`.

`ex_1_24 ()` builds one generator from the fixed seed 42 and runs
`fast_prime` at 20 rounds over the same twelve primes exercise 1.22
found, threading the one generator through every call. Every result is
`true`: Fermat's Little Theorem holds for every witness `a` when `n` is
truly prime, so a genuine prime always passes the test regardless of
which values the generator happens to draw — there is no randomness risk
on these inputs, only on numbers that might be Carmichael numbers
(@ref{Exercise 1.27}).

Since the Fermat test is `Theta(log n)`, testing primes near 1,000,000
should take only a small constant-factor longer than testing primes near
1,000 — nothing like the `sqrt(1000)` slowdown exercise 1.22's search
shows. In practice, on this platform, a single Fermat test is again too
fast for `Sys.time` to resolve at any of the four thresholds, exactly the
clock-resolution point exercise 1.22 raises; a fair comparison needs many
repeated timed calls, not one.
