# Exercise 5.42: lexical addressing in the code generators

With `CompilerConfig(lexical = true)`, `compile-variable` and
`compile-assignment` ask `find-variable` for the name's frame number
and displacement and emit `lexical-address-lookup` and
`lexical-address-set!` with the address as one list constant. A name
the compile-time environment cannot see stays a global
`lookup-variable-value`, so only true locals take the fast path.

`lexicalAddressRuns()` compiles the book's nested `f` example
lexically. The innermost body reads `z` at (0 1), `y` at (0 0), and
`x` at (2 0), in the compiler's right-to-left operand order, and the
test pins those three instructions. It then runs the applied example,
where `(f 3 4)` applied to five arguments computes `(* 3 6 10)`,
through the machine's `lexical-address-lookup` and
`lexical-address-set!` operations, which resolve environment words
through the table and index frame slots in binding order. The run
answers the book's 180.
