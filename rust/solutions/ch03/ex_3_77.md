# Exercise 3.77: integral with delayed integrand

## Approach

The exercise's direct integral is the `integers-starting-from` style:
the answer is the initial value followed by a running total, each step
adding dt times the current integrand element. Rewritten for feedback
systems, the integrand arrives delayed: `integral_direct_delayed`
conses the initial value, and the answer's first tail thunk forces the
integrand -- exactly once, since tails are memoized -- then runs a
`running_total` loop that answers the empty stream when the integrand
is empty (so a finite integrand yields a finite integral: the initial
value plus one element per integrand element) and otherwise conses
`accumulated + dt*head` onto the delayed rest, whose own `cons_stream`
delay is the recursion's delay of tail. The solve loop plugs in
directly: `dy` maps f over the answer stream itself and is supplied as
the delayed integrand. The tests pin both demands: (a) integrating the
integers 0..=9 at dt = 1 from 0 answers the triangular totals
k(k-1)/2 -- 0, 0, 1, 3, 6, 10, 15, 21, 28, 36, 45 -- and a full walk
terminates after exactly 11 elements, proving the stream ends with its
integrand; (b) carrying dy/dt = y from y0 = 1 at dt = 0.001, element
1000 is the Euler value (1 + dt)^1000: the run answers
2.716923932235896, within 1e-2 of e (the book pins 2.71692...), and
identical to element 1000 of the section's own `solve` -- both
integrators perform the same additions in commuted order, so they agree
to the last bit.

## Map class

`T`. The statement translates whole. The one Rust wrinkle: the delayed
integrand is an `FnOnce` closure forced inside the memoized first tail,
mirroring `(delay ...)`; the loop function carries the running total as
an accumulator, where Scheme rebinds the parameter.

## Deviation

None.
