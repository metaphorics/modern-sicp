# Exercise 3.76: smooth as reusable combinator

## Approach

`smooth` maps the average over the stream and its own tail, so output
element k is the mean of input elements k and k+1 -- each element the
average of TWO SUCCESSIVE input elements, one element shorter for a
finite input. The zero-crossing extraction is then the section's own
`make_zero_crossings` run unchanged on the smoothed signal (that is the
detector this solution uses, not the 3.75 fixed form): with smoothing
extracted as a component, the extractor needs no knowledge of -- or
change for -- the conditioning, Eva Lu Ator's modularity point. The run
pins the smoothed sense prefix (1.5, 1.75, 1.25, 0.75, 0.2, -1.05,
...) and its crossings: -1 at index 5 and +1 at index 10. The two real
crossings survive and no spurious crossing appears, because the noisy
dip here is a single sample wide and its pairs still average to the
signs around it. No crossing index shifts relative to the raw 3.74
answer: the pair (0.5, -0.1) still averages positive (0.2) at index 4
and (-0.1, -2) turns the average negative (-1.05) at index 5. Relative
to the 3.75 fixed form the crossings run one index earlier (5 and 10
versus 6 and 11) -- the same averaged values, one index apart, since
smooth's element k mixes raw k with k+1 while the fixed form's k-th
average pairs k with k-1.

## Map class

`T`. The statement translates whole. The one Rust wrinkle: the map's
second argument is `s.tail()`, forcing the memoized tail for the call;
`stream_map2` stops at the shorter stream, which is exactly the
one-element-shorter smooth of a finite input.
