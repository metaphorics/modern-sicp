# Exercise 4.55: simple Microshaft queries

## Approach

Each lookup is a direct pattern query over the shared typed personnel
database (`microshaftDatabase` in `ex_4_55.ts`, assertions in the book's
order):

1. `supervisedByBen` names everyone Ben supervises.
2. `accountingJobs` uses a dotted tail to catch any accounting job, not
   one specific title.
3. `slumervilleAddresses` matches the town while leaving the street
   detail unspecified — the three Slumerville streets have different
   shapes, so only a dotted tail catches all three.

The driver collects one transcript per lookup; `answerLines` drops the
echoed query line. Simple queries answer in database assertion order.

## Numbers

Three supervisees (Hacker, Fect, Tweakit), two accounting employees
(Scrooge and Cratchet), and three Slumerville residents (Bitdiddle,
Reasoner, Aull). The tests pin the full rendered lines, matching the
book's printed transcripts up to notation.

## Class and deviations

Translated row. Deviation: patterns and answers are typed query data
rendered in the neutral bracket notation (`job(["Scrooge", "Eben"],
["accounting", "chief", "accountant"])`), not the book's parenthesized
display; dotted tails instantiate flat. No query text is parsed.
