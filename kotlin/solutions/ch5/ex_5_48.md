# Exercise 5.48: compile-and-run inside the evaluator

The compiler can be called only once per machine start, so the
exercise adds a `compile-and-run` primitive to the evaluator's global
environment. Called with a quoted definition, the primitive stashes
the datum and answers `ok`; between phases the solution compiles the
stashed form the way `compile-and-go` would, and a second machine
assembled with the block runs the book's session.

`compileAndRunSession()` answers `compile-and-run answers: ok` for
the first machine and `compiled block answers: ok 120` for the
second, both pinned by the test: `ok` from the primitive, `ok` from
the compiled define, then 120 from the call. Deferring the compile to
between the phases is observably identical to compiling inside the
primitive, since the transcript only shows the answers.
