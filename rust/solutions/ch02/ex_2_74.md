# Exercise 2.74: Insatiable Enterprises' division files

## Approach

Each division's file is a tagged `Value`, tagged with the division's
name, and each division installs `get-record` and `get-salary` under
that tag. The two divisions built here genuinely differ in structure:
the north division's file is an alist of `(name . record)` pairs, and
each record is itself an alist keyed by field-name symbols
(`address`, `salary`); the south division's file is a flat list of
records, and each record is the property list
`(name n address a salary s)`, with no separate key layer at all.
Headquarters' `get_record(table, name, file)` reads the file's own tag,
looks up the division's `get-record` handler, and hands it the name and
the bare contents — the handler owns its division's layout, and
headquarters never sees it. `get_salary(table, record)` does the same,
dispatching on the tag `get_record` attached to the record it returned,
so a division's record structure is its own business at every step.
`find_employee_record` searches every division's file in turn and stops
at the first record that is not the book's `#f` miss value. Part (d) —
a company Insatiable acquires — is a third division installed with its
own tag and its own `get-record`/`get-salary` handlers; headquarters'
three procedures do not change, which the test
`part_d_a_third_division_needs_only_an_install` runs directly.

## Map class

`A`: division record schemas need per-division adapters, matching the
map's Rust class for this row.

## Deviation

The book leaves `get-record`'s miss behavior open; this edition keeps
the book's own `#f` at the dynamic layer (both divisions' handlers
answer `Value::Bool(false)` on a miss, exactly as an unfound `assoc` or
`memq` would) and lets `find_employee_record` be the one place that
raises the miss into `Option`, rather than turning every handler into a
typed error for what the book treats as an ordinary negative result.
