# Exercise 3.13: make-cycle closes the ring

## Approach

The book asks what `last-pair` returns on the ring `make-cycle`
builds over `(a b c)`. The Rust solution never calls `last_pair` on
the closed ring, since that walk cannot terminate; it answers the
question the exercise is really after, that no walk down `cdr`s ever
reaches the empty list. It closes the ring with `make_cycle`, then
follows exactly three `cdr` steps from the first pair and checks
`eq_pair` against the starting cell: after `a`, `b`, and `c` the walk
is back where it began, which is the ring the diagram shows. A
companion test confirms `last_pair` still answers the ordinary chain
before it is closed.

## Map class

`A: shared mutable cells need Rc RefCell`. The ring lives in shared
mutable cells under `Rc`, and closing it is one `set-cdr!` on the
last cell's `RefCell`, visible through every handle into the chain.

## Deviation

The terminated walk replaces the infinite one. The book's answer is
that `last-pair` loops forever, and a program that hangs proves
nothing a test can hold; the fixed-length walk with the identity
check shows the same cyclic structure and stays runnable.
