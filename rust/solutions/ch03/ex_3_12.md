# Exercise 3.12: append! mutates the tail of x

## Approach

The book runs copying `append` and then mutating `append!` over
`x = (a b)` and `y = (c d)`, asking what the tail of `x` is after
each. The Rust solution strings the four printed answers in order,
and it strings them at the moment each is read: a `Value::Pair` is a
live handle, so `to_string` freezes the structure as it stands. After
the copying `append`, `x`'s tail is still `(b)`; after `append_bang`,
the same read answers `(c d)`, because `append_bang` overwrote the
last cell of `x` with a handle to `y`'s first cell. The test also
checks `eq_pair` between `w`'s cells and `y`'s, so the shared tail is
proven by identity, in the spirit of the book's pointer diagrams.

## Map class

`A: shared mutable cells need Rc RefCell`. The chains live in shared
mutable cells under `Rc`, and the exercise is the same pointer
argument made visible in the types: `append_bang` takes and returns
`Pair` handles, and the mutation one caller observes is visible to
every other holder of the same cells.

## Deviation

None. The exercise keeps the book's structures and its four printed
results exactly; the strings are compared against the book's answers.
