# Exercise 2.71 — skewed trees for n = 5 and n = 10 (translate)

The map class is `T`: only the syntax changes. For an alphabet of `n`
symbols with relative frequencies `1, 2, 4, ..., 2^(n - 1)`, every
merge in `successive_merge` combines the single heaviest tree built
so far with the next-heaviest symbol, which is always at least as
heavy, since `1 + 2 + ... + 2^(k - 1) = 2^k - 1` is always one less
than the next symbol's weight `2^k`. The result is one long spine:
the heaviest symbol ends up as the sole leaf one level below the
root, and the lightest ends up `n - 1` levels down, at the bottom of
the spine. Encoding the most frequent symbol therefore always takes 1
bit, and encoding the least frequent always takes `n - 1` bits,
whatever `n` is — this is the shape the book's Figure 2.18 hints at
for a much less skewed alphabet, taken to its extreme.

Sample: `ex_2_71 5` is `(1, 4)`; `ex_2_71 10` is `(1, 9)`, confirming
the `1` and `n - 1` bit counts for both requested sizes.
