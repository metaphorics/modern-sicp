# Exercise 5.16: instruction tracing

The tracing machine is another one-loop override: when the switch
`traceOn` is up, `TracingMachine.execute()` appends the instruction's
rendered text to the machine transcript just before the instruction
executes, so the trace is exactly the executed instructions in run
order, never a listing of the controller.

`tracedGcdTrace()` runs the gcd machine with the switch on and pins
all 26 lines: the trace begins at the first
`(test (op =) (reg b) (const 0))`, walks the five-line loop once per
division step, and ends at the final taken
`(branch (label gcd-done))`; the trailing `gcd-done` label produces
no line because a label is not an instruction and the machine halts
on reaching it. The line count equals the 5.15 counter's 26, which is
the cross-check that tracing observes the same loop the counter
counts.

The switch is part of the contract and has its own pin: a second run
with `traceOn` false executes the same machine and leaves the
transcript empty, so a tracing machine that traced unconditionally
would pass the 26-line pin and fail this one.
