# Exercise 5.38: open-coded primitive calls

Ordinary application compilation evaluates the operator, builds an argument list, and emits a runtime test with primitive and compound-procedure branches. Open coding recognizes selected primitive calls at compile time instead. For a binary operation, the compiler evaluates the operands into `arg1` and `arg2`, then emits the machine operation directly into the requested target and applies the requested linkage. `spreadArguments` handles nested operand expressions and preserves argument-register values when evaluating another operand could overwrite them.

For more than two operands, the Kotlin implementation extends `+` and `*` by folding binary operations: it combines the first two operand values, then folds each remaining operand into the accumulator in `val`. It preserves `arg1` where needed across nested evaluation. Other open-coded operations require exactly two operands. The actual open-coded name set is `+`, `-`, `*`, `<`, and `=`, as recorded in the shared compiler.

`openCodedRuns` compares compiled factorial statement counts with open coding disabled and enabled, then runs factorial and arithmetic examples through the open-coded compiler. The solution test checks that the open-coded factorial listing is shorter, factorial of `5` answers `120`, `(+ 1 2 3 4)` answers `10`, and `(< 1 2)` answers `#t`. These are Kotlin implementation checks; no count from another host is assumed.
