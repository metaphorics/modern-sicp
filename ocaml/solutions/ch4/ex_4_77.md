# Exercise 4.77 — delayed filtering for `not` and `lisp-value` (translate)

The section's filters are frame filters: correct only when the filter's
variables are already bound. Applied to the empty frame the 4.4.3
example `(and (not (job ?x (computer programmer))) (supervisor ?x ?y))`
kills every frame — the wrong answer — and a `lisp-value` with an
unbound argument is an error. The solution's frames carry promises: a
variant evaluator whose frames are the substrate frame plus the pending
filters accumulated so far. A filter whose query is fully bound in the
current frame is applied immediately (the efficiency the exercise asks
for); otherwise it rides on the frame and is fulfilled in the driver's
settle step, after all other operations have run. Fulfilled filters use
the substrate's own `qeval`/`execute`, so the settled semantics are the
section's exactly; a promise still unfulfillable at settle time keeps
its frame and counts as unresolved. The dispatch table is not mutated.

Counting rule: `deferred` counts promise attachments; `fulfilled`
counts settle-time applications, whether the frame survives or not; the
8 fulfillments of the first query are its 8 supervisor frames (6 kept,
2 programmers dropped). A query where the filter can run immediately
(the reversed salary query) shows `deferred=0`.
