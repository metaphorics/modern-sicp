# Exercise 5.24: cond as a basic controller form (T)

## Approach

The controller gains `ev-cond`, a loop over the clause list. Each
iteration takes the first clause, advances the walk in `unev`, and
tests the predicate through `eval-dispatch`; a true predicate (or an
`else`) selects the clause, and its actions are evaluated by
`ev-sequence`, so the clause's last expression is still in tail
position. The clause under test rides in `proc`, whose live value
every enclosing argument loop has already saved on the stack. A
clause is raw list structure: the predicate is its first element and
its actions are the rest, which is what `cond-predicate` and
`cond-actions` extract.

Two answers the derived form gives for free are handled explicitly:
a selected clause with no actions returns the predicate's value (the
book's answer for `(cond (p))`), and no true clause with no `else`
answers `#f`, exactly what `cond->if` would have produced.

## Map class

`T`.

## Sample answer

`(classify 0)`, `(classify 1)`, and `(classify 7)` answer `zero`,
`one`, and `many`; the bodyless `(cond ((= 1 1)))` answers `#t`; the
cond with no true clause and no `else` answers `#f`.
