# Exercise 4.11: environment frames as association lists

## Approach

The book proposes a representation change: frames as association lists
of `(name . value)` pairs instead of the runtime's `PersistentMap`
frames, and asks which environment operations must change. The answer
here is: all four, and only the four. `AlistFrames` subclasses
`Evaluator` and overrides exactly the env-op seam (`lookupVariable`,
`setVariable`, `defineVariable`, `extendEnvironment`) so every
variable touch and every procedure call runs over the alist
representation, at every nesting depth, because the base clauses all
route through the seam. Each `Env` frame slot carries its alist as one
binding under a reserved key; `alistGlobal` seeds the global frame with
`setupEnvironment`'s bindings so the whole chain speaks one
representation. `define` conses a fresh `(name . value)` pair onto the
front (the book's define-variable! shape); `set!` scans outwards and
rewrites the value slot of the nearest pair with `set-cdr!`-style
mutation; lookup returns the first pair's value; extend-environment
conses the parameters onto the fresh frame's alist and keeps the
runtime's arity contract (`WrongArity`), which a reimplementation could
otherwise silently drop.

## Map class

`T`.

## Deviation

None. The runtime's `Env` type is fixed by the seam's signatures, so the
alist lives in the frame slot the four operations own; nothing outside
the overridden operations reads the map-shaped frame.

## Answer

- `(define z 2) z` prints `2`; `(bump)` (whose body is
  `(set! z 10) z` with no `z` of its own, so the `set!` walks to the
  global alist frame and rewrites its pair) prints `10`; then `z`
  prints `10`: transcript `"2\n10\n10\n"`.
- `z` bound only inside a returned call's frame reads
  `"2\nError: unbound variable: z\n"`: the walk stops without a hit.
- An arity mismatch still faults:
  `"Error: extend: wrong number of arguments, expected 2, got 1\n"`.
