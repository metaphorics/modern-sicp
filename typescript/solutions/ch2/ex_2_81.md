# Exercise 2.81: Louis Reasoner's self-coercions

## Approach

Part (a) installs Louis's identity coercions (`scheme-number` to
`scheme-number`, `complex` to `complex`) and traces `exp` of two ordinary
numbers: `apply-generic` finds no `exp` entry for the argument types --- the
operation exists only for `(scheme-number scheme-number)`, which is the point
--- then finds the identity coercion, coerces, and retries, landing in the
same missing entry after two wasted dispatches. Part (b): Louis is wrong for
`apply-generic` with more than two arguments in general, and the identity
entries convert nothing only when no coercion is needed at all. Part (c) is
the guard: when both argument tags are equal, `apply-generic` never consults
the coercion table. This exercise builds its own operation and coercion
tables, so the identity entries never leak into the section system the later
exercises share.

## Numbers

With the identities installed and no `exp` entry found, the trace applies the
coercion twice and ends in the same "No method for these types" report ---
`exp` never runs; with the part (c) guard, same-type arguments answer
directly from the table on the first dispatch.

## Map class

A (coercion map keyed by type tuples): the coercion table is keyed by the
ordered pair of tag strings, one entry per `from`/`to`.

## Deviation

The exercise keeps its private tables instead of installing Louis's
identities into the section tables, so the shared system stays clean while
the trace still shows the book's behavior.
