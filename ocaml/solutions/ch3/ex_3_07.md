# Exercise 3.7: make-joint shares one account (translate)

The map class is `T`. `make_joint` wraps the underlying account
closure in a new closure that checks a second password before
delegating; it holds no state of its own; the shared state lives
entirely in the balance `ref` closed over by the original
`make_account` call, so a withdrawal through the joint access and a
read through the original access see the same balance, exactly
because they are the same closure under two different password
gates. This is the section's aliasing lesson (`peter-acc` and
`paul-acc` naming one object, not two) reproduced structurally: no
equality test is needed to show it, since the joint account has
nothing else it could be.

Sample: `ex_3_07 ()` is `(Balance_response (Balance 60),
Deposit_response 60)`: Paul withdraws 40 from the shared $100
balance through his own password, and Peter's own access (a
zero-amount deposit, since the account has no dedicated balance
query) reads the same $60 back.
