## Exercise 1.26: an explicit multiplication doubles the recursion

Approach: each version counts its own calls through a shared one-element
`IntArray` (a plain closure `var` would be simpler, but the private
`calls` accumulator is threaded explicitly here so both call trees are
counted the same way). `expmodSquare(4, 64, 97)` makes 8 calls: one call
per halving of 64 down to 0 (`64, 32, 16, 8, 4, 2, 1, 0`), since `square`
evaluates the one recursive call's result once, wrapping it, then squares
the number itself. `expmodDouble(4, 64, 97)` makes 191 calls, because its
even branch evaluates the recursive call twice as source text
(`expmodDouble(...) * expmodDouble(...)`), and Kotlin, having no
common-subexpression sharing across two independent call expressions,
runs both, doubling the call count at every level below the top,
instead of halving the exponent for one shared value.

Class: T (translate). Explanation, in Eva's terms: writing `square(x)` on
a bound result computes the recursive call once and reuses its value;
writing `x * x` where `x` is itself a call to `expmodDouble` computes the
call twice, so each level of the recursion spawns two half-sized calls
rather than one, turning the doubling-each-level tree that `square`
avoids back into the shape of a full binary recursion tree, which is
Theta(n) nodes for an exponent of `n` rather than Theta(log n).
