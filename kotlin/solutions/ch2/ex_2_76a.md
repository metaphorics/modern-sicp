## Exercise 2.76a: add a type via module extension

Approach: `installPolarDegRepresentation` installs a third representation (
polar with the angle in degrees) into exercise 2.76's
`RepresentationTable`, entirely from this new file, calling only the
table's existing `put`. `RepresentationTable`, `installRectRepresentation`,
and `installPolarRepresentation` do not change at all.

`ex_2_76a` proves two things: the rectangular package's `real-part`
handler is the exact same object reference before and after the degrees
package installs (the additive-install claim, by pointer identity, the
same proof exercise 2.76 uses for rectangular and polar), and the new
package itself computes the right real part for a 60-degree angle.

This is exercise 2.76's own comparison acted on rather than just
described: data-directed style is the one of the three strategies that
lets a type arrive as pure module extension. The sealed hierarchy `RepZ`
from 2.76's explicit-dispatch strategy could not gain this representation
the same way: a new subtype there would force an edit to every
exhaustive `when` already built over it, in whichever file that `when`
lives.

Class: this edition's tailored addition, chosen from the map's idea
column for 2.76 ("add type via module extension"). It extends exercise
2.76 rather than replacing it, keeping 2.76's own number and adding
2.76a per the section's addition convention.

Deviation: none; the map's own idea phrase is implemented directly.
