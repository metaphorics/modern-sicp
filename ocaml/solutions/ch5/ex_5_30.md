# Exercise 5.30: errors signaled inside the evaluator

Both parts are built, and the places that needed the change are the
two the exercise's answer names.

(a) `lookup-variable-value` answers a distinguished condition code for
an unbound variable: a pair tagged with a reserved symbol no object
symbol can spell. `ev-variable` tests the code and goes to
`signal-error`.

(b) `apply-primitive-procedure` checks every application: a wrong
operand count, `car` of a non-pair, or division by zero returns the
condition code instead of escaping the machine, and `primitive-apply`
tests it. The condition code cannot be a user value because its tag
symbol starts with a character the reader never produces;
`signal-error` unwraps the code and reports the detail.

`ex_5_30 ()` runs the caught failures, each pinned: `car` of a symbol,
division by zero, an unbound variable, a wrong operand count, and then
a clean factorial that still answers `120`, so the checks did not slow
the correct path down or change its answers.
