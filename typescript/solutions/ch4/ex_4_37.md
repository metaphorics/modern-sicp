# Exercise 4.37: Ben's generator

## Approach

Ben is correct about the search size. His `hsq` prune rejects a
candidate `j` before the hypotenuse search is ever entered, so fewer
backtracking continuations are queued. The guest has no floating
`sqrt`, so the root is the floored integer root and Ben's integrality
requirement is the squaring-back check `k * k === hsq`: the same
rounding the float version performs implicitly. `failureCounts()`
reads the live `SearchRun.failures` field from both real programs;
there is no handwritten counter.

## Numbers

Both programs produce the same six triples as 4.35. The tests compare
the measured counter values and require Ben's count to be lower; exact
counts remain observable from `failureCounts()` without pinning a
particular engine traversal count.

## Class and deviations

Translated row; the integrality-check rewrite described under Approach
is the one adaptation. Deviation: the dynamic counter comparison is
pinned instead of a literal count, because deferred continuation
counting is an engine-level search metric whose exact value may change
without changing the lesson.
