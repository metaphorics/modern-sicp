# Exercise 5.5: hand simulation of the factorial and Fibonacci machines

The map class is `T`. The statement asks for a hand simulation of the
machines of Figure 5.11 and Figure 5.12 on a nontrivial input, showing
the stack at each significant point. Both machines run with n = 3: each
descends past at least one recursive call, and the Fibonacci machine
branches at both call sites.

The edition's trace format, stated once: every `Save` and every
`Restore` is one line, written in constructor notation as `Save "r"` or
`Restore "r"`; a restore line also names the word it recovers and the
register it lands in; every taken `Branch` and every return through
`Goto_reg "continue"` is one line naming the target. The stack is
written as an OCaml list with its top first, as `stack=[...]`;
straight-line instructions and untaken branches are omitted. The traces
come from `Handsim` in `solutions/ch5/sec_5_5.ml`,
a direct transcription of the controller semantics (its own pc, flag,
register file, and stack) that shares only the base machine's operation
table with the simulator, so the trace is the hand model's answer, not
the simulator's.

For factorial n = 3 (`ex_5_05 ()`'s first thirteen lines):

```
Save "continue" stack=[fact-done]
Save "n" stack=[3; fact-done]
Save "continue" stack=[after-fact; 3; fact-done]
Save "n" stack=[2; after-fact; 3; fact-done]
branch taken to base-case
return to after-fact
Restore "n" n=2 stack=[after-fact; 3; fact-done]
Restore "continue" continue=after-fact stack=[3; fact-done]
return to after-fact
Restore "n" n=3 stack=[fact-done]
Restore "continue" continue=fact-done stack=[]
return to fact-done
answer 6
```

The stack peaks at depth 4 (two frames, each holding `continue` and
`n`), and the two `return to after-fact` lines show the nested
unwinding: the inner level multiplies first, then the outer.

For Fibonacci n = 3 (the next twenty-five lines, `answer 2` last):

```
Save "continue" stack=[fib-done]
Save "n" stack=[3; fib-done]
Save "continue" stack=[afterfib-n-1; 3; fib-done]
Save "n" stack=[2; afterfib-n-1; 3; fib-done]
branch taken to immediate-answer
return to afterfib-n-1
Restore "n" n=2 stack=[afterfib-n-1; 3; fib-done]
Restore "continue" continue=afterfib-n-1 stack=[3; fib-done]
Save "continue" stack=[afterfib-n-1; 3; fib-done]
Save "val" stack=[1; afterfib-n-1; 3; fib-done]
branch taken to immediate-answer
return to afterfib-n-2
Restore "val" val=1 stack=[afterfib-n-1; 3; fib-done]
Restore "continue" continue=afterfib-n-1 stack=[3; fib-done]
return to afterfib-n-1
Restore "n" n=3 stack=[fib-done]
Restore "continue" continue=fib-done stack=[]
Save "continue" stack=[fib-done]
Save "val" stack=[1; fib-done]
branch taken to immediate-answer
return to afterfib-n-2
Restore "val" val=1 stack=[fib-done]
Restore "continue" continue=fib-done stack=[]
return to fib-done
answer 2
```

The trace shows exactly the save/restore discipline 5.6 then
challenges: at `afterfib-n-1` the `Restore "continue"` recovers the
caller's return address, and the very next `Save "continue"` pushes
that same word back for `afterfib-n-2` to recover.

Cross-check, pinned by the test suite: the same controllers run through
the simulator answer 6 and 2 for n = 3 (the hand model and the
simulator agree), the hand model's step and save counts for fib 6
equal the simulator's executed-instruction and push counts, and the
modified machine of 5.6 answers like the original on n = 0 through 9.
