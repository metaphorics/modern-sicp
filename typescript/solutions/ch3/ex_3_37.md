# Exercise 3.37: expression-style constraint combinators

## Approach

The book shows the converter written as an expression,
`(c+ (c* (c/ (cv 9) (cv 5)) x) (cv 32))`, and asks for the c-procedures
that make it work: each builds its output connector, wires the
module's primitive constraint between its inputs and the output, and
answers the output, so compound constraints compose without naming
intermediates, the footnote's point about returning compound objects
as values. The edition spells `cadd` (adder x y z), `cmul`
(multiplier x y z), `cdiv` (a fresh z with x = z * y, wired as
multiplier y z x), and `cconst` (constant into a fresh connector),
then builds `celsiusFahrenheitConverterExpr` as the book's one-line
expression.

## Pins

Hand composition: `cmul(cconst(6), cconst(7))` reads 42;
`cdiv` of that 42 and 7 reads 6; `cadd` of 42 and 6 reads 48. The
converter, fresh per case: setting C = 25 makes F read 77; setting C
= 100 makes F read 212; on a fresh network setting F = 212 makes C
read 100 (backward through the expression, the division directions
resolving). Forget flow, measured: C = 25 gives F = 77; forgetting C
as user leaves both C and F unset; then setting F = 212 makes C read
100 and F read 212.

## Map class

`T: combinators over the module's primitive constraints, returning
connectors`.
