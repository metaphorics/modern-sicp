# Exercise 3.65: ln 2 approximation streams

## Approach

The statement builds the series ln 2 = 1 - 1/2 + 1/3 - 1/4 + ... the
way the section built pi: `ln2Summands` produces the alternating
reciprocals, and `ln2Stream` sums it. Three approximation sequences
come off that stream: the partial sums themselves, `ln2EulerStream`
(the section's `euler-transform`), and `ln2AcceleratedStream` (the
tableau of repeated transforms, read down its first column with
`accelerateSequence`). The statement's question, how rapidly the
sequences converge, is answered with `streamLimitWithTerms`, the
exercise-3.64 stream limit reporting how many elements a 0.0001 search
examined in each sequence.

stage buys roughly an order of magnitude or more.

## Map class

T (translate: syntax changes only). The statement's two definitions

## Deviation

Two performance deviations, both forced by the same executed
comparison and both value-preserving, with identical pins across
variants.

First, `ln2Stream` binds the stream locally and references it from its
own tail instead of calling the module's `partialSums`. The module's
version re-invokes itself on every tail force, which measured as
quadratic time in the prefix length: 14.6 s to walk the first 10000
harmonic partial sums against 2 ms for the locally bound shape, with
element values identical (pinned equal at index 9999).

Second, `ln2Summands` carries the sign as a generator parameter
instead of the statement's `stream-map` of `-x` over the recursive
call. The statement's shape wraps one more negation layer around the
rest per element, so element k sits k map cells deep: allocation
measured quadratic, 251 cells per element at element 500, and the
10000-term walk of the partial sums allocating 12.4 GB in 17 s, enough
to abort a vitest worker with an out-of-memory SIGABRT. The signed
generator emits the identical sequence with one cell per element; the
pinned partial sums, euler values, and accelerated values are the same
numbers either way.

The exercise's comparison needs exactly that ten-thousand-term walk,
so both fixes are what make the statement's question answerable by
execution inside a test.
