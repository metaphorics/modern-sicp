# Exercise 4.78: the query language as a nondeterministic program

## Approach

Each driver query becomes a search program: the driver's real
answer lines are embedded as guest strings, `choose` picks among
them, and `require` filters. The populated bridge answers the
Hacker line by search; the empty bridge contrasts the driver's
`No.` line with search's silent zero answers. Unification and
frame extension are subsumed by lexical scope plus choice
filtering; rule application becomes procedure call with
backtracking resumption instead of stream combination.
## Numbers

Three supervisee lines bridge; one Hacker line answers; the
self-supervision query prints the driver's `No.` line against zero
search answers. The tests pin the bridge size, the filtered
answer, and the empty contrast.
## Class and deviations

Translated row. Deviation: the embedding is runtime string
interpolation of live driver output, labeled as such — not a
fixture, and claiming no native proof. The memoize-versus-
re-execute difference is architectural comparison prose grounded
in both runs' observable shapes.
