# Exercise 1.3: the sum of the squares of the two larger of three numbers

## Approach

This is a direct (`T`) translation: the book's `sum-of-squares` from 1.1.4
already exists in this section (`ch01::sec_1_1::sum_of_squares`), so the
exercise is which two arguments to pass it:

```rust
pub fn sum_squares_two_larger(a: i64, b: i64, c: i64) -> i64 {
    if a >= b && a >= c {
        sum_of_squares(a, b.max(c))
    } else if b >= c {
        sum_of_squares(b, a.max(c))
    } else {
        sum_of_squares(c, a.max(b))
    }
}
```

## Names need no special case

The three-way comparison is ordered so that ties are handled without a
separate branch: when two (or all three) arguments are equal, either `if`
that catches the tie is correct, because `sum_of_squares` is symmetric in
its two arguments and squaring an equal value twice is the same computation
either way it is reached. This mirrors the book's own note in 1.1.4 that a
procedure's behavior should not depend on which of two equal-role arguments
is named which.

## Test

`sum_squares_two_larger(1, 2, 3) == 13` (`2² + 3²`), the tie case
`sum_squares_two_larger(2, 2, 2) == 8` (`2² + 2²`), and the all-negative
case `sum_squares_two_larger(-1, -2, -3) == 5` (`(-1)² + (-2)²`, the two
values closest to zero, which are the two "larger" negative numbers).
