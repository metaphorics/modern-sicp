# Exercise 3.72: sums of two squares in three ways

## Approach

Same machinery as 3.71 with the square-sum weight `i^2 + j^2` and runs
of three or more consecutive equal weights, each emitted as the number
paired with its list of representations. The stream yields

- 325 = (1, 18), (6, 17), (10, 15)
- 425 = (5, 20), (8, 19), (13, 16)
- 650 = (5, 25), (11, 23), (17, 19)
- 725 = (7, 26), (10, 25), (14, 23)
- 845 = (2, 29), (13, 26), (19, 22)
- 850 = (3, 29), (11, 27), (15, 25)

The test pins those six entries exactly and checks that every
representation in the prefix squares back to its number. The scan to
the next qualifying run is a cursor loop inside the tail thunk, so the
rare hits stay off the stack.

Independent check: a python3 brute force over `i^2 + j^2` for
`1 <= i <= j < 200` produces exactly the same six numbers with exactly
the same representations in the same order. (The frequently quoted
1105 is the ninth such number, behind 925 and 1025; it is not part of
the first six.)

## Map class

`T` (map row 3.72: the two-squares variant translated to Kotlin's
memoized streams as written).

## Deviation

None.
