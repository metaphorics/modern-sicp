# Exercise 2.22 — the iterative square-list bug (translate, one
adapted clause)

The map class is `T`, with one recorded deviation. Louis's first
version translates literally: `iter rest (car * car :: answer)`
conses every square onto the front of the accumulated answer, so the
process runs the list left to right while building the result right
to left, and `ex_2_22_louis [1; 2; 3; 4]` returns `[16; 9; 4; 1]`.

The deviation: the book's second attempt, `(cons answer (square
(car things)))`, is rejected by OCaml's type checker before it can
print anything — consing the accumulated list onto the front of a
one-element list makes `answer` both an `int list` and an `int`
element of a list, an occurs-check failure. The statement therefore
asks why the rejection happens rather than why bad output appears,
and the answer is the type-system reading of the same structural
mistake: the nesting Scheme printed as `((((()) 1) 4) ...)` is
exactly the shape OCaml refuses to give a `int list -> int list ->
int list` function.
