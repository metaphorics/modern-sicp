# Exercise 5.36: operand evaluation order

The compiler's default order is right to left. `constructArglist` reverses the compiled operand sequences; it evaluates the last operand first to initialize `argl`, then evaluates earlier operands and conses their values onto the front. This produces the procedure's argument list in source order while evaluating side effects in reverse order.

The Kotlin compiler makes the alternative explicit with `CompilerConfig(leftToRight = true)`. `operandOrderRuns` evaluates `(list (record 1) (record 2))` with a logging primitive under both configurations, so the log exposes evaluation order without confusing it with the final list order. It also compares compiled statement counts for both configurations. The implementation's measured counts are equal: changing which operand initializes `argl` does not add another list-building step.
