# Exercise 4.79: environments instead of renaming

## Approach

Renaming is demonstrated, not described: the colliding rule
spells its body with `?father` while the query uses `?father`
for the grandson, and the engine still answers Irad — every rule
variable carries a fresh application-id suffix, so capture is
structurally impossible. The tests pin the answer, the suffix
shape, counter monotonicity across renamings and raw calls, and
the occurs check refusing `?x = [?x]`. The environment
alternative — rule scope as an extended frame, hypothetical
assertion as contextual deduction, block structure as nested
rule scopes — is designed in prose, which this open-ended
exercise invites.

## Numbers

One answer under the collision; two suffixed head variables;
monotone ids; one refused cycle. Direct rule application over
the empty frame yields the same single frame as the driver.

## Class and deviations

Translated row. Deviation: engine integration of environment
scoped application stays follow-up work (the exercise marks
itself open-ended); what runs is the renaming baseline the
alternative must match, plus the occurs check both designs need.
All bindings go through exported engine operations.
