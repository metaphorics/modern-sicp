# Exercise 3.11: where an account's local state lives (replace)

The map class is `R` for this edition: the SICP exercise asks for the
environment diagram of Scheme's message-dispatching `make-account`,
whose `dispatch` answers quoted symbols. This edition's account is a
record of closures over one captured ref cell (the shape 3.1.1
introduced), so the replacement asks for the same three answers about
that structure: state lives in the single cell each `make_account`
call allocates; the record's `withdraw` and `deposit` fields close
over that one cell, so a deposit is visible to the next withdrawal;
and a second account's cell is fresh, untouched by the first
account's traffic.

The interactions of the statement are replayed directly: `acc` starts
at 50, `acc.deposit 40` answers 90, `acc.withdraw 60` answers
`Balance 30`, and a second account `acc2` built with 100 still reports
100 afterwards. Physical inequality of the two records
(`not (acc == acc2)`) confirms the drawing's bottom line: two
accounts share only the compiled code of their closures, never a cell.

Sample: `ex_3_11 ()` answers
`(90, Balance 30, 100, true)`.
