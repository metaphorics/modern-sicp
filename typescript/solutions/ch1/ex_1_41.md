# Exercise 1.41: the double combinator puzzle

## Approach

`double(f) = x => f(f(x))`. The puzzle's expression `double(double(double))`
parses as `double` applied to `(double(double))`: the inner application makes
a procedure that applies its input four times, the outer one re-doubles that
to sixteen applications. With `inc` adding 1, the answer is `5 + 16 = 21`.

## Numbers

`double(inc)(5)` is `7` and `double(double(inc))(5)` is `9`, the ladder the
statement builds. The full expression `double(double(double))(inc)(5)` is
`21`. As a sanity check on the combinator's reach,
`double(x => 3 * x)(2)` is `18`.

## Class and deviations

Translated row, per the map. The book's `((double (double double)) inc) 5`
is written in the host's call syntax; the parse and the answer are
unchanged. One disclosed typing deviation: the statement's own expression
applies `double` to itself, which a number-specific signature refuses to
compile (tsc TS2349/TS2345 on the self-application), so `f`'s type is a
parameter `T` - the same generalization Scheme's universal application
gives for free. Every call in the tests still runs on numbers.
