# Exercise 1.4: the operation chosen by a conditional

## Approach

The conditional expression evaluates to a procedure and the surrounding
call applies it: `b > 0` picks an adding arrow, otherwise a subtracting
one. The statement of the book's trick survives, but the operator choice
had to move one level up, and the adapted statement says why: TypeScript's
`+` and `-` are syntax, not values, so a conditional in this eager host
cannot return an operator name - it can only return a procedure for the
call to apply.

## Numbers

`aPlusAbsB(3, 5)` is `8` and `aPlusAbsB(3, -5)` is also `8`; `b = 0`
takes the subtraction branch (`aPlusAbsB(2, 0)` is `2`), matching the
book's strict `>`. A fast-check property pins the behavior as
`a + Math.abs(b)` over generated inputs.

## Class and deviations

Adapted row: the statement changes because the host differs - in Scheme
the conditional returns the operator `+` or `-` itself. The TypeScript
form picks between two arrow functions instead, and the statement asks
for that reason explicitly.
