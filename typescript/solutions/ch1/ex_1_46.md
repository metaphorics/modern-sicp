# Exercise 1.46: iterative improvement abstraction

## Approach

`iterativeImprove(goodEnough, improve)` returns a function that loops:
while the guess is not good enough, replace it with its improvement,
then return the accepted guess. The map's recorded shape for this
exercise is that loop inside the returned function, because an arrow
cannot call itself by name and Node gives no tail-call guarantee; the
loop makes each search independent of the others (no shared state).
Square root of 1.1.7 (tolerance 0.001, average with x/guess, start 1)
and the fixed-point search of 1.3.3 (tolerance 0.00001, improve is f
itself) are then one-line applications of the abstraction.

## Numbers

`sqrtIterativeImprove(2)` returns `1.4142156862745097`, `2.1e-6` from
`Math.sqrt(2)`; the 1.1.7 pins reproduce at `sqrtIterativeImprove(4) =
2.0000000929222947` and `sqrtIterativeImprove(9) = 3.00009155413138`.
`fixedPointIterativeImprove(cos, 1)` returns `0.7390893414033928`, the
book's cosine fixed point. For `x^x = 1000` via `y |-> log(1000)/log(y)`
from the guess 2, the search stops at `4.555540912917957`, where
`y^y` is within `0.05` of 1000 - successive-difference tolerance stops
one step short of the true root `4.555532257...`, the honest cost of
the `1e-5` stopping rule. A halving search run from 1 and from 64
confirms the improver is stateless across searches.

## Class and deviations

Adapted row, per the map: "loop inside returned function". Scheme's
self-calling `try-again` closure becomes the while loop, the same
host-truth concession the section module documents for fixedPoint. No
other deviation.
