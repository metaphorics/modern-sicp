# Exercise 3.78: solve-2nd feedback loop

## Approach

The Figure 3.35 network is two delayed integrals and a feedback adder:
`y` is the integral of the delayed `dy` starting at `y0`, `dy` is the
integral of the delayed `ddy` starting at `dy0`, and `ddy` is the
scaled sum `a dy + b y` read back from both integrals. The Rust form
names the two streams with `self_stream` and hands each integral its
integrand as a thunk to the section's `integral_delayed`, which forces
it only when the integral's first tail element is demanded. That
discipline is exactly what closes the loop: when `dy`'s integrand runs,
both definitions are complete, so `ddy` reads finished streams whose
heads are `dy0` and `y0`. The increment order is the book's
`add-streams` Euler order -- the element added to `int` is `dt` times
the integrand's current element -- so `y[1] = y0 + dt (a dy0 + b y0)`
and so on down the memoized spine. The test runs `a = 0, b = -1`, the
harmonic oscillator, and checks `y` against cos `t` at indices 0, 50,
157, 314; explicit Euler both lags the phase and slowly pumps the
amplitude, so the measured errors (0, 2.2e-3, 5.9e-5, 1.6e-2) set the
tolerances 1e-12, 0.01, 0.001, 0.05.

## Map class

`T`. The statement translates whole: the constants, the initial
values, and the looped network are the statement's own. The one Rust
wrinkle is naming: a Rust definition cannot name itself the way
`(define y ... y ...)` does, so the two self-referential streams get
`self_stream` names read only inside the delayed thunks, and the
`delay` of the book's `(integral (delay dy) y0 dt)` becomes the `move
|| dy` thunk `integral_delayed` wants.

## Deviation

None. The network is the diagram's, both integrals go through the
module's `integral_delayed`, and the answer reports the pinned `y`
samples of the one run the exercise asks to study.
