# Exercise 4.76: `and` as a merge join (translate)

The series `and` scans the data base once per frame the first conjunct
produced: `n²/k` matcher calls when a query yields `n/k` frames. The
merge strategy runs the conjuncts separately over the incoming frames
and joins the outputs: `merge_frames f1 f2` folds the base evaluator's
exported `unify_match` over `f1`'s bindings onto `f2`, so common
variables must agree and the rest union; `conjoin_merge` cross-produces
the pairs, counting one compatibility check per pair. The variant is a
top-level dispatcher (`and` handled by the merge join, everything else
delegated to `Eval.qeval`); the global dispatch table is never mutated,
so sibling demos are unaffected.

Deliberate deviation: a merged pair may come from different incoming
frames, so the join is exact for the driver's one empty input frame
(the book's setting) and a superset filter for multi-frame inputs; both
demos run on the empty frame, where the answers are identical to the
series `and`. The pair count is the measured compatibility-check cost:
2 job-programmer frames × 8 supervisor frames = 16 for the first query,
8 × 9 = 72 for the reversed one: the factor-of-`k` saving the exercise
derives.
