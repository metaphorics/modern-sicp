# Exercise 2.41: ordered triples with a fixed sum

## Approach

Three nested mappings over enumerateInterval(1, n) pick i, then j, then
k; the innermost map emits `list(i, j, k)` for the k that survives the
filter `k !== i && k !== j && i + j + k === s`, and flatmap flattens the
two outer levels. Distinctness is checked against the already-chosen i
and j, so no triple repeats a value, and since all three positions range
over the full interval, every ordering of a qualifying set appears once
per permutation.

## Numbers

`length(orderedTriples(5, 10))` is 12: exactly the sets {1, 4, 5} and
{2, 3, 5} sum to 10 within 1..5, and each has 3! = 6 orderings. The
display contains both `"(1 4 5)"` and `"(5 4 1)"`, confirming both order
directions are present.

## Map class

`T`: the book's nested-mapping solution translates directly; the
edition's unary map puts the triple construction inside the innermost
map rather than a three-argument list form.

## Deviation

The batch spec's test sketch rendered the triples by mapping `showList`
over them, but this edition's `showList` double-quotes string elements,
which would wrap every triple in quotes and break the substring checks.
The test displays the triple list itself, printing the same unquoted
string; the solution code is unchanged.
