# Exercise 3.42: Ben's once-created serialized procedures

## Approach

Safe. The serializer's state lives in its mutex, not in the wrapper,
so creating the protected procedures once at construction and answering
the same ones per request allows exactly the concurrency the text's
version allows: any number of calls, serialized one at a time by the
one mutex. The solution builds `BenAccount` with `serializedArg`, the
one-argument form of the serializer, and the tests run the same
scenario (interleaved deposits and withdrawals with injected switches)
against both versions and assert identical final balances. The book's
Scheme point survives intact: there is nothing to save here, because
the serializer is shared state, not per-call state.

## Map class

`T`. Ben's account and the question are the statement's own.

## Deviation

The book's `make-serializer` is indifferent to the wrapped procedure's
shape; Kotlin's arity is in the type, so the serializer has a named
one-argument form (`serializedArg`) that Ben's once-created wrappers
use. The section text says so where it defines the serializer.
