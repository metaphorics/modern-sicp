# Exercise 5.18: traced registers

The exercise asks to print a message whenever a register is read or
written; this edition traces the writes, the path the machine can
observe without perturbing the run. `TracedRegister` overrides the
one write path, `store`, appending the register's name, its old
content, and the incoming value to a sink before storing, and
`TracedRegisterMachine` overrides the one register factory,
`newRegister`, so every named register of the machine is a traced
one. The flag is an ordinary register created by the base
constructor, so only the controller's registers report.

The subclass construction is the trap of this exercise, and the
landed form is deliberate: the base `Machine` constructor allocates
its registers from its argument list before the subclass's fields
exist, so `TracedRegisterMachine` passes an empty list and allocates
every register itself in an `init` block that runs after `sink` is
initialized. The pin shows the ordering is right: the log opens with
`a: *unassigned* -> 12` and `b: *unassigned* -> 8`, the driver's own
input writes, reported like any other store.

`tracedRegisterGcdLog()` pins the whole run on gcd(12, 8): eight
store lines, the two inputs, then `t` taking each remainder (4, then
0) and the register shuffles walking a and b down to 4 and 0, and
finally the answer read back, `gcd(12, 8) = 4`. The old-content chain
in the log (`a: 12 -> 8`, `a: 8 -> 4`) is exactly the gcd
computation, one reported store per machine write.
