# Exercise 5.19: breakpoints

A breakpoint is set at a label with a 1-based offset: the book's
`(set-breakpoint gcd-machine 'test-b 4)` sits just before the
assignment to `a`, three instructions past the label, and resolves to
an instruction index at set time, a past-the-end breakpoint being a
typed failure. The monitor checks the breakpoint set as the machine
ARRIVES at an instruction; `proceed` executes the instruction the
machine rests on and the checks resume, so each stop is examination,
not a trap.

`ex_5_19 ()` on gcd(12, 8): start stops at `test-b 4` with
a = 12, b = 8; proceed stops there again with a = 8, b = 4; proceed
completes with a = 4. `cancel_breakpoint` removed, a rerun on (20, 14)
completes with a = 2; two breakpoints set and `cancel_all_breakpoints`
given, a run on (25, 15) completes uninterrupted.
