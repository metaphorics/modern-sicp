# Exercise 3.6: generate and reset rand

## Approach

The book's two symbols become the members of the request union:
`{ _tag: "Generate" }` and `{ _tag: "Reset", newValue }`. The hidden
state is one `Ref`, so a reset re-seeds the very cell generate draws
from and the repeatable-sequence property is structural rather than
promised. Generate is the section's `Ref.modify` over `randUpdate`;
reset is `Ref.setAndGet`, answering the state it installed (the book
leaves the reset call's value unspecified).

## Numbers

From seed 42 the sequence is `11355432`, `2836018348`; a reset to `42`
replays exactly that pair. A reset to `7` mid-sequence makes the next
generate answer `randUpdate(7) = 1892583`. Two generators keep
independent state; resetting the first to the second's seed makes
their future draws coincide.

## Map class

T (plain port).

## Deviation

The reset request answers the new state; Scheme's `((rand 'reset) v)`
call's value is unspecified in the book.
