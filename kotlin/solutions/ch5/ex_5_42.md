# Exercise 5.42: lexical addressing in the code generators

Lexical addressing replaces a local name lookup with a pair of
indices: the distance to the frame containing the name and its slot
inside that frame. A name not found in any lexical frame remains a
global lookup.

`lexicalAddressingReport` resolves `n`, `product`, and `counter` in a
two-frame model, checks that the addresses are distinct, and fetches
their corresponding values. It also compiles the same Kotlin guest
program with `CompilerOptions(lexicalAddressing = true)` and with
the option disabled. Those compilations exercise the option; the
report's address and value verdicts come from the model in
`E5_39.kt` through `E5_41.kt`, not from pinning the book's Scheme
instruction positions.
