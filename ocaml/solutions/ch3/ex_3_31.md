# Exercise 3.31: why accept-action-procedure! runs its action immediately (translate)

The map class is `T`: the question is about the agenda's scheduling
discipline, not about any Scheme-specific machinery, so the answer
translates as a direct comparison between `Circuit.wire`'s
`add_action` (which runs the action once at attach time, as the book
does) and `make_wire_without_initial_run`, a variant built for this
exercise whose `add_action` only appends to the action list. Without
the initial run, a gate wired up after its inputs are already settled
never computes its first output: the output wire keeps its
power-on-reset value of 0 until some later signal change triggers
propagation, which is exactly the bug Louis Reasoner's proposal would
introduce.

Sample: `ex_3_31 ()` answers `(1, 0)`.
