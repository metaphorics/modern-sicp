# Exercise 2.22: the iterative `square-list` bug

## Approach

The first rewrite is implemented and shown to produce the reversed
answer: prepending each square while visiting front to back mirrors the
visit order. The second rewrite cannot be built on `List<i128>` at all,
and that is the edition's sharpened answer to "this doesn't work
either": `List::cons` takes its element by value, and a `List` is not an
`i128`, so the swapped arguments are a compile error (E0308) in Rust
where Scheme only reveals the misshape at print time. To show the shape
Scheme would build, the solution models the swapped `cons` on the
section's `Nest` type, where the answer wraps the growing structure in
ever-larger branches: `((((() 1) 4) 9) 16)` instead of a flat list.

## Map class

`T`: the statement translates, with the second "explain" half made
concrete by the type system's rejection plus a `Nest`-based
reconstruction of Scheme's result.

## Deviation

The second demonstration uses `Nest` rather than raw pairs, since the
edition has no improper pairs; the printed shape carries the same
lesson.
